# counter — battle/cinclude-1：B（默认保留 `#include`，严格模式按包启用）

| 项 | 值 |
| --- | --- |
| 主张 | **B**：语言默认保留 `#include`；新增 `--strict-c-include` 或 `ct.pkg` 的 `c-include = forbid`，由项目/包主动启用；`.m.ct` + shim 仍为官方封装路径 |
| 基线 | `85579c4d`（v0.63.2）；证据在 `/tmp` 由 HEAD 源码重建的自举链上取得 |
| 结论 | **B 胜出**（J-1/J-2/J-4/J-5/J-6）；J-3 只算有条件成立：B 不承诺 `#include` 单点规则能封死全部 C 边界 |

**B 的形态。** 默认路径一字不改：无开关时 `#include` 照旧直通（C 超集契约）。启用二选一，CLI 覆盖清单：
`ct build --strict-c-include`，或 `ct.pkg` 写 `c-include = forbid`（默认 `allow`）。strict 作用域是
`.ct` / `.h.ct` 的**直接** `#include`；`.m.ct` 的 prologue 与 `.shim.h/.c` 仍是官方封装出口。回退只删
开关/清单键，源码零改动，不需要版本级迁移。

### 2.4 对 B 不利的证据（明示）

- **默认放行就是原状**：688/1289 个 `.ct` 继续可直连 C，A 想解决的“绕开封装”在默认路径原样存在；strict 是 opt-in，可能无人启用。
- **strict 不是沙箱**：`extern`（4 行，`errno` 就要求它，spec 1801）与 `#ct-raw`（17 行/8 文件）不经过 `#include`；只禁 include 时它们照常编译。
- **清单键对旧工具无约束力**：未知 `ct.pkg` 键只报警告（`Pkg.h.ct` 424–437，package-guide 70）；旧版 `ct` 会忽略 `c-include = forbid`。须用 `requires` 钉版本；`ct verify` 不读 `ct.pkg`（package-guide 123）。
- **strict 对 `.h.ct` 有代价**：shim 只为 `.m.ct` 探测（spec 680），严格库包若在公开头暴露 C 类型，只能改 opaque/`void *`。

## 6. E5：A 的最强论点（steelman）与逐条反驳

A 原文（question.md）：**“`.ct` / `.h.ct` / `.m.ct` 默认不得出现 `#include`；C 声明只能通过 `.shim.h` 暴露”**（15 行）；
**“现有 688 个含 `#include` 的 `.ct` 文件必须迁移；迁移期用显式 `allow-c-include` 文件/包标记 grandfather，默认关闭”**（16 行）；
**“编译器自身与 `lib/std` 也必须按 shim 迁移，不能永久豁免”**（17 行）。

A 最强之处：**只有默认翻转才改变“新代码”的行为；opt-in 在无人启用时等于没改，grandfather 又能把旧代码全部放行，最后仍回到现状。** 且官方 `.m.ct`/shim 路径已存在，迁移看起来只是一次性成本。

1. **“官方路径已存在”只对 `.m.ct` 成立。** `.h.ct` 旁的 shim 被忽略（P5）；`.h.ct` 的 include 会进入生成头（Emitter 1563–1572）。A 要覆盖 `.h.ct`，必须新增“header shim”能力。
2. **自举链挡住了“机械迁移”。** ct-ast 由 L2 构建，L2 连 `.m.ct` import 都不能解析（P4）；A 的 17 行“必须迁移”等于要求解冻 L2 或换构建器，不是 688 次文本替换。
3. **默认翻转并不实现 A 自己的目的。** `extern` 与 `#ct-raw` 不经过 include；A 的 18 行只说“限制或至少纳入同一策略”，没有机制。扩到 `extern` 会破 `errno` 用法（spec 1801）与 C 超集；不扩则仍是“可绕过的默认”。
4. **A 的 grandfather 就是 B 的包策略，只是更差；且 490+172 个测试/示例文件是夹具，不是“绕开基础库”的生产代码。** `allow-c-include` 默认关闭 = 688 文件/包逐个标记，形成长期双轨；B 的 `c-include = allow|forbid` 作用域是包、可 grep、可一键回退，且不破坏未启用的消费者；A 在迁移压力下会收敛到 B，纳入夹具只会制造 golden 重生成与评审噪声。

## 7. 结论与失效条件

**结论：B 胜出。** J-1/J-2/J-4/J-5/J-6 由证据支持：默认保留使自举链、`lib/std`、688 个现有文件零迁移；
严格模式落在包/项目层，机械可查、可回退；`.m.ct` + shim 的官方路径不被破坏。J-3 **有条件成立**：B 明确
不把“只禁 include”宣传成防绕过沙箱；若需要零绕过，把 `c-raw = forbid`、`c-extern = forbid` 作为同一
opt-in 策略包启用，仍不破坏默认路径。

**B 的失效条件（反证清单）：**

1. strict 无法在不改默认的前提下实现，或 `c-include = forbid` 无法用 `requires`/锁文件钉住版本（旧工具静默忽略）→ “零迁移”与 J-6 的机械验收失效。
2. 裁判把 J-3 解释为“必须阻止 `extern`/`#ct-raw`”，而 B 拒绝把它们并入策略 → B 在该判据上失败。
3. 严格库包必须在公开 `.h.ct` 暴露 C 类型且不接受 opaque/`void *` → strict 对该类包不可用；B 需保留 `.h.ct` 例外或新增 header shim。

**生效范围**：默认路径不变；strict 只约束主动启用的项目/包；`.m.ct` prologue 与 `.shim.h/.c` 的现有契约
不变；本文件不改源码/规范/测试，实现需另立 phase 并按 G4/G5 补负例与文档。
