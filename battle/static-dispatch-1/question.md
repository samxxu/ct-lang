## 位置 A（提案原案）

1. **R1**：接收者静态类型为具体 struct 时，trait 方法调用直接发 `<S>_<T>_<m>(…)`；只有接口值 / 指针 / 数组元素保留 vptr。称“纯发射端改动，不动解析与符号表”。
2. **R2a**：返回局部接口值的悬垂读改为硬错（或物化），称当前仍是“静默悬垂（实测 200 ≠ 201）”。
3. **R2b**：方法结果作接收者（`f().m()` / `chain().next()`）提升为 `__ct_tmpN`，打通 README §0.1 完整路径。
4. **R3a**：起草《稳定子集冻结清单》三档；**R3b**：版本位规整二选一（接受偏移并机器化 / 1.0 重对齐）；**R3c**：包仓状态只读索引页。

## 位置 B（反证席）

1. **R1** 的前提真，但“纯发射端 + 所有具体接收者”不成立：跨单元 impl 的方法符号是 `static`，消费者只能经 vptr 派发；静态化要么导出方法（ABI 变更），要么只做同单元子集。
2. **R2a** 的悬垂读已由 SH-75 修复（SH-75 收口，`0 201`）；当前残留的是“堆物化 + 进程寿命盒子”的既有取舍，属设计决策，不是 P0 bug。
3. **R2b** 只对“方法结果”成立；自由函数结果、固有 `impl` 结果已经可作接收者。SH-73 是 battle/langcap-1 判过的 **C 设计拒绝**，不是漏实现；且 R2b-J1 与“断点 1 仍在”自相矛盾。
4. **R3a** 的稳定子集清单仍是真缺口；**R3b** 已被主规范 1.16.0 的 `v<M>-PH-<n>` 与 PH-67 取代；**R3c** 属外部包仓，不是 CT 可执行项。
