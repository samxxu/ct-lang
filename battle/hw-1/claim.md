## 6 E5 对 B 最强论点的 steelman 与逐条反驳

B 原文见 `question.md:23-29`；五条逐条回应，最锋利的是 B1、B3。
1. **B1“pilot 应在 PH-64 之前：先用真实板暴露 freestanding/alloc/const 需求，再冻结契约”**——steelman：真实板能暴露 host 测不到的 ABI/volatile/中断约束。反驳：pilot 的 H1/H2 交付物就是 UART/GPIO/状态机（`ct-hardware-pilot-proposal.md:65-70`），不需要容器；而它今天第一步就会撞上 E1-1 与 E1-4，H0/H1 的时间会花在已知缺陷上。契约三条（constructor、单元拉取、const）在 host 上一条命令可测（E1-3/4、E2），不需要板；先冻结还让 H0 的“版本冻结”只发生一次。pilot 失败仍可 no-go。
2. **B2“freestanding 不应一刀切禁容器：`Str` 只用 malloc/free，若 `--alloc` 映射它们应可用；`Vec` 需要 realloc 的话把 alloc 扩成 malloc/free/realloc，而不是禁容器”**——steelman：`Str.h.ct:25/39` 与 `Vec.h.ct:153` 证明 `Str` 只用 malloc/free、`Vec` 增长只用 realloc。反驳：E1-4 的 `nm -u Vec.o` 还列出 `abort/fprintf/stderr/memcpy/memset`，加 realloc 不足以 freestanding 化；且 `--alloc` 是“允许堆”的托管契约，`Str` 的 Drop 会把 `free` 带回启动路径。A 的让步：`Str` 记 **deferred**（触发 = pilot P0 证明需要 **且** `--alloc` 映射 malloc/free），`Vec/Map` 仍不在 freestanding 支持。
3. **B3“const vtable 条件化（仅 freestanding）可避免全量 ABI/golden 变更；或先 pilot 再决定”**——steelman：模式条件化确实能让托管侧字节不变。反驳：**全量 golden 变更不存在**（E4：实测 0 文件/0 行）；条件化买不到成本，却让 `.h` 形状随模式变，跨模式链接与后续门禁多一维。一次到底更便宜、更可测（E3-P3）。
4. **B4“PH-64 的 S1/S2/S3 是 CLI/生成契约，不是语言特性；`layout(plain)` 可以先做文档，不应阻塞”**——回应：A 本就只把 `layout(plain)` 写进文档、不立语法（A 第 6 条），此点无分歧；“不是语言特性”恰恰说明它便宜、host 可验、无设计风险，应作为 pilot 的前置冻结项，而不是 pilot 的产出。
5. **B5“先做 P0 + pilot，再决定 PH-64 是否拆成两个小相（freestanding/alloc 与 const vtable）”**——回应：拆相与顺序正交。PH-64 的 S1/S2/S3 已按独立提交/独立回退设计（提案 §5），无需 pilot 就能决定拆分；若 pilot 暴露新需求，按 issue 重开 PH-64 即可，不必用 pilot 预占契约。

## 7 结论：A 胜出/不成立的条件

**A 胜出需全部成立**：① EDITOR 把 J-1 裁定为**语义零变化 + 50 行 banner 随 V-3 变化**（坚持字面零变化则 A 的 J-1 不成立，A 主动改口径）；② P0 行为修复只在 ct-ast（L0/L1/L2 只改版本号），新夹具进 `test/ast`；③ PH-64 开卡前修正 AGENTS §0.3 的 `d`，版本位 `v0.63.0`；④ `Str` 按 deferred 登记（A 对 B 的唯一实质让步），`Vec/Map` 不在 freestanding 支持；⑤ E3-P3 跨模式链接夹具转绿，const 一次到底不留双形态。

**A 不成立（任一）**：E3-P2 在 PH-64 收口后仍做不出机械 freestanding 基线（顺序应倒转）；pilot P0/P1 以证据证伪“无需容器”；P0 出现非 banner 的既有 golden 语义 diff，或 P0 必须改 L0/L1/L2 才能成立；const 一次到底引入跨模式/跨单元链接失败或 `check-warnings` 红（E3-P3 红）。

**J-6 收口**：新需求文档以本主张为骨架，逐条 `REQ-*` 写优先级、验收命令、依赖（P0/PH-64/pilot）与来源；`question.md` 与两份提案中的“建议”一律标为提案，不写成已承诺。
