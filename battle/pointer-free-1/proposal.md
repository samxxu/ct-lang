# 提案：指针退场——`box` 句柄 / `new` 表达式 / 切片 / `ref`·`out` / `Str` 一等化

> 状态：草案（供评审）
> 基线：v0.77.0
> 定位：语言层增量（一个新关键字 `new`、四个内建类型形态），非重写；
>       指针**永不禁止**，本提案把指针从「日常类型」降级为「逃生通道」。
> 总目标一句话：日常 `.ct` 代码里没有指针、没有 own、没有 defer、没有 errdefer——
> 它们与 goto 同列「逃生通道」一节。

---

## 1. 背景与动机

CT 的句柄机制已在 `Vec<T>` / `Map<K,V>` 上验证：用户全程不碰指针，引用计数 + 借用视图 +
失效检测在句柄协议内零成本运转。但句柄目前只覆盖「容器」一个场景，应用代码里指针的
五大日常用途——堆单对象、多返回、数组传递、字符串、回调——全部仍裸奔。

本提案把这五个场景逐一收进句柄/值类型，配套最小语法增量。设计原则与全程讨论结论：

- **机制最小化**：每一场景只新增一个概念，且尽量复用既有机制（Vec 句柄、花括号初始化、
  CFG 定值检查、PH-65 边界）；
- **零禁止**：指针、own、defer、errdefer 在任何层级都保持合法；
- **初始化单一化**：不存在「构造函数 vs 花括号」双轨——花括号是唯一初始化语法，
  需要校验时用普通工厂函数（命名约定 `make_*` / `new_*`），零新语法。

## 2. 设计总览

```
┌──────────────────────────────────────────────────────────────┐
│ 日常层（默认）                                                  │
│   单对象堆分配   → box<T> 句柄      new T { .a = 7 }          │
│   多返回        → ref / out 参数标注                            │
│   数组传递      → T[] 切片（{ptr,len} 值类型）                  │
│   字符串        → Str 一等字面量类型                             │
│   回调          → 函子参数类型 (A, B) => R                     │
├──────────────────────────────────────────────────────────────┤
│ 逃生层（合法、不鼓励、圈禁在边界）                                │
│   指针 / own / defer / errdefer / malloc                      │
│   适用：FFI 内部、MMIO、自定义分配器、未句柄化的资源             │
└──────────────────────────────────────────────────────────────┘
```

## 3. 分场景设计

### 3.1 `box<T>` 内建句柄 + `new` 表达式

**`box<T>`**：`Vec` 句柄机制泛化到单元素——头部结构（refs + data）+ retain/release +
借用视图 + 失效检测，实现与 `Vec` 同构，零新机制。

**`new` 表达式**（全提案唯一新关键字）：

```
new_expr ::= "new" type_name braced_init
box<Record> r = new Record { 7, "x" };
box<Record> s = new Record { .tag = "y", .id = 8 };   /* 指定初始化完全兼容 C */
```

规则：

- 花括号部分与 `T x = { ... };` 的初始化语法**逐字节相同**（位置式 + `.field =` 指定式，
  无第三种初始化语法）；
- `new` 使对象落在堆上、返回 `box<T>` 句柄；无 `new` 时 `T x = { ... };` 照旧是栈上值，
  行为不变；
- 块出口自动 `release`，refs 归零时先跑 `Drop`（若声明）再 free；
- **无构造函数**：需要不变式校验时写普通工厂函数（`Record make_record(Str tag)`），
  命名约定 + lint 提示，不进入语言。

### 3.2 `ref` / `out` 参数标注

```ct
void scale(ref int x, int f)   { x = x * f; }        /* ref: 可读写的调用者变量 */
bool parse(Str s, out int len) { if (s.len==0) return 0; len = s.len; return 1; }
/* 调用点：scale(v, 2); parse("ab", n); —— 传变量本身，无 & 无指针 */
```

- 发射端生成指针，源码层指针消失；
- `out` 参数在每条退出路径必须被写：复用 PH-70 的 CFG 定值检查，未写为硬错；
- `ref`/`out` 只接受**左值变量**（拒绝字面量/表达式，报错位置在形参声明）。

### 3.3 切片 `T[]`：数组的函数间形态

三种形态分工：

| 类型 | 本质 | 用途 |
| --- | --- | --- |
| `T a[5]` | 栈上定长存储 | 局部数组、C 互操作 |
| `T[]` | `{ptr, len}` 值类型 | 函数参数、子切片 |
| `Vec<T>` | 引用计数句柄 | 动态长度、跨函数持有 |

- **定长数组 → 切片**：`sum(int[] a)` 传 `int data[5]` 自动补 len，`int *a, int n`
  双参数约定与 `sizeof` 衰减坑同时消失；
- **子切片**：`a[2..]`、`a[1..n]` 零拷贝，与 `Str.slice` 同构；
- **Vec → 切片**：**显式**转换（`v.as_slice()` 或借用视图），不开放隐式转换——
  所有权语义保持单一显式入口；
- `foreach` 接受三种形态（现有数组/Vec + 切片）。

### 3.4 `Str` 一等字面量类型

- 字符串字面量默认类型 `char *` → `Str`；
- `char *` 退守为「C 边界类型」：合法于 shim、`.m.ct` recipe、raw 块；应用代码中
  由 lint（建议级）引导迁移，**不硬禁**；
- `std::str` 方法宿主迁移到 `Str`；格式化走 len，消除 `%s` 截断类隐患；
- 性能模型：`Str` 按值传递与现行一致（16 字节），`len` O(1)；ABI 边界转换圈在
  shim 内。

### 3.5 函子参数类型

```ct
void sort(int[] a, (int, int) => int cmp) { … }
sort(v, (a, b) => b - a);    /* 闭包形参类型可从函子签名推导 */
```

- 消灭 `void *env` + `(*fn)` 声明噪音（PH-75 已打通闭包入方法实参，本项补签名层）；
- 发射形态不变（fn + env）。

## 4. 配套规则

1. **不鼓励的软手段**（全部非强制）：std 与官方包全句柄化；`ct check` 对 pub API 裸指针
   给建议级诊断；patterns.md 推荐写法全部用新类型；
2. **圈禁边界**：PH-65 strict C 边界维持现状（管 `#include`/`#ct-raw`/`extern`/函数式宏，
   **不管指针类型**）——指针在任何 `.ct`/`.h.ct` 中永远合法；
3. **std 的后续责任**：File / Socket / Mutex 等常用资源句柄化，是 defer/errdefer 从日常代码
   完全退场的**前提**——作为本提案的 Wave 2 配套任务登记。

## 6. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| `new` 返回句柄而非指针，偏离 C++ 预期 | 文档明示「CT 的 `new` 返回句柄」；语义近 Java/C# 引用 |
| 引用计数循环泄漏**静默发生**，无任何报警 | README/教程显式契约：「引用环 = 泄漏，责任在作者」；与 Rust 的编译期拒泄漏明确区分 |
| `Str` 默认化是 ABI 级行为变化，旧代码字面量 `char *` 批量报错 | 迁移窗口：`c-boundary: allow` 单元豁免 + lint 自动修复建议（脚本级） |
| `box<T>` 头部开销被指「非零成本」 | 与 Vec 同构的开销模型；独占场景仍可选 `own` 路线（逃生层） |
| 软引导力度不足，风格分裂 | 官方包/patterns/tutorial 三处示范 + 审计复审（本提案落地后一轮 patterns.md 复查） |

## 7. 非目标

- 借用检查 / 别名分析 / 并发证明（沿用 PH-71 非目标声明，不动摇）；
- 禁止或硬限制指针、own、defer、errdefer 的任何使用；
- 构造函数语法（工厂函数约定已覆盖）；
- 惰性迭代器（维持此前结论：语言层不可达）；
- `new` 的数组/容器形态（`new int[] {...}` / `new int[100]` 均被拒：
  Vec/Map 花括号字面量已覆盖，定容用 `reserve`）；
- GC。

## 9. 开放问题

1. `new` 是否允许省略左侧类型（`auto r = new Record { ... };`）？倾向不允许
   （CT 不做类型推导的一贯立场），评审裁定。
2. `out` 参数是否允许多个（`f(out int a, out int b)`）？语义无冲突，倾向允许。
3. `box<T>` 与 `Vec<T>` 的借用视图规则若有出入，以谁为准？倾向以 Vec 为准逐字复用。
4. `Str` 迁移窗口的 lint 自动修复是否进入 v0.x 补丁位，还是随 S5 一次性落地？
5. pub API 裸指针的建议级诊断，是 `ct check` 默认开还是 opt-in？
