## 2 新增 E1-r2：同一"正常头文件"今天就能产出可被 C 链接的库制品

> 与 T2 的 E1 不重复：T2 只做了 `nm`（符号静态/外部）；本轮是**新命令**——外部 C 消费者编译、链接、运行。


**这条证据说明三件事**：

1. `test/modules/p34_pub_generic` 这个"含泛型 `pub` helper 的库"今天已经能产出**纯 C 可链接**的制品：头里只有 `from_lib`，泛型 helper 不出现，C 消费者零适配即可运行（`from_lib(4)=4`）。
2. 所以 A 的 L39-1 不是"阻止一个不可实现的承诺"，而是**撤销一个今天已经可用、且正是 J-1 所要求形态**（只导出 `from_lib`）的产物。主张席 §4.3 第 3 条"现有测试与产品路径不受影响"在此不成立：受影响的是 `--emit-c` 这条既有产品路径在 `--lib` 下的一致性。
3. 主张席的 E1-2 自己展示了同一份 `lib.h`（`claim.md:101`：只有 `from_lib`）。**既然现状已经把 `id` 判为"不可导出且不报错"，A 要做的不是发现新事实，而是把既有的"可导出集合"定义从"C 兼容子集"改成"全量 pub 或整建失败"**——同一编译器、同一单元，两条出口给相反结论。

## 5 A 若做"泛型 `pub` 跳过"修正：是否仍违反 J-1 / J-2？

这是本轮最实质的问题。必须分两种修法，结论不同：

### 修法 (a)：**静默跳过**（`pub T id<T>` 不进 `.abi.h`，不报错、不中止）

- **J-1 / J-2 在三夹具上恢复**：f2 不再整建失败，`.abi.h` = `{lib_add}`，与作者意图一致；`p34_pub_generic` 也能成库（本轮 E1-r2 证明今天的 `--emit-c` 产物恰好就是这个形态）。**这一点我承认：a 修法下我的 C1/C6 失效。**
- **但 J-5 直接失败**：`question.md:22` 要求"被拒绝的签名必须给出 `file:line:col` 与原因，**不得静默丢弃**"。作者写了 `pub`，被无声丢弃，正是 J-5 禁止的形态；主张席在 E1-2 里已经展示了这种静默（`lib.h` 无 `id`、无诊断），并把"把这个静默变成 L39-1"当作 A 的必要性。
- **且主张席自己的 E3（`claim.md:347`）判它"不是 A"**："得到一个静默省略 `id`/`max2` 的 `.abi.h`，则 A 没有成立（实现退化成了 B 的静默剔除）。"

**结论**：a 修法用 J-1/J-2 换 J-5，同时按主张席自定的可证伪条件已不再是 A。它是 B 的隐式版——"标记"从显式声明变成"签名恰好 C 兼容"。

### 修法 (b)：**跳过 + 警告**（不中止，但报 `file:line:col` 诊断）

- J-5 恢复；J-1/J-2 的三夹具也通过。
- **但 J-1 在通用情形仍失败**：导出面 = "全部 C 兼容的 `pub`"，签名兼容是**必要**条件，不是作者意图。C 兼容的内部 helper 会被强制导出，作者没有任何手段排除。HEAD 实例：`selfhost/ct-ast/**/*.h.ct` 的 72 个 `pub` 顶层函数全部 C 兼容（T2 扫描），其中 `Symbols.h.ct:423 pub int ct_impl_add(...)`、`:431 pub int ct_tmpl_find(const char *name)` 是跨单元内部访问器——b 修法下它们会全部进入 `.abi.h`，与"作者明确要导出的集合"无关。
- 这也正是"隐式 ABI 增长"（主张席 §7 预判第 4 条、`claim.md:375`）：作者每加一个 C 兼容的跨单元 helper，ABI 面就悄悄长一项，且没有审查点。

**最终回答**：
- **不修正（硬错）**：违反 J-1、J-2（已实证）。
- **(a) 静默跳过**：J-1/J-2 三夹具通过，违反 J-5；且按 `claim.md:347` 已不是 A。
- **(b) 跳过 + 诊断**：J-1/J-2/J-5 三夹具通过，但 J-1 的通用情形（导出集合 = 作者意图）仍失败，因为签名兼容 ≠ 意图。

所以"A 做泛型跳过修正"不是把 A 修好，而是**把 A 收缩成 B 的一个隐式变体**；它不再是本庭的 A（`claim.md:21` 定义含"硬错…不写任何产物"）。若主张席要提 (b)，那是一个新方案，应按 §7.10 另行立案、由原反对席再评审——不能作为本庭 A 的补丁。

## 6 己方最弱处（本轮更新的自助披露）

1. **我的 J-1 论证是"意图不可判定"，不是"意图相反"**：`main.ct:9` 只证明 `id` 有 CT 用途，不能证明作者**不想**把它给 C 消费方（作者从未写过声明）。若裁判接受主张席的前提"`pub` 即导出意图（S-1）"，A 的 J-1 就成立。我的证据能推翻的是"`pub` 必然等于 C 意图"，不能推翻"作者可以这样打算"。
2. **J-3 和 J-4 我完全让给主张席**：A 在语言面/实现面确实更小；若裁判按"三项全过才 up"，A 已拿下 J-3/J-4/J-5，只在 J-1/J-2 上失分。
3. **撤回条件**：若主张席能给出"作者意图 = 全部 C 兼容 `pub`"的正面依据（例如 P34 或 PH-39 明写"`.h.ct` 里每个 C 兼容 `pub` 都承诺 C ABI"），我撤回 J-1 主张；目前该依据不在 HEAD 文本里，S-1 是争点自身，不能自证。
