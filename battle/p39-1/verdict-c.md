## 2 逐条判定

### 2.1 J-1 意图一致 —— **不成立**

**C 的规则**（`C-proposal.md:26-27`）：候选面 = 根单元；根单元内 C 兼容 `pub` 一律导出（C-2）。作者只有两个输入：把哪个单元当根、把哪个 `pub` 放进非根单元（C-4′）。

**为什么不成立**：
1. **同根单元内没有函数级选择。** 主张席在 `claim-review.md:16` 写「**成立（文件级），但不解决函数级**」，并承认「同一根单元内仍不能逐个选」。判据（`question.md:18`）要求「只导出作者要的」；文件级控制只把失败面从 N 个单元缩到 1 个单元，类别错误仍在。
2. **实例已出证**：`counter-review.md:79` 的 E2-r3a 给出 `selfhost/ct-ast/frontend/sym/Symbols.h.ct:405` `pub struct StructTmpl *ct_tmpls(int *n);`——C 兼容的主类型访问器，该单元作根即被 C-2 强制写进 `.abi.h`；唯一排除手段是拆单元，而 `AGENTS.md:452` 要求「围绕主类型留在同一文件」（E2-r3b，`counter-review.md:80`）。C-4′ 不是零成本，也不是「明确要导出」的声明。
3. **f3 仍不成立**：C-4 保留 D39-6 的硬错，f3 原样作根 exit 1（`C-proposal.md:63` 自认）；主张席的「可接受」以 C-4′ 重排为前提（`claim-review.md:30-35`），而 J-1 的判据文本没有「重排后算过」这一档。
4. f1/f2 的通过依赖 B1（`claim-review.md:62`、`counter-review.md:86`）；W3/W4 只证明泛型跳过与今天符号面等价，不提供意图信号。

**本席不采用的论证**：W8（`--lib` 未实现）只说明 P-C1…P-C6 不可执行（§3），不作任何一方的胜证；J-1 的失败由 C-2 的规则文本 + E2-r3a 的 HEAD 实例独立成立。

### 2.2 J-2 既有代码零语法改动 —— **不成立**

- C 自报「成立 3/5 + `lib/std` 自动路径」（`C-proposal.md:64`）：`xunit_box`、`ns_types` 两个 trait 值单元与 `Str.h.ct` 作根仍按 D39-6 硬错，需 B2 才能成库（`counter-review.md:87`）。
- 判据原文（`question.md:19`）要求 `lib/std/**`、`test/modules/**` **不改一行即可构成 `--lib` 库**；3/5 不是全绿。
- W2 证明非根 `pub` 必须保持 external（`nm -u main.o` 有 `_add`、`shapes.o` 有 `T _add`），这只说明 C-1 与 HEAD 链接语义相容，不解决两个 trait 单元不能作根。
- 残余失败由 D39-6（用户已批）造成——本席在 D-001 已把它归为用户决定，但在本条判据上仍记 **不成立**（判据文本未满足），并把它转成 open-question 的裁定项。

### 2.3 J-3 语言面最小 —— **成立**

- 零关键字、零语法、零新 CLI：C-1…C-7 全是卡面语义规则（`claim-review.md:64`、`counter-review.md:88`）。
- 需要 B1+B3 是**冻结/语义批准**，不是语法批准；J-3 只计语言面，故成立。
- 注意：J-3 成立不等于可落地——B1/B3 未批前不得实现（§4）。

### 2.4 J-4 实现成本 —— **成立（设计层，附条件）**

- 2 文件 / 约 55–75 行（`C-proposal.md:89-91`），≤80；G1/G3/G4 判据零改动。
- W1：`fn_start`（`Module.h.ct:723`）/`fn_end`（`:742`）夹住本单元 parse，`Unit.h.ct:27-28` 已声明——「只扫根」不需要新字段，成本估算有代码依据（限制：单态化实例是否落在区间内需 `is_pub`/`ntparams` 过滤，未实测）。
- W5/W6：`struct Fn` 无 `col`（`Symbols.h.ct:80-116`），但 `sem_error` 的列号由调用方给（`Diag.h.ct:85`），回读声明行可得正确列（`id=7`、`max2=7`、`add=9`）；**必须剥掉 `<...>`**，朴素实现得 `col=15`（W6 后半）。这一细节还没进 C §5 的实现清单，落地时须补。
- 条件：若 (b) 拿不到列号，C 自己规定回单方案评审并可能 3 文件（`counter-review.md:89`、`C-proposal.md:97`）——届时 J-4 不再是「≤2 文件」，须记偏差。
- 判定成立（设计层），落地按 G8 复核。

### 2.5 J-5 可诊断 —— **不成立**

**真改善**：根单元内泛型从「零诊断省略」（V2）变成带 `file:line:col` 的 L39-1w；W6 证明回读列号可行，W5 证明硬错通道 `sem_error` 天然带列。这一格通过。

**但整条判据不成立**，两条独立反例：

1. **`pub extern` 无任何诊断。** 今天 `--emit-c` 的生成头里有 `int lib_fn(int);`（E1-r3b，`counter-review.md:62-73`；源码 `test/modules/extern_decl/lib.h.ct:6`）。C 的 `.abi.h` 会省略它，而 C 的规则集里没有一条诊断覆盖它（D39-2 / C-7 `C-proposal.md:33` / `phase39-draft.md:201`）。作者写了 `pub`，产物里没有，stderr 一个字都没有——这正是 J-5「不得静默丢弃」禁止的形态。它同时证伪 C 自己的承诺：`C-proposal.md:53`「作者写下的每个 `pub` 都有明确去处」、`:67`「无静默路径」。
2. **非根 `pub` 的观测粒度回退。** 今天非根 `pub` 在**它自己的生成头**里有逐函数原型（E1-r3a：`int helper(void);`，`counter-review.md:42-58`）；C-1 把它移出 `.abi.h` 后只剩 C-5 一条**无位置**汇总（`C-proposal.md:31` 自认「无位置可指」）。J-5 要求「被拒绝的签名必须给出 `file:line:col` 与原因」，汇总行不满足。
3. 补充：L39-1w 是 warning、非阻断，不开 `-Werror` 时产物照出（`counter-review.md:29`），诊断强度低于硬错；这不单独构成 J-5 失败，但放大了第 1、2 条的后果。

## 3 为什么是 `rejected`（§7.9）

- C 满足 J-3、J-4；**J-1、J-2、J-5 不成立** → 「主张方案满足全部判据」不成立。
- 反证清单中 F-C1（同根 helper 强制导出，J-1）、F-C2（`pub extern` 无诊断，J-5）、F-C3（非根 `pub` 无逐条位置，J-5）、F-C6（trait 单元不能作根，J-2）被 W1–W8 或 HEAD 实例证实（`counter-review.md:94-104`）。
- **不是 `undecidable`**：J-1/J-5 的失败来自 C 的规则文本与 HEAD 实例（E1-r3a/E1-r3b/E2-r3a），不依赖未实现的 `--lib`；W8 只说明六条可证伪预测不可执行，本席把它列为「执行层无法判定」，不作双方胜证，也不改变规则层判定。
- 与 A 的判决结构一致（J-3/J-4 成立，J-1/J-2 不成立），但 C 多出的 J-5 也不成立——C 不是 A 的合格替代，只是把失败面收窄。
- **本判决不判 B 成立**：B 在本庭从未过庭、无 E1–E5，且其原始定义（「未标记的 `pub` 不导出也不报错」）本身撞 J-5。`rejected` ≠ B 成立。

## 5 给用户的决策要点（≤10 行；两案二选一，本席不替你选）

1. **选 C（零新语法）**：批准 B1（泛型从硬错改「跳过 + 列号诊断」）+ B3（冻结卡变更签字：O2/§1.1/§3.1/L39-2/R2/R3/E39-3/负例台账）。
2. C 的失败面：同根 C 兼容 helper 仍全导出（作者不能逐函数选）；`pub extern` 与非根 `pub` 无逐条 `file:line:col`；多单元公开 API 需再造 wrapper 根；trait 值单元不能作根（除非另批 B2）。
3. C 的回退：撤 `--lib` 分支，语言面零残留，`ct build`/`--emit-c` 逐字节不变。
4. **选 B（1 次语法批准）**：批准 `pub export` 标记或 `--export` 清单，函数级导出意图，J-1 正面解决。
5. B 的失败面：既有 `.h.ct` 要加标记才能成库（J-2 的「不改一行」不成立）；成本约 100–160 行（J-4 超 80）；未标记 `pub` 仍需单独设计诊断（J-5）；编辑器高亮、文档、负例同步。
6. B 的回退：撤标记语法 + 高亮/文档，比 C 的面大。
7. **两案都未通过全部判据**：本庭判 A `rejected`、C `rejected`，不判 B 成立；选哪条是成本/风险取舍，不是胜负。
8. **默认（2026-12-01 前无裁定）**：按 §4 的默认规则走 C 的 B1+B3 提请；不获批则 R2/R3 顺延、不以 A/B 替代。

## 7 失效条件（C 的判决何时重开）

1. 用户批准 B1（泛型诊断）或 B2（trait 值降级）→ J-1/J-2 的失败面变化，须按新规则重判。
2. C 的 C-2/C-7 修订为「根内也有函数级过滤」或「`pub extern`/非根 `pub` 有逐条位置诊断」→ J-1/J-5 需重判。
3. 列号回读 (b) 实测失败 → J-4 的 2 文件上限不再成立，须记偏差并重审。
4. `--lib` 落地后 P-C1…P-C6 任一条不符 → C 的实现面与本文断言不符，须重开。
