## 0 一句话

**C = 把导出面从「本次构建所有非内建 `.h.ct` 单元」收窄到「`--lib` 的根单元」，根单元内按符号类别分级处置：C 兼容签名导出；无外部符号的泛型模板跳过并给 `file:line:col` 诊断；有外部符号但签名不可 C 表达的按 D39-6 硬错。作者用「列不列进 `--lib`」与既有的 `import` 文件组织控制导出集——零新语法、零新 CLI 选项、≤2 文件。**

它同时满足：A 的零新语法 / 可诊断 / 低成本；B 的作者可控导出集 / 不静默丢弃。**函数级**标记（B 的 `pub export`、`--export` 清单）在零新语法约束下不可得——C 明示这是上限，不假装解决。

## 1 规则（C-1…C-7）

| 规则 | 内容 | 落码（相对卡面） |
| --- | --- | --- |
| **C-1 候选面 = 根单元** | 导出候选集 = `--lib` 命令行给出的**根 `.h.ct` 单元**内有定义（`Func.body >= 0`）的 `pub` 函数。被 `import` 的非根单元**不进**导出面；其 `pub` 的跨单元可见语义不变（`language-spec.md:617`） | 卡面 O2（`:37`）与 §3.1 规则 1（`:100`）：`非内建 .h.ct 单元` → `根单元`。`Module.h.ct` 的扫描范围从「全部单元」缩到「根单元」，比 A 更小 |

| **C-3 泛型模板：跳过 + 诊断** | 根单元内带定义、带 `pub` 的泛型模板（`ntparams > 0`，含 `T: Trait` 约束）→ **不写原型、不中止**，输出一条 `文件:行:列: warning: '<name>' not exported: generic template has no external symbol`（L39-1w） | 消解 `:45` 与 `:60/:102/:134` 的矛盾，取 `:45` 的处置；机械依据见 verify.json V3/V10。**需批准 B1** |

### 1.1 与 p39-2（归档符号面）的边界

非根单元的 `pub` 函数**必须保持 external**（根单元要跨单元调用它），因此它会出现在归档的 `nm -g` 里，但不在 `.abi.h` 中。**「归档的 `nm -g` 应不应当只剩导出面」不是本庭的争点**：它已由 `battle/p39-2` 立案，并由 `docs/decisions/D-002.md` 判 `rejected`（A 侧「接受内部符号 + 快照」不成立；B 侧「链接期本地化」的部分判据也不成立，按 §7.10 出口 1 另出 C）。本方案只决定**哪些函数进 `.abi.h`**（= 根单元的 C 兼容 `pub`），不裁定符号面：

- 若 p39-2 的 C 采纳链接期本地化/合并归档，则非根 `pub` 的符号面由那一轨处理，C 的 `.abi.h` 集合不受影响；
- 若 p39-2 的 C 退化为「快照 + 文档」形态，则 `E39-2` 的快照必须显式列出这些符号（沿用 `:40` 的非承诺面口径），但那是 p39-2 的裁定，不是本方案的主张；
- 本方案**不**预判 `:125`（「导出函数是唯一 default 可见的符号」）与 `:177`（E39-2）怎么改——它们属 D-002 的生效范围。

| P-C4 | 对 P-C1 的 `.abi.h` 断言 | 不含 `_iface` / `_vtbl` / `Vec_` / `Map_`；`nm -g --defined-only` 与 `expected.nm` 逐行相等 | C-2/C-7 不成立 |
| P-C5 | `ct build --emit-c test/modules/p34_pub_generic/lib.h.ct` | 产物 sha256 与 HEAD 相同（`:144` 的零回归） | C-7 不成立 |
| P-C6 | `ct build --lib` 一个只有泛型 `pub` 的根单元 | exit 0；`.abi.h` 只有 banner + 版本宏；stderr 有 L39-1w | C-6 不成立 |

任一条不符：C 不成立，按 §7.10 第 2 项登记 `verdict: undecidable` 的 open-question（owner：REQ；截止：下一次 PH-39 评审；默认规则：保持 D39-6 硬错并回到 A 的失败面）。

## 8 与 B 的关系（为什么这不是偷偷采纳 B）

- B（`pub export` / `--export` 清单）**未被采纳**，也没有通过任何判据：它需要 `AGENTS.md:469` 的用户批准，本庭记录里没有。
- C 的「作者可控」是**文件级**的，用的是既有 `import` 与命令行输入，不是「看不见的标记」；B 的「函数级」控制 C 明确做不到。
- 若用户将来批准 `--export <清单>` 或 `pub export`，它们与 C **正交**：可以在根单元内再过滤（C-1 缩到更小集合），也可以整体替换 C-1。C 不挡 B 的路，也不假装自己实现了 B。
