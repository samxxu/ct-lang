# hw-2 的 C 方案（§7.10 出口 1）

同时满足两侧最强约束：

- 主张席最强约束：**不改 `frontend/sym`**（实例表判据已够用，改符号表代价大）；
- 反对席最强约束：**不得漏判、不得子串误命中**（REQ-HW-011 的"只按实际使用拉取"要可机械验收）。

## 做法

1. **符号解析（补齐漏判）**：`Module` 在 emit 前遍历**非内置**单元的 `N_CALL` 节点，取 `text3[0] ? text3 : text2`
   经 `sym->find_func` 得到函数行号，若该行号落在某内置单元的函数区间（`units[u]` 的 `fn_start…fn_end`，
   若该字段不存在则在 `builtin_live_for` 内用"名字属于该单元 `.h.ct` 的导出集"代替），置该单元为活。
   覆盖 `str_from` / `str_len` / `str_release` 等 10 个小写导出函数。
2. **词边界文本扫描（消误命中）**：`file_mentions` 的两个调用点改为词边界匹配
   （前后字符不是 `[A-Za-z0-9_]`），并跳过 `//` 与 `/* */` 注释、`"…"` 与 `'…'` 字面量；
   同时把 262144 B 的定长 `fread` 改为分块扫描（消除"大文件截断"这条漏判路径）。
3. **保留真实依赖**：`Vec` 活 → `Str` 活（`lib/std/Vec.h.ct` 38 处 `Str`），顺序仍按 `builtin_units[]` 槽位。

## 代价（E4）

| 项 | 值 |
| --- | --- |
| 改动文件 | 1（`selfhost/ct-ast/frontend/module/Module.h.ct`） |
| 改动行数 | 约 30–40 行（新增一个遍历 + 一个词边界扫描器，替换 2 处调用） |
| 影响门禁 | `check-ast` 的 `p64_on_demand` 段（新增 2 条夹具）；`p39 r8` 基线（产物集合不变则应不变）；`test/pkg` 不受影响（包测试不用 `Str` 判活） |
| 回退步骤 | `git revert <impl-sha>`；探针与夹具分开提交，回退实现后探针恢复红 |

## 验收（探针新增两条，红→绿）

| # | 输入 | 现状 | C 方案后 |
| --- | --- | --- | --- |
| P1 | 只调 `str_len(str_from("hi"))`（源码无 `Str` 字面量） | 产物缺 `Str.c`，`cc` 退 1 | 拉入 `Str.c`，`cc` 退 0、运行输出与预期一致 |
| P2 | `struct Struct { int x; }`（无 `Str` 使用） | 误拉 `Str.c`（3089 B） | 产物只有自身 `.c` |
