## 现象

同一棵目录树里两行相邻注释给出的强制级别互斥：

```text
L16: 包仓库的**根目录就是包根**：`ct.pkg`、`LICENSE` 与源码单元并列，不嵌套子目录。
L20: ├── ct.pkg          # 清单（唯一必填文件）
L21: ├── LICENSE         # 许可证（必填，见 §5）
```

而 §5（L88）又说：

```text
- 每个包必须有 `LICENSE` 文件；`licence` 键只是约定，工具不校验文件内容。
```

## 证据

工具只强制 `name` / `version`：`read_manifest` 缺失清单时报
`ctc: cannot open './ct.pkg'`，字段缺失报对应诊断；`LICENSE` 既不读也不校验。
D18-9 的决策是「包内必须有 `LICENSE`」——这是**发布约定**，不是工具校验项；
`test/pkg/run.sh` 也没有「缺 LICENSE 被拒」的用例。

## 影响

作者无法判断 `LICENSE` 缺失会不会被 `ct get` / `ct install` / CI 挡下；「唯一必填」这句
正是被 §5 与实现同时否定的那一句。

## 修复建议

统一为两级措辞：

- `ct.pkg`：**工具必填**（缺 `name` / `version` 即拒绝）；
- `LICENSE`：**发布约定必备**（工具不校验，审核 / 索引收录时人工检查）。

L20 保留「唯一必填文件」，把 L21 的「必填」改成「发布约定必备，工具不校验」即可消除矛盾。

## 验证

删掉包内 `LICENSE` 后 `ct get` / `ct install` 仍成功——这与修改后的措辞一致。
