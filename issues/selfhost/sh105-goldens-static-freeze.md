## 实施卡（REQ 侧，2026-11-21）

### 实测结论（先纠正三个前提）

1. **ct-ast 不为普通 `.ct` 写 `.h`**：`ct compile` / `ct build` 只对 `.h.ct` 输入写同名 `.h`。
   因此静态 golden 只能钉 `.c`；L1 的 `.expected.h` 不适用于 ct-ast。头文件面继续由
   `.h.ct` 夹具与 L1 旧门禁覆盖，本卡不制造“假 H 期望”。
2. **banner 带版本号**：`Generated by ct v0.88.0 from <输入>` 会让每次版本 bump 改动全部 25 份
   golden。比对时两侧都做 `s/v[0-9]+\.[0-9]+\.[0-9]+/vX/` 归一化；golden 文件本身按生成时
   版本入库，不做手工改写。
3. **ct-ast 与 L1 golden 0/25 字节一致**（实测 v0.87 二进制；v0.88 发射器只动切片/`match`，
   类别不变，DEV 用 v1.0 二进制复核）。差异是两代发射器，不是 bug：
   | 类别 | 命中用例数（/25） | 例子 |
   | --- | --- | --- |
   | 源码注释被丢弃 | 24 | `// 01: canonical case…` 只在 L1 输出里 |
   | `const` vtable | 24 | `struct Greeter_vtbl *vt` → `const struct Greeter_vtbl *vt` |
   | 指针空格 | 19 | `char *name` → `char * name` |
   | 新增前向声明 | 25 | `struct Person;` 提前 |
   | 原型位置 / 形态 | 24 | `int main(void);` 提前 / `static` 原型归一 |

   结论：**不能复用 L1 的 `.expected.*` 作为新门禁的期望**；按方案 A 以 ct-ast 重新基线。

### 产物与布局

- 新增目录 `test/goldens/ast/`：25 份 `<case>.c`（只有 `.c`，无 `.h`）。
- 新增脚本 `selfhost/check-goldens-ast.sh`：只接受一个 ct-ast 二进制参数；不构建 L0/L1/L2。
- 新增差异清单 `docs/planning/j6-evidence/goldens-l1-vs-ast.md`：25 行，列
  「用例 / 注释丢弃 / const vtable / 指针空格 / 前向声明 / 原型 / 其他」，逐行按实测打勾；
  其他类差异必须写一行说明，不允许“同上”。

### 生成命令（从仓库根执行，DEV）

```sh
mkdir -p test/goldens/ast
for f in test/cases/*.ct; do
    b=$(basename "$f" .ct)
    CT_STD_DIR=$PWD/lib/std "$CTAST" "$f" -o "test/goldens/ast/$b.c"
done
```

`$CTAST` 必须是本次收口的 ct-ast 二进制；生成后同一二进制跑新门禁必须全绿。

### 新门禁判据

| 项 | 要求 |
| --- | --- |
| 输入 | `test/cases/*.ct` 与 `test/goldens/ast/<case>.c` 一一对应 |
| 比对 | 跑 ct-ast → 临时 `.c`；两侧 banner 版本归一化后 `cmp` 字节一致 |
| 覆盖 | 每个用例必须有 golden；多出或缺失都在报告里列出，不得静默跳过 |
| 失败 | 编译非零 / golden 缺失 / 字节不符 / 覆盖不一致，任一即退出 1 |
| 独立 | 树上没有 `selfhost/l1`、`selfhost/l2` 也能跑（脚本不引用它们） |
| 输出 | 逐例 `PASS <case>` / `FAIL <case>`；末尾 `check-goldens-ast: N/N` |

### 与现有门禁的关系

- `check-goldens.sh`（gate 2）保留到 L1/L2 退役；它继续以 L1 为中心。
- 新门禁只钉 ct-ast 发射字节；行为断言仍以 `check-ast`（1576 项）为主 oracle。
- 本卡不删 L1/L2；退役另开卡，前置是本门禁全绿且 gate 12 进 CI。

## 现象

`check-goldens.sh` 目前以 L1/L2 为对照系；直接删除 L1/L2 会同时丢掉 oracle 与回归基线。

## 期望

1. 在删除 L1/L2 之前，把整套 golden 语料转为**静态期望文件**：
   - 每个用例的期望 C/H（或规范化摘要）入库；
   - `ct-ast vs 静态 golden` 成为独立门禁，不再依赖 L1/L2；
2. 覆盖现有全部语料与示例；未覆盖项列出清单，不得静默跳过；
3. 静态化的输入/生成命令与版本记录在文件头，保证可复现；
4. 静态化完成并全绿后，才允许 L1/L2 退役。

## 验收

- 新门禁在无 L1/L2 的树上可独立跑；
- 与静态化前的 L1/L2 对照结果一致（或差异逐条登记）；
- 回滚：保留旧 tag，静态文件可重新生成。
