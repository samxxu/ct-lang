# LANG-9 · 结构体字段全部导出、字段级 `pub` 被原样发射成非法 C

| 项 | 值 |
| --- | --- |
| 模块 | lang（可见性 / ABI） |
| 严重度 | **High**（ABI 锁死 + 静默坏产物） |
| 优先级 | **P1** —— 负责人指定「按下游 ABI 被锁死定，不要排低」 |
| 状态 | **verified**（2026-11-20，REV） |
| 锚点 | `v0.53.1`（`2fd55841`） |

## 精确触发条件

1. `.h.ct` 里 `pub struct` 的字段无论是否带 `pub`，**全部**写进生成头 → 消费者可 `sizeof`、
   可栈上分配、可直接读写字段；实现侧改一个字段就是破坏性变更。
2. 字段上写 `pub` 时，解析器把该行当原始 C 文本透传，生成头里**逐字保留 `pub int fd;`** →
   `cc` 报 `unknown type name 'pub'`，而 ct-ast 退出 0。

## 最小复现

```sh
mkdir -p lib out && cd .
cat > lib/s.h.ct <<'EOF'
namespace lib;
pub struct Conn {
    pub int fd;
    int secret;
    int flags;
}
pub Conn *conn_new(int fd);
impl Conn {
    pub int get_secret(void) { return self->secret; }
}
EOF
cat > prog.ct <<'EOF'
#include <stdio.h>
import lib::s;
int main(void) { printf("%d\n", (int)sizeof(Conn)); return 0; }
EOF
ct-ast build --emit-c prog.ct -o out && cat out/s.h
```

## 实际行为

生成头（整段，逐字）：

```c
#ifndef S_H
#define S_H

/* Generated by ct v0.53.1 from ./lib/s.h.ct (multi-file mode: exported types; the matching .c
   includes this header).
   Generated output is not covered by the GPL and may be used without restriction (LICENSE.EXCEPTION). */

struct lib_Conn;
struct lib_Conn {
    pub int fd;
    int secret;
    int flags;
};
struct lib_Conn * lib_conn_new(int);
int lib_Conn_get_secret(struct lib_Conn *);

#endif
```

编译该产物：

```text
out/s.h:10:5: error: unknown type name 'pub'
   10 |     pub int fd;
      |     ^
```

而 `ct-ast build --emit-c` 自身 **rc=0**，无任何诊断。

字段可见性实测（全部字段非 `pub`）：

```ct
pub struct Conn { int fd; int secret; }
```

```ct
Conn c = { 1, 42 };
printf("%d %d\n", (int)sizeof(Conn), c.secret);
```

```text
8 42
```

消费者能算大小、能直接读私有字段，且 `out/s.h` 里 `secret` 与 `fd` 并列导出。

## 期望行为

二选一，且**不能静默**：

- 若支持字段级可见性：`pub` 字段进头，非 `pub` 字段只进 `.c`，消费者 `sizeof` / 访问私有字段应硬错；
- 若不支持：字段上的 `pub` 必须硬错（`a struct field cannot be 'pub'`），不得原样透传成非法 C；
  同时登记「不透明句柄」为唯一 ABI 私有手段。

## 已有的可用手段（不是缺陷）

`pub struct X;`（**只声明不定义**）+ 指针 API 是**可用**的：

```ct
namespace lib;
pub struct Conn;
pub Conn *conn_new(int fd);
pub int conn_secret(Conn *c);
```

生成头只有前置声明，没有布局：

```c
struct lib_Conn;
struct lib_Conn * lib_conn_new(int);
int lib_conn_secret(struct lib_Conn *);
```

所以「ABI 私有」的**表达方式存在**（不透明句柄），缺的是「同类型里部分字段公开」这种粒度；
后者按能力缺口登记，不算缺陷。

## 影响面

- 任何发布头文件的包（ct-http、ct-sse、ct-json、ct-fsguard）都把布局写进了 ABI：
  加/改/重排字段都是破坏性变更，包作者只能整体换类型名或走版本化；
- 下游可以直接 `sizeof` 栈上分配，编译器没有机会阻止（头里已有完整定义）；
- 私有字段对**同构建内的其它单元**同样可见（头是共享的），也与跨包消费者一样，
  `--ns-root` 的目录校验不涉及字段。

## 定位线索

- 生成头的导出面走「多单元导出类型」路径，把 `pub struct` 的定义整段抄进 `.h`；
- 字段解析不识别 `pub`，struct 体按原始 C 文本保存（所以 `pub` 原样进产物）。
- 相关既有记录：[SH-71](../selfhost/sh71-host-map-unit-boundary.md)（单元边界）、
  [PKG-2](../packages/pkg-2-ct-install-package-root-import.md)（跨包 include 根）——均不覆盖本条的字段可见性。

## 修复方向

先做「不静默」：字段文本里出现 `pub` 时硬错。字段级可见性是更大的工程（需要把 struct 体拆成
头/实现两份并生成两套定义），建议单独立相，不塞进本轮 P1 修复。

## 处置（2026-11-19，PH-73）

- 提交：`1e08d0c9`（R1），`92e3e3be`（R2/R3 验收与文档）
- 改动：字段前缀 `pub` 进入解析器并登记 `Field.is_pub`；`emit_type_decl` 对
  「部分 pub」的 struct 发射 `#ifdef CT_UNIT_PRIVATE` 全量 / `#else` 仅 pub 两份；
  单元 `.c` 先定义 `CT_UNIT_PRIVATE` 再包含头。无字段 `pub` 的 struct 保持旧行为；
  带 `use` 的 struct 暂不切分。
- 验证：`sh test/ast/p73_export.sh <ct-ast>` → `OK p73/export`；`p73_abi`/`p73_docs`
  同样绿；消费者读私有字段在构建期失败。
