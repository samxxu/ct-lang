### 2.1 关键证据

**DOC-45（教程自相矛盾）**——同一节里注释与正文相反：

```c
    delete p;                     /* -> if (p) { Box_Drop_drop(p); free(p); p = 0; } */
```

```text
- **`delete p;`** 立刻释放：有 `Drop` 就先调 `drop()`，再 `free`。**不置空**——`p` 仍是悬空指针，
  要继续用就先自己 `p = 0;`。
```

实测：`delete p; printf("%d", p == 0);` 打印 `1`。

**DOC-46（README 变换表）**——同一张表里 `delete` / `own` / `borrow` 三行都停在旧行为：

```text

| `borrow T *c = pool.acquire(...);` | … 作用域闭合 `}` / 行首 `return` 之前插入 … |
```

### 3.1 复现记录

**SH-34（High）**：文件作用域 `borrow` 被静默透传

```ct
struct Conn { int fd; } use Handback;
impl Handback for Conn { void handback() { self->fd = 0; } }
borrow struct Conn *g = 0;
int main(void) { return 0; }
```

```text
$ ./ct-ast b2.ct -o b2.c ; echo $?
0
$ grep -n borrow b2.c
10:borrow struct Conn * g = 0;
$ cc -std=c99 -c b2.c
b2.c:10:1: error: unknown type name 'borrow'
```

同一编译器对 `own` 的文件作用域形态是硬报错（`'own' is only allowed inside a function body`），
两条路径只差在 `Parser` 的那个 `if`。

**SH-35（High）**：同层赋值吃掉 handback

```ct
int main(void) {
    borrow struct Conn *c = acq();
    struct Conn *q = c;
    printf("q %d\n", q->fd);
    return 0;
}
```

```text
$ ./ct-ast b11.ct -o b11.c ; echo $?
0
# 生成的主函数：末尾没有 handback，也没有告警
int main(void) {
    struct Conn * c = acq();
    struct Conn * q = c;
    printf("q %d\n", q->fd);
    return 0;
}
```

把 `q = c;` 删掉，出口立刻出现 `if (c) { Conn_Handback_handback(c); c = 0; }`。判定冲突在
`check_borrow_store`（同层放行）与 `leak_assign`（提到就清 `autodrop`）之间。

**SH-36（High）**：`return` 里读字段也取消释放

```ct
int work(void) {
    borrow struct Conn *c = acq();
    return c->fd;
}
```

```text
$ ./ct-ast h1.ct -o h1.c ; echo $?
0                                  # 没有任何告警
$ sed -n '/int work/,/^}/p' h1.c
int work(void) {
    struct Conn * c = acq();
    return c->fd;                  # 没有 handback
}
$ ./h1
9
in_use 1                           # 槽位泄漏
```

`own` 侧同形态（`return b->n;`）会泄漏并给出**误报性质**的 `potential leak`；
L2 对同一输入生成相同的函数体，所以这是 ct-ast 与 L2 共有的老缺陷，但 `borrow` 让它多了一种「完全无告警」的形态。

**SH-37（Medium）**：`static` 局部接住借用

```text
$ cat b8.ct | sed -n '/^void f/,$p'
void f(void) {
    static struct Conn *s;
    borrow struct Conn *c = acq();
    s = c;
}
$ ./ct-ast b8.ct -o b8.c ; echo $?
0
```

**SH-38（Medium）**：跨单元不可用

```text
conn.h.ct:    pub struct Conn { … } use Handback;
conn_impl.ct: impl Handback for Conn { void handback() { self->in_use = 0; } }
main.ct:      borrow Conn *c = conn_get();

$ ./ct-ast build main.ct -o out
main.ct:5:5: error: struct 'Conn' uses trait 'Handback' but has no impl
```

把 `impl` 搬进 `main.ct` 即通过——限制来自「校验与发射都只看本单元」。

**SH-39（Low）**：impl 写在后面

```text
k1.ct:5:5: error: struct 'Conn' uses trait 'Handback' but has no impl
```

`impl Handback for Conn` 就在文件末尾。

**SH-40（Medium）**：`delete` 非左值

```ct
static int *get(void) { return 0; }
int main(void) {
    delete get();
    return 0;
}
```

```text
$ ./ct-ast g1.ct -o g1.c ; echo $?
0
$ sed -n '/int main/,/^}/p' g1.c
int main(void) {
    if (get()) { free(get()); get() = 0; }
    return 0;
}
$ cc -std=c99 -c g1.c
g1.c:10:37: error: expression is not assignable
```

修复前同一输入是 `if (get()) free(get());`，可以编译。

**SH-41（Medium）**：移交被误报

```ct
struct Box *make(void) {
    own Box *b = malloc(sizeof(struct Box));
    b->n = 5;
    return b;
}
```

```text
$ ./ct-ast n1.ct -o n1.c
n1.ct:6: warning: potential leak: 'b' (Box*) allocated but never deleted
$ ./l2 n1.ct -o l2n1.c
（无告警）
```

运行结果正确（调用方 `delete` 时 `drop 5` 触发一次），只是误报。

## 4. 未覆盖与不采纳

- **`goto` 静默失效**：`borrow` 跨 `goto` 跳过声明时不归还，与 `own` 同源且设计文档已声明；本轮不重复立案。
- **不区分池对象与栈对象**：`borrow struct Conn *c = &stack_obj;` 会照样在出口调 `handback`，这是设计
  （§4.40「已知限制」），不立案。
- **`store(c)` 与 `s->p = c` 不检查**：设计已声明不做跨过程分析，不立案。
- **`trait Handback` 用户自定义会被内建遮蔽**：与内建 `Drop` 同一处理，属既有约定，记为 Info 不立案。
- **`ct compile compile.ct` 之类文件名冲突**：`compile` 关键字只在 `argv[1]` 位置消费，风险极低，不立案。
- **`test/README.md` 的 63+9=72 计数**：实测 72 个负例、63 条在 `fixture|message` 表、另 9 条
  （含 `integer_suffix_lll` / `integer_suffix_uu`）在独立循环或单条 `grep -q` 里钉消息，与文档口径一致，不立案。
- **batch 39 的在途改动**（`docs/design/batch39-shim-layer/**` 等）：上一轮已明确不评判，本轮同样不涉及。
