## 2. 测试覆盖度

### 2.1 诊断覆盖分桶

ct-ast 的诊断入口是 `tool::diag`（`ct_sem_error` / 告警存储）与驱动层的 `fprintf(stderr, "ctc: …")`。
机械统计：**357 个源级报告点**（`fail(` / `fail_at(` / `fail_driver(` / `ct_sem_error(`），
约 **160 条不同的消息字面量**，另有 **71 处 `ctc:` 驱动级消息**。

负例的三种判据完全不同：

| 判据 | 数量 | 说明 |
| --- | --- | --- |
| 有夹具且**消息文本被钉死** | 56 / 68 | `check-ast.sh:1036-1379` 的 `"fixture\|message"` 循环 + 7 处独立 `grep -q` |
| 有夹具但**只断言退出码与位置** | 12 | `check-ast.sh:1020-1030` 通用循环只匹配 `file:line:col: error: ` |
| **无任何夹具** | 约 140 | 容量上限、boxing、驱动 I/O、路径长度、解析形状守卫等 |

12 个未钉死消息的夹具（`grep` 在 `check-ast.sh` 中命中数为 0）：
`assign_target`、`bitops_assign_target`、`extern_function`、`map_bad_arg`、`map_bad_arity`、
`map_bad_method`、`map_dup`、`map_unknown_arg`、`map_unknown_trait`、`missing_semi`、
`undeclared_var`、`unknown_trait`。

**可达但无用例**（探针实测，均非零退出）：`too many variables` / `types` / `structs` /
`traits` / `functions` / `parameters` / `nested scopes` / `calls` / `labels in one function` /
`gotos in one function` / `trait methods` / `warnings` / `map bindings` / `map parameters` /
`used traits` / `imports` / `exported type names`，以及 `output must end in .c`、
`output name too short`、`cannot write the output file|header|map`、`too many inputs`、
`too many -I roots`、`output path is too long`、`map path is too long`、
`output directory is too long`、`short read`、`cannot open the input file`。
其中只有 `MAX_MAPS`（`check-ast.sh:829`）与 `MAX_ERRORS`（`:1771`）有夹具。

### 2.2 语言特性 → 测试形态矩阵

`docs/language-spec.md` §4 共 38 节（中文 4.1–4.38）。`test/cases` 仍是 25 个 L0 时代的 golden，
`grep -lE 'switch|enum|union|goto|__attribute__|_Static_assert|_Atomic|_Alignas' test/cases/*.ct`
命中 **0**。因此：

| §4 范围 | 节数 | 逐字节 golden | 行为探针 | 无测试 |
| --- | --- | --- | --- | --- |
| 4.1–4.8（trait/struct/impl/多态/堆/组合） | 8 | `test/cases` 25（L1/L2 逐字节） | `test/ast/01–10,12,19,23,24` | 0 |
| 4.9 AutoDrop | 1 | `test/modules/autodrop*`（仅 L2 比对） | `test/ast/11` | 0 |
| 4.10 `map` | 1 | `test/modules/map*`（仅 L2 比对） | `test/ast/11,13,14,15,20,22` | 0 |
| 4.11 跨单元 `pub`/`extern`/`.h.ct` | 1 | `test/modules/split,hdr,inc,pub_global,…`（仅 L2） | `test/ast/26` | 0 |
| **4.12–4.38**（函数指针、switch/do、enum、union、goto、位域、匿名成员、static 局部、复合字面量、变参、C11、`__attribute__`、后缀、头文件顺序…） | **27** | **0** | `test/ast/21,25,27–56` | 0 |

`check-ast.sh` 对 `test/ast/*/prog.ct` 的判据是 D34：**退出码 + 零警告构建 + 程序输出**
（`:213-248`），不比较生成文本；`test/modules` 也只 `cmp expected.out`（`:390-653`）。
唯一涉及 ct-ast 产物的 `diff` 是 `check-ast.sh:1924` 的 L0 种子关——它验证的是
「ct-ast 编出的 C 编译器能复现 `test/cases` golden」，**不是 ct-ast 自己的代码生成**。

结论：**ct-ast 的生成 C 没有任何逐字节 oracle**。这不会让现有用例变红，但它使「改写错但运行输出仍对」
的退化无法被发现（历史审计把这类问题单列为 silent non-rewrite 类）。

### 2.3 负例与门禁质量

- **56/68 精确、12/68 仅位置**：见 2.1；消息措辞改动不会被任何门禁发现。
- **compile / build 双模式的特性镜像缺失**：`test/ast` 只走 compile，`test/modules` 只走 build。
  4.12–4.38 的 27 节里，没有任何一节在两种模式都被执行（只有 batch 30 的 `.h.ct` 规则两模式都覆盖）。
- **build 模式的 CLI 错误分支**：只断言了 `build needs -o`（`:1592`）。`build` 下的
  `-o`/`-I`/`--ns-root` 缺参、未知选项、`--std` 非法、无输入、`too many -I roots`、
  `too many inputs`、写失败、路径过长均无断言；同一批分支只在 compile 模式被测（`:1518-1600`）。
- **`check-warnings.sh` 的扫描面**：`selfhost` 产物 + `test/ast` + `test/cases` + `examples` +
  `test/modules` + `bindings`，**不含 `test/patterns`、`test/archive`、`test/acceptance`**
  （`:96-198`）。`test/patterns` 仍被 `check-ast.sh:272` 以 `-Wall -Wextra` 构建，故有间接兜底。
- **无 CI**：仓库没有 `.github/` 或任何 CI 配置；九道门禁只靠手工执行 `check-all.sh`。
- **夹具卫生**：`missing_method.ct` 在 `test/errors/` 与 `test/ast/errors/` 各有一份，两份内容不同
  （L0 版测 impl 缺方法，ct-ast 版测 SH-8 的 NULL vtable），但同名容易在清点覆盖率时重复计数。
- **`test/README.md` 的层图已过期**：见 3.5。

### 2.4 探测到的行为事实（非覆盖问题）

用 200 字符标识符探针时发现：ct-ast 对标识符**静默截断到 159 字符且 `exit 0`**，与
`docs/language-spec.md:59,63` 的「超过 127 字符报 `identifier too long`、不静默截断」相反。
两个只在前 159 字符之后不同的标识符会被截成同名，生成的 C 直接出现 `redefinition`：

```text
$ /tmp/a/ct-ast c.ct -o c.c ; echo $?
0
$ gcc -Wall c.c
c.c:7:9: error: redefinition of 'aaaa…(159 个 a)'
```

同一输入在 L0 上也是 `exit 0`。这条独立记入 [SH-23](../../issues/selfhost/ct-ast-identifier-truncation.md)。

   「改写错但输出仍对」的层。

7. **加 CI 或至少一个 `make check` 别名**（CI-4），让九关不再依赖个人记忆。
