# test/ — 分层地图

> 中文 · [English](#english)

`test/` 下每个子目录的**归属层级**、**数据形状**与**驱动脚本**如下。两套负例约定**不同**：
`errors/` 用 `<name>.ct` + `<name>.expected-err` 做逐字节比对；`ast/errors/` 是裸 `.ct`，
由 `check-ast.sh` 只断言退出码（无 `.expected-err`）。

| 目录 | 层级 | 形状 | 驱动脚本 |
| --- | --- | --- | --- |
| `run.sh` | L0 | 八层驱动器：build → unit → cases → examples → dialect → errors → limits → cli | 自身 |
| `unit/` | L0 | 白盒单测 `test_helpers.c`（直接 `include selfhost/ctc.c` 以触达 static 函数） | `run.sh` 的 unit 层 |
| `cases/` | L0 | golden 正例：扁平文件对 `<name>.ct` + `.expected.c` / `.h` / `.out` | `run.sh` 的 cases 层 |
| `errors/` | L0 | 负例：扁平文件对 `<name>.ct` + `<name>.expected-err` | `run.sh` 的 errors 层 |
| `archive/` | L0（历史） | Phase 0.3 移出的越位特性 fixture，Phase 2–5 的对差基线，**不跑** | `selfhost/check-archive.sh` |
| `modules/` | CT 线 | 特性/多单元探针：一目录一用例（输入 + `.expected.*` + 可选 `<mode>.args` 驱动提示，可含 `src/`） | `selfhost/check-ast.sh`、`selfhost/check-archive.sh` |
| `ast/` | CT 线 | `01..18` 行为探针：一目录一用例（`prog.ct` + `prog.expected.out`）；`ast/errors/` 为裸负例 | `selfhost/check-ast.sh` |
| `acceptance/` | 跨层 | 端到端验收清单（`ast_spike.ct` / `ast_parse_spike.ct`）；`PENDING` 属预期、**不阻断** | `test/acceptance/run.sh` |
| `pkg/` | 跨层 | 包管理器 `ct get` / `ct install` 用例 | `test/pkg/run.sh` |

`run.sh` 只驱动 **L0**（`selfhost/l0/ctc.c`）；CT 线（`selfhost/**`）的关卡由 `selfhost/check-all.sh` 聚合，
见 [README §5](../README.md#5-测试) 与 [selfhost/README.md](../selfhost/README.md)。

> `*.expected.*` 一律由编译器生成后人工核对，**禁止手写**；只有在确认编译器行为变更是有意为之
> 之后，才重新生成它们（见 [AGENTS.md](../AGENTS.md) §6）。

## English

Below is each subdirectory under `test/` with its **layer**, its **data shape** and its **driver**.
The two negative conventions **differ**: `errors/` pairs `<name>.ct` with `<name>.expected-err` for a
byte-for-byte diff, while `ast/errors/` holds bare `.ct` files that `check-ast.sh` asserts on exit
code alone (no `.expected-err`).

| Directory | Layer | Shape | Driver |
| --- | --- | --- | --- |
| `run.sh` | L0 | the eight-layer driver: build → unit → cases → examples → dialect → errors → limits → cli | itself |
| `unit/` | L0 | white-box unit tests in `test_helpers.c` (includes `selfhost/l0/ctc.c` to reach statics) | `run.sh`'s unit layer |
| `cases/` | L0 | golden positives: flat pairs `<name>.ct` + `.expected.c` / `.h` / `.out` | `run.sh`'s cases layer |
| `errors/` | L0 | negatives: flat pairs `<name>.ct` + `<name>.expected-err` | `run.sh`'s errors layer |
| `archive/` | L0 (historical) | Phase 0.3 over-reach fixtures, the Phases 2–5 diff baseline; **not run** | `selfhost/check-archive.sh` |
| `modules/` | CT line | feature / multi-unit probes: one directory per case (input + `.expected.*` + an optional `<mode>.args` hint, may nest `src/`) | `selfhost/check-ast.sh`, `selfhost/check-archive.sh` |
| `ast/` | CT line | behavioural probes `01..18`: one directory per case (`prog.ct` + `prog.expected.out`); `ast/errors/` holds bare negatives | `selfhost/check-ast.sh` |
| `acceptance/` | cross-layer | the end-to-end acceptance checklist (`ast_spike.ct` / `ast_parse_spike.ct`); `PENDING` is expected and **non-blocking** | `test/acceptance/run.sh` |
| `pkg/` | cross-layer | package-manager `ct get` / `ct install` cases | `test/pkg/run.sh` |

`run.sh` drives **L0** (`selfhost/l0/ctc.c`) only; the CT line's gates (`selfhost/**`) are aggregated by
`selfhost/check-all.sh` — see [README §5](../README.md#5-tests) and
[selfhost/README.md](../selfhost/README.md).

> `*.expected.*` are always generated by the compiler and reviewed by hand — **never hand-written**.
> Regenerate them only after confirming the behaviour change was intended (see [AGENTS.md](../AGENTS.md) §6).
