# Phase 51 — 指针接收者 `.` 调用的发射缺陷（链式前置）

> **状态：规划中**（草案，待评审；未立项；**影响面待 S0 确认**；本轮只写卡，不改代码）
> **归属**：本仓库维护规格与判据；**实现由外部 DeepSeek harness 执行**（交接见 [计划 §10](phase46-52-plan.md)）。
> **基线**：`94556f29`（规划提交，`CTC_VERSION 0.44.1`）。
> **依赖**：无硬前置；但**必须先于 [phase52.md](phase52.md) 的连写验收**，也是任何链式方案的共同前置。
> **规模**：50–120（选「硬错」）／100–250（选「自动解引用」）；合计按 S0 结论取一档（±40%）。
> **版本**：收口 bump `v0.51.0`；tag / push 需用户单独授权。
> **纪律**：不新增链式语法；不改 `->` 的既有语义；不改 `self` 在方法体内的绑定方式。

## 0 背景与缺口

**事实（评审一 §0.4、§7.5，来源为实测探针）**：对指针接收者用 `.` 调用方法时，`ct-ast` 发射
`S_f(&p)`，把 `struct S **` 传给形参为 `void *` / `struct S *` 的方法。

```c
struct S *p = ...;
p.f();          /* 生成 S_f(&p) */
```

`cc` 只给 `incompatible pointer types` warning（不是 error），**非空时结果就已经错**——
不是「中间为 0 才崩」。任何链式写法（`a.get("b").get("c")`、包层 `JsonRef` 连接）都会踩到，
因此它排在所有链式语法之前。

**代码锚点（S0 复核）**：

| 主题 | 位置 |
| --- | --- |
| `N_MCALL` 的发射入口 | `selfhost/ct-ast/backend/emit/Emitter.h.ct:4863` 起 |
| 接收者提升 / 取址规则（`into` 块） | `Emitter.h.ct:2374-2376`（「指针接收者被拷贝；左值值接收者就地取址」） |
| 具体「`.` 对指针接收者取址」的分支 | **S0 定位**；本卡不预设行号 |

**未确认的部分**：仓库内有多少既有代码依赖「`.` 调用于指针接收者并通过 `cc` warning 混过去」。
S0 必须给出计数（`test/`、`examples/`、`lib/std` 三处），这个计数决定 D51-1 的取值。

## 1 目标 / 非目标

### 1.1 目标

| 编号 | 内容 |
| --- | --- |
| O1 | `.` 作用于指针接收者时**不得**再发射 `S_f(&p)`：要么解析期硬错要求 `->`，要么自动解引用发射 `S_f(p)` |
| O2 | `->` 路径行为不变（正确传入 `p`） |
| O3 | 生成 C 在 `-Werror=incompatible-pointer-types` 下编译通过（本相新增的产物级断言） |
| O4 | 修法取向按 S0 计数冻结：零依赖 → 硬错（D51-1A）；有依赖 → 自动解引用（D51-1B）且需用户签字 |

### 1.2 非目标

| 不做 | 理由 |
| --- | --- |
| 支持「方法结果作接收者」（SH-73 / B-2） | 独立缺陷，100–300 行且改既有生成物；本相只堵 `S**` |
| 支持指针接收者进入 `[]` 协议 | PH-52 明确不做（评审一 §3） |
| 改 `.` 与 `->` 的语法合法性（两者均可写） | 本相只改发射/诊断，不动文法 |
| 自动解引用链（`p.q.f()` 多层） | 属链式语法，单独评估 |
| 把 warning 升成 error 就算修好 | 不修发射只升告警仍是错值；O3 是产物级验证，不是修法 |

## 2 设计决定

| 编号 | 决定 | 为什么不用另一种 |
| --- | --- | --- |
| **D51-1A** | 若 S0 统计到**零处**既有依赖：解析期硬错，要求写 `->`（L51-1） | 最小、不静默、不动生成物；符合「禁发射坏 C」 |
| **D51-1B** | 若存在既有依赖：`. ` 对指针接收者自动解引用，发射 `S_f(p)`，并给迁移清单与一段兼容说明 | 保住既有写法；但要重生成 golden，且需用户签字（本卡不自行选） |
| **D51-2** | 判定只按「接收者静态类型是否为指针」一个条件，不看结果类型 | 结果类型无关；缺陷在实参形态 |
| **D51-3** | 不改变 `->` 的发射，也不改变 `self` 在方法体内的绑定 | `self` 绑定由 PH-42 / PH-45 冻结 |
| **D51-4** | 新增产物级断言：生成 C 以 `-Werror=incompatible-pointer-types` 编译 | 现有门禁只跑 `cc` 默认告警，缺陷因此长期不可见 |

## 3 诊断

| 编号 | 触发 | 文案（草案，仅选型 A） |

## 8 交接：复现与验收锚点

### 8.1 现状复现（基线 `94556f29`，全部在 `/tmp`，不入仓）

前置：按 [计划 §10.2](phase46-52-plan.md) 构建 `$work/ct-ast`。

```sh
mkdir -p /tmp/p51 && cd /tmp/p51
# pr.ct: pub struct S { int id; }  impl S { pub int get_id() { return self.id; } }
#        func main() { struct S *p = S_new(); int got = p.get_id(); printf("got=%d\n", got); }
"$work/ct-ast" pr.ct -o pr.c ; echo "ct rc=$?"
cc -std=c99 -c pr.c -o pr.o ; echo "cc rc=$?"
grep -n 'S_get_id(&p)' pr.c
```

| 观察点 | 期望现状 | 说明 |
| --- | --- | --- |
| `ct rc` | 0 | 不报错、不警告 |
| `cc rc` | 0，但有 `incompatible pointer types` warning | **精确文案以本机为准**（评审一只记录「只给 warning」，未逐字抄录） |
| 生成 C | 命中 `S_get_id(&p)` | 形参是 `void *` / `S *`，实际传 `S **` |
| 运行 | `got` 为错值（非 `p->id`） | 非空时结果已错，不是「空指针才崩」 |

### 8.2 验收锚点（外部可见证据）

| 证据 | 判据 | 允许变化 | 不允许 |
