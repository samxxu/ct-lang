## 0 背景与解决的问题

### 0.1 缺口①：闭包块体 `return` 误用外层 `ret_type`

规范已写下的契约（[language-spec.md §4.53](../language-spec.md)，`:2190-2191`）：数组、闭包、函数指针等
静态类型判不出的位置**一律静默**。实现没有做到：

| 事实 | 证据 |
| --- | --- |
| return 的两处判定直接读 `self->sym->ret_type` | `frontend/parse/Stmt.h.ct:1955`（L32-4 分支）、`:1993`（L32-3 / L32-5 分支） |
| `parse_closure` 从不设置 `sym->ret_type` | `frontend/parse/Expr.h.ct:4560-4646`（`ret_type` 只在函数 / 方法体设置：`Parser.h.ct:283`、`:1643`、`:3061`、`:3215`、`:3582`） |
| 现成的闭包深度计数器 | `Expr.h.ct:402`（`ncl_stack`）、`:4615-4619`（压栈）、`:4638-4639`（弹栈） |
| 假阳性 | `examples/18_generic_string_table/generic_string_table.ct:103`、`:105`：合法的 `char *` 被报 `expected 'int'`，只在 `ct check --types` 下出现 |
| 漏判 | 外层 `void` 时闭包体 `return err:;` 通过，并给返回 `int` 的 trampoline 发出 `return;`，`cc` 报 `non-void function ... should return a value` |

**判定**：这是「规范已承诺、实现未兑现」，不是新特性。S1 在 return 判定前置 `ncl_stack == 0`，恢复
§4.53 已写下的跳过契约；**不**给闭包做返回类型推断（那是 [phase43.md](phase43.md) §0.2 记录的独立缺陷，
本相只按契约绕过，不宣称修复）。

### 0.2 缺口②：指针基类型 / 层数在五个位置两种判据

| 事实 | 证据 |
| --- | --- |
| 通用内核在「两侧都是指针」时直接放行 | `frontend/parse/Expr.h.ct:6120`：`if (strchr(formal, '*') && strchr(actual, '*')) return 0;` |
| 调用实参位置却能判基类型 | `Expr.h.ct:1402-1414`：`arg_class` 得 `r == 2` 后按 `find_struct` 比较，不一致报 `argument <n>: expected '…', got '…'` |
| 四处放行 | 初值 / 赋值 / `return` / 容器与泛型固有方法实参都走 `chk_assignable`，全部被 `:6120` 短路 |
| 一处必报 | 普通函数调用实参走 `:1402-1414` |
| 触发条件已满足 | `phase32-draft.md:423`（T32-1）写「出现真实误用且容器元素形态稳定后再做层数 / 基类型比较」；实测 `struct User *u; struct Admin *a; u = a;` 在 `check` / `check --types` / `build` 三入口均 rc=0 |

**判定**：同一条 `chk_assignable` 内核在两个调用点两套判据，内部不自洽。S2 让 `:6120` 复用
`:1402-1414` 已有的 `r == 2` 解析逻辑（不新建第二个兼容内核），把四个位置拉到与调用实参同一判据。

## 1 目标 / 非目标

### 1.1 目标

| 编号 | 内容 |
| --- | --- |
| O1 | 闭包块体内的 `return` 不再按外层 `ret_type` 判，恢复 §4.53「闭包一律静默」；`--types` 在 40 个 example 上不再出现该假阳性 |
| O2 | 指针基类型 / 层数在初值 / 赋值 / `return` / 容器实参四个位置与调用实参同判据；`void *` ↔ 任意对象指针、裸 `0`、typedef、数组、闭包、函数指针的跳过面不变 |
| O3 | 零回归：正例语料 `--types` 输出除该假阳性消失外逐字不变；461 语料 rc 平价（新增负例除外）；生成 C 与既有 golden 不变 |

### 1.2 非目标

| 不做 | 理由 |
| --- | --- |
| 闭包返回类型推断 / 闭包独立 `ret_type` | 独立特性；见 phase43 §0.2，本相只按契约跳过 |
| 默认路径全量类型检查 | 策略变更 + 全量 golden 重生成，见 `REQ-TYPE-1` |
| CFG / 数据流所有权分析 | 仓库无 CFG、无 pass 框架，见 `REQ-MEM-1` |
| 跨过程逃逸 / 借用经调用或字段逃逸 | 需写入摘要，见 `REQ-MEM-2` |
| 比较运算符、条件、`switch`、`sizeof`、`_Generic`、宏、struct 字段初值 | 沿用 §4.53 的判定面，不扩写 |
| 改 `build` / `compile` 的严重级或把 `--types` 设为默认 | 策略变更，另案 |
| 改 `void *` 双向转换、裸 `0`、typedef、数组、闭包、fnptr 的跳过面 | 沿用 D32-4 / D32-6 冻结口径 |

## 2 设计决定

| 编号 | 决定 | 为什么不用另一种 |

## 3 诊断

| 编号 | 触发 | 文案 | 位置 |

| **L45-1** | 同层数、两侧指针、基类型不同（`struct A *` ← `struct B *`、`struct A *` ← `char *`） | `initializer: expected '<T>', got '<U>'` / `assignment:` / `return:` / `argument <n>:` | 表达式起点（实参为实参起点） |
