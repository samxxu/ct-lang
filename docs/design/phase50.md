## 0 背景与缺口

**缺口① 取用形态不一致**（[gaps](../proposals/language-capability-gaps.md) C-2）：

| 容器 | 签名 | 取到的是什么 |
| --- | --- | --- |
| `Vec<T>` | `pub T get(int i)` | 按值；越界返回零值 `T`（先 `memset`） |
| `Map<K, V>` | `pub V *get(K k)` | 指针；缺键返回 `0` |

同一句「取元素」在两种容器上要写两种调用点；换容器实现就要改调用点。

**缺口② 越界 / 缺键与真实值不可区分**（C-3，[ct-json](../proposals/ct-json-capability-blockers.md) J-7）：

```text
missing=0x0    /* Map 缺键 */
oob=0          /* Vec 越界，与真实元素 0 同形 */
```

`Vec::get` 的注释写明这是有意行为（`lib/std/Vec.h.ct:92-99`）；`Map` 选了 NULL。两者都对，但没有统一契约，
调用方无法区分「取到 0」与「没取到」。

**缺口③ 释放契约没写**（评审二 §5.4）：容器 `release` **不跑**元素 Drop（`Vec<L>` 中 `L use Drop`
时 `release()` 后没有 `L drop`，生成的 `__elem_release` 是 `(void)e;`）。这是现状事实，不是本相要改的行为，
但必须写进契约，否则包方会误以为 `delete` 容器等于递归释放。

## 1 目标 / 非目标

### 1.1 目标

| 编号 | 内容 |
| --- | --- |
| O1 | `Vec<T>` 增加 `has(int)` 与 `try_get(int, T *out) → int`；`Map<K, V>` 增加 `has(K)` 与 `try_get(K, V *out) → int` |
| O2 | 既有 `get` 的签名、零值语义、缺键返回 `0` 全部**不变**（零迁移） |
| O3 | 契约写清两条：越界/缺键只能用新入口区分；容器 `release` 不跑元素 Drop，元素释放归调用方显式遍历 |
| O4 | 两容器的「取用」入口在调用点同形：`if (v.try_get(i, &out))` / `if (m.try_get(k, &out))` |

### 1.2 非目标

| 不做 | 理由 |
| --- | --- |
| 改 `Vec::get` 为返回值 / 改 `Map::get` 为返回值 | 会破坏既有夹具与「缺键 = NULL」契约；C-2 的结论就是「加并行入口，不改既有」 |
| 自动释放容器元素 / 让 `release` 跑元素 Drop | 所有权不在容器；改默认会产生双释放风险，需独立相 |
| `has` / `try_get` 的遍历顺序或复杂度承诺 | 仍是线性扫描，不引入索引 |
| 越界插入 / 缺键自动建槽 | 写入语义归 `set` / `put`，已在 PH-29 冻结 |
| 把 `try_get` 做成语言内建（`v[i]?` 一类） | 不做新语法；纯库入口 |

## 2 设计决定

| 编号 | 决定 | 为什么不用另一种 |
| --- | --- | --- |
| **D50-1** | 只加并行入口，不改 `get` | C-2 的结论：统一成 `T *` 会改 `Vec<int>` 的零值语义，统一成值会让 `Map` 无法表达缺键 |
| **D50-2** | `try_get` 返回 `int`（1 命中 / 0 未命中），结果写出参 | 与仓库既有 `int` 返回码风格一致；避免引入 `Option` 造成的额外装箱 |
| **D50-3** | `has` 与 `try_get` 不合并成一个入口 | `has` 供「只判存在」的调用点；`try_get` 供「取一次」的调用点，避免 TOCTOU 式两次查找 |
| **D50-4** | `release` 行为不变，只写契约 | 改它会动全部容器生成物与所有权预期；本相是「让失败可判」，不是「改释放语义」 |
| **D50-5** | `Str` 键的 `has` / `try_get` 沿用 PH-47 的比较 | 不引入第二套键比较 |

## 3 诊断

无新增编译器诊断（纯库入口）。契约违反由文档与夹具约束：

| 编号 | 场景 | 处置 |
| --- | --- | --- |
| — | 用 `get` 的零值判断「是否命中」 | 文档写明不可区分；包指南给 `try_get` 的标准写法 |
| — | `try_get` 出参为 `0` / 类型不符 | 由 `cc` 兜底（与 `ct check` 的 opt-in 边界一致），本相不加解析期检查 |
