# 第三十五批：设计模式覆盖（2026-10-31）

> 锚点：`5a84563`（第三十四批收口），工作树干净。
> 目标（用户确认）：**不新增语言特性**。OO 的目的是完整支持设计模式所依赖的语言
> 特性；`trait` / `impl`、接口值 / 数组 / 字段、组合、`namespace` / `import`、`map`、
> `own` / `Drop` 一旦确立就足够。继承、泛型、类型检查、可见性修饰符保持
> language-spec §8 的「明确不支持」，它们是设计决定，不是待办。

## 1. 做法

用现有语言写六个可运行的模式程序，作为「特性足够」的构造性证明：

| 模式 | 验证的机制 |
| --- | --- |
| Strategy | trait + `impl` + 接口参数（按值装箱） |
| Observer | 接口数组字段 + 主题指针 + 变量下标赋值 |
| Decorator | 接口字段持有同接口实现（嵌套两层） |
| Composite | 接口数组字段 + 递归 + 接口参数传入数组元素 |
| Factory Method | 返回接口的工厂函数 + 堆对象装箱 |
| Template Method | 自由函数持有骨架，步骤抽成 trait |

每个是一份 `prog.ct` + `expected.out`；`check-ast.sh` 新增「design patterns」一节，
按行为用例的方式编译、零告警构建、运行、比对。**不改编译器**。

## 2. 决策

- **D-1 测试放 `test/patterns/`，不进 `test/ast/`**：它们验证的是语言组合能力，
  不是某个 AST 构造；单独一节的名字也更直白。
- **D-2 只加测试与文档**：如果某个模式写不出来，先记录具体卡点与最小复现，再评估
  是否值得动语言；本批没有遇到这种卡点。
- **D-3 `docs/patterns.md` 给出「模式 → 机制」对照**，并写明无继承 / 无泛型时的三条
  替换规则（组合代替继承、单态或接口擦除代替泛型、骨架放自由函数代替模板方法），
  以及其余 GoF 模式的落法。
- **D-4 边界照旧**：没有编译期类型检查（错配到 C 编译器才报）；接口数组是固定容量；
  语言不提供动态容器。

## 3. 验证

- `check-ast.sh` 的六个 `pattern/*` 断言全过。
- 生成物在 clang 与 GNU GCC 16 下都零告警，输出与 `expected.out` 一致。
- 三关数字如实记录；不改生成物、不改 golden、不 bump 版本。
