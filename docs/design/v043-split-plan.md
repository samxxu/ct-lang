## 2. 拆分依据（CT 内部逻辑）

### 2.1 什么必须同相：语义闭环

- **错误出口类型契约**（PH-43）与 `?`（PH-44）是两件事，不是一相的上下半场：前者约束的是既有的
  `return err:`，后者引入新语法与新临时量。但后者依赖前者，否则 `?` 的失败分支会把同一条静默坏 C
  放大成语法级隐患。
- **`?` 的语法、语义、发射、Drop 失效化**必须同相：只做解析不做发射会留下「能过语法检查但生成坏 C」的
  中间态，正是本方案要消灭的形态。
- **ADT 的声明、构造、`match`、穷尽检查**必须同相：只交付 tagged union 而不做穷尽检查，等于把一个
  半成品语法交给用户，且后续再补穷尽会改诊断面与夹具，属于「先应付、后面再补」，本方案明确禁止。

### 2.2 什么有硬前置

- **PH-44 → PH-43**：`?` 的失败分支语义是 `return err: <外层 Result>::err(t.err)`；PH-43 之前，
  `return err:` 的载荷类型不被检查。若先上 `?`，用户仍可用显式写法制造静默坏 C，而 `?` 的展开又依赖
  该检查来保证 E 是否一致。故 43 必先。
- **PH-46 → 前置无**：ADT 不依赖 43/44 的代码路径，但它改 Parser/Emitter 的公共面，必须独占时间窗。

### 2.3 什么互相独立

- **PH-45 ABI 校验**：只新增 CLI 子命令与导出面重算，不引入新语法、不改类型系统。它与 43/44 的唯一
  实质交集是 `Emitter.h.ct` 里的哈希算法（见 §5，S0 决定是否提取共享助手）。
- **PH-43 与 45** 可任意先后；把 43 放前面是因为它修正确性缺口。

### 2.4 工量是否落在单相可交付区间

以已收口相的实测/卡面估算校准（`docs/design/phase38-draft.md:9` 合计 410–790；
`phase40-draft.md:8` 合计 460–750；`phase42-draft.md:8` 合计 590–1030；PH-40 实际编译器改动
`git diff --stat v0.39.0 v0.40.0 -- selfhost/ct-ast/` = 3 文件 +271/−14）：

- 43、45 落在「单相可交付」的小区间（<700）；
- 44 与 PH-40/PH-42 同量级；
- 46 明显超出单相历史区间，因此必须用**切片数**控制风险（S1–S10），而不是把能力砍半。

## 5. PH-45 ABI 消费端校验

**一句话**：`ABI_HASH` 今天只发射不校验；新增只读子命令，重算导出面哈希并与 `.abi.h` 比对，让「有度量」
变成「有门禁」。

**现状（S0 必须核对）**

- 发射：`selfhost/ct-ast/backend/emit/Emitter.h.ct:5336-5337`（`<BASE>_ABI_VERSION 1`、`<BASE>_ABI_HASH`）。
- 规范：`docs/language-spec.md:2254-2262`（§4.57），导出面只取根 `.h.ct` 的 `pub` 函数，泛型模板不导出
  （L39-1w），按值 struct / 接口值 / 容器 / `own` 拒绝（L39-1）。
- 唯一消费点：`test/modules/p39_lib/r3_probe.sh:22`，只断言「宏存在」，不比对数值。
- 名字占用：`selfhost/ct-ast/main.ct:116-117` 的 `verify` 已派发给 `tool::pkg::ct_pkg_verify`
  （`selfhost/ct-ast/tool/pkg/Pkg.h.ct:1941`，校验 `ct.lock`），**不得复用 `verify`**。
- 文档：`docs/package-guide.md:110-116`、`docs/glossary.md:154`。

**范围（闭环）**

1. 新子命令 `ct abi-check <root.h.ct> <old.abi.h>`（名字与参数形式在相卡冻结；不得复用 `verify`）。
2. 重算导出原型集合与 FNV-1a 哈希，与头文件里的 `<BASE>_ABI_HASH` 比对；根必须是 `.h.ct`。
3. 退出码：一致 0；不一致 1；输入/格式错误 1（`file:line:col` 或 `abi-check: …` 诊断）。
4. 输出差异：按符号列出 `-`（旧有今无）、`+`（今有旧无）、`~`（签名变化），便于定位。
5. **只读、零网络、零子进程、不写文件**（与 `ct verify` 的离线口径一致）。
6. 版本宏 `ABI_VERSION` 不是 1 时拒绝比对（L45-3），不猜兼容性。
7. 哈希算法必须与发射端**逐位一致**；S0 决定是提取共享助手还是在 checker 里复刻并加差分夹具锁死。
8. 可运行样例：`test/abi/run.sh` 端到端（编译库 → 生成 `.abi.h` → 比对 0 → 篡改原型 → 比对 1），
   注册进 `check-ast.sh`；**不新增 `check-all.sh` 的门禁条数**（避免改 11 道门禁的文档口径）。

**完整性边界**

| 维度 | 内容 |
| --- | --- |
| 交付后能用 | 任意 `.abi.h` 与当前源码的导出面做一次离线一致性校验，得到 0/1 与逐符号差异 |

| 不能做的反馈 | 明确拒绝并说明原因（如「泛型模板不进入 ABI 面」），不静默给 0 |

## 6. PH-46 非泛型 ADT + `match` + 穷尽检查

**一句话**：带载荷的枚举值 + 构造 + 判别 + 穷尽式 `match`，作为一个完整语言特性交付；不做「先上 tagged
union、穷尽以后再说」的半成品。

**现状（S0 必须核对）**

- `pub enum` 今天是 **C 枚举常量集合**（`docs/language-spec.md:711-747`），无载荷、无标签联合。
- 无 `match` 关键字、无值级模式；Phase 33 的 pattern 是 impl 类型 pattern（`docs/language-spec.md:2220-2228`）。
- `Option`/`Result` 是普通泛型 struct，不是 enum（`docs/language-spec.md:2153-2161`；`docs/glossary.md:84`）。
- 仓库自估：`docs/modern-oo-gap.md:170` D2「枚举带载荷 + 模式匹配」= 1,500–3,000 行，难度 L。
- 自举约束：新 AST 节点必须能过 `check-ast.sh` 的自举 fixpoint（编译器编译自身）。

**范围（闭环）**

1. **声明**：`enum Name { A(int), B(char *, int), C }`；有载荷成员即 ADT，无载荷成员作为纯标签成员共存。
   既有「全无载荷」的 `enum` 保持 C 枚举语义不变（D46-1，S0 冻结）。
2. **构造**：`Name::A(1, p)`、`Name::C`；参数个数/类型按成员声明检查。
3. **判别**：`match (expr) { case A(x): …; case B(p, n): …; case C: …; }`，支持 `default:` 兜底。
4. **穷尽**：无 `default` 时，缺失成员即硬错并列出缺失项；有 `default` 时不做缺失检查。
5. **可达性**：重复 case、被 `default` 或前序 case 完全覆盖的 case 报错。
6. **绑定**：每个 case 的绑定个数与成员声明一致；绑定类型即载荷类型；绑定在 case 体内只读（赋值/取址
   明确禁止，理由见 non-goals）。
7. **载荷约束**：载荷类型必须可平凡复制（标量/指针/无 Drop 的 struct）；含 `Drop` 的类型暂不允许作载荷，
   给硬错而不是静默复制（D46-2）。
8. **布局与发射**：`struct Name { int tag; union { … } u; }`；构造/判别/取值全部静态生成，无运行时反射、
   无间接层；不改变既有 C 枚举的发射形态。
9. **与 `switch` 的关系**：`match` 是新语法，不改 `switch` 语义；`match` 只接受 ADT 值。

**完整性边界**

| 维度 | 内容 |
| --- | --- |
| 交付后能写 | 任意非泛型带载荷枚举；构造；穷尽 `match`；`default` 兜底；纯标签成员；按值传递/返回（平凡复制） |
| 不能写 | 泛型 ADT（`enum Option<T>`）；嵌套构造子模式（`case A(B(x))`）；载荷含 `Drop` 的类型；把 ADT 当 C 枚举常量用；对 C 枚举写 `match` |
| 不能写的反馈 | 全部编译期硬错（见下表）；不存在「少写一个 case 仍能编译」的路径 |
| 为什么载荷先限制平凡复制 | 绑定语义（按值还是按引用）与 Drop 归属是一套独立的拥有权设计，硬塞进本相会把 `own`/Drop 规则改坏。给硬错是诚实的边界，不是静默降级 |

**诊断清单**

| 编号 | 触发 | 文案 |
| --- | --- | --- |
| L46-1 | `match` 的操作数不是 ADT | `match needs an ADT value` |
| L46-2 | 非穷尽且无 `default` | `non-exhaustive match: missing '<A>', '<B>'` |
| L46-3 | 不可达 case | `unreachable case '<A>'` |
| L46-4 | 重复 case | `duplicate case '<A>'` |
| L46-5 | 绑定个数/构造参数个数不符 | `case '<A>': expected <m> bindings, got <n>` |
| L46-6 | 载荷类型含 `Drop` | `'<T>' cannot be an ADT payload (needs Drop)` |
| L46-7 | 成员不存在 / 构造参数类型不符 | `'<X>' is not a member of '<E>'` / `'<E>::<X>': expected '<T>', got '<U>'` |
| L46-8 | 对 case 绑定赋值或取址 | `a case binding is read-only` |

**不做（non-goals）**

| 不做 | 理由 | 后续 |
| --- | --- | --- |
| 泛型 ADT | 与单态化/Drop 交互，需独立设计 | PH-47（未定稿） |
| 嵌套构造子模式 | 需要递归模式 AST 与乘积穷尽分析 | PH-47（未定稿） |
| 迁移 `Option`/`Result` 布局 | 破坏已发布 struct 布局与 Drop 胶水契约 | PH-47 且需版本化迁移规则 |
| 载荷含 `Drop` 的拥有权语义 | 与 `own`/Drop 规则耦合 | PH-47 |
| 模式守卫（`case A(x) if x > 0`） | 会让穷尽判定变成不可判定问题 | 不做 |
| 零载荷 ADT | 与既有 C 枚举不可区分，保持原语义 | 不做 |

**工量构成（相对仓库自估的增量）**

仓库对「枚举带载荷 + 模式匹配」的自估是 1,500–3,000 行（`docs/modern-oo-gap.md:170`），只覆盖语言实现。
本相要求四件套闭环，因此在其上增加诊断夹具 200–300（正 8 / 负 12 + 自举矩阵）与文档 80–150
（spec 新节、教程、术语、双语 README），合计 1,780–3,450，取 **1,800–3,300**；多出来的部分就是
「诊断 + 文档 + 门禁」，不是能力缩减或能力膨胀。

**风险**

1. `enum` 语义分叉（C 枚举 vs ADT）是最大的兼容风险；D46-1 必须在写代码前冻结，并用矩阵覆盖
   零载荷/混合载荷/嵌套 struct/enum 作字段。
2. 自举 fixpoint：新节点与模式表必须能被自身编译器解析与发射，任何 `MAX_*` 增长要按既有纪律处理。
3. 穷尽分析的文案与顺序要稳定，否则夹具会因成员排序抖动而脆弱；成员顺序按声明序。
4. 工量上限高，必须有切片级红证；不允许「先合并一半再补诊断」。

## 11. 建议先立哪一相

**PH-43**，理由按权重排序：

1. **正确性优先**：它修的是「编译器判得出、却静默发射非法 C」。仓库的底线是「禁发射坏 C、禁吞错」，
   这类缺口优先级高于任何语法糖。
2. **它是 `?` 的硬前置**：`?` 的失败分支就是 `return err:`；先建契约再加糖，避免把同一条缺口放大成
   语法级隐患，也避免 `?` 的 E 校验变成第二套类型规则。
3. **它最小、可在一相内把四件套流程跑通**：实现面只有一处门槛改动，风险可控；用它把「S0 现状核查 →
   红证 → 实现 → 文档同步 → 门禁接入」的模板固定下来，后续相照抄。
4. **`?` 的收益大但只晚一相**：不是长期绕路，且 `?` 的消歧规则与 `ret_type` 形态需要单独冻结，放在
   43 之后评审质量更高。
