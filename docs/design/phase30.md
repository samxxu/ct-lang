### 1.2 一句话目标

新增**语句形态**与**值形态**的接收者语境块：`<receiver> into { … }`，块内用 `.name`
访问接收者成员/方法、用 `$` 指代接收者自身，编译期完全脱糖为铺开的 C，不引入运行时。

### 1.4 不做

| 不做的东西 | 一句话理由 |
| --- | --- |
| 嵌套接收者块 | 内层 `$` 指向哪层需要额外规则与诊断；先禁，出现真实需求再放开 |
| `with (expr) { … }` 形态 | 接收者作为函数参数需要括号；`into` 是后置词，形态更短（B30-1） |
| 裸形态 `expr { … }`（无关键字） | 与控制块视觉混淆、难 grep、诊断无法点名（B30-2） |
| 块嵌在任意子表达式中（如 `f(x into { … })`） | 提升语句的插入点不唯一；v1 只开「三个值位置 + 语句位置」的完整后缀链（§2.8） |
| 接口值 / 动态类型接收者 | `.name` 的字段与方法无法在编译期解析；与动态派发的「静态类型必须已知」同源 |
| `own` 接收者（AutoDrop） | `$ = …` 会经过旧值释放路径，双重释放 / 泄漏面未定；本相显式拒绝（L30-4），留待专用阶段 |
| 命名空间宿主的静态映射（`tick::Ticker`）作接收者 | 没有对象可绑定；`A::B::T.m(…)` 已能表达，`into` 无从谈起 |
| 匿名函数 / 块内新作用域语义 | 块与宿主函数同一作用域，不做闭包 |
| `const` / 文件作用域 `static` 初始化里的块 | 块内有语句，不是常量表达式 |
| 宏、属性、反射形式的替代语法 | 与零运行时、C 超集口径冲突 |

## 2. 语义

### 2.1 语法与解析边界

```c
/* 语句形态 */
AppConfig::instance() into {
    .host = "0.0.0.0";
    call_outer_function($);
    log_config(.host, $->port);
};

/* 值形态：初始化器 / 赋值 / return */
AppConfig *cfg = AppConfig::instance() into {
    .host = "0.0.0.0";
    .port = 8080;
};
```

- `into` 是**上下文关键字**，写法与 `foreach` 一致：词法仍是标识符，解析器在
  「一个 primary/postfix 表达式之后 + 下一个 token 为 `into` + 再下一个为 `{`」时进入块；
- 接收者表达式只接受 **primary/postfix 形态**（标识符、字段访问、调用、限定名、`$` 除外）。
  `a + b into { … }` 报 L30-2，不静默绑定到 `b`；
- 值位置仅三处：声明初始化器、赋值右值、`return`；其他位置出现 `into {` 报 L30-1；
- 语句形态末尾 `;` 可省（省掉时按空语句处理）。

### 2.2 `$` 与 `.name`

`$` 在两种语境里**同名不同绑定**：range 初值的 `$` 是生成序列的当前**下标值**
（§4.47 的 `((int)k)`，从 `start` 起），`into` 的 `$` 是**接收者本身**。两者都不是标识符、
不进符号表，但语义不能互相套用。

| 语境 | 绑定 | 能力 | 发射 |
| --- | --- | --- | --- |
| range 初值 `a..b(expr)` | 生成序列的当前下标值（从 `start` 起） | 只读整数；`&$` / `$++` 报错 | `((int)k)` |
| 接收者语境块 | 接收者表达式本身 | 按 C 左值规则；可 `&$`、`$->x`、作实参、`$ = expr`（`own` 接收者除外） | `__ct_recvN` 或 `(*__ct_recvN)` |

- `.name` 与 `$` 同源：`.name` = 「自身的成员」，`$` = 「自身」；
- `.name` **优先绑定接收者**，不与同名局部变量/参数竞争；带点的名字才走接收者；
- 名字解析顺序：字段 → struct 方法 → trait impl（按 `use` 顺序取第一个）→ **类型宿主静态映射**；
  多候选完全沿用块外规则（类型宿主沿用其既有 `ambiguous type-host map` 文案），本相**不新增
  歧义码**；只有无候选才报 L30-5；静态映射宿主的细则（shim、成员表、recipe 替换）见 §2.7；
- 块外 `$` 维持既有诊断 `unexpected token`（`range_index_outside` 已钉住），本相不新增 L30
  文案、不改既有 golden；
- L24-11（`the range index '$' is not a variable`）只约束 **range 语境**；进入 `into` 块后 `$`
  是接收者左值，`&$` / `$ = expr` 合法——本相**部分取代** L24-11 的适用范围，Phase 24 的三条
  定点检查与既有 golden 均不变。

### 2.3 接收者求值与 value category

接收者只求值一次，提升规则按表达式类别而定，**不得一律按值提升**：

| 接收者类别 | 提升 | `.name` | `$` | 静态映射实参 |
| --- | --- | --- | --- | --- |
| 指针 | `T *__ct_recvN = expr;` | `__ct_recvN->name` | `__ct_recvN` | `__ct_recvN` |
| 左值值类型 | `T *__ct_recvN = &expr;` | `__ct_recvN->name` | `(*__ct_recvN)` | `(*__ct_recvN)` |
| 右值值类型（仅值形态） | `T __ct_recvN = expr;` | `__ct_recvN.name` | `__ct_recvN` | `__ct_recvN` |

静态映射 recipe 的首个绑定参数是**值语义**，用最后一列替换；成员糖用 `.name` 列。两者不能混：
把 `int n` 的左值接收者按指针传给 recipe，会变成 `host_twice(&n)` 而不是 `host_twice(n)`。

若左值也按值提升，`*p into { .x = 1 }` 会改成临时副本而不是 `*p`，属静默错误。

### 2.4 值形态的结果

值形态的结果是**接收者本身**（Kotlin `apply` 语义），不是块内最后一条语句的值：

- 指针接收者 → 结果类型是指针；
- 值类型接收者 → 结果是（配置后的）值；左值接收者先原地修改，再把值复制给目标；
- 块内语句的值一律丢弃；块内允许 `return` / `break` / `continue`，它们作用于宿主函数
  与宿主循环（本块不建立函数作用域、不建立新的跳转边界）；
- 结果可继续接后缀（`.m()` / `->f` / `.f` / `[i]`）；块只决定接收者，链上后续调用的返回值
  才是整个表达式的值（§2.8）。

### 2.5 诊断

| 码 | 触发 | 文案（草案） |
| --- | --- | --- |
| L30-1 | `into {` 出现在不允许的语法位置（任意子表达式等） | `'into' block is not allowed here` |
| L30-2 | 接收者不是 primary/postfix 表达式（如 `a + b into`） | `'into' needs a variable, field or call on its left` |
| L30-3 | 接收者静态类型未知 | `cannot determine the receiver type of this 'into' block` |
| L30-4 | 接口值或 `own` 接收者 | `'into' cannot take an interface or 'own' receiver` |
| L30-5 | `.name` 在已知成员表上找不到成员/方法（歧义沿用既有文案） | `no member '<name>' on the 'into' receiver` |
| L30-6 | 裸语句形态（无后缀）的右值接收者（写入会丢弃） | `an 'into' statement needs a writable receiver` |
| L30-7 | 嵌套 `into` 块 | `nested 'into' blocks are not supported` |

常量/文件作用域初始化里的块：`initializer is not a constant expression`（复用既有诊断，
不新增码）。

### 2.6 与既有语法的关系

- `foreach` / `loop` / `if` 均以关键字开头，不冲突；
- `(Type){ … }` 是复合字面量，走既有「类型名 vs 表达式」判定，不受影响；
- `expr into { … }` 的首 token 是表达式，C 语法里该位置后接 `{` 原本非法，因此不破坏
  既有 C 代码；`into` 作标识符的代码也仍合法（上下文关键字）；
- `into` 是后置后缀：`}` 之后的 `.` / `->` / `[` 一律归块外（§2.8），不参与块内语句。

### 2.7 静态映射（含 shim）宿主

`.m.ct` 的类型宿主与 `into` 天然同构：两者都只依赖接收者的**静态类型**，都在调用点展开为裸 C，
都不产生 wrapper / vtable / 运行时。因此静态映射对象可以直接当接收者，**不需要新机制**；这也让
「块内 `.name`」与「块外 `recv.name`」保持同一套查找规则。

| 宿主形态 | 例子 | 作 `into` 接收者 | 说明 |
| --- | --- | --- | --- |
| 指针别名 / 不透明句柄 | `pub type FileHandle = struct ct_file *;` | ✅ | 指针类别；`.read(5)` → `ct_file_read(r, 5)` |
| C 值结构体 | `pub type CBuilder = struct Builder;` | ✅ | 左值/右值值类型；链式方法返回新值，用 `$ =` 接 |
| 内建 C 拼写 | `for type char *` / `int` / `double` | ✅ | 走同一 `type_key`；数组按既有规则 decay |
| 命名空间宿主 | `for namespace tick` | ❌ | 没有对象；写 `tick::Ticker.bump(2)` |
| 接口值 / 动态派发 | trait 变量 | ❌ | L30-4；字段与方法无法静态解析 |

规则：

1. `.m(args)` 走与块外完全相同的查找：struct 方法 → trait impl（按 `use` 顺序取第一个）→
   类型宿主；类型宿主多候选沿用既有 `ambiguous type-host map for method '<m>' ...`，不另立
   L30 码。
2. 方法必须带括号；无括号的 `.name` 按字段处理。CT 结构体有成员表，缺成员走 L30-5；
   **不透明 C 宿主没有成员表**，`.field` 原样发射 `recv->field`，由 C 编译器判定（`#line` 映回 `.ct`）。
3. recipe 的首个绑定参数在被提升的接收者上替换 **1 次**，用 §2.3 最后一列的值形态：
   指针 `ct_file_read(__ct_recv0, 5)`、左值值类型 `host_twice((*__ct_recv2))`、
   右值值类型 `builder_value(__ct_recv1)`。
4. 接收者已提升为变量，recipe 里对它的多次引用总是满足「实参可重复」的约束；`into` 因此
   放宽了 `s.trim().len()` 这类写法，而不是收紧。
5. `$` 是提升量的左值（`own` 接收者整体拒绝，见 L30-4）：值宿主 `$ = .add(1)` 重绑提升量；
   指针接收者的 `$ = other` 只重绑块内变量，**不写回**调用点的指针变量，需要在块外另行赋值。
6. shim 装配不变：消费者 `.c` 自动 `#include "<base>.shim.h"`，`ct build` 追加 `-I`，存在的
   `.shim.c` 进同一条 `cc` 行；`into` 不新增 shim 约定，也不改变 `--emit-map` 条目
   （仍是 `"static": true`、`"host": "type"`）。
7. 链式调用：只有**首个前导点**绑定接收者，链上后续 `.m()` 是普通 postfix，按前一步返回值的
   静态类型照常解析。因此块内 `.add(1).add(2)` 与块外 `b.add(1).add(2)` 语义完全一致，
   `into` 只是省掉了链头的接收者名字。

### 2.8 块结束后继续链式（后缀链）

`into` 的结果是接收者本身，所以它整体是一个**后缀表达式**：`}` 之后可以继续接 `.m(args)`、
`->field`、`.field`、`[i]`。块负责“进入语境配置对象”，出块后对象继续沿链往前推：

```c
int pos = open_file("a.txt") into {
    .write(9);
}->pos;

struct Builder b = builder_make(10) into {
    $ = .add(1);
}.add(2).add(3);

int len = read_line() into {
    .trim();
}.len();                  /* 静态映射宿主同样适用 */

AppConfig *cfg = AppConfig::instance() into {
    .host = "0.0.0.0";
} into {
    .port = 8080;
    printf("%s\n", $->host);   /* 第二段看到的仍是同一对象 */
};
```

展开（链头替换为接收者的值形态，块内语句提到宿主语句之前）：

```c
struct ct_file *__ct_recv0 = open_file("a.txt");
ct_file_write(__ct_recv0, 9);
int pos = __ct_recv0->pos;

struct Builder __ct_recv1 = builder_make(10);
__ct_recv1 = builder_add(__ct_recv1, 1);
struct Builder b = builder_add(builder_add(__ct_recv1, 2), 3);

AppConfig *__ct_recv2 = AppConfig::instance();
__ct_recv2->host = "0.0.0.0";
AppConfig *__ct_recv3 = __ct_recv2;
__ct_recv3->port = 8080;
printf("%s\n", __ct_recv3->host);
AppConfig *cfg = __ct_recv3;
```

规则：

1. **绑定方向**：`{` 前的表达式是接收者；`}` 后的后缀作用在块的结果（接收者）上；块内最后
   一条语句不会“漏”到块外。
2. **可以连续多段**：`a into { … } into { … }` 合法，等价于对同一对象连续进入两个语境；每段
   的接收者是上一段的结果（指针仍指向同一对象；值类型按 §2.3 提升，必要时产生一个临时副本，
   语义不变）。**嵌套**（块内再写 `into`）仍禁（L30-7），因为内层 `$` 的归属会歧义。
3. **位置**：允许出现在三个值位置（初始化器 / 赋值右侧 / `return`）与表达式语句；仍不允许
   作为任意子表达式（如 `f(x into { … }.m())`，L30-1），以保证提升语句的插入点唯一。
4. **可写性**：裸语句 `x into { … };`（无后缀）仍要求可写接收者（L30-6）；带后缀时是值表达式，
   右值接收者合法，如 `builder_make(10) into { … }.print();`。
5. **求值次数**：链头仍是提升量 `__ct_recvN`（左值值类型为 `(*__ct_recvN)`），不是原表达式；
   工厂函数只调用一次，链上第一个方法看到的正是块内修改后的对象；多段 `into` 按书写顺序
   依次提升。

## 3. 脱糖矩阵

```c
/* 语句形态，指针接收者 */
AppConfig *__ct_recv0 = AppConfig::instance();
__ct_recv0->host = "0.0.0.0";
call_outer_function(__ct_recv0);
log_config(__ct_recv0->host, __ct_recv0->port);

/* 值形态，右值值类型接收者 */
AppConfig __ct_recv1 = make_config();
__ct_recv1.host = "0.0.0.0";
AppConfig cfg = __ct_recv1;

/* 值形态，左值接收者 */
AppConfig *__ct_recv2 = &cfg2;
__ct_recv2->port = 8080;
cfg = *__ct_recv2;
```

静态映射宿主（`map trait … for type …`，含 shim）。源码：

```c
/* A. 指针宿主：pub type FileHandle = struct ct_file *; */
FileHandle f = open_file("a.txt") into {
    printf("tell %d\n", .tell());
    printf("read %d\n", .read(5));
};

/* B. 值宿主：pub type CBuilder = struct Builder;（方法返回宿主本身） */
struct Builder b = builder_make(10) into {
    $ = .add(1).add(2).add(3);
    printf("mid %d\n", .value());
};

/* C. 标量宿主：map trait IntOps for type int */
int n = 21;
n into {
    printf("twice %d\n", .twice());
};
```

展开：

```c
/* A */
struct ct_file *__ct_recv3 = open_file("a.txt");
printf("tell %d\n", ct_file_tell(__ct_recv3));
printf("read %d\n", ct_file_read(__ct_recv3, 5));
FileHandle f = __ct_recv3;

/* B */
struct Builder __ct_recv4 = builder_make(10);
__ct_recv4 = builder_add(builder_add(builder_add(__ct_recv4, 1), 2), 3);
printf("mid %d\n", builder_value(__ct_recv4));
struct Builder b = __ct_recv4;

/* C：左值值类型，recipe 拿的是值不是指针 */
int *__ct_recv5 = &n;
printf("twice %d\n", host_twice((*__ct_recv5)));
```

三例都不生成 wrapper / vtable / 盒装接口值：`.read` / `.add` / `.value` / `.twice` 在调用点消失，
产物与手写 `ct_file_read(f, 5)`、`builder_add(b, 1)`、`host_twice(n)` 一致。

### 3.1 可读性对比样例（`into` × 链式）

本节四组样例同时是**文档示例与夹具**（`test/ast/160–163`）：同一逻辑各写两遍，断言运行输出
一致；生成 C 经 E30-9 的归一化命令（去 banner / `#line`、`__ct_recvN` 折叠）后逐字节相同。
**夹具**的手写侧把接收者变量命名为 `__ct_recv0…`，与 `into` 侧的提升量同名；下文 `cfg` / `b` /
`f` 只是可读性示意，不是夹具里的实际变量名。
对比口径是**接收者名字出现次数**与**用户可见的临时变量 / 自赋值**，不是行数——`into` 省掉的
是重复的主语，不是把语句压成一行。

**A. 字段配置 + 外部调用（指针宿主）**

```c
/* 手写：主语 cfg 出现 5 次 */
AppConfig *cfg = AppConfig::instance();
cfg->host = "0.0.0.0";
cfg->port = 8080;
validate_config(cfg);
register_shutdown(cfg, cfg->port);
```

```c
/* into：主语出现 1 次，动作按顺序排列 */
AppConfig *cfg = AppConfig::instance() into {
    .host = "0.0.0.0";
    .port = 8080;
    validate_config($);
    register_shutdown($, .port);
};
```

**B. by-value 链式（`$ =` 接整条链）**

```c
/* 手写：临时变量 + 自赋值 */
struct Builder b = builder_make(10);
b = b.add(1).add(2).add(3);
return b;
```

```c
/* into：无用户可见临时变量、无自赋值 */
return builder_make(10) into {
    $ = .add(1).add(2).add(3);
};
```

生成物：`return` 前只有一次提升与一次嵌套调用
`__ct_recv0 = builder_add(builder_add(builder_add(__ct_recv0, 1), 2), 3);`。

**C. 句柄连续操作（生命周期动作留在块外）**

```c
/* 手写：主语 f 出现 4 次 */
struct ct_file *f = open_file("a.txt");
int n = ct_file_read(f, 5);
ct_file_write(f, n);
printf("tell %d\n", ct_file_tell(f));
close_file(f);
```

```c
/* into：块只描述“对 f 做什么”，close 留在块外 */
struct ct_file *f = open_file("a.txt") into {
    int n = .read(5);
    .write(n);
    printf("tell %d\n", .tell());
};
close_file(f);
```

**D. 块后继续后缀链（`into` 作为后缀表达式）**

```c
/* 手写：临时变量只为读一个字段 */
struct ct_file *f = open_file("a.txt");
ct_file_write(f, 9);
int pos = f->pos;
```

```c
/* into + 后缀链：配置完直接沿链读字段 */
int pos = open_file("a.txt") into {
    .write(9);
}->pos;
```

```c
/* 链式宿主：块内接第一跳，块后继续推 */
struct Builder b = builder_make(10) into {
    $ = .add(1);
}.add(2).add(3);
```

| 组 | 接收者名（前 → 后） | 用户可见临时变量 | 自赋值 | 生成 C（归一化后） |
| --- | --- | --- | --- | --- |
| A | 5 → 1 | 0 → 0 | — | 逐字节相同 |
| B | 4 → 0 | 1 → 0 | 1 → 0 | 逐字节相同 |
| C | 4 → 1 | 0 → 0 | — | 逐字节相同 |
| D | 2 → 0 | 1 → 0 | — | 逐字节相同 |

两者配合的读法是「**主语只出现一次，动词按顺序排**」：块内每行以 `.` 开头，视觉上天然对齐；
链式负责把同一主语的连续变换串成一个表达式，`into` 负责把不同类动作（字段写入、方法、
外部函数调用）收进同一个语境。B / D 两组收益最大：手写版的 `b = b.add(…)` 自赋值、
只为读一个字段而引入的临时变量，在 `into` 版里都消失了，块结束后还能继续沿链往前推。

## 4. 决策

| 编号 | 决策 | 判据 |
| --- | --- | --- |
| D30-1 | 用**后置关键字 `into`**，不用 `with` | `with` 在 Kotlin/Swift 都是函数，需要括号传参；`into` 直接吃前面的表达式（B30-1） |
| D30-2 | `into` 是**上下文关键字** | C 里 `into` 是合法标识符；全局保留会破坏 C 超集（Z3 / Z6） |
| D30-3 | 不支持裸形态 `expr { … }` | 可 grep、可诊断、不与控制块混淆（B30-2） |
| D30-4 | `$` 复用为「当前语境的自身」 | 与 Phase 24 的 `$` **符号复用、绑定不同**（range = 当前下标值，本相 = 接收者）；`$` 不是合法 C 标识符，比 `self` 安全（B30-3） |
| D30-5 | `.name` 优先绑定接收者 | 前导点是显式标记，消除 Pascal/D `with` 的遮蔽问题 |
| D30-6 | 接收者只求值一次，按 value category 提升 | 工厂有副作用；左值不得退化成副本（R1 / R2） |
| D30-7 | 值形态返回接收者本身 | 配置对象的用例要求结果就是它（B30-4） |
| D30-8 | 值位置只开初始化器 / 赋值 / `return` | 控制优先级与诊断面；其余位置的 `into {` 报 L30-1 |
| D30-9 | 禁止嵌套块 | `$` 的归属会出现二义；先禁 |
| D30-10 | 接口值 / `own`（AutoDrop）接收者拒绝 | 接口字段与方法无法静态解析；`own` 的 `$ =` 会经过旧值释放路径，双重释放 / 泄漏面未定（L30-4） |
| D30-11 | 语句形态要求可写接收者 | 右值写入会静默丢弃；值形态才允许右值 |
| D30-12 | 块不建立新作用域、不建立跳转边界 | 它是语句序列，不是闭包；`return` 语义与宿主函数一致 |
| D30-13 | **静态映射类型宿主**（含 `.shim.h` / `.shim.c`）可作接收者 | 两者都只依赖静态类型、都在调用点展开；不支持会让 `.name` 在块内外语义不一致（B30-6） |
| D30-14 | recipe 的接收者实参用**值形态**（左值值类型 `(*r)`），成员糖用 `->` / `.` | recipe 的绑定参数是值语义；传 `&r` 会把 `host_twice(n)` 变成 `host_twice(&n)`（§2.3） |
| D30-15 | `$` 是可写左值（`own` 接收者除外）；`$ = expr` 只重绑块内提升量 | 值宿主的链式方法返回新值（`builder_add`），没有 `$ =` 就无法用 `into` 配置它 |
| D30-16 | 命名空间宿主不可作接收者 | 没有对象；`A::B::T.m(…)` 已达意，`into` 无绑定目标 |
| D30-17 | `into` 是后缀表达式，结果为接收者，可继续接 `.m()` / `->f` / `.f` / `[i]`，也可连续多段 `into` | 「进入语境、出来仍是我」；块后接链才能把配置与后续读取写成一条表达式；多段只是同一后缀的重复应用，无需额外限制 |
| D30-18 | `$ = expr` 在**非 `own`** 的值宿主与指针接收者上都开放：值宿主重绑提升量，指针只重绑块内指针变量（§2.7 规则 5）；`own` 接收者整体拒绝 | 与 L30-4 同一条边界；不让释放语义在语法糖里隐式发生 |

## 5. Battle 记录

### B30-1 `into` vs `with`

- **`with` 派**：Kotlin `with(x) { … }`、Swift `with` 辅助函数心智成熟，读者零成本。
- **`into` 派**：两者都是**函数**，需要括号与参数位置；本构造是后置词，接收者就是前面的
  表达式，`with` 会迫使写法变成 `with (expr) { … }`，多一层括号与一个参数槽。
- **裁决**：`into`。判据是「形态贴合」：本构造不是函数调用，不应借用函数形态；
  词义上把 `into` 定义为「进入接收者语境」，不取 Rust `Into` 的转换义。

### B30-2 关键字 vs 裸形态

- **裸形态派**：`expr { … }` 更短，省一个词。
- **关键字派**：可 grep、诊断能点名「接收者语境块」、不与 `if/loop` 块视觉混淆；
  且裸形态在 `a + b { … }` 这类边界上无法给读者明确提示。
- **裁决**：关键字。判据是可维护性（N4）压过每处少 5 个字符。

### B30-3 `$` vs `self` / `this`

- **`self`/`this` 派**：主流语言心智直接。
- **`$` 派**：CT 是 C 超集，`self`/`this` 都是合法 C 标识符，保留为关键字会破坏既有代码；
  `$` 在 C 里非法，作 sigil 零冲突；且 Phase 24 已把 `$` 用作 range 的当前下标值，
  复用同一符号比引入第二个 sigil 更省心智（绑定不同，§2.2）。
- **裁决**：`$`。判据是 1.0 兼容与语义统一。

### B30-4 值形态返回接收者 vs 最后一条语句的值

- **最后值派**：更像 Rust 块 / Kotlin `run`，表达力更强。
- **接收者派**：用例是「构造 + 配置 + 交出」，返回接收者才让 `T x = expr into { … }` 成立；
  返回最后值会迫使读者在块尾写 `$`，反而更啰嗦。
- **裁决**：接收者。判据是目标用例的直接性；需要最后值时用普通语句块。

### B30-5 按类别提升 vs 一律按值提升

- **一律按值派**：实现简单，一个 `T __ct_recvN` 走天下。
- **按类别派**：左值/指针接收者的写入必须落回原对象，否则 `*p into { .x = 1 }` 静默失效。
- **裁决**：按类别。判据是语义正确性优先于实现便利。

### B30-6 只支持 CT struct vs 静态映射宿主同权

- **只支持 CT struct 派**：成员表只在编译器里已知，`.name` 能严格校验；实现面更小。
- **同权派**：`.name` 应只依赖**静态类型**，不应依赖「这个类型是谁声明的」；否则同一个
  `.read(5)` 在 `into` 内外行为不同。静态映射（含 shim）正是 CT 与 C 互操作的主场景，
  把它排除会让新语法在最需要的地方不可用。
- **裁决**：同权。不透明 C 宿主没有成员表，`.field` 交给 C 编译器判（`#line` 映回 `.ct`）；
  方法查找、歧义、recipe 替换全部复用既有路径（D30-13 / D30-14）。

### B30-7 `into` 与链式编程的协同

- **独立看待派**：`into` 解决「配置一个对象」，链式解决「连续变换」，是两个特性。
- **协同派**：两者叠加时收益最大——块内首跳省掉接收者名字（`.add`），后续跳保持链式
  （`.add(1).add(2)`），by-value 宿主再用一条 `$ =` 接住整条链；读者看到的是
  「对谁、做什么」，而不是重复的对象名与中间变量。
- **裁决**：协同。示例：`struct Builder b = builder_make(10) into { $ = .add(1).add(2).add(3);
  printf("%d", .value()); };`，展开为一次嵌套的三层 `builder_add` 调用，无中间变量、无 wrapper。
