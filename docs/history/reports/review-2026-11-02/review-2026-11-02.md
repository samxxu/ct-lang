## 1. 方法与基线

1. 先固定锚点：`git log` 取 `59f80e6`（18.0）…`553d300`（18.6 收口）六个提交，再逐文件读未提交 diff；
   把「版本 bump 的机械改动」与「18.x 的实质改动」分开核对。
2. 机械项用可判定的方法验：五处 `CTC_VERSION` 取值；71 个 golden 把 `v0.17.0` / `v0.18.0` 归一成 `vX`
   后做集合差（结果为空，确认**仅 token 变化**）；`check-all.sh` 的 `run_gate` 计数。
3. 18.0 逐条走分配路径：`sym_alloc` 的幂等守卫、`calloc` 零初始化是否等价于原静态零初始化、
   `sym_alloc()` 的调用点是否早于任何符号访问、是否残留 `sizeof(数组)` 假设。
4. 分发面不复用旧副本：从 GitHub 重新 clone `ct-pkg/{hal,hal-posix,clib}` 的 `v1.0.0`，
   用 `ct-pkg/index` 的 `tools/gen-index.sh` 重算摘要，与线上 `index` 三行逐一比对。
5. 文档侧逐句回读被引用代码：作者指南里「`ct verify` 校验依赖覆盖」「`ct get` 是唯一子进程调用点」

### 3.1 关键证据

**PKG-1（Medium）**——契约写 `int now_ms()` 且「monotonically non-decreasing」，实现却是绝对毫秒：

```ct
int hal_posix_now_ms(void)
{
    struct timespec ts;

    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (int)(ts.tv_sec * 1000 + ts.tv_nsec / 1000000);
}
```

`2^31 ms ≈ 24.86 天`；越过 `INT_MAX` 后为负。`examples/wave1-demo` 只断言 `clock=1`（相邻调用递增），
`packages.yml` 的 host / aarch64 job 跑的是同一份 demo，因此 CI 永久不会暴露它。

**DOC-55（Medium）**——`pkg_verify` 只调 `pkg_verify_lock`：

```ct
/* `ct verify`: the offline half of install -- no manifest, no command. */
static int pkg_verify(const char *prog)
{
    ...
    if (pkg_verify_lock(prog, lname, lver, &nlock) != 0) return 1;
    printf("verified %d package(s)\n", nlock);
    return 0;
}
```

依赖覆盖在 `install`（[Pkg.h.ct:1241-1255](../../../../selfhost/ct-ast/tool/pkg/Pkg.h.ct#L1241-L1255)），
测试也只覆盖摘要篡改（[run.sh:599-615](../../../../test/pkg/run.sh#L599-L615)）。
另一处「唯一子进程」与 Phase 17 的 D17-9 冲突：`ct build` 默认在
[Module.h.ct:1078-1080](../../../../selfhost/ct-ast/frontend/module/Module.h.ct#L1078-L1080) 解析 `$CC` 并用
`system()` 执行。

**CI-5（Low）**——过滤清单与计划原文不一致；外部仓库侧只能靠 nightly（已接受），但**本仓库的包工具**
改动静默跳过包门禁，而 `Pkg.h.ct` 恰好是这条端到端链的核心。

**SH-48（Info）**——18.0 的验收口径是「L2 能编 ct-ast」，不是「上限对齐」。当前 ct-ast 用 30 个 struct、
L2 上限 64，余量约 34 个；不是现行缺陷，但下一次 struct 增长会先在 L2 处失败，报错位置容易误导。

## 4. 已检查但不立案

- **`packages.yml` 两个 job 各自重复整条四层自举**：维护重复，不是缺陷；抽 composite action 属优化。
- **`ct.pkg` 的 `licence` 键工具不解析**：D18-3 已确认「仅约定」，与 DOC-57 的措辞问题分开。
- **`hal-posix` 的 `hal_posix_gpio_state` 非 `static`**：单单元程序内无符号冲突；多实例 / 多包同链时才需注意。
- **`clib::Stdio.printf` 只接受单个 `int` 实参**：D18-5 的「最小面」决策，spec 已声明。
- **roadmap 版本记录的「接替」标注不统一**（`v0.16.3` 有、`v0.17.0` 无）：既有惯例漂移，属措辞级，
  不单独立项；随 DOC-56 一起收拾即可。
- **18.1 的 `.m.ct` / `.h.ct` 后缀与 demo 输出**：`strlen=4` 与已发布 `unsigned long strlen` 一致，
  之前怀疑的 `%lu` 不匹配在已发布内容上**不存在**（`/tmp` 旧副本才是旧签名）。
- **索引摘要与本地副本不一致**：复核为「本地副本旧于已发布 tag」，不是缺陷；以 tag 重算结果为准。
