## 1. 基线与方法

```text
$ bash selfhost/check-all.sh
== summary: 118 passed, 0 failed ==                 # 1) test/run.sh
L1 golden coverage: 25 pass, 0 new, 0 pending, 0 regression   # 2) check-goldens
...                                                 # 3)–7) 全绿

== 31 checks, 0 failed ==                           # 6) editor grammar
== summary: 20 pass, 0 new, 0 pending, 0 regression ==   # acceptance（不阻断）

```

方法：

1. 文档侧先做机械核对（`ls` 计数、`grep` 代码里的消息/常量、`git check-ignore`、`wc -l`），
   再逐条回读被引用的代码位置，避免把「文档说 A、代码是 B」误判为「文档旧」而其实是指代不同编译器。
2. 代码侧对每个候选缺陷先在 `/tmp/ctaudit` 用真实二进制复现（编译 → `cc -Wall -Wextra` → 运行），
   只有能给出输入、输出或代码路径证据的才立案。
3. 已知在册、复核仍复现的条目（SH-7 等）不重复立案；本轮不评估 batch 39 的在途改动。

### 3.1 复现记录

**SH-25**（High）：

```ct
trait T { int m(); }
struct Inner { int x; } use T;
impl T for Inner { int m() { return 0; } }
typedef struct Wrap { Inner items[2]; } WrapT;
int main(void) { WrapT w; w.items[0].x = 1; return 0; }
```

```text
$ ./ct-ast td.ct -o td.c ; echo $?
0
$ grep -n 'WrapT w' td.c
34:    WrapT w = { .items.__t_vptr = &Inner_T_vtable };
$ cc -Wall -Wextra -std=c99 -c td.c
td.c:34:23: error: field designator cannot initialize a non-struct, non-union type 'struct Inner[2]'
```

同一份源码改用 `struct Wrap w;`（走 tag 行，`dims` 完整）即正常——缺陷只在别名行。

**SH-27**（Medium）：`struct` 与 tag 分写两行时，前瞻跨过换行且不回退 `line`：


```text
$ ./ct-ast ln.ct -o ln.c

```
