### 4.1 证据

**DOC-58**——`issues/README.md` 第 57 行：

```text
- 硬关卡计数随阶段演进：6 → 7 → 8 → 9 → 10 → **11**（当前共 **11** 道：第 10 道是文档门禁
  `test/docs/check-docs.py`，第 11 道是 `test/std/run.sh`；…）。…现状一律以 `check-all.sh` 的
  「11 hard gates green」…为准。
```

而 `check-all.sh:84-87` 是：`10) std layer`、`11) semantic entry (Phase 19.4)`、`12) docs`。
本轮 `check-docs` 自报 `12 hard gates`。这条之所以再次漂移：**docs 门禁只校验 `docs/**`、根 `README.md`
与 `glossary.md`，不扫描 `issues/README.md`**，所以加门禁时不会被它挡住。

**DOC-59**——教程的 CLI 表（中文 `506-522`、英文 `1063-1078`）列了 `ct <in>` / `compile` / `build` /
`get` / `update` / `install` / `verify` / `-v` / `-h`，但没有 `ct check`；README 的同一张表（`39` / `118`）
有。教程还把 `--diagnostics` 只描述成「告警格式」，没有 check 下 `severity` 的说法（README 有）。

**SH-49**——`ct check` 的早退块在第 307 行，而 `.m.ct` 守卫与默认输出路径解析在 240–262 行：

```text
$ ct-ast check m.m.ct
ctc: a .m.ct unit produces no output; import it from a .ct unit
rc=1
```

`ct check` 本身不产生输出，这句话对 check 模式不成立；同理，输入路径过长时会在 `default_output`
处报 `output path too long`，而检查并不需要输出路径。修复方向：把 check 早退块前移到路径解析之前，
并给 `.m.ct` 一条 check 专用措辞（或明确拒绝并说明原因）。

**TEST-14**——`76-81` 行：

```bash
if "$work/ct-ast" check "$work/clean.ct" >… 2>… \
        && [ ! -s "$work/clean.out" ] && [ ! -s "$work/clean.err" ]; then
    ok …
else
    bad "check: clean unit" "exit $?; $(cat "$work/clean.err")"
fi
```

`else` 里 `$?` 是最后一个 test 的返回值；若 `ct-ast` 退出 1、但两个 `[ -s ]` 都成功（例如退出 1 却没留
stderr），`$?` 会是 0。头部第 11–14 行还声称验证「同一单元走 `ct compile` 仍是 `warning:` 且写 `.c`」，
实际只对歧义一类做了该断言，arity / 类型 / 漂移都没有对照。

## 5. 已检查但不立案（Info）

- **`set_strict` 作用于所有诊断 kind**，不只四类：`potential leak` / 借用逃逸在 check 下也会变 `error:`。
  实测 `own` + `Drop` 的探针在 compile / check 下都不再报（SH-33 的 AutoDrop 之后已难触发），
  故记为「实现比文档宽，但当前不可达」，等 leak 重新可达时再决定是收窄还是写进 README。
- **19.0 的发射形态没有本地断言**：`test/ast/37_empty_stmt` 只比较运行输出，旧 GNU 写法在 Apple clang
  下照样能编能跑；只有 gcc 12 的 CI 会挡住回退。属「CI 有覆盖、本地无」，不单独立项。
- **`ct check` 静默忽略 `--emit-map`**：check 块在发射前返回，开关被吞掉且无提示；低频。
- **arity / 类型检查同时作用于 `ct compile`**（D19-4 有意保留）：`check-warnings.sh` 新增的四段语料断言
  （arity / type / ambiguity 恰好一条 / impl 参数）兜住了 383 文件的零误报。
- **`check-semantics.sh` 每个用例都重建四层自举**：单次约多 30 秒，属门禁成本，不是缺陷。
