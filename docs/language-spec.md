## 0. 快速开始

```c
#include <stdio.h>

trait Shape { int area(void); }

struct Rect { int w; int h; } use Shape;

impl Shape for Rect {
    int area(void) { return self->w * self->h; }
}

int main(void) {
    struct Rect r = { 3, 4 };
    Shape s = r;                 /* 接口值：自动装箱 */
    printf("%d\n", s.area());    /* 12 */
    return 0;
}
```

```sh
ct build hello.ct -o hello && ./hello   # 单文件也可直接 ct-ast hello.ct -o hello.c
ct check --types hello.ct               # 可选类型检查
```

写代码前先记住五条：

1. 顶层构造以行首关键字开始（`trait` / `struct` / `union` / `enum` / `impl` / `pub` / `namespace` / `import`）；普通 C 声明与语句原样透传。
2. ct-ast 解析整棵 AST，**函数与全局可先用后定义**（自动补原型）；类型与 trait 必须先声明，`impl` 必须在两者之后。
3. `struct` 值加 `use Trait;` 后才有 vptr；`Trait x = s;` 把 struct 变量装箱成胖指针，`x.m()` 动态派发。
4. 资源用 `own` / `delete` / `Drop` / `defer` / `errdefer`；错误用 `Result<T,E>` 加后缀 `?` 或 `return err:`。
5. `ct build` 自动加载 `lib/std` 的 `Vec` / `Map` / `Option` / `Result` / `Str`，不需要 `import`。

## 中文

### 1. 源文件模型（ct-ast）

一个 `.ct` 文件是一个编译单元，可包含**顶层构造**与普通 C 代码；ct-ast 解析整棵 AST 后发射 C，
不做按行透传。三条入口：

| 入口 | 用途 |
| --- | --- |
| `ct-ast file.ct -o file.c` | 单文件编译（不解析 `import`） |
| `ct build main.ct -o prog` | 多文件构建；`import` 生效，最后调用 `cc` |
| `ct build --emit-c main.ct -o dir` | 多文件构建，只写生成的 `.c` / `.h` |

**单元类型**：`.h.ct` 发布接口；`.m.ct` 可被 `.h.ct` / `.ct` 单元 import（`map` 单元与 shim
依赖它，夹具 `map_unit_cross` 钉住这个方向）；普通 `.ct` 单元不能被 import（`resolve_import`
明确拒绝，提示改名 `.h.ct`）。`import a::b;` 由 `-I` 根目录解析到对应单元。

**顶层构造**（ct-ast 接受，详见 §3）：

```
import / namespace / pub / extern
trait / struct / union / enum / typedef
impl（trait impl、固有 impl）、泛型 struct / impl / 函数
函数定义、全局变量声明、static 断言、raw C 文本
```

**顺序规则**（与 L0 不同，P1）：

- 函数与全局**可以先用后定义**：ct-ast 自动发射原型 / `extern` 声明（探针 `order.ct`：`main` 先调 `later()`，rc=0）。
- `struct` / `union` / `enum` / `trait` 必须先声明；`impl` 必须在 trait 与 struct 之后。
- 变量仍遵守块作用域；同一作用域内重复声明按既有规则处理（§6）。

生成物第一行固定是溯源注释 `Generated by ct v<版本> from <输入路径> -- do not edit; ...`
（`.h` 头部也有一段等效注释），它不属于源文件内容。

#### 1.1 编译器代际与 L0/L2 差异（唯一集中处）

| 维度 | L0（`selfhost/l0/ctc.c`） | L2（`selfhost/l2/**`） | ct-ast（主线，本文默认） |
| --- | --- | --- | --- |
| 解析方式 | 单趟、行首关键字、按行透传 | 多单元行重写管线（旧） | 全 AST |
| 定义顺序 | 必须先定义后使用 | 旧管线规则（见 §10） | 先收集后发射 |
| 模块语法 | 不认 `namespace` / `pub` / `import` / `ct build` | 认 | 认 |
| 接口数组 / 构造点装箱 | 不支持 | 支持（相对 L0 扩展） | 支持 |
| `map` | 不支持 | 不支持 | 支持 |
| `Drop` / `#line` / 泄漏诊断 | 不支持 | 支持 | 支持 |
| 用户可见容量上限 | 见 §7 表 | 旧管线额度 | 更高，见 §7 |
| 用途 | 差分 oracle / 引导种子 | 回归 oracle（只修 bug） | 安装入口 `ct` |

L0 命中不认识的构造时直接报错（`'namespace' is not supported by this compiler` 一类）；需要写
种子兼容代码时，按「定义先于使用、构造与语句不同行、不用模块语法」约束自己。L2 是 Phase 3–8
的旧多单元管线，能力冻结、只修 bug。

**正文默认 ct-ast。** 上表是 L0/L2 差异的集中处；正文里零散的 L0/L2 提及只作历史边界或诊断语境
（§4.8 接口代际、§6 已知问题、§7 容量、§9 诊断、§10 L2-only），不再新增此类插叙。

> 出处：本表按 [DOC-72](../issues/docs/doc-72-spec-audit-followup.md) 的 B2-1 收敛；DOC-72 仍保留
> 「正文零散提及收敛」的剩余项。

### 2. 词法与书写要求（ct-ast）

- 关键字按**独立单词**识别；`traitx`、`my_struct` 不会被误判。`into`、`foreach` 是上下文关键字，
  只在特定位置生效（§4.49、§4.52）。
- `namespace` / `pub` / `import` 是 ct-ast 的正式关键字，不是普通标识符；在 L0 里才会被拒绝。
- 标识符为 `[A-Za-z_][A-Za-z0-9_]*`；超过 159 字符报 `identifier is too long`，
  不再静默截断（L0 种子的上限是 127 字符）。
- 空白、换行、`//` 行注释、`/* */` 块注释可自由插入；ct-ast 丢弃注释，生成物只带 banner。
- 字符串 / 字符字面量按 C 转义规则接受。**v0.53.1 起**：表达式位置超过 158 字节的字符串字面量
  在编译期报 `string literal is too long (max 158 bytes; split it)`，不再静默截断；
  更长的文本请拆成相邻字面量（它们会拼接）或写入初始化器。
- 固定容量上限越界一律报错（§7），不静默丢数据；v0.53.1 起字符串字面量也归入这一类。

### 3. 语法总览

ct-ast 的顶层构造（只列构造与语义入口；产生式细节以 §4 各小节为准，本文不写伪 EBNF）：

| 构造 | 形态 | 语义入口 |
| --- | --- | --- |
| 导入 / 命名空间 | `import a::b;`、`namespace a::b;` | §1、§4.10 |
| 可见性 | 顶层 `pub`；`impl` 方法级 `pub` | §4.60 |
| 外部声明 | `extern` | §4 |
| trait / struct / union / enum / typedef | `trait T { … }`、`struct S { … } use T;` | §4.7–§4.8、§4.51 |
| impl | `impl T for S { … }`、固有 `impl S { … }` | §4.60 |
| 泛型 | 泛型函数、泛型 struct、泛型 trait | §4.48、§4.51、§4.54、§4.55 |
| 函数 / 全局 | `ret name(params) { … }`、`[pub] T g = …;` | §1、§5 |
| static 断言 / raw 文本 | `static_assert(…)`、`#ct-raw` 块 | §4.41 |

语句层是 C 的子集加上下列 ct 构造：

| 构造 | 形态 | 说明 |
| --- | --- | --- |
| 声明 / 赋值 | C 形态 | 支持初始化式、复合字面量、指定初始化 |
| 控制流 | `if` / `else` / `while` / `for` / `do…while` / `switch` / `goto` / 标签 | C 语义 |
| 范围 for | `loop(0..n) { … }` / `loop(x) { … }` | 隐式 `i`、`$`；见 §4.28 |
| 容器遍历 | `foreach (vec) { … item … }` | 数组、`Vec`、`Map`；见 §4.49 |
| 资源 | `own` 声明、`delete`、`defer { … }`、`errdefer { … }` | §4.9、§4.58 |
| 错误 | `return err: e;`、`expr?`、`Result<T,E>` | §4.61、§4.62 |
| 后继块 | `expr into { … }` | 接收者上下文；见 §4.52 |
| 可选链 | `p?.f` / `p?[i]` | 仅指针接收者；见 §4.65 |

#### 3.1 表达式（ct-ast）

ct-ast 按 C 的优先级解析表达式，支持的运算符子集由紧到松为：

| 层级 | 运算符 |
| --- | --- |
| 后缀 | `()` `[]` `.` `->` `++` `--` |
| 一元 | `!` `~` `-` `+` `&`（取地址） `*`（解引用）、强制转换、`sizeof` |
| 乘除 | `*` `/` `%` |
| 加减 | `+` `-` |
| 移位 | `<<` `>>` |
| 比较 | `<` `>` `<=` `>=` `==` `!=` |
| 位与 | `&` |
| 位异或 | `^` |
| 位或 | `\|` |
| 逻辑 | `&&` `\|\|` |
| 条件 | `?:` |
| 赋值 | `=` 以及复合赋值 `+=` `-=` `*=` `/=` `%=` `&=` `\|=` `^=` `<<=` `>>=` |

生成物给每个二元 / 一元运算都加括号，因此源码语义不依赖 C 侧的优先级重排。
`ct` 是全 AST 重写，**不要求语句与构造分行**；L0 才有按行限制。

### 4. 展开规则

#### 4.1 trait → vtable 类型

```c
trait Greeter { void greet(); int add(int a, int b); }
```

```c
struct Greeter_vtbl {
    void (*greet)(void *);
    int (*add)(void *, int, int);
};
```

每个方法多出一个前置参数 `void *`；参数列表在 vtable 中**只保留类型、去掉参数名**。

#### 4.2 struct + use → 追加 vptr 字段

```c
struct Person {
    char *name;
    int age;
} use Greeter;
```

```c
struct Person {
    char *name;
    int age;
    struct Greeter_vtbl *__greeter_vptr;
};
```

字段体原样保留，vptr 字段按 `use` 的书写顺序追加在末尾。

#### 4.3 impl → 静态方法 + vtable 变量

```c
impl Greeter for Person {
    void greet() {
        printf("Hello, %s\n", self->name);
    }
}
```

```c
static void Person_Greeter_greet(void *self) {
    struct Person *_self = (struct Person *)self;
    printf("Hello, %s\n", _self->name);
}

static struct Greeter_vtbl Person_Greeter_vtable = {
    .greet = Person_Greeter_greet
};
```

- 生成函数的参数是「`void *self` + impl 中书写的方法参数」，函数体第一行固定为 `_self` 强转。
- 方法体的缩进按最小公共缩进去除后重新以 4 空格排版。
- **方法体走与顶层代码完全相同的重写管线**：先把 `self`（指向当前 struct 的指针）与 impl 中书写的
  方法参数登记进变量表，再逐行 `transform_line`，最后把标识符 `self` 重命名为 `_self`。因此方法体内
  的各类接收者都会被派发，与顶层代码无差别：
  - 兄弟方法：`self->other()` → `_self->__<trait>_vptr->other(_self)`；
  - 字段链：`self->field->m()` → `_self->field->__<trait>_vptr->m(_self->field)`（可递归，见 §4.5）；
  - 方法参数：`o->m()` → `o->__<trait>_vptr->m(o)`、`v.m()` → `v.__<trait>_vptr->m(&v)`；
  - 方法体内局部变量：`P q; q.m();` → `q.__<trait>_vptr->m(&q)`。
  - **同名跨 trait**：宿主 `use` 的多个 trait 都声明方法 `f` 时，裸调用 `s.f()` 按 `use` 顺序**取第一个**
    匹配（`s.__<首个 trait>_vptr->f(&s)`）。顺序即语义，属**已知限制**；要调用另一个实现，需把 `s`
    装箱成目标 trait 的接口值（`struct B_iface x = B_of(&s); x->f();`）或改名。
- 只要某个方法体会产生派发，就会在方法函数之前先输出一行前向声明
  `static struct <Trait>_vtbl <Struct>_<Trait>_vtable;`，以解决 vtable 变量的前向引用
  （C 的 tentative definition，随后再带初始化式定义，合法）。
- vtable 初始化项按 **impl 中的书写顺序**排列（探针 `vt.ct`：trait 先声明 `b`、impl 先写 `a`，生成物 `.a` 在前），
  不是 trait 中方法的声明顺序；只影响生成物形状，不影响派发。
- 跨单元（ct-ast `build` 模式）：当 trait 与 struct **都标 `pub`** 时，vtable 改为外部链接——声明单元的
  头文件发射 `extern struct <Trait>_vtbl <Struct>_<Trait>_vtable;`，实现单元给出定义，消费单元可直接装箱。
  其它情况仍为 `static`，且同一对 `struct`/trait 的 `impl` 必须位于同一编译单元。

#### 4.4 变量声明 → 限定 `struct` + 追加 vptr 指定初始化

```c
Person p = { .name = "Tom", .age = 36 };
```

```c
struct Person p = { .name = "Tom", .age = 36, .__greeter_vptr = &Person_Greeter_vtable };
```

规则：

| 源码形态 | 处理 |
| --- | --- |
| `Person p = { … };`（指定初始化） | 前缀 `struct `，并在 `}` 前追加 vptr 指定初始化项 |
| `Person p = { "Tom", 36 };`（位置式初始化） | 同上：追加的 vptr 项接在位置式元素之后（C99 允许 `{ 1, .v = 0 }` 混用） |
| `Person p = {};` / `Person p;` | 前缀 `struct `；空列表追加 vptr，无初始化式则补上 `= { <vptr> }` |
| `struct Person p = { … };` | 同上（已有限定符时不重复添加） |
| `static Person p;` / `static Person ps[2];` | 前缀 `static` 原样保留；ct-ast 在静态初始化式里写 vptr（L0 才走 `__ct_init`） |
| `Person *p = …;` | 前缀 `struct `，其余原样输出；指针变量**登记为指针**，故 `p->m()` 会重写为 `p->__t_vptr->m(p, …)` |
| 其它类型 | 完全不动 |

被识别为「结构体类型变量」的名字会登记进变量表，供后续方法调用重写使用。

#### 4.5 方法调用重写

```c
p.greet();
p.greet_name("Jerry");
```

```c
p.__greeter_vptr->greet(&p);
p.__greeter_vptr->greet_name(&p, "Jerry");
```

触发条件（满足 1 或 1′，且 2–4 全满足才重写）：

1. 左边是一个标识符，且它在**本文件此前**已被登记为某 struct 类型的变量（`T x`、`T *x`、
   `T x[n]`、`T *x[n]` 均可）；**或**
1′. 左边是一次调用 `f(...)`，且 `f` 的返回类型是**此前已登记的 struct**（值返回或指针返回均可，
   如 `f().m()`、`mk()->m()`、`f().a.b.m()`）；
2. 若该变量是数组或指针，其后可先跟一个下标 `[<表达式>]`（表达式可为任意平衡内容，例如
   `ps[i]`、`ps[i + 1]`、`ps[f()]`）；
3. 之后是 `.`、`->`，或一串字段跳（每跳 `.field` / `->field`），且**最终**成员名是（跳转后那个
   struct 的）某个 trait 的**方法名**；
4. 成员名后紧跟 `(`。

方法归属的判定顺序：按该 struct `use` 子句中的 trait 顺序查找，**取第一个**声明了该名字的 trait。

重写细节：

- 形如 `x.m()` 的无参调用 → `x.__t_vptr->m(&x)`（不产生多余逗号）。
- 形如 `x.m(a)` → `x.__t_vptr->m(&x, a)`。
- 指针接收者不补 `&`：`p->m()` → `p->__t_vptr->m(p)`，`p->m(a)` → `p->__t_vptr->m(p, a)`。
- 数组元素 / 指针下标：`ps[i].m()` → `ps[i].__t_vptr->m(&ps[i])`；`T *ps[n]` 的元素**自身是指针**，
  故 `ps[i]->m()` → `ps[i]->__t_vptr->m(ps[i])`；而 `T *p` 上的 `p[i]` 是值，补 `&`。
- 指针字段链按**每跳字段是否为指针**决定 `.` 或 `->`，末跳经指针则不补 `&`：
  `a.next->m()` → `a.next->__t_vptr->m(a.next)`；`a.next.m()`（`next` 是值字段）→ `a.next.__t_vptr->m(&a.next)`。
- 参数内部的嵌套调用会被继续处理：`q.add(1, q.add(2, 3))` → `q.__greeter_vptr->add(&q, 1, q.__greeter_vptr->add(&q, 2, 3))`。
- **总则**：动态派发要求接收者的**静态类型已知**；lowering 需要重复接收者或取其地址时，先把它物化为
  `__ct_tmp<N>`，且**只允许**在语句行首或赋值 / 声明初始化式的右值行首物化（位置与语义条件见下条）。
  接收者本身是一次**方法调用**的形态（`a.m().n()`，AST 里是 `N_MCALL`）当前一律拒绝，不会静默产出坏 C；
  L0 / L2 的行重写管线同样拒绝「方法结果再调方法」的链（`c.inc()->inc()`），因为没有临时量承载方法返回值。
  类型宿主（§4.10）不走这条路径，不受此限；链式构建器的合法形态与边界见 §4.10.1。
- **右值接收者**（条件 1′）：接收者先被提升为一个临时变量，求值**恰好一次**，再按上面同一规则派发。
  临时变量名为 `__ct_tmp<N>`（`N` 在单个文件内递增，从 0 开始）：
  - 值返回：`f().m(a)` → 前一行 `struct S __ct_tmp0 = f();`，本行 `__ct_tmp0.__t_vptr->m(&__ct_tmp0, a)`；
  - 指针返回：`mk()->m(a)` → 前一行 `struct S *__ct_tmp0 = mk();`，本行 `__ct_tmp0->__t_vptr->m(__ct_tmp0, a)`。
  - 提升**只允许**在两种位置：接收者位于**语句行首**（`f().m();`），或位于**赋值 / 声明初始化式的
    右值行首**（`int r = f().m();`）。这两种位置求值无条件且有序，提升到前一行**不改变语义**。
  - 接收者出现在其它位置（如 `x = 1 + f().m();`、`g(f().m());`）时无法在不改变求值顺序的前提下重写，
    **按 `文件:行:列: error:` 报错退出**，而不是产出明知编不过的 C。
  - 提升出的临时变量声明文本为等宽对齐的源行缩进；它在生成的 `.c` 中占一行。
- 字符串字面量、字符字面量、注释内的内容**永不重写**。
- `impl` 方法体与顶层代码共用同一重写管线：方法体内的 `self->m(...)`、字段链 `self->f->m(...)`、
  参数接收者 `o->m(...)`、局部变量接收者 `q.m(...)` 都按同一规则重写（见 4.3）。
- **仅变量下标接收者的表达式会被求值两次**（`ps[i]` 在产物里出现两遍），因此带副作用的下标
  （如 `ps[i++]`）不保证正确；右值接收者（1′）用临时变量，只求值一次。

#### 4.6 普通函数的签名 → 限定 struct 类型

```c
void show(Person p);
static Person make(char *n);
Person *pick(Person *a, Person *b);
```

```c
void show(struct Person p);
static struct Person make(char *n);
struct Person *pick(struct Person *a, struct Person *b);
```

规则：

| 源码形态 | 处理 |
| --- | --- |
| 返回类型里的已知 struct 名（含 `static` 等前缀词、多词类型、指针返回） | 原地插入 `struct `（其余字符原样保留） |
| 值参数 `Person p` | 插入 `struct `；**有函数体时**把参数登记进变量表（`ptr=0`），使体内 `p.m()` 可被重写 |
| 指针参数 `Person *q` | 插入 `struct `；登记为指针（`ptr=1`），使体内 `q->m()` 可被重写 |
| 函数原型 `void f(Person *q);` | 只限定类型，**不登记**参数（没有函数体） |
| 参数已写成 `struct X …` | 不重复插入 `struct ` |
| `if` / `while` / `else if` / `return …` 等语句 | 不会被误判为函数签名 |
| 参数**列表本身跨多行**的签名 | 不识别，按原样透传 |

#### 4.7 组合、数组与堆对象（构造语义）

vptr 在「构造点」写入：对象**自身**的 vptr 写进初始化式；**嵌套字段 / 数组元素 / 堆对象**改用
**声明之后的赋值语句**（避免追加的 `.field` 指定初始化覆盖用户自己写的 `.field = {…}`）。

| 源码形态 | 处理 |
| --- | --- |
| `struct Shop { Person owner; };` | 字段类型补 `struct `：`struct Person owner;` |
| `Shop s;` | `struct Shop s = { … };` 之后追加 `s.owner.__greeter_vptr = &Person_Greeter_vtable;` |
| `s.owner.greet();` | `s.owner.__greeter_vptr->greet(&s.owner);` |
| `Person ps[3];` | 声明 + 块内循环 `for (…; __ct_i < 3; …) ps[__ct_i].__greeter_vptr = …;` |
| `ps[0].greet();`、`ps[i].greet();` | `ps[0].__greeter_vptr->greet(&ps[0]);`（下标可为任意表达式） |
| `Person *ptrs[2]; ptrs[0]->greet();` | `ptrs[0]->__greeter_vptr->greet(ptrs[0]);`（元素自身是指针） |
| `struct Box { Person *who; } … b.who->greet();` | `b.who->__greeter_vptr->greet(b.who);`（指针字段链） |
| `delete q;` | `if (q) { free(q); q = 0; }`（`q` 必须是已登记的指针变量；ct-ast 会置空） |

命名与限制：

- 数组展开的循环变量固定为 `__ct_i`，包在块内。
- **文件作用域的对象 / 数组**：ct-ast 直接把 vptr 写进静态初始化式
  （`Person p = { .__greeter_vptr = &Person_Greeter_vtable };`）；L0 种子才需要
  `static void __ct_init(void) __attribute__((constructor))` 在 `main` 前补写。
- 数组支持声明时初始化与变长数组（`int a[] = {…};`、`int a[n];`），ct-ast 逐元素补 vptr；
  只有无法静态求值的接口数组初始化才会落到块内循环。
- **ct-ast 会改写类型名**：`sizeof(Person)` 发射为 `sizeof(struct Person)`，不必手写 `struct`。
  L0 种子不改写。

#### 4.8 接口多态（trait 作类型）

每个 trait 额外生成一个**接口值类型**（胖指针，`self` + 该对象的 vtable）：

```c
struct Greeter_iface { void *self; struct Greeter_vtbl *vt; };
```

| 源码形态 | 处理 |
| --- | --- |
| `Greeter g;` | `struct Greeter_iface g = { 0, 0 };` |
| `Greeter g = p;` | `struct Greeter_iface g = (struct Greeter_iface){ (void *)&p, &Person_Greeter_vtable };` |
| `Greeter g = q;`（`q` 是 `Person *`） | 同上，`self` 取 `q` 本身（**不加 `&`**） |
| `g = s;` | 按 `g` 的 trait 装箱后再赋值 |
| `void announce(Greeter who);` | `void announce(struct Greeter_iface who);` |
| `announce(p);` | `announce((struct Greeter_iface){ (void *)&p, &Person_Greeter_vtable });` |
| `Greeter pick(void);` | `struct Greeter_iface pick(void);` |
| 返回接口的函数里 `return p;` | `return (struct Greeter_iface){ (void *)&p, &Person_Greeter_vtable };` |
| `g.greet();` | `g.vt->greet(g.self);` |
| `g.greet_name("Jerry");` | `g.vt->greet_name(g.self, "Jerry");` |

**接口作为 struct 字段**（值字段 `T x;` → `struct T_iface x;`；指针字段 `struct T *x;` → `struct T_iface *x;`）：

| 源码形态 | 处理 |
| --- | --- |
| 字段 `Node lhs;` / `struct Node *lhs;` | 字段类型展开为 `struct Node_iface lhs;` / `struct Node_iface *lhs;` |
| `s.lhs.show();` / `self->lhs.show();` | `s.lhs.vt->show(s.lhs.self);`（值字段经 `.`，字段链可递归） |
| `s.p->lhs->show();` | `s.p->lhs->vt->show(s.p->lhs->self);`（指针字段经 `->`） |
| `s.lhs = v;`（**值**接口字段） | 按字段声明的 trait 装箱：`s.lhs = (struct Node_iface){ (void *)&v, &Lit_Node_vtable };` |

规则与限制：

- 设计上只允许**变量**、`&变量` 或「返回同款接口」的调用装箱；类型无法推断 → `die`。
  **v0.53.1 起**：`T t = mk();`（`mk()` 返回 struct 值）这类不可取址的右值在编译期硬错
  `cannot box an rvalue struct; assign it to a variable first`，不再发射 `(void *)&mk()` 交给 `cc`。
  需要装箱时先落到变量：`struct S tmp = mk(); T t = tmp;`。
- 装箱的目标 trait 由**声明/赋值的左值**或**当前函数返回类型**决定；实参则由**函数签名表**决定。
  ct-ast 会先收集整单元再发射，因此不受定义顺序限制；L0 种子必须定义先于使用。
- 被装箱的 struct 必须 `use` 了该 trait；跨 trait 装箱 → `die`。
- **不做**隐式空检查：空接口值（`{0,0}`）上派发会崩，与 C 一致。
- **接口数组 / 指定初始化（ct-ast v0.53.1）**：接口值数组、接口指针数组、接口数组字段、
  `Pair p = { .lhs = v };` 指定初始化与堆对象装箱都支持（逐元素 / 逐字段装箱）；
  仍不支持的是带聚合初始化式的接口指针（`T *g = { ... };`）与接口接收者的 `into`。
- **L0 限制（本文所述）**：接口**数组**不支持，声明即 `die`；接口字段**不参与**构造点递归，`Node lhs;`
  声明后为空（`vt == NULL`），需自行赋值；装箱仅覆盖**语句赋值**（`s.lhs = v;`），**指定初始化式**
  （`Pair p = { .lhs = v };`）中的接口字段**不装箱**；**指针**接口字段（`struct T *x`）只支持派发，
  赋值保持原样（需要已有胖指针的地址，如 `s.x = &someIface;`）。
- **CT 侧（L2）已扩展**：`selfhost/l2/**` 放开上一条的全部限制，并给出统一的「接口值 / 指向接口值的指针 / 接口值数组 / 接口指针数组」模型；装箱规则在**赋值、构造点、`return`、实参**四处完全一致：

| 形态 | 含义 | 派发 | 下标元素的种类 |
| --- | --- | --- | --- |
| `T x` | 接口值（胖指针） | `x.m()` → `x.vt->m(x.self)` | — |
| `T *x` | 指向接口值的指针 | `x->m()` → `x->vt->m(x->self)` | `x[i]` 是**值**（`x[i].m()`） |
| `T xs[n]` | 接口值数组 | `xs[i].m()` → `xs[i].vt->m(xs[i].self)` | 值 |
| `T *xs[n]` | 接口指针数组 | `xs[i]->m()` | 指针 |
| 形参 `T xs[]` / `T *xs` | 同上，函数体内可下标 | 同左 | 值 |

  另有：接口**数组字段**（`Node items[4]`、`self->items[i].eval()`）、指针接口字段的下标（`s.f[0].m()`）、**构造点**装箱（`Pair p = { .l = v, .ptr = &v };`，值字段与指针字段各走各的 box 路径）、以及**堆对象装箱**（`Num *p = malloc(sizeof(struct Num)); Expr e = p;`）。**仍不支持**：带聚合初始化式的接口指针（`T *g = { ... };`）。**struct 类型的数组字段**（`struct Duo { Num ab[2]; }`）L0 / L2 不支持，**ct-ast 已支持**（逐元素写 vptr，见 §6）。理由同顶部状态说明：本文对 L0 依旧准确，新能力只属 CT 线（L2 / ct-ast），由 `test/acceptance/run.sh` 钉住。

#### 4.9 AutoDrop（Phase 5 新增，仅 CT 线）

`own` 是一个**上下文关键字**，只出现在声明行的行首：它把变量标记为「持有对象生命周期」，
编译器在作用域出口自动释放。它是 Phase 5 新增项，**L0（`ctc.c`）不认识它**（会原样透传），
由 CT 线实现：L2（`selfhost/l2/**`，冻结 oracle）与 ct-ast（安装入口）。两者在出口注入的**位置要求**上
自 v0.16.0 起不同，见下表与约束。

| 源码形态 | 处理 |
| --- | --- |
| `own Person *p = malloc(sizeof(struct Person));` | 去掉 `own` 后照常声明；登记 autodrop |
| `own Person *p = make();`（工厂返回 `struct Person *`） | 同上；初始化式可以是**返回类型字面量为 `struct X *` 的函数调用**（PH-49） |
| `own Person *p = 0;`（零值） | 去掉 `own` 后照常声明，但**不登记** autodrop（零值不拥有对象，块尾不释放） |
| 声明作用域的闭合 `}`（行首） | 在该行之前插入 `if (p) { Person_Drop_drop(p); free(p); p = 0; }` |
| 每个 `return` 之前（L2 要求行首；ct-ast 无位置要求） | 同上，插入全部 autodrop 变量的释放（声明逆序） |
| 每个 `break` / `continue` 之前（仅 ct-ast） | 同上，只释放该循环体（含嵌套块）自建立以来登记的 autodrop 变量；`switch` 只登记 `break` 基线，`case … break` 不会碰循环外的 `own` |
| `delete p;` | 既有的 `free`/`drop` 照旧；同时取消 autodrop（不重复释放） |
| `p = …;`（重新赋值） | 取消 autodrop（所有权已转移，不再兜底） |
| `p` 以**独立值**形式出现在赋值右值（`q = p;`）或 `return` 的返回表达式中 | 取消 autodrop（逃逸）；读取字段 / 元素（`x = p->n;`、`x = p[0];`）**不**算逃逸 |

约束与限制：

- 初始化式只有三种：`malloc(...)`、`calloc(...)`，或一个**自由函数调用**且其 `Symbols` 记录的返回类型
  字面量为 `struct X *`（X 必须与声明的结构体一致，PH-49 D49-1）。判定只看调用点与符号表返回串，
  不做表达式类型推导；`&x`、字段取址、指针算术等其他指针表达式仍是 L49-1 硬错。
  必须是**结构体指针**且该 struct 必须 `use Drop`；否则编译期报错。
- **零值**初始化（`= 0`）合法但不登记 autodrop：块尾不释放，也不产生诊断；运行时工厂返回 0 时依赖
  既有的 `if (p)` 守卫。同一作用域对同一标识符写两次 `own` 是 L49-2 硬错（不做数据流分析；
  嵌套作用域的同名遮蔽不受影响）。
- `own` 只允许出现在**函数体内**。文件作用域的 `own` 变量仍报旧文案；写在**返回类型位置**的 `own`
  （`own struct P *make(void)`）保持拒绝，但报 L49-3 并指向调用点写法。不支持数组形态
  （`own T *ps[n]`）。
- 同一作用域的多个 `own` 变量按**声明逆序**释放。
- L2 要求闭合 `}` 与 `return` 位于**行首**；行内形式（`b->n = 1; }`、`if (p) return 0;`）编译期报错，
  不静默跳过——逐行注入无法把释放语句安全地放进条件分支。**ct-ast 只对 `}` 有该要求**：`return`
  无位置要求，分支内与行内的 `return` 都会在它之前注入（v0.16.0 起，见 §4.40）。
- `goto` 跳出声明作用域不会触发释放；`break` / `continue` 不是这样：ct-ast 在它们之前释放循环体（含嵌套块）登记的 autodrop 变量，与 `return` 同一套机制（见 §4.45 的 `loop` 说明）。
- `static` 局部变量不能是 `own`（`a static local cannot be 'own'`）：静态对象的生命期不归作用域管。
- 逃逸判定是**保守**的：变量以独立值形式出现在赋值右值或 `return` 行上即取消 autodrop；漏放（内存泄漏）
  优于错放（重复释放 / 释放借用对象）。

#### 4.9.1 块级 `defer`（Phase 38，仅 ct-ast）

```c
int load(void)
{
    int fd = open_db();
    defer { close_db(fd); }
    defer { flush_db(fd); }   /* 先 flush，再 close */
    return use_db(fd);        /* 返回值先求值，再跑 defer */
}
```

- **语法**：`defer { … }` 只能出现在函数体内的语句位置，后面必须紧跟 `{`；其它位置的 `defer`
  仍是普通标识符（D38-7）。只收块形态，没有 `defer expr;`。
- **顺序**：同一块内按源码逆序执行（LIFO），内层块先于外层块。
- **四条出口**：正常落出、`return`、`break`、`continue` 都执行对应块的 defer。`return expr` 先把
  返回值放进临时量，再跑 defer，最后返回该临时量，所以 defer 改写局部变量不影响返回值。
- **与 `own` 的顺序**：同一块内 defer 先于 `own` 的自动释放；两组各自 LIFO（D38-4）。既有
  `own` 的释放点不变。
- **诊断**：`goto` 跨出/跨入带 defer 的块报 `a goto cannot cross a block with defer`；defer 内
  `return` / `break` / `continue` / 嵌套 `defer` 报 `a defer block cannot transfer control`；defer 内
  label 报 `a defer block cannot declare a label`；`switch` 内 defer 报
  `defer is not allowed inside a switch`（v1 不定义 case/fallthrough 语义，case 内嵌套块也禁止）；
  文件作用域 defer 报 `defer is only allowed inside a function`。
  **v0.53.2 起** `.h.ct` 单元的函数体与 `.ct` 一致，`defer` / `errdefer` 均可用；此前后缀检查会报
  `defer is not allowed in a .h.ct unit`（L38-3）与 `errdefer is not allowed here`（L40-5），该限制已撤销。
  `.m.ct` 是映射单元，本就不能定义函数（`a .m.ct unit cannot define a function`），两种块在那里不可达。
- **不做**：`errdefer`、`try` / `?`、全局作用域的 defer、defer 内的控制转移、`switch` 内 defer（T38-1–T38-4）。

#### 4.10 `map`（Phase 11 新增 + SH-20 扩展，仅 ct-ast）

`map` 把一个 trait 的方法绑定到一处具体的 C 调用，并为该绑定发射包装函数与一张 vtable。宿主有两种
形态；**Phase 11.2 已把两者接入派发**——被当作 trait 接口值使用时（赋给 `T` 类型的变量、传给 `T`
接口参数、从接口返回、或作为函数实参），装箱会使用绑定的 vtable，从而作为该 trait 的实例运行：

- **对象宿主**：`map trait T for instance x { … }`，`x` 是已声明的全局变量，接口值的 `self` 指向它。
- **命名空间宿主**（SH-20）：`map trait T for namespace A::B { … }`，绑定的是命名空间里的一组函数，
  没有对象可挂，接口值的 `self` 为 `NULL`。

`map` 是 Phase 11 新增项，**L0 与 L2 都不认识**，只由 **ct-ast**（`selfhost/ct-ast/main.ct`）支持。

**零成本静态映射（第三十八批，已实现）**：`.m.ct` 编译期映射单元、静态 trait、命名空间静态调用
`host::Trait.method(…)` 与类型宿主 `map trait T for type <ctype>`——绑定在**调用点**直接展开为裸 C
调用，不生成 wrapper / `_iface` / `_vtbl` / vtable，跨单元同样零成本。规格见
[design/batch38-map-unit/spec.md](history/design/batch38-map-unit/spec.md)。本节其余内容描述动态 `map`，
其产物与行为不变。

```c
trait Controller {
    int send(char *buf, int len);
}
struct Uart { int fd; };
struct Uart uart1;                                    /* 对象宿主：必须是已声明的全局变量 */

map trait Controller for instance uart1 {
    send(buf, len) -> mock_uart_send(&uart1, buf, len);
}

namespace hal;
pub trait Writer { int write(char *buf, int len); }
int hal_write(char *buf, int len) { return len + buf[0]; }

map trait Writer for namespace hal {                  /* 命名空间宿主：没有对象 */
    write(buf, len) -> hal_write(buf, len);
}
Writer w = Writer::hal;                               /* 装箱：self 为 NULL，vt 指向 hal_Writer_vtable */
```

符号命名：宿主路径把 `::` 换成 `_` 得到 `h`，trait 的 C 名记为 `tr`；若 `tr` 已经以 `h_` 开头则
`p = tr`，否则 `p = h_tr`。包装函数是 `p_<方法>`，vtable 是 `p_vtable`。对象宿主的 `h` 是实例的
C 名（如 `uart1`），命名空间宿主的 `h` 是宿主路径（如 `hal`）。

| 产物 | 规则 | 示例 |
| --- | --- | --- |
| 包装函数 | `<宿主>_<Trait>_<方法>`，首参 `void *self`（体内 `(void)self;`）；对象宿主的**直绑不生成**，命名空间宿主**必然生成** | `static int uart1_Controller_send(void *self, char *buf, int len)`；`static int hal_Writer_write(void *self, char *buf, int len)` |
| vtable 变量 | `<宿主>_<Trait>_vtable`，指定初始化 `.方法 = 包装函数`（直绑时为被绑定的 C 函数本身） | `static struct Controller_vtbl uart1_Controller_vtable = { .send = uart1_Controller_send };` |

约束与限制：

- `for` 之后只能跟 `instance` 或 `namespace`，其它写法编译期报错。
- 对象宿主的 `x` 必须是**已声明的全局变量**（文件作用域），否则编译期报错。实例名可写成**命名空间
  限定形式** `A::B::h`（2b.3）；全局按命名空间 mangling（见 §4.11），实际绑定的 C 名是 `A_B_h`，
  实例的 vtable 与包装函数也以它为前缀（`A_B_h_T_vtable`）。
- **不合成宿主**：编译器不会替未声明的名字合成对象（拼写错误会变成静默的宿主）。没有对象可挂时用
  **命名空间宿主**（`map trait Writer for namespace hal { … }`），而不是伪造 `void *netlib;` 占位变量
  ——后者仍可用，但已不必要。
- 命名空间宿主的路径逐段写 `A::B`。装箱 `T::A::B` 在找不到对应 map 时报
  `no map binds trait 'T' to namespace '<宿主路径>'`（`<宿主路径>` 按源写法回显，如 `nosuch` / `a::b`）。
- 命名空间宿主**不接受直绑**：没有 `self` 可以交给被绑函数，`-> fn;` 会被拒绝
  （`a namespace host has no self: bind with a wrapper call`）。
- 命名空间宿主的装箱语法是 `Trait::ns`，且**只能作为接口值**使用；放进其它上下文（如 `int x = Writer::hal;`）
  报 `a namespace host value is only usable as an interface value`。`Trait::ns(...)` 仍是限定调用，不产生装箱。
- `T` 必须是已定义的 trait；无 vtbl 的 trait 不可映射。
- 绑定方法名必须是 `T` 的既有方法，`( … )` 里的参数个数须与 trait 声明一致。
- 绑定必须覆盖 `T` 的**每一个**方法，且每个方法**只绑一次**：漏绑会让 vtable 留一个空指针槽（调用即崩溃），
  重复绑定会发射两份同名包装函数（C 重定义）；两种情况都在编译期报错。
- `->` 右侧（CALL）是**两级绑定**：
  - **直绑**：调用名是裸 C 函数名（纯标识符）时零生成，vtable 槽直接指向它；直绑不校验签名，
    被绑函数必须自行满足 trait 的槽类型（首参 `void *`）。命名空间宿主禁用直绑（见上）。
  - **fallback**：调用含表达式或成员路径时生成宿主级包装函数。每个实参按标识符逐个校验：字符串 / 字符
    字面量、数字字面量、`.` / `->` 后的成员名、`A::B` 限定名直接放行；其余标识符必须是左括号内的形参名、
    本 map 的实例、此前已声明的变量或 ALL_CAPS 宏，否则编译期报错。
- 多个 map 可作用于同一实例或同一命名空间；`MAX_MAPS`（64）是 map 构造总数上限，超限报错。
- **跨单元**：vtable 在 `pub` trait 且（对象宿主）实例是有 `pub` 全局时外部链接（同 §4.11 的 impl 规则）；
  命名空间宿主没有实例，只看 `pub` trait。头文件声明 `extern`、声明单元给出定义，其它单元可直接装箱。
  否则包装函数与 vtable 发射在**声明该 map 的单元**的 `.c` 里（`static`），不会重复出现在其它单元。
- **派发（11.2 / SH-20）**：对象宿主装箱用**实例级** vtable——
  `Controller c = uart1;` → `c = (struct Controller_iface){ (void *)&uart1, &uart1_Controller_vtable };`
  （注意不是 struct 级的 `&Uart_Controller_vtable`）。因此**即便 `Uart` 未 `use Controller`**，
  `uart1` 也能作为 `Controller` 实例使用。命名空间宿主装箱写成
  `Writer w = Writer::hal;` → `w = (struct hal_Writer_iface){ (void *)0, &hal_Writer_vtable };`。
  此后 `c.send(...)` / `w.write(...)` 都经 `<接口>.vt->方法(<接口>.self, ...)` 派发到包装函数；
  命名空间宿主的 `self` 恒为 `NULL`，被绑函数不得解引用首参。
- `--emit-map` 的 JSON 新增 `maps` 字段，逐条列出 trait / instance / file / line 与 `bindings`
  （method → 生成符号）；每个 map 另有 `"host": "instance"|"namespace"` 标明宿主形态，
  每个 binding 还有 `"wrapper": true|false` 区分 fallback 与直绑。

**静态映射（第三十八批，仅 ct-ast）**

`.m.ct` 是**映射单元**：只允许 `namespace`、`import`、`#include` / `#define`（prologue）、`pub trait`
（只写抽象方法）、`pub type`（类型别名，见 §4.42）、`map` 与 `_Static_assert`；函数 / 全局 / 类型声明、
`impl` 与对象宿主都报错。它
**不产生任何产物**（无 `.c` / `.h`、不进末尾 `cc` 行、不写缓存），只能在 `ct build` 里被 import；
`ct compile` 直接拒绝 `.m.ct` 输入。同一 root 下同名 `foo.h.ct` 与 `foo.m.ct` 并存时报 import 歧义；
映射单元只能 import 另一个映射单元。

三种单元的产物与用法：

| 后缀 | 发布 `.h` | 可 import | 可单独 build | 用途 |
| --- | --- | --- | --- | --- |
| `<name>.ct` | 否 | 否 | 是 | 实现 / 入口；接口写在同目录的 `.h.ct` |
| `<name>.h.ct` | 是 | 是 | 是 | 发布类型、`pub` 声明与 vtable 接口 |
| `<name>.m.ct` | 否 | 是（映射单元之间） | 否（`ct compile` 直接拒绝） | 静态映射 recipe |

`import` 的搜索顺序：先 importer 所在目录，再按 `-I` 顺序逐个 root；每个 root 先探 `<name>.h.ct`、
再探 `<name>.m.ct`，两者都没有才回落到 `<name>.ct` 并报
`only a .h.ct unit can be imported: rename 'x.ct' to 'x.h.ct'`。

`.h.ct` 文件名与其中的**主类型**同名（`Parser.h.ct` ↔ `struct Parser`，入口 `main.ct` 例外）是
**仓库约定**、不是编译器规则：`selfhost/check-ast.sh` 的 unit-name lint 只扫描 `selfhost/ct-ast/**`，
用户工程不受检查。

声明在 `.m.ct` 里的 `pub trait` 自动是**静态 trait**：没有 `_iface` / `_vtbl` / vtable，不能 `impl`、
不能进 `use`、不能作类型、不能装箱（`T::host`），也不能带默认体。

两类宿主：

- **命名空间宿主**：`map trait T for namespace A::B { m(p…) -> callee(…); }`，trait 必须声明在
  宿主命名空间内；调用写成 `A::B::T.m(args)`，直接展开为 recipe 里的 C 调用（无接收者、无 `self`）。
- **类型宿主**：`map trait T for type <ctype> { m(recv, p…) -> callee(…); }`，首个绑定参数是接收者，
  trait 方法本身不声明它；绑定参数个数 = 方法参数个数 + 1。调用 `value.m(args)` 时按接收者的静态
  类型（数组先 decay 成元素指针）做规范化文本比较，命中后把 `recv` 换成接收者表达式；普通
  struct / 接口方法优先，查找失败才回退到类型宿主，多个候选报歧义。接收者与 `for type` 的主机
  拼写都先按 §4.42 展开类型别名，再参与这里的文本比较，因此别名与底层拼写是**同一个宿主**。
  接收者可以是任意**静态类型已知**的表达式——字面量、字段链、调用结果都行；recipe 只把接收者替换
  一次，因此 `s.trim().len()` 这类链式写法合法且可继续链（只有动态派发才需要 `__ct_tmpN`）。
- **限定调用消解同类型多映射**（P20-01）：两个包把同名方法绑到同一宿主类型时（如都把 `len` 绑到
  `char *`），未限定的 `value.m(args)` 会因两个候选报歧义；写成 `a::ALen::len(value, args)` 只保留
  该 trait 的映射。限定名按符号名规则拼接（`a::ALen` → `a_ALen`），最后一段必须是该静态 trait 的
  方法，因此不会劫持同名的命名空间函数；首实参是接收者，规则与 `value.len(args)` 相同（数组先
  decay）。歧义诊断把两种限定写法前置在 hint 里。
- **闭包实参（Phase 25，仅 ct-ast）**：静态映射调用与普通函数调用同口径接收闭包——闭包实参必须落在
  宿主方法相邻的 `ret (*fn)(void *env, …)` + `void *env` 形参对起点，arity 按两项计；recipe 必须把
  这个实参的 `fn` 与 `env` 各引用一次。闭包落在非 `(fn, env)` 位报 L25-1，`fn` / `env` 重复引用报
  L25-2、未成对引用报 L25-4，闭包跟在 `...` 尾部报 L25-3。合法的 `a.each(4, (int x) => …)` 展开为
  `ct_each_int(a, 4, __ct_cl_tramp_0, &(struct __ct_cl_env_0){ … })`，无运行时对象、无 vtable；
  落位细则见 §4.44。

recipe 替换（逐出现点）：

| recipe 写法 | 生成的 C |
| --- | --- |
| `p`（值位） | `(<actual>)` |
| `&p`（后接的不是 `[`） | `&(<TP>){<actual>}`（C99 compound literal） |
| `&p[…]` | `&((<actual>)[…])` |
| `sizeof p` | `sizeof(<TP>)`（不求值） |
| `p.field` / `p->field` / `p[i]` | `((<actual>).field)` / `((<actual>)->field)` / `((<actual>)[i])` |
| 参数没有求值出现 | 调用式前缀 `(void)(<actual>), `（按绑定参数顺序） |
| `p++` / `p--` / `p = …` / `p += …` | 编译期报错 |

一个参数最多一次求值出现；出现多次时实参必须是可重复表达式（字面量、变量或它们的稳定成员
链），否则要求先提局部变量。`<TP>` 是该绑定参数的声明类型（类型宿主的接收者是 `host_type`）。
`sizeof` 后只接受不加括号的绑定参数（`sizeof p`）；`sizeof(p)` 会替换成实参值的大小，故作为
编译期错误拒绝（`map recipe takes 'sizeof p', not 'sizeof(p)'`）。

`.m.ct` 的 prologue（`#include` / `#define`）按整行去重后展开进**消费者** `.c` 顶部（banner 之后），
消费者不写这些 `#include` 也能编译；消费者 `.h` 不含 prologue。`ct compile` 不解析 import，
故不参与展开。

**伴随 C shim（第三十九批，仅 ct-ast）**：映射单元可以让同目录同名的 C 文件承担 recipe 写不出的
形状——宏 / 语句宏、全局量（`errno` / `stdin`）、需要类型转换的调用、变参前缀转发、无 userdata 的
回调。约定是 `<base>.shim.h` 与 `<base>.shim.c`（两个都可选，但**有 `.shim.c` 就必须有
`.shim.h`**，否则报 `a shim source needs a matching .shim.h: <头路径>`）。

- 编译器只为 `.m.ct` 探测 shim（`foo.h.ct` / `foo.ct` 旁的 `foo.shim.h` 被忽略）；命中的文件必须是
  可读普通文件，否则报 `a shim header is not a readable file` / `a shim source is not a regular file`。
- 两个映射单元的 shim 同名但目录不同 → 构建失败：
  `ctc: shim base name '<base>' is ambiguous: <dir1> and <dir2>`（不静默取先命中者）。
- 消费者的生成 `.c` 自动出现 `#include "<base>.shim.h>"`（在该单元的 prologue **之前**，按整行
  去重）；shim 头按**文件名**解析，`ct build` 因此在该 `cc` 行打印 `-I <shim 目录>`（同一目录
  只一次）。
- 存在的 `<base>.shim.c` 直接列入同一条 `cc` 行的源文件（不复制、不进产物目录），头文件式 shim
  只增加 `-I`。
- shim 两文件的 `mtime.size` 折叠进映射单元的缓存 key，任一方变化都会重建消费者。
- `.m.ct` 仍然零产物；shim 不是生成物，也不是编译器构建步骤。

`--emit-map` 的静态条目带 `"static": true`、`"host": "namespace"|"type"`、类型宿主另有
`"type": "<ctype>"`，每个 binding 带 `"inline": true`、`"wrapper": false` 与 `"symbol": <callee>`；
带 shim 的静态条目还带 `"shim": {"header": "<path>", "source": "<path>"}`（无 `.shim.c` 时省略
`source`）。动态 `map` 的字段与取值不变。

#### 4.10.1 链式构建器范式：权威定义与两档路径

本节是这条范式的**唯一权威定义**；README、tutorial、bindings §8 只引用本节，不再各自解释。

**范式定义（三段，顺序固定）：**

1. 以字符串为起点，不是构造器。
2. 通过 factory 创建由 trait 定义的对象类型，不是 struct；struct 是实现细节，不出现在使用者代码里。
3. 链式调用挂在接口上，配置方法返回同一接口类型。

**两档路径与判断依据**（紧邻定义，就近可查）：

| 判断项 | 轻量路径 | 完整路径 |
| --- | --- | --- |
| 对象有没有状态 | 没有 | 有 |
| 要不要多实现 | 不要 | 要 |
| 调用方是否需要面向接口 | 不需要 | 需要 |
| 写法 | 基本类型直接挂寄生方法 / 类型宿主映射；方法返回自身类型即可继续链 | 字符串 → factory → 由 trait 定义的对象类型 → 接口上链式 |
| 代表样例 | [examples/48_string_steps](../examples/48_string_steps/src/main.ct) | 目标形态见本节；当前可运行形态见 [examples/47_chain_factory](../examples/47_chain_factory/src/main.ct) |
| 代价 | 无 vtable、无装箱 | 有装箱；当前链式段受限 |

轻量路径不是「不完整的错写法」：无状态、单一实现的转换直接挂方法就够了，套 trait 只会多一层绕。
反过来，只有对象有状态、需要多个实现、调用方要面向接口时，才值得走完整路径。

**0.44.1 实测状态（逐段）：**

- **第 1 段成立**：`char *` 上的 `.m.ct` factory 可用，字面量可以起手。`map trait … for type char *`
  只能写在 `.m.ct`，消费单元 `import` 该映射单元后方法才存在。
- **第 2 段不成立（语言限制）**：能放类型宿主的单元看不见接口，能看见接口的单元不许放类型宿主。
  - `map trait … for type char *` 写进 `.h.ct` → `error: a type host is only allowed in a .m.ct unit`（rc=1）。
  - 改写在 `.m.ct` 并 `import` 接口所在的 `.h.ct`：未给 `-I` 时
    `ctc: cannot resolve import 'http/http'`；给了 `-I` 时
    `error: a .m.ct unit can only import another .m.ct unit`（rc=1）。反方向 `.h.ct` import `.m.ct`
    同样报 `ctc: cannot resolve import`。
  - `.m.ct` 自身也不能承载接口：`error: a .m.ct unit cannot declare a type` /
    `error: a .m.ct unit cannot contain an impl`。三个位置都试过，**没有**同时满足两个约束的位置。
  - 因此字符串 factory 只能接到 C shim 函数（静态宿主），或把 factory 写成 `.h.ct` 的自由函数
    （起点不再是字符串）。
- **第 3 段部分成立，但不能连跳**：
  - 接口值**落变量后逐跳调用**成立：`HttpRequest r = x; HttpRequest r2 = r.header(...); int s = r2.send();`
    编译、`cc`、运行全部通过（实测 `status=201`，rc=0）。
  - 方法调用的结果不能直接作下一跳接收者：
    `error: method receiver must be a variable, an element, a call or a field chain`（SH-73，未修）。
    所以 `.header(...).timeout(...)`、`.send().status()` 这类连跳写不出来，每个中间结果都必须落变量。
  - 返回接口值的**调用点推断已修（SH-72）**：`HttpResponse res = req.send();` 不再报
    `cannot infer the type to box`，可以编译。
  - `return self;` 的装箱自 **SH-74** 起发射 `(void *)_self`（此前误发 `&_self`，指向已返回的栈帧）。
  - **已修（SH-75，v0.44.2 起）**：impl 方法或自由函数返回**局部**接口值时，ct-ast 先
    `malloc` 一份副本再装箱（`(void *)__ct_box`），返回后不再悬垂。探针 `sh75.ct` 实测 `0 201`，
    夹具 `239_local_iface_return` 覆盖该形态。§4.10.1 以下对 0.44.1 的描述仅作历史对照。

因此在 **0.44.1 及以前**，完整三段不能原样写出来：第 2 段被单元矩阵挡住（语言限制），
第 3 段被 SH-73 与「返回局部接口值悬垂」挡住。v0.53.1 上悬垂已解除（SH-75），但 **SH-73 的
「方法接收者必须是变量 / 元素 / 调用 / 字段链」限制仍在**；可运行形态继续受 §4.5 与
§4.11 跨单元装箱边界约束。

- **A. 轻量静态映射链**（[examples/48_string_steps](../examples/48_string_steps/src/main.ct)）：
  满足第 1 段与链式，不满足第 2 段（没有 trait 对象）。
- **B. 带状态的静态宿主链**（[examples/47_chain_factory](../examples/47_chain_factory/src/main.ct)）：
  满足第 1 段与链式，宿主在映射单元内部是 struct，不满足第 2、3 段。

**当前可运行形态的约束：**

- `map trait … for type …` 只能出现在 `.m.ct`；消费方必须 `import` 该单元，方法才存在。
- 配置方法按值返回宿主；每一跳展开成裸 C 调用，无 vtable、无装箱。
- 经典 `impl` / 固有 `impl` 的方法结果不能作下一跳接收者（§4.5）；返回 struct 的 trait 方法还会
  发射未加 `struct` 限定的非法 C。不要把「`impl` 方法返回 `self` 的链」写成标准路径。
- 不透明 C shim 函数的调用结果没有 CT 侧静态类型，不能直接起手；先落到变量，或包一层带显式
  返回类型的 CT 函数。
- `impl char *` 不存在：`impl` 的属主必须是已声明 struct 名；`impl Trait for char *` 报
  `impl for undefined struct 'char'`，裸 `impl char *` 报 `impl of an unknown trait`。

逐条实跑证据（六种 `impl` 形态、接口返回、生成 C 对比、逐层对照表）见
[history/reports/chain-builder-paradigm/probe.md](history/reports/chain-builder-paradigm/probe.md)。

#### 4.11 跨单元链接：`pub` 全局与 `extern`（ct-ast）

- `pub int g_counter = 5;` 在其定义单元的 `.c` 里发射定义，在该单元的 `.h` 里发射 `extern int g_counter;`；
  其它单元 `import` 后即可按名引用。`pub` 只表示导出：未标 `pub` 的全局仍只属于本单元。
- `extern int lib_flag;` 只声明、不定义：声明进入 `.h`，本单元的 `.c` 不发射定义，符号由外部 C 目标文件
  或库提供。`extern` 不能带初始化式（编译期报错）。`extern` 同样接受函数原型
  （`extern int lib_fn(int);`）：只声明、不定义，`pub extern` 的原型进入 `.h`；`extern` 的名字不参与
  mangling，因为它指向 C 库的符号。
- 导出的类型（`pub struct` / `pub trait` / `pub typedef`）在命名空间内仍可**用裸名**引用：消费者写
  `Writer w;` 或 `struct Uart u;`，编译器解析到 `hal_Writer` / `hal_Uart`。两个被导入的命名空间导出同名
  类型时，裸名报错并要求用别名 import（`import a::b::T as T;`）。类型的**限定写法**（`struct A::B`）仍不支持。
- 命名空间内的全局变量按命名空间 **mangling**：`namespace A::B; int h;` 的 C 名是 `A_B_h`，因此两个命名空间
  可以各有一个 `h` 而不会在链接期冲突。`extern` 是例外——它声明的符号由 C 库提供，保留原名与空命名空间。
- 导入单元可以用**限定名**引用导出的全局：`a::h` 读写 `a_h`；只有一个候选时裸名同样可用。若两个被导入的
  命名空间导出同名全局，裸名会被拒绝并提示改用限定名，避免静默选错对象。
- **导出函数与方法只能用限定名调用**：消费方写 `lib::thing_new()`、`obj.method()`；
  裸写 `thing_new()` 报 `needs a qualified call`。裸名放宽只适用于类型（`Writer` / `struct Uart`）
  与全局变量，不适用于函数。
- `namespace A::B;` 必须与单元相对 `--ns-root` 的目录一致（如 `a/b/x.h.ct`）；不一致时报
  `namespace 'A::B' does not match the directory '…'`。`--ns-root` 缺省为构建根目录。
- 跨单元可装箱的边界：`impl` 的 vtable 仅在 **`pub` trait 且 `pub` struct** 同时成立时外部链接——
  头文件声明 `extern struct T_vtbl S_T_vtable;`，实现单元给出定义（不再是 `static`）；否则保持单元私有。
  同一 `struct` 的同一 trait 只能有一个 `impl`，重复定义在编译期报错并指出首个定义所在位置。

#### 4.11.1 可见性：`pub` 只作用在顶层声明（ct-ast）

- `pub` 决定**顶层声明**是否跨单元可见：顶层函数、`typedef`、`struct` / `trait` 与全局变量。未标
  `pub` 的顶层函数和全局只属于本单元；未标 `pub` 的类型只出现在本单元的生成物里。
- 跨单元导出的顶层函数必须写在 `.h.ct` 里并标 `pub`；`.ct` 单元里的 `pub` 声明仍不能被 `import`
  （§4.51 的 `only a .h.ct unit can be imported`）。
- `pub struct` 的固有 `impl` 块中，方法**默认私有**：只在同单元可见，定义发 `static`，不进 `.h`；
  写 `pub` 才进 `.h`、才有外部链接、才允许跨单元调用（§4.60，Phase 42）。`pub` 只允许出现在
  `.h.ct` 单元的 `pub struct` 固有 `impl` 方法上；trait `impl T for S` 的方法随导出的 vtable 可达，
  写 `pub` 报 L42-2。
- 单元内私有 helper 既可以写成 `impl` 里不带 `pub` 的方法，也可以沿用 `.ct` 文件里的 `static`
  自由函数。

#### 4.11.2 字段级可见性（LANG-9 / PH-73）

- `.h.ct` 的 `pub struct` 允许给字段加 `pub`。**只要该 struct 至少有一个字段标了 `pub`**，公开头
  只发射这些 `pub` 字段；未标 `pub` 的字段只出现在实现单元自己的视图里（`.c` 先
  `#define CT_UNIT_PRIVATE 1` 再包含头，头内用 `#ifdef CT_UNIT_PRIVATE` 给全量布局）。
- 没有任何字段标 `pub` 的 struct 保持旧行为（全部字段进头），以免一次性打断既有代码；迁移时可以
  逐字段加 `pub`。
- 带 `use Trait` 的 struct 暂不切分公开/私有布局（vtable 字段与实现耦合），整份布局进入头文件。
- 消费者读私有字段会在构建期失败（公开头没有该字段）；确实需要隐藏布局时，用不透明句柄：
  `pub struct Conn;`（只前置声明）+ 返回 `Conn *` 的 API。
- ABI：增删/改序 `pub` 字段是破坏性变更；未标 `pub` 的字段可以自由调整。`ct build --lib` 的
  `.abi.h` 同理只反映公开面。

#### 4.11.3 链中物化 `expr$name`（PH-76）

方法调用之后可以写 `$name`，把这一跳的返回值**物化到已声明变量**，链继续以该变量为接收者：

```ct
M x;
N y;
a.m()$x.n()$y;        /* 等价于：x = a.m(); y = x.n(); */
```

- 只允许出现在**语句表达式**的链中；条件、实参、下标、声明初始化式与 `return` 暂不支持（v1）。
- `$name` 只允许紧跟方法调用；目标必须是同一函数内已声明的简单变量（不要求初始化），类型必须等于该跳返回类型，`ct check --types` 在 `$` 处报 `'$' target: expected ...`。
- 同一链可多次物化，按顺序覆盖；每个调用只求值一次（生成 `{ x = call; ... }`）。
- **拒绝**：`own`/`borrow`/`const` 目标、可选链之后（`?.`）、type-host 与 `.m.ct` recipe（v1 范围外）。
- 不改变所有权/装箱/AutoDrop；**不修复 SH-73**（临时接收者仍被拒，变量接收者只是绕法）。

#### 4.12 函数指针（ct-ast）

声明位置支持 `ret (*name)(params)`：参数、struct 字段、全局与局部。生成 C 与源码同形，名字留在类型内部。

```c
int (*p)(int);
struct Box { int (*op)(int); };
static int apply(int (*fn)(int), int v) { return (*fn)(v); }
```

- `typedef` 可用：`typedef int (*BinOp)(int, int);` 发射为 `typedef int (*BinOp)(int, int);`，
  别名可作局部、参数与 struct 字段；typedef 一个函数指针数组同理（`typedef int (*Table[2])(int, int);`）。
- 函数指针数组把维度写进声明子内部：`int (*tbl[2])(int, int);`。全局可带初始化器
  （`static int (*tbl[2])(int, int) = { plus, minus };`），局部可逐元素赋值，struct 字段同样支持
  （`int (*cb[2])(int);`）；`tbl[i](x)` 直接调用。
- 文件作用域的初始化器可以命名本单元的函数（`static int (*gp)(int, int) = plus;`）：原型先于全局发射。
- 赋值接受 `p = handler;` 与 `p = &handler;`；函数名作为右值时发射其 C 名。`#include` 引入的库函数
  同样可用（`p = strcmp;`）：CT 符号表里没有的名字原样发射，由 C 编译器按原型校验；普通调用一直如此。
- 调用接受 `p(args)` 与 `(*p)(args)`，两种写法统一发射为 `(*p)(args)`。函数指针字段可以直接调用：
  `c.add(2, 3)`（`.`）与 `p->add(2, 3)`（`->`）分别发射为 `c.add(2, 3)` 与 `p->add(2, 3)`。
- 限制：不返回函数指针；不支持嵌套函数指针（`int (**f)(int)` 报
  `nested function pointers are not supported`）；函数指针数组不能作参数（报
  `function-pointer arrays are not supported as parameters`）；一条声明只写一个名字
  （`int (*a)(void), (*b)(void);` 报错）。

#### 4.13 `switch` 与 `do-while`（ct-ast）

```c
switch (key) {
case 1:
    out = 10;
    break;
case 2:
case KIND_B:                  /* 两个标签共享下一段语句 */
    out = 20;
    break;
default:
    break;
}

do {
    total = total + i;
    i = i + 1;
} while (i < 4);
```

- 一个标签拥有从自身到下一个标签（或 `}`）之间的语句，因此 `case` 与它后面的 `break` 同处一级缩进；
  连续的 `case 1: case 2:` 共享下一段语句，中间可以没有语句。
- `case` 的取值是任意整数常量表达式：数字、字符字面量、枚举成员、`#define` 常量、括号与算术 / 位运算、
  一元 `- ! ~`、`sizeof`、`offsetof`，一律原样发射并由 C 折叠，因此 `case (1 << 2):` 与 `case 1 + 2:` 都合法。
  表达式里出现普通变量（`case key + 1:`）报 `a case label must be an integer constant`；
  整棵树就是单个名字（宏名或已声明全局）时始终放行。
- `switch` 体可以直接写声明，但**不能**紧跟在标签之后（C 的标签不构成作用域）：
  `case 1: int x;` 报 `a declaration cannot follow a case label; wrap it in a block`；
  标签后直接就是 `}` 报 `a case label needs a statement`。
- `switch` 体内的 `own` 被拒绝（`own is not supported inside a switch`）：一个 case 可能被跳过、也可能贯穿，
  按顺序块假设的释放点不成立，留待所有权分析支持 case 可达性。
- `do-while` 的体可以带花括号，也可以只写一条语句；`while (...)` 之后必须写 `;`，否则报
  `a do statement must be followed by while (...)`。
- `case` / `default` 出现在 `switch` 体之外（包括 `switch` 体内的嵌套块）报
  `a case label is only allowed inside a switch`。
- 重复的 case 值原样发射，由 C 编译器报错；`case 1 ... 5:` 范围标签见 §4.25。

#### 4.14 `enum`、常量表达式与 `offsetof`（ct-ast）

```c
enum Color { RED, GREEN = 5, BLUE, };

typedef enum Mode { Fast, Slow } Mode;

struct Point { int x; int y; };
typedef struct Pair { int a; int b; } Pair;

int off = (int)offsetof(struct Point, y);
```

```c
enum Color {
    RED,
    GREEN = 5,
    BLUE
};

typedef enum Mode {
    Fast,
    Slow
} Mode;

/* struct Point / Pair 的定义不变；offsetof 原样发射 */
int off = (int)(offsetof(struct Point, y));
```

- 顶层 `enum Tag { … }` 的标签必填（缺标签报 `expected an enum name`），花括号紧跟其名，没有前置声明形式；
  允许尾逗号。同一命名空间内重复的标签报 `duplicate enum 'Color'`。
- `typedef enum [Tag] { … } Alias;` 两种写法都接受：有标签时 `enum Tag` 与 `Alias` 都是类型名。
- 类型名与 struct 同规则：`enum Color c;` 与裸名 `Color c;` 等价，前者发射 `enum <C 名>`，裸名由编译器补回 `enum` 前缀。
- 每个成员都是文件作用域的 `int` 常量，命名空间 mangling 与全局变量相同（`namespace a::b;` 里的 `RED` 发射为 `a_b_RED`）。
- 成员初值必须是整数常量表达式，否则报 `an enum value must be an integer constant`。初值不做折叠，
  `GREEN = RED + 1` 原样发射；无初值的成员不发射 `= …`，自增语义交给 C。
- `pub enum` 的声明进入依赖单元的生成头文件，成员作为常量导入消费单元：裸名 `Mid` 与限定名 `app::High` 都能用。
- `offsetof(<struct 类型>, <字段>)` 是**内建**（CT 没有预处理器，无法把它当宏）：第一个参数接受 `struct S`
  与 typedef 别名；编译器校验结构体存在且字段存在，否则报 `offsetof needs a struct type` /
  `struct 'S' has no field 'f'`（前向声明的结构体字段未知，放行交给 C）。
- 生成物按原样发射 `offsetof(struct S, f)`，因此**源文件必须自己写 `#include <stddef.h>`**——
  生成物只透传源文件里的 `#include`，不会替它补。

#### 4.15 `union`（ct-ast）

```c
union Value { int i; char c; long long ll; };

typedef union Tagged { int i; char c; } Tagged;

typedef union { int a[2]; long long ll; } Wide;

struct Holder { int tag; union Value v; };
```

- `union` 与 `struct` 是同一套记录文法：标签必填的前置声明形式相同（`union Value;` 也接受），
  `typedef union [Tag] { … } Alias;` 两种写法都接受，允许尾逗号，`};` 与 `}` 都可收尾。
- 标签与 struct 标签共享一张表但**类型类别不同**：`union Value v;` 与裸名 `Value v;` 等价，
  前者发射 `union <C 名>`，裸名由编译器补回 `union` 前缀。命名空间 mangling 同 struct。
- `pub union` 的声明进入依赖单元的生成头文件，消费单元按裸名引用。
- **没有 `use` 子句**：union 的成员共享同一块存储，追加 vptr 字段会与用户成员冲突，因此
  `union Value { … } use Greeter;` 报 `a union cannot use a trait`。同一标签的第二个函数体报
  `duplicate union 'Value'`。
- `offsetof` 同样接受 union 类型（`offsetof(union Value, c)`），字段校验与 struct 共用一套代码；
  字段缺失报 `union 'Value' has no field 'd'`。
- 既无标签也无别名的**顶层**记录定义（`union { int a; float b; };`）没有可引用的类型名，
  不在本文描述的范围内；作为**成员**出现的匿名 struct / union 见 §4.18。

#### 4.16 `goto` 与标签（ct-ast）

```c
static int find(int n) {
    int i;
    int found;

    found = -1;
    for (i = 0; i < n; i++) {
        if (i * i == 9) {
            found = i;
            goto done;
        }
    }
done:
    return found;
}
```

- 语句层接受两条 C 的跳转形式：`goto <label>;` 与 `<label>:`。生成物同形：标签独占一行，
  `goto` 原样发射。
- 标签是**函数作用域**：同一函数内重复的标签报 `duplicate label '<name>'`（即使分处不同的块）；
  `goto` 的目标必须出现在同一个函数里，否则在函数体解析结束时报
  `label '<name>' is not defined`（位置指向那条 `goto`）。不同函数可以复用同名标签。
- 标签拥有语句链，规则与 `case` 相同：从标签到下一个标签（`goto` 标签 / `case` / `default`）或 `}`
  之间的语句都属于它，发射时整条链缩进一级。连续的标签（`again: done:`）允许，第一条标签拥有第二条：
  发射为嵌套标签，语义不变。因此 `goto` 既可以向后跳（手写循环），也可以向前跳出
  多层循环或 `switch`。
- 标签后不能直接跟声明（C 的标签不构成作用域）：`again: int x;` 报
  `a declaration cannot follow a label; wrap it in a block`，把声明包进块即可。
- 标签不能直接碰 `}`（C99 要求标签后面必须有一条语句）：`again: }` 报 `a label needs a statement`。
  最省的写法是空语句 `again: ;`（见 §4.21）。
- `goto` 可以跳入 / 跳出块与循环（C 允许）。`goto` 跳出 `own` 的声明作用域**不会**触发自动释放（§4.9）；释放只在块尾、`return`、`break` / `continue` 前注入。
- 一个函数最多 64 个标签与 64 条 `goto`，超出报 `too many labels in one function` /
  `too many gotos in one function`。
- 已知边界：`out:` 直接接 `case 2:` 不在子集内——标签链在 `case` / `default` 处终止，链空即按上面
  的「标签需要一条语句」报错。

#### 4.17 位域（ct-ast）

```c
struct Flags {
    unsigned a : 3;
    unsigned b : 5;
    unsigned : 4;            /* 填充位：无名 */
    unsigned c : 8;
};

typedef struct {
    unsigned kind : 2;
    unsigned size : 6;
} Header;
```

- 字段可以带位宽：`<type> [name] : <宽度>;`。`struct`、`union`、`typedef struct { … }` 的匿名体
  以及 `pub` 版本都支持。
- 宽度是整数常量表达式，规则与 `case` 取值相同：数字、字符字面量、枚举成员、宏名、括号与算术 /
  位运算、一元 `- ! ~`、`sizeof`、`offsetof`。宽度**不做折叠**，原样发射，因此
  `unsigned nib : NIBBLE;`（宏为 `(1 << 2)`）与 `unsigned m : (2 + 2);` 都成立。表达式里出现
  变量（`a : (w + 1)`）报 `a bit-field width must be an integer constant`；整棵树就是单个名字时
  始终放行（可能来自 `#define`）。缺宽度报 `expected a bit-field width`。
- 名字可以省略：`unsigned : 4;` 是填充位。空名不进成员查找，不影响同 struct 的其它字段。
- 位域必须是整数类型：指针（含函数指针）与显式 `struct` / `union` 类型报
  `a bit-field must have an integer type`；typedef 别名放行，由 C 编译器判断。
- 不能是数组：`int a[2] : 3;` 报 `a bit-field cannot be an array`。
- 一条声明可写多个声明符：`unsigned a : 3, b : 5;`，与普通字段的 `int lo, hi;` 同一文法。
- 位域不写入 `structs[]` 的维度槽，因此成员访问的类型推断、普通字段的 `offsetof` 与 vptr 追加
  都不受影响；带 `use` 的 struct，vptr 字段排在该 struct 的所有位域之后。
- `offsetof` 取位域在 C 里是未定义行为，不做特殊处理。

#### 4.18 匿名成员（ct-ast）

```c
struct Outer {
    int tag;
    union {
        int i;
        struct {
            short lo;
            short hi;
        };
    };
    unsigned bits : 4;
};
```

- 记录体内直接写 `struct { … };` 或 `union { … };`（**无名字**）就是匿名成员（C11）。它的成员名
  **提升**进外层记录：`o.i`、`o.lo`、`o.hi` 都按提升后的名字访问，`sizeof(struct Outer)` 由 C 计算。
- 可以嵌套：匿名 `union` 里再放匿名 `struct`，名字逐层提升。匿名成员里可以有位域，`use` 的
  vptr 字段仍排在外层记录的最后。
- 提升后的名字在解析期写进外层记录的字段表，因此成员访问的类型推断、`offsetof(struct Outer, i)`
  的字段校验、以及 trait 字段的 vptr 初始化（`.obj.__x_vptr`）都不需要第二套代码。
- 提升后重名（与已有具名字段同名，或两个匿名成员之间同名）报 `duplicate member '<name>'`。
- 两条拒绝的形态：`union { int i; } u;`（无名记录类型的**具名**字段）报
  `an anonymous record member cannot have a name; tag the record instead`；
  空的 `union { };` 报 `an anonymous record needs a member`。
- 匿名成员是 C11 语法：生成物照原样发射嵌套记录，用 C99 编译时需要编译器把它当扩展接受
  （`cc -std=c99` 下 clang / gcc 都不告警）。

#### 4.19 `static` 局部变量（ct-ast）

```c
static int next_id(void) {
    static int n = 0;
    n = n + 1;
    return n;
}

static const char *greeting(void) {
    static const char *msg = "hi";
    return msg;
}
```

- 函数体内可以写 `static <type> name[dims] [= init] (, name …)*;`：对象具有静态存储期，
  跨调用保持取值，未写初始化器时按 C 规则零初始化。生成物原样发射 `static` 前缀。
- 初始化器不做折叠：是否常量由 C 编译期判断（`initializer element is not constant`）。
- 声明本身与普通局部变量相同（`declare_var` 照常登记），因此成员访问、数组下标、方法调用
  的类型推断都不变；带 trait 的 struct 仍由编译器补 vptr 初始化器
  （`static struct Pair p = { .__named_vptr = &Pair_Named_vtable };`，常量地址，合法）。
- 静态对象不归作用域管，因此：`static own …` 报 `a static local cannot be 'own'`；
  static 声明**不**进入泄漏分析，`static T *p = malloc(...)` 这种刻意的单例不会被报泄漏。
- `static` 后面必须是声明：`static;` 报 `expected a declaration after 'static'`。
- 范围外：`static` 直接跟在 `case` / goto 标签之后仍按「声明不能跟在标签后」拒绝；
  `for (static int i = 0; …)` 见 §4.21。

#### 4.20 复合字面量（ct-ast）

```c
struct Point { int x; int y; };

p = (struct Point){ 1, 2 };
total = sum_point((struct Point){ 3, 4 });
tail = (struct Point){ .y = 9, .x = 8 }.y;

static struct Point make(int x, int y) {
    return (struct Point){ x, y };
}
```

- `(type){ … }` 是 C99 的复合字面量：一个**临时对象**。它可以用在赋值右侧、实参、`return`，
  也可以直接接 `.field` / `[i]` 后缀。
- 花括号里的内容按声明的初始化器处理：位置式、指定式（`.y = 9`）、嵌套花括号、字符串字面量都原样发射；
  ct-ast 不折叠初始化器，是否常量由 C 判断。
- 带 trait 的 struct 由编译器补 vptr 项：
  `(struct Pair){ 10, 20 , .__named_vptr = &Pair_Named_vtable}`。
- 类型必须是**对象类型**：`(struct P *){ … }` 报 `a compound literal needs an object type`。
- 范围外：数组类型 `(int[]){ … }`（类型文法不读 `[]`，报 `unexpected token`）；
  对复合字面量直接调 trait 方法（`((struct Pair){ … }).val()`）不支持——**动态派发**的接收者允许形态
  仍是变量 / 元素 / 调用 / 字段链，先赋给变量再调用；类型宿主（§4.10）不受这四种形态限制，recipe
  直接把接收者替换一次。
- 存储期由 C 决定：函数内是自动存储期，文件作用域是静态存储期，ct-ast 不做区分。

#### 4.21 空语句与 `for` 首句的 `static`（ct-ast）

```c
for (i = 0; i < 3; i++) ;

if (n == 0) ;
else n = 1;

switch (i) {
case 3:
    ;
    break;
default:
    break;
}

for (static int i = 0; i < 2; i++) {
    total = total + 1;
}
```

- `;` 是空语句：`for (...) ;`、`while (c) ;`、`if (c) ; else …` 都可以写，
  也是「标签后必须有语句」的最省写法（`case 3: ;`、`done: ;`）。空语句不发射任何字符，
  外层块的 `{` `}` 照常输出。
- `for` 的首句可以写 `static` 声明：初始化只执行一次，变量跨调用保持取值，
  因此第二次进入同一 `for` 时直接以余值判断条件。
- 标准 C 的 `for` 首句只允许 `register` 或无存储类（C99 6.8.5.3），`static` 在那里是 GNU 扩展；
  ct-ast 因此把它提到一个自带的块里发射——`{ static int i = 0; for (; i < 2; i++) … }`：
  初始化仍只跑一次、名字的作用域不变，生成的 C 是标准 C99，gcc 与 clang 都接受。
- 空语句与 `for` 首句的 static 都不新增诊断；`static` 后面不是声明时沿用
  `expected a declaration after 'static'`。

#### 4.22 变参函数（ct-ast）

```c
#include <stdarg.h>

static int sum_all(int n, ...);

static int sum_all(int n, ...) {
    va_list ap;
    int total;
    int i;

    total = 0;
    va_start(ap, n);
    for (i = 0; i < n; i++) {
        total = total + va_arg(ap, int);
    }
    va_end(ap);
    return total;
}
```

- 参数表末尾可以写 `...`，它前面必须至少有一个具名参数（`int f(...)` 报
  `'...' needs a named parameter before it`）。声明与定义都支持，原型同样带 `...`。
- `va_list` 是内置类型词，`va_list ap;` 是普通声明，原样发射。
- `va_arg(ap, <类型>)` 是内建（第二个实参是类型，不能按普通调用解析），发射为同形调用；
  它的类型就是括号里写的类型，因此可以直接参与运算或赋给同类型变量。
- `va_start` / `va_end` 是普通调用：ct 不声明它们，与 `printf` 一样按未知被调函数发射，
  由源文件的 `#include <stdarg.h>` 提供声明。
- 普通 trait 的方法不能变参：`impl` 里出现 `...` 报 `a trait method cannot be variadic`
  （vtable 槽位是固定的函数指针类型）；trait 声明本身也不接受 `...`，会在参数位置报
  `expected a type`。**例外**是 `.m.ct` 里的静态 trait：它没有 vtable 槽位，方法签名可以以
  `...` 结尾，对应 map recipe 也必须带 `...` 把其余实参原样转发（缺任一侧分别报
  `a variadic trait method must forward '...' in its binding` /
  `this binding forwards '...' but the trait method is not variadic`）。

#### 4.23 内置类型词与 `inline`（ct-ast）

```c
#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

static volatile int ticks;

static inline int twice(int v) { return v + v; }

inline static int thrice(int v) { return v + v + v; }

static int first(int *restrict p, int n) { return p[0] + n; }

static bool positive(int32_t v) { return v > 0; }
```

- 类型关键字与 L0 / L1 / L2 对齐：`void` / `char` / `short` / `int` / `long` / `float` /
  `double` / `signed` / `unsigned` / `_Bool` / `bool` / `const` / `volatile` / `restrict` /
  `struct` / `union` / `enum` / `size_t` / `ssize_t` / `ptrdiff_t` / `wchar_t` /
  `int8_t`–`uint64_t` / `FILE` / `DIR` / `va_list`。声明**原样发射**，语义由 C 与对应头文件负责。
- `volatile` / `restrict` 是类型的一部分，因此 `volatile int x;`、`int *restrict p`、
  `volatile unsigned char *reg;` 在全局、局部、字段、参数、返回值上都成立。
- `inline` 是函数说明符：顶层接受 `static inline` 与 `inline static` 两种顺序，发射为
  `static inline ` / `inline `。生成的**原型**不带 `inline`（C 允许原型与定义不同）。
- `inline` 后面不是函数（`inline int value = 1;`）报 `'inline' can only declare a function`。
- 范围外：无（`_Static_assert` 见 §4.26；`_Alignas` / `_Alignof` / `_Generic` 见 §4.35；
  `__attribute__((…))` 见 §4.36；浮点字面量见 §4.24）。

#### 4.24 浮点字面量（ct-ast）

```c
double d = 1.5;
float f = 2.25f;
long double ld = 3.5L;
double tiny = .5;
double big = 1.5e3;

n = (int)9.99;              /* 截断为 9 */
```

- 支持 `<digits>.<digits>`、以点开头的 `.5`、带指数的 `1e9` / `1.5E-3`，以及后缀
  `f` / `F` / `l` / `L`。字面量按**原文**发射，因此后缀与指数写法都不会丢。
- 整数不受影响：`0x1F` / `0755` 仍按十六进制 / 八进制读成数值，并按十进制发射；
  `1...5` 里的三连点仍是范围 / 变参记号，不会被当成小数点。
- 浮点字面量**不是**整数常量表达式：`case 1.5:` 报 `a case label must be an integer constant`
  （位域宽度、枚举值同理）。
- 范围外：十六进制浮点（`0x1p3`）；`printf` 的格式串与实参类型匹配由用户负责，与 C 一致。

#### 4.25 `case` 范围标签（ct-ast）

```c
switch (score) {
case 0 ... 59:
    return 1;
case 60 ... 89:
    return 2;
case 90 ... 100:
    return 3;
default:
    return 0;
}

switch (c) {
case 'a' ... 'z':
    return 1;
case 'A' ... 'Z':
    return 2;
default:
    return 0;
}
```

- `case <low> ... <high>:` 按原样发射。两端都是整数常量表达式，规则与单值标签相同
  （`const_ok`，或整棵树是单个名字时放行）；任一端出现变量报
  `a case label must be an integer constant`。
- 范围标签与单值标签可以混排在同一个 `switch` 里；区间重叠、上下界颠倒不检查，交给 C 编译器。
- 缺下端（`case ... 5:`）在表达式位置报 `expected an expression`。
- 范围是 GNU 扩展（C23 正式化）：`cc -Wall -Wextra -std=c99` 下 clang 与 gcc 都接受且不告警，
  这是本特性的编译期依赖。

#### 4.26 `_Static_assert`（ct-ast）

```c
struct Pair { int a; int b; };

_Static_assert(sizeof(int) == 4, "int is four bytes");
_Static_assert(sizeof(struct Pair) >= 8, "a pair holds two ints");

static int check(int v) {
    _Static_assert(sizeof(char) == 1, "char is one byte");
    return v;
}
```

- 文件作用域与函数体内都可以写 `_Static_assert(<条件>, "<消息>");`，生成物同形。
- 条件必须是整数常量表达式（规则同 `case` 标签），否则报
  `a static assertion needs a constant condition`；消息必须是字符串字面量，否则报
  `a static assertion message must be a string literal`。消息可以省略（C23 放宽）。
- 文件作用域的多条断言统一在「类型之后、原型之前」发射，因此断言里引用本单元上面
  定义过的 struct / enum 仍然成立；引用**后面**才定义的类型则不行。
- 判定的最终结果仍由 C 编译器给出（断言失败时是它的错误消息）。
- 范围外：无（`_Alignas` / `_Generic` 见 §4.35；`__attribute__((…))` 见 §4.36）。

#### 4.27 一条声明多个字段（ct-ast）

```c
struct Buf {
    char name[8];
    unsigned len, cap;
    int *data, count;
    unsigned a : 3, b : 5;
    struct Range first, second;
};
```

- 记录体内的一条声明可以写多个声明符，共享同一类型：`int lo, hi;`、`unsigned len, cap;`。
  第一个声明符的拼写作为共享类型，后续声明符各自补上自己的星号、维度与位宽。
- `*` 只属于带它的那个声明符：`int *data, count;` 里 `data` 是 `int *`，`count` 是 `int`，
  与局部声明的规则一致。
- 位域可以成列：`unsigned a : 3, b : 5;`，每个声明符各自检查宽度与类型。
- 函数指针仍是一声明一个名字：`int (*a)(int), (*b)(int);` 报
  `a function pointer declares one name`。
- 字段表按名字逐个登记，因此成员访问、`offsetof`、匿名成员提升、vptr 追加都不受影响。

#### 4.28 数组长度表达式（ct-ast）

```c
#define WIDTH 4
#define SLOTS (WIDTH * 2)

static int g_tbl[WIDTH * 2];

struct Box {
    int cells[SLOTS];
    char name[(1 << 3)];
    short pairs[WIDTH + 1];
};

int main(void) {
    int local[WIDTH + 1];
    return local[0];
}
```

- 方括号里除了数字、单个名字与空之外，还可以写**表达式**：宏乘倍数、位移、括号求和等，
  一律按源码原文发射，因此 `[MAX_NAME * 2]` 与 `[(1 << 3)]` 都成立，长度由 C 折叠。
- 单个名字若解析为枚举成员，仍按其 C 拼写（命名空间 mangling 后的名字）发射；多 token 的
  表达式不做这种归一化，原样保留。
- 维度只用于发射与「是不是数组」的判定，因此数组长度是表达式还是字面量，对成员访问、
  `sizeof`、`offsetof` 与 vptr 初始化没有区别。
- 运行期长度（VLA）同样原样发射，由 C 判断；维度里的字符串字面量不做特殊处理。

#### 4.29 前缀 `++` / `--`（ct-ast）

```c
while (n && s[n - 1] == 0) s[--n] = 9;
i = *(--p);
j = ++i;                       /* j 取更新后的值 */
k = i++;                       /* k 取更新前的值 */
```

- 前缀自增 / 自减与其它一元运算符同级：操作数是再一个一元表达式，因此
  `s[--n]`、`*--p` 与独立的 `--n;` 都按 C 的读法成立。
- 值是**更新后**的值，与后缀形式相反；ct-ast 只按原顺序发射运算符与操作数。
- 没有额外限制，也不需要类型推断（与后缀形式处境相同）。

#### 4.30 初始化器的长度（ct-ast）

```c
static const char *kw[] = {
    "void", "char", "short", "int", "long", "float", "double", /* ... 一整张表 */
};

static const char *notes[] = {
    "单个列表项也可以是长字符串，整项保留",
    "short"
};
```

- 花括号初始化器不再受节点的 160 字节 `text` 字段限制：捕获与重写各用独立的
  大缓冲区（单个初始化器 4 KiB，重写后 16 KiB，单个列表项 4 KiB），最终文本存进
  arena 的字符串池。
- 因此关键字表、消息表这类长列表，以及由长字符串组成的列表项，都能完整保留。
- 超出上述上限仍报 `error: initializer is too long`，初始化器本身不静默截断。
  表达式位置的字符串字面量在 v0.53.1 起同样报硬错
  `string literal is too long (max 158 bytes; split it)`；相邻字面量会先拼接，不受该上限约束。

#### 4.31 变参函数指针（ct-ast）

```c
typedef int (*logger_fn)(const char *fmt, ...);

struct Sink {
    const char *name;
    logger_fn log;
};

static logger_fn g_log = say;
static logger_fn tbl[2] = { say, say };

p = counts;                 /* 局部变量同样可以指向变参函数 */
r = p(2, 3, 4);
s.log("sink %s %d\n", s.name, r);
```

- `...` 属于函数指针**签名拼写**的一部分：它连同其余参数一起写进 `(*)(…)`，因此
  typedef、结构体字段、指针数组与局部声明都自动带上它（§4.22 已说明 `...` 的含义）。
- 与 §4.22 的规则一致：`...` 前面必须至少有一个具名参数。`(...)` 与 `(void, ...)`
  都报 `a variadic function pointer needs a named parameter before '...'`。
- 通过指针调用就是普通调用，多余实参原样透传；ct 不检查实参类型（与 `printf` 一致）。

#### 4.32 逗号表达式（ct-ast）

```c
i = 1, j = 2;
for (i = 0, j = 10; i < 3; i++, j--) sum = sum + j;

bump(&i), bump(&j);
x = (i++, j * 2);              /* 取值位置要加括号 */
```

- 一个完整表达式可以是若干「赋值表达式」用 `,` 连成的列表：从左到右求值，值是最后一项。
- 接受的位置：
  - 表达式语句、以及 `for` 的初始化子句与步进子句（三者共用同一个解析入口）。每个操作数
    按赋值表达式解析，所以 `i = 1, j = 2` 就是 `(i = 1), (j = 2)`，与 C 的读法一致；
  - **括号内的取值位置**：`x = (a, b);`、`f((a, b))`、`while ((a, b))`。此时列表就是一个
    普通表达式，值取最后一项；括号里的操作数也可以是赋值（见 §4.34）。
- 生成物把列表写成 `(a, (b, c))`：右结合只是解析产物，求值顺序仍是左到右。
- 仍然不做：`for` 条件子句里**不带括号**的逗号（`for (; a, b; )`）。实参之间的 `,` 永远是
  分隔符，要写取值逗号必须加括号。

#### 4.33 头文件里的类型名（ct-ast）

```c
#include <time.h>

static time_t g_base;

struct Stamp {
    time_t when;
};

static void show(time_t t) { printf("%ld\n", (long)t); }

int main(void)
{
    time_t now;                /* 未知类型 + 名字 */
    time_t *ref;               /* 未知类型 + `*` + 名字 */
    now = 7;
    ref = &now;
    show(*ref);
    return 0;
}
```

- ct 不展开 `#include`，头文件里的 typedef 对解析器就是未知名字。在声明位置上，
  「未知标识符 + 声明符名」的序列按类型处理，拼写原样发射，是否真是类型交给 C 编译器判断。
- 判据：该名字既不能是已登记的类型（struct / union / enum / trait / typedef），也不能是
  已声明的变量或函数，还不能是语句关键字。所以 `return found;`、`goto done;`、
  `own Box *b` 仍按语句解析，`a * b;`（`a` 是变量）仍是表达式。
- 转换与 `sizeof` 里同样可用：`(time_t)raw`、`(time_t *)&t`、`sizeof(time_t)`。
  判据比声明位置更严——括号里的名字必须紧跟 `)`（可隔着若干 `*`），并且既不是
  已声明的变量 / 函数，也不是全大写宏常量。因此 `(f(x))` 仍是被括号包住的调用，
  `(MAX) + 1` 仍是表达式。
- 头文件里的 `enum` 常量不走这两条判据：`enum` 的定义不解析，普通表达式里会被当作未声明变量
  （全大写拼写除外），见 §4.43。

#### 4.34 表达式里的赋值（ct-ast）

```c
while ((c = getchar()) != EOF) { … }
if ((n = parse(line)) > 0) { … }

x = (a = b = 0);          /* 右结合 */
y = (arr[0] = 4) + 1;     /* 下标目标 */
z = (p->n = 7);           /* 成员目标 */
w = (a += 2);             /* 复合赋值 */
```

- 括号里，以及 `if` / `while` / `do … while` / `switch` / `for` 的条件里，赋值可以当作
  取值使用：`(c = getchar())` 的值就是赋进去的值；`a = b = 0` 右结合；`+=` 等复合赋值同样可用。
- 语句层的赋值完全不变：`x = 1;` 仍由语句解析，生成物不加括号。
- 目标必须是变量、成员、下标或解引用，否则报 `assignment target is not assignable`。
- 目标是 `own` 变量时拒绝：`an 'own' variable can only be assigned in a statement`。
  所有权（AutoDrop / 泄漏分析）只在语句层记账，值位置的赋值会绕过它，所以宁可报错。

#### 4.35 C11 对齐与泛型选择（ct-ast）

```c
_Alignas(16) int g_a;            /* 文件作用域 */
static _Alignas(16) int g_b;

struct Frame {
    _Alignas(8) int kind;
    int size;
};

int main(void)
{
    _Alignas(16) int local;      /* 块作用域 */

    printf("%d\n", (int)_Alignof(double));   /* 只接受类型名，不接受操作数 */

    int n = 0;
    double d = 0.0;
    int kind_n = _Generic(n, int: 1, double: 2, default: 3);   /* 1 */
    int kind_d = _Generic(d, int: 1, double: 2, default: 3);   /* 2 */
    return 0;
}
```

- `_Alignas(…)` 是类型拼写的一部分：解析器把它**原样**放到声明类型之前，全局、局部、字段、
  参数、`typedef` 五个入口因此自动生效，不需要额外语法。生成物写成
  `_Alignas ( 16 ) int x`，是否合法由 C 编译器判断。其他说明符仍写在前面
  （`static _Alignas(16) int g;`）；`_Alignas(16) static int g;` 这种顺序不在子集内。
- `_Alignof(type)` 与 `sizeof(type)` 共用一个节点，只接受**类型**形式：写 `_Alignof x`
  报 `_Alignof needs a type in parentheses`（C11 本来也只允许类型）。
- `_Generic(…)` 整段透传：控制表达式与每个分支都交给 C 编译器（各 token 之间补一个空格），
  类型匹配与分支选择都由它完成。ct 不读分支，所以分支里的 trait 调用、装箱等重写
  **不会发生**——分支要写成 C 编译器自己能接受的代码。
- 三者都由 ct-ast 解析并重新发射；L0 / L2 的透传行为不变。生成的 `.c` 保留 C11 拼写，
  因此构建它的 C 编译器需要接受该写法（clang 与 GCC 都可以）。

#### 4.36 GNU `__attribute__((…))`（ct-ast）

```c
static void trace(const char *fmt, ...) __attribute__((format(printf, 1, 2)));

int g_tick __attribute__((aligned(16)));

struct Frame {
    int kind __attribute__((aligned(8)));
    int size;
} __attribute__((packed));

typedef int word __attribute__((aligned(8)));

static int twice(int n __attribute__((unused))) { return 2 * n; }
```

- `__attribute__((…))` 是 GNU 扩展，ct 只负责把它**原样带进生成物**：属性列表（含
  `format(printf, 1, 2)`、`aligned(8)` 这类嵌套实参）按 token 原文捕获，连续的多个
  `__attribute__` 组一起捕获，在声明的**同一尾部位置**重新发射；语义完全交给 C 编译器。
- 接受的位置：函数声明与定义（参数表之后、`;` 或 `{` 之前）、形参（名字/维度之后）、
  结构体字段（名字/维度之后；位域的宽度之后）、全局变量（声明符之后、`=` 之前）、
  `typedef` 别名之后、`struct` / `union` / `enum` 定义体的 `}` 之后，以及**声明符之前的前缀写法**
  （`__attribute__((unused)) static int x;`）与**局部变量**（前缀或尾部写法）。
- 边界：`impl` 方法与 trait 方法上的属性仍不在子集内。未闭合的属性列表报
  `unterminated __attribute__`；同一声明同时写在两个捕获位置报
  `duplicate __attribute__ on one declaration`。
- 生成的 `.c` 保留属性原文，因此构建它的 C 编译器需要认识它（clang 与 GCC 都接受）。

#### 4.37 整数字面量后缀与其余 C 拼写（ct-ast）

```c
_Noreturn void stop(void);
static_assert(1 + 1 == 2, "arithmetic works");

unsigned long a = 0xFFu;      /* 大小写不限 */
long b = 0777L;
unsigned long long c = 1ULL;  /* 写法顺序不限：uLL / LLu / lL 都成 */

static int mix(const int *__restrict a, int *__restrict__ b) { return *a + *b; }
```

- 整数字面量接受 `U` / `L` / `UL` / `LL` / `ULL` 及其任意大小写与顺序（十进制、十六进制、
  八进制同路径）。后缀只影响**数值与类型**，不保留原拼写：发射时按数值重新写成十进制
  （`0xFFu` → `255U`、`16l` → `16L`、`0777L` → `511L`），不要依赖生成物里出现原字面量。
- 非法组合（`U` 多于一个、`L` 多于两个）报 `an integer suffix may be U, L or LL`。
- 值仍存放在 `long` 里：超过 `LONG_MAX` 的 `ULL` 字面量会按 `long` 回绕，这是既有的容量
  边界（与浮点字面量按拼写保留的做法不同）。
- `static_assert` 是 `_Static_assert` 在 C23 / `<assert.h>` 下的同义拼写，两者都接受，
  生成物统一写 `_Static_assert`。
- 函数声明的 `_Noreturn` 以**第一处声明**为准：`_Noreturn void f(void);` 之后的
  `void f(void) {}` 不会把它抹掉。
- `__restrict` / `__restrict__` 与 `restrict` 同义，原样保留在类型拼写里。

#### 4.38 头文件里的写法顺序（ct-ast）

```c
_Atomic(int) counter;                          /* 也可写 _Atomic int */
_Alignas(16) static int aligned;
__attribute__((aligned(32))) static int tagged;

__attribute__((unused)) static int helper(int n);   /* 原型在前，定义不带属性 */

int main(void)
{
    _Alignas(8) static int local;
    __attribute__((unused)) int spare = 7;
    int trailing __attribute__((unused));

    printf("%d\n", (int)sizeof(_Atomic(int)));
    return 0;
}
```

- `_Atomic(type)` 与裸 `_Atomic` 都作为类型拼写原样保留，声明、块作用域、cast 与 `sizeof`
  都能识别；原子语义完全由 C 编译器负责。
- `_Alignas(…)` 可以写在存储类**之前**（文件与块作用域都接受）。发射统一为规范顺序
  `static _Alignas ( 16 ) int aligned;`；同一声明写两次报
  `duplicate _Alignas on one declaration`。
- GNU `__attribute__((…))` 可以写在**声明符之前**：全局变量、函数原型 / 定义、局部变量；
  局部变量也接受尾部写法。无论源里写在哪一侧，发射都放在声明尾部（局部变量的 `=`
  之前）。同一声明两侧都写报 `duplicate __attribute__ on one declaration`；属性后面
  不是声明时报 `an attribute must prefix a declaration`。
- `_Atomic(type)` 的括号未闭合报 `unterminated _Atomic`。
- 边界：`typedef` / `trait` / `impl` / 记录定义上的属性仍不在子集内；`_Alignas` 的语义
  （能否用于某个对象）由 C 编译器判断。

#### 4.39 trait 默认方法（第三十六批，仅 ct-ast）

```ct
trait Logger {
    int write(char *buf, int len);                 /* abstract */

    int write_all(char *buf, int len) {            /* default */
        int sent = 0;
        while (sent < len) sent = sent + self->write(buf + sent, len - sent);
        return sent;
    }
}

struct Conn { int fd; } use Logger;                /* 全 default：impl 整块可省 */

impl Logger for Conn {
    int write(char *buf, int len) { return send(self->fd, buf, len); }
}
```

- 展开语义：默认体在**每个采纳点**各展开一份，函数名仍是 `<Struct>_<Trait>_<method>`，
  vtable 槽与普通 impl 方法一致；`self->other()` 沿用既有派发规则生成
  `_self->__<trait>_vptr->other(_self, …)`。不共享一份，也不新增派发路径。
- `self` 在默认体里是 `struct <S> *`：可读字段、可派发兄弟方法、可调自由函数。采纳的 struct
  由 `use` 决定，所以同一 trait 被两个 struct 采纳时生成两份实现。
- 覆盖优先级：impl 显式方法 > 默认方法。抽象方法仍必须实现，缺失仍报
  `trait method 'x' is not implemented for struct 'S'`；全 default 的 trait 只写 `use` 即可
  （外来类型写空 `impl T for S { }`，见 D-3）。
- 诊断：默认体互相派发成环、没有抽象叶子时报
  `trait 'T' has no non-default method to break the cycle`（位置在 trait 声明行）；默认体在某个
  struct 上不成立（例如用了 `self->fd` 而该 struct 没有 `fd`）时报
  `trait T::m (declared at <path>:<line>) cannot be expanded for struct S: <reason>`，
  指回 trait 声明而不是采纳点。
- 边界：不做字段注入、不做 supertrait、不做 trait 层共享默认体；`Drop` 不受影响。

#### 4.40 `borrow` 与 `Handback`（Phase 5 续，仅 ct-ast）

`borrow` 与 `own` 一样是**上下文关键字**：只在参数列表或语句行首被识别，其它位置仍是普通标识符
（函数名 `borrow` 不受影响）。它表达「这个指针是借来的：出口归还，绝不释放」。`Handback` 是
**内建 trait**（照 `Drop` 处理：无 vptr、无 vtable，只发 `<S>_Handback_handback`），用户不自己声明。

```c
struct Conn { int fd; int in_use; } use Handback;

impl Handback for Conn {
    void handback() { self->in_use = 0; }      /* 归还：对象仍活着 */
}

void render(borrow struct Conn *c)             /* 阶段一：参数注解，代码生成零变化 */
{
    printf("%d\n", c->fd);
}

int main(void)
{
    borrow struct Conn *c = acquire(0);        /* 阶段二：声明 + 出口自动归还 */
    render(c);
    return 0;                                  /* → if (c) { Conn_Handback_handback(c); c = 0; } */
}
```

| 源码形态 | 处理 |
| --- | --- |
| 参数 `void f(borrow Request *r)` | 去掉 `borrow`；参数登记为借用（代码生成不变） |
| `borrow Conn *c = expr;` | 去掉 `borrow` 后照常声明；登记为借用 |
| 声明作用域的闭合 `}` / **每个** `return` 之前（分支内、行内均可，无位置要求） | 插入 `if (c) { Conn_Handback_handback(c); c = 0; }`（与 `own` 共用一张表，按声明逆序） |
| `delete c;`（`c` 是借用） | 编译错误：借用对象不归本作用域 |
| `g = c;` / 外层局部 `x = c;` | 编译错误：借用的生命期比目标短 |
| `c = other;`（借用句柄重新赋值） | 编译错误：会静默丢失归还动作 |

约束与限制：

- 参数与声明都必须是**结构体指针**；数组、`static` 局部、`switch` 体内一律报错；文件作用域直接用
  `borrow` 报 `'borrow' is only allowed inside a function body`。
- 借用句柄**不可重新赋值**，也**不可存入** `static` 局部或文件作用域变量（一律编译错误）——
  这三条都会让归还动作静默丢失。
- 声明必须带初始化式，且类型须 `use Handback` 并已有 `impl Handback for S`；缺失即报错
  （不提供默认空体，否则「归还」会静默变成空操作）。
- 出口注入与 `own` 同构：**不释放内存**，只调 `handback` 并置空——归还后对象仍在池里，可能被他人借走。
- `return c;`（局部借用逃逸）报 `warning: a borrowed pointer escapes through 'return'` 并**取消注入**；
  `return r;`（借用参数逃逸）只警告。
- `Handback` 实现在**被借出的对象**上（出口时编译器只有 `T *c`），与 `Drop` 一致。
  但结构体表按**翻译单元**重建：`impl Handback for S` 必须与 `borrow` 同单元，跨单元借用会报
  `struct '<S>' uses trait 'Handback' but this unit has no impl`（与 `Drop` 的跨单元限制同源）。
- 已知限制（诚实标注）：`store(c)`（实参未标 `borrow`）与字段级 `s->p = c` 不检查；`goto` 跨过声明
  静默失效；不区分池对象与栈对象。**不要宣称「有了 borrow 就不会悬垂」**。

诊断文本（英文、小写、无句号、标识符单引号）：

```text
'borrow' is only allowed inside a function body
'borrow' requires a struct pointer parameter
'borrow' requires an initialiser of struct pointer type
struct '<S>' does not use trait 'Handback'
struct '<S>' uses trait 'Handback' but this unit has no impl
a borrowed pointer cannot be deleted
a borrowed pointer cannot be reassigned
a borrowed pointer cannot be stored in '<name>' (its scope outlives the borrow)
'borrow' is not supported inside a switch
'borrow' does not support arrays
a static local cannot be 'borrow'
warning: a borrowed pointer escapes through 'return'
```

设计与实现说明见 [design/borrow.md](history/design/borrow.md)。

#### 4.41 raw 透传（`#ct-raw`，Phase 17.3，仅 ct-ast）

ct-ast 逐节点重新生成 C，因此它无法重写的 C 片段（宏、手写函数、`#pragma`）需要一个显式的
原样通道：`#ct-raw` 与 `#ct-endraw` 之间的一切**逐字节**进入生成的 `.c`，从不经过词法/语法分析。

```c
#include <stdio.h>

#ct-raw
#define TRIPLE(x) ((x) * 3)
static int raw_helper(int n)
{
    return n + 1;
}
#ct-endraw

int main(void)
{
    printf("%d\n", TRIPLE(raw_helper(2)));
    return 0;
}
```

| 形态 | 处理 |
| --- | --- |
| `#ct-raw` 单独一行且**位于第 1 列** | 打开块；块内容按源顺序插入顶层声明的流中 |
| 块内任何文本 | 原样复制到字面量池，发射时逐个字节写出（不 token 化、不补空格） |
| `#ct-endraw` 单独一行且位于第 1 列 | 关闭块；生成的 `.c` 在块后写 `#line <块后第一行>`（仅 `--line` 或驱动要求时） |
| `--no-line` | 块文本照旧原样发射，只是不写 `#line` 重锚 |
| `.h.ct` 单元 | 块只进 `.c`，不进 `.h` |

约束与诊断：

- 一个块最多 **32768 字节**（超限报 `raw block exceeds 32768 bytes`）。
- 标记必须在**第 1 列**（`  #ct-raw` 报 `#ct-raw must start at column 1`），其后只允许空白。
- 未闭合在**起始行**报 `unclosed #ct-raw (expected #ct-endraw)`；孤立的 `#ct-endraw` 报
  `#ct-endraw without #ct-raw`；关闭行后跟非空白文本报 `unexpected text after #ct-endraw`。
- 只在普通 `.ct` / `.h.ct` 单元可用：`.m.ct` 的 prologue 白名单仍只放行 `#include` / `#define`。
- L0 / L1 按行透传，本来就会原样输出块内容；本规定只约束 ct-ast。编译器**自身源码**
  （`selfhost/ct-ast/**`）不得使用块，由 `selfhost/check-ast.sh` 的护栏检查。

#### 4.42 类型别名 `type`（Phase 20，仅 ct-ast）

映射单元常需要给自己映射的 C 类型起一个可读名字。过去这个只能在 `.shim.h` 里写 `typedef`
（于是名字变成真实的 C 类型）；`type` 声明把它变成**纯编译期同义词**：

```c
namespace png;

pub type PngReader = struct ct_png_reader *;

pub trait Reader { int width(); }
map trait Reader for type PngReader { width(r) -> ct_png_width(r); }
```

每次出现 `PngReader` 都展开成底层拼写（这里 `struct ct_png_reader *`），生成的 C 里只有底层
类型，**不发射任何 typedef**。

- **星号归属**：别名只替换源码中写的那个名字，名字后手写的 `*` 原样保留。因此
  `pub type T = struct S;` 让 `T *` 与 `struct S *` 同键；`pub type T = struct S *;` 让裸 `T`
  与 `struct S *` 同键。用别名替换 shim 里的 `typedef struct S S;`（源码到处写 `S *`）时必须用
  前一种，否则每个使用点都会多出一层指针。
- **允许的位置**：只有 `.h.ct` 与 `.m.ct`。普通 `.ct` 不可被 import，别名无法传播，故报
  `a type alias is only allowed in a .h.ct or .m.ct unit`。`.m.ct` 里的别名必须是 `pub`，
  否则报 `a type alias in a .m.ct unit must be 'pub'`（映射单元没有私有接口）。
- **语法**：`[pub] type Name = <类型>;`。`type` 是上下文关键字，只有 `type IDENT =` 这一形状
  进入别名分支，`type` 作类型名或变量名的旧写法不受影响。右侧走与普通声明相同的类型读取器，
  因此 `struct` / `enum` / `union` 限定、指针与整型同义词规范化都会发生。
- **目标可以是不透明的 C 类型**：右侧出现本单元没声明过的名字（`sqlite3_stmt`、`FILE`）时按
  不透明 C 拼写保留。这是用别名替换 shim typedef 的地基。
- **在 host key 之前展开**：接收者的静态类型与 `for type` 的主机拼写都先展开别名，再做 §4.10
  的规范化文本比较。于是 `map ... for type SqliteStmt` 与 `map ... for type sqlite3_stmt` 是
  **同一个宿主**，不会产生两条平行映射。两者与同一 trait 的同名方法同时存在时，声明期不报错，
  调用点报 `ambiguous type-host map for method '<m>' on type '<key>': '<p1>' and '<p2>'`
  （与现有 map 的懒失败行为一致）。
- **可见性**：与 `map` 和 C 头文件一致，走 **import 传递闭包**——import 了 `a`，则 `a` import
  的单元导出的别名都可见；只导出 `pub` 别名，私有别名不跨单元。
  - 本单元使用但未 import：`type alias 'Text' is declared in <path>:<line> but this unit does not import it`。
    只有 `pub` 别名会给出这条诊断；其它单元的私有别名按不透明 C 拼写处理。
  - 两个可达单元导出同名不同目标：`type alias 'X' is exported by both <p1> and <p2>`；同名同目标
    视为同一个同义词，不报错。
- **声明顺序**：同一单元内先声明后使用。使用点早于声明：
  `type alias 'Text' must be declared before it is used`。解析器在单元开头预扫描顶层
  `type IDENT =`，因此这条诊断针对的是别名而不是“未知类型”。
- **循环**：`pub type A = B; pub type B = A;` 报
  `type alias cycle: 'B' -> 'A' -> 'B'`（在形成闭环的那条声明上报，链从该声明开始）。
- **与已有名字冲突**：与 struct / trait / typedef 同名报
  `type alias 'X' conflicts with an existing type`；同单元重复声明报
  `duplicate type alias 'X'`；与 `import a::b::C as D;` 的 `D` 同名同样按冲突处理。
- **目标不能是 trait**：类型宿主需要具体拼写，别名指向 trait 报
  `type alias 'X' cannot name a trait`。
- **与 `import ... as` 的分工**：`import a::b::C as D;` 给**已导出的类型名**换一个本地引用名；
  `type D = C;` 给**任意类型拼写**（包括不透明 C 类型、指针）起同义词。前者只能指向被导入单元
  导出的名字，后者不看导出表；两者同名时按上一条报冲突。
- **不产生 C**：别名不发射 typedef、不进 `--emit-map`、不改变生成的 `.h`；消费者的 `.h` / `.c`
  里看到的始终是底层拼写。单文件编译（不解析 import）只能看到同一单元内的别名。

诊断一览：

| 情形 | 消息 |
| --- | --- |
| 普通 `.ct` | `a type alias is only allowed in a .h.ct or .m.ct unit` |
| `.m.ct` 非 `pub` | `a type alias in a .m.ct unit must be 'pub'` |
| 使用早于声明 | `type alias 'X' must be declared before it is used` |
| 未 import 的 `pub` 别名 | `type alias 'X' is declared in <path>:<line> but this unit does not import it` |
| 两个单元导出同名异目标 | `type alias 'X' is exported by both <p1> and <p2>` |
| 与已有类型 / 导入别名重名 | `type alias 'X' conflicts with an existing type` |
| 同单元重复 | `duplicate type alias 'X'` |
| 循环 | `type alias cycle: '<first>' -> … -> '<first>'` |
| 目标为 trait | `type alias 'X' cannot name a trait` |

#### 4.43 外部 C 符号：CT 认识哪些、不认识哪些（DOC-64）

CT 没有预处理器：`#include` 只按整行透传到生成物，头文件内容不参与解析。因此一个来自 C 头文件的
名字能否在 CT 源码里使用，取决于 CT 自己的判据，而不是头文件写了什么：

| 头文件里的东西 | CT 的判据 | 典型用法 |
| --- | --- | --- |
| 全大写标识符（`MAX_SIZE`、`EOF`、`SEEK_SET`） | 按宏放行：不展开，原样发射 | `buf[MAX_SIZE]`、`x == EOF` |
| `typedef` 类型名（`time_t`、`size_t`） | 按类型放行（§4.33） | `time_t now;`、`(time_t)raw` |
| 函数声明（`getchar`、`strlen`） | 按普通函数调用 | `c = getchar();` |
| `stdin` / `stdout` / `stderr` | 三个特例名字直接放行 | `fputs(s, stdout)` |
| `errno` | **不放行**，需自己写 `extern int errno;` | 声明后 `return errno;` |
| `struct` / `union` / `enum` 的**类型名** | 只认识 CT 自己定义或登记的标签（§4.33） | `struct tm *t;` |
| **`enum` 常量**（`Fast`、`Severity_Warn`） | **不认识**（恰好全大写的除外，见下） | `x == Fast` → `error: use of an undeclared variable` |
| 小写 `#define`（`#define limit 4`） | 不展开、不放行，同样是未声明变量 | 换成全大写名或走 shim |

- 全大写是**纯拼写启发式**：`SEEK_SET` 能过，只是因为它长得像宏，被原样发射、交给 C 编译器求值——
  这不代表 CT 解析了那个 `enum`。同一头文件里若有 `enum Mode { Fast, Slow };`，`x == Fast` 立刻报
  `error: use of an undeclared variable`（解析期诊断，`ct build` / `ct check` 都失败）。
- 数组长度是例外：`int a[Fast];` 里的单个裸名按常量放行并原样发射（§4.28）；**普通表达式与 `case`
  标签不放行**——`case SEEK_SET:` 能过只因为它是全大写，`case Fast:` 会报未声明变量。
- 想让 CT 侧直接调用 enum 常量，用映射单元 + 伴生 C shim 包一层（五行即可）：

```c
/* posix/seek.shim.h —— 与 seek.m.ct 同目录、同基名 */
#include <fcntl.h>
static inline int ct_seek_set(void) { return SEEK_SET; }
```

```c
/* posix/seek.m.ct */
namespace posix;

pub trait Seek { int set(void); }

map trait Seek for namespace posix {
    set() -> ct_seek_set();
}
```

消费者 `import posix::seek;` 之后写 `posix::Seek.set()`，生成物里展开为 `ct_seek_set()`；`ct build`
会自动补 `-I posix/`（§4.10、tutorial §9.2）。把 `static const int` 直接放进 shim 头不够：声明在
头文件里，CT 看不见；在 CT 源码里再声明一次又与定义重复。所以推荐函数包装（或全大写 `#define` 别名）。

#### 4.44 闭包（Phase 21，仅 ct-ast）

**语法**：闭包字面量 = 带类型的参数列表 + 箭头 + 表达式或块体。

```c
int apply(int base) {
    int n = 3;
    int (*add)(int x) = (int x) => x + n + base;                    /* 表达式体 */
    void (*dump)(int x) = (int x) => { printf("%d\n", x + n); };    /* 块体 */
    return add(5);
}
```

- **表面类型复用函数指针声明**：返回类型由左侧声明给出，不推断；不引入 `auto`（D21-1）。
  参数必须带类型；无参写 `()`；`void` 返回就声明 `void (*f)(…) = …`。
- 箭头只在「`)` 之后、表达式起始位置」被识别；`>=`、`==`、`->` 不受影响。
- 字面量可直接作实参（D21-14）：它必须落在被调方相邻的 `ret (*fn)(void *env, …)` + `void *env`
  参数对的起点；返回类型与逐参类型取宿主 `fn` 的签名，arity 按两项计。

**捕获语义**（D21-2）：

- 捕获集合 = 闭包体内自由出现的**外层函数 / 外层闭包的局部变量与参数**；全局变量、函数名、
  枚举常量、类型名不捕获。
- **按值捕获、创建点求值**：每个捕获在生成的 env 结构里占一个同名字段；创建时拷贝当前值。
  指针按值拷贝是浅拷贝，通过 `*p = …` 写回是允许的。
- **捕获名只读**：体内写捕获名（`=` / `++` / 复合赋值）报
  `a captured variable cannot be reassigned inside a closure`；取地址 `&n` 报
  `the address of a captured variable cannot be taken inside a closure`。
- 捕获 `own` / `borrow` 变量报 `a closure cannot capture '<name>' (it is 'own' or 'borrow')`；
  捕获另一个闭包变量报 `a closure cannot capture another closure`。
- 捕获数组报 `a closure cannot capture the array '<name>' (capture a pointer to it instead)`：
  C 的数组没有值语义，env 里的一次赋值无法完成拷贝。
- 嵌套闭包：内层从外层 env 字段读值再拷贝，不建立 env 之间的指针链。

**闭包变量是绑定，不是值**（D21-13 / D21-16）：

- 闭包变量在声明处创建，之后可以**调用**（`add(5)`），也可以把绑定本身整对交给一个 `(fn, env)`
  参数（`ring_each(add)`）：填进去的是它的 trampoline 与环境地址，参数表必须与宿主尾部一致。
  `(fn, env)` 是传输形态，不是值。
- 拷贝 / 重赋值 / 作字段或数组元素报 `this closure is a binding, not a value (inline it or use a
  struct + trait)`；作返回值报 `a closure cannot escape through 'return'`；传给不是 `(fn, env)` 对的
  位置报 `a closure argument must fill a '(fn, env)' parameter pair`，参数表不匹配报
  `this closure's parameter N is '…', but the expected type is '…'`。
- 闭包变量只能声明在函数体内；`.h.ct` 里的函数指针只是普通函数指针，不承载闭包绑定。
  全局（含 `.h.ct` 的 `pub` 全局）的初始值不能是闭包字面量，报
  `a closure cannot be stored in '<name>' (its scope outlives the closure)`。

**ABI 与生成物**：`(fn, env)` 两词，`env` 是第一个参数，与档① `impl` 的 `(void *self, …)` 同形
（D21-4）。生成物 `__ct_cl_env_<N>` / `static __ct_cl_tramp_<N>` / `__ct_cl_env_v_<N>` 发在本单元
`.c` 的文件作用域、不进 `.h`；零闭包单元逐字节不变（D21-15）。命名、`#line` 重锚与诊断的完整约定见
[closure-conventions.md](closure-conventions.md)。

**静态映射调用（Phase 25，仅 ct-ast）**：静态映射调用（类型宿主 / 命名空间宿主的静态 trait）与普通
调用同口径接收闭包实参，展开形态与四条诊断（L25-1–L25-4）见 §4.10。区别只在落位：recipe 按 `fn` /
`env` 两个槽位分别引用这个实参，必须各引用一次；环境仍是栈上的复合字面量，shim 必须在本次调用里
同步消费（见 [closure-conventions.md](closure-conventions.md)）。

**限制清单**：

| 限制 | 表现 |
| --- | --- |
| 不能进 `.h.ct` | 头文件里只有普通函数指针；闭包变量只在函数体内声明；全局 / `pub` 全局的初始值不能是闭包字面量 |
| 不能捕获数组 | C 数组没有值语义：`a closure cannot capture the array '<name>' (capture a pointer to it instead)` |
| 不能作返回值 | `a closure cannot escape through 'return'` |
| 不能作字段或元素 | `a closure cannot be stored in a field, an element or a container` |
| 闭包变量只在声明处可用 | 可以调用，或整对交给 `(fn, env)`；不能拷贝 / 重赋值 / 交给普通变量 |
| `qsort` 类 API 接不了 | 这类 C 回调没有 `void *` 环境槽，闭包无处放 env |

**`(fn, env)` 回调约定**：容器 / 算法接受闭包时，回调只有一种形态——
`ret (*fn)(void *env, …)` 且 `void *env` 紧跟其后；`env` 必须是第一个参数，容器不得保存它
（env 活不过调用它的栈帧）。没有 env 槽的 C API（`qsort`）两档都接不了；需要持久化上下文就走档①
（`struct` + `trait`；ct-pkg 的 `Callable` 签名族随该仓发布，本仓未内置）。

**未防护面**（诚实标注）：env 以 `void *` 交给不透明接收方后被保存（E8）、`goto` 跨过闭包声明
（E9），编译器都不分析。

### 5. 命名规则（稳定契约）

命名空间前缀属**已移出 L0 的特性**，已由 Phase 2 在 `selfhost/l2/**` 恢复（本文不描述它）。

| 产物 | 规则 | 示例（trait `Greeter`，struct `Person`，方法 `greet`） |
| --- | --- | --- |
| vtable 类型 | `<Trait>_vtbl` | `struct Greeter_vtbl` |
| 接口值类型 | `<Trait>_iface` | `struct Greeter_iface`（胖指针 `{ self, vt }`） |
| vptr 字段 | `__<trait 全小写>_vptr` | `__greeter_vptr` |
| 方法实现 | `<Struct>_<Trait>_<method>` | `Person_Greeter_greet` |
| vtable 变量 | `<Struct>_<Trait>_vtable` | `Person_Greeter_vtable` |
| 隐式参数 | 固定为 `self`，函数体内强转目标固定为 `_self` | — |
| 数组循环变量 | 固定为 `__ct_i`，包在自己的块内 | — |

#### 5.1 源码命名约定（语言 + 标准库 + ct-pkg，稳定契约）

> 适用范围：CT 语言自身暴露的名字（内置类型、`lib/std` 内置层）、`std` 包，以及所有 ct-pkg 包。
> 目标：同一生态不出现 `read_file` / `readFile` / `ReadFile` 三种写法。

| 类别 | 规则 | 正例 | 反例 |
| --- | --- | --- | --- |
| 函数 / 方法 | 必须 `snake_case`，以动作动词开头 | `read_file`、`to_lower`、`has_prefix` | `readFile`、`ReadFile`、`file_reader` |
| 类型（struct / union / enum / trait / 类型别名） | 必须 `PascalCase`，首字母大写；缩写按词处理 | `Vec`、`Map`、`Str`、`HttpEntry` | `vec`、`http_entry`、`HTTPEntry` |
| 小驼峰 | 任何标识符位置都不使用 | — | `readFile`、`httpEntry`、`parseJSON` |
| 变量 / 字段 / 常量 | 不得用小驼峰；默认 `snake_case` | `line_count`、`http_entry` | `lineCount`、`httpEntry` |

补充：

- 类型参数允许单大写字母（`T`、`K`、`V`），不要求拼成单词。
- 「动作动词开头」按评审判断；`get_` / `set_` / `has_` / `is_` / `to_` / `from_` 等前缀视为动词。
- **保留名（封闭清单，只豁免「动词 / 前缀开头」一条，不豁免大小写规则）**：
  - 内置层：`Vec.len`、`Vec.has`、`Vec.at`、`Map.len`、`Map.has`（`Str` 只有字段 `len` 与自由函数
    `str_len`，**没有 `len` 方法**，因此不进保留名）；
  - `std` 包：`std::str::String.len`（即 `std::str.len`；std 侧若改名为 `CStrOps`，CT 待其发版后
    再同步本条，不预先改）、旧 `std::vec` 的 `len` / `at`、
    旧 `std::map` 的 `len`、`std::num` 的 `max` / `min`（`int` / `long` / `long long` 三个宿主）。
  这些是存量豁免（`std::num` 的两个名字是 std `0.2.0` 的既有名），不因本条改名；
  **新增查询方法不得加入本清单**，仍按动词 / 前缀规则。
- **映射层 trait 不是值类型**：`std::str::String`、`std::io` 的 `Path` / `File` 挂在宿主
  （`char *` / `IoFile *`）上提供方法，名字按 trait 的 PascalCase 规则，但不得当 struct 或类型别名使用；
  是否改名（例如 `String` → `CStrOps`）由所属 ct-pkg 包决定，CT 不替包保留或改名。`Path` / `File`
  分别映射 `char *` 与 `IoFile *`，与内建 `Str` / `Vec` 无关。
- **不设「数学惯用词」类例外**：`max` / `min` 是按名字登记的存量豁免，不是一类新前缀；
  新的数学接口（`abs` / `clamp` / `sum` 等）不得据此免检，确需例外时逐个登记并留决策记录。
  理由：类别例外无法机械判定，闭名单可审计；libc 例外已有精确边界（同名直映射），不再开第二个
  模糊口子。
- 名词开头不合规：`last_error` 这类名字必须改为 `get_last_error`；`std` 已按此改。
- 小驼峰存量名（如 `findChar`、`startsWith`、`readFile`、`codepointCount`）**不进入保留名**：
  它们只适用下文的「存量按包节奏清理」，不豁免大小写规则。

**libc 直映射例外**：只有把 libc 同名函数零成本映射进来的接口，才保留 libc 拼写
（`printf`、`puts`、`fflush`、`sqrt`、`fabs` 等）。边界：

- 必须与 C 库函数同名，且展开为同名调用，不额外改变语义；
- 包装函数（增加校验、默认值、错误转换、命名空间前缀）一律 `snake_case`；例如 `print_line`
  内部调用 `puts`，该包装不得命名为 `puts`；
- 用户包不得为了规避本条把自有函数命名为 libc 名；例外只适用于 libc 映射单元。

**存量处理**：

- **新代码强制**：新增或重命名的声明必须符合上表；不合规的改动在评审阶段拒绝。
- **存量按各包自身节奏清理**：不要求一次性重命名；包维护者在自己的破坏性版本里逐步改。
- 公开 API 重命名属破坏性变更，按包版本规则升主版本并给迁移说明；涉及 ABI/生成符号的改名
  （如 `ct_buf`）单独评估，不在本条强制窗口内。
- 编译器本轮不做自动 lint；判据由评审按上表与下列规则核对。

**判据（评审用）**：

1. 函数 / 方法名匹配 `^[a-z][a-z0-9_]*$`，且首词为动词或上列查询前缀（保留名清单除外）；
2. 类型名匹配 `^[A-Z][A-Za-z0-9]*$`，缩写作 `Http` 不写 `HTTP`；
3. 任何标识符不匹配小驼峰形态（首词小写后紧跟大写，如 `readFile`）；
4. libc 例外仅限同名单映射调用；包装层不得占用 libc 名；
5. 存量文件未触碰的旧名不判失败，改动行必须合规。

### 6. 语义约束与已知问题

#### 6.1 会被诊断的约束

| 约束 | 违反时 |
| --- | --- |
| `use` 引用的 trait 必须已定义（且出现在该 struct 之前） | `error: struct 'S' uses undefined trait 'T'` + `exit 1` |
| `impl` 的 trait 与 struct 必须已定义 | `error: impl for undefined trait/struct 'X'` + `exit 1` |
| struct 必须 `use` 了对应 trait 才可 `impl` | `error: struct 'S' does not use trait 'T'` |
| impl 不得出现 trait 未声明的方法 | `error: method 'm' is not declared in trait 'T'` |
| impl 必须实现 trait 的**每一个**方法（ct-ast：带默认体的方法可不写） | `error: trait method 'm' is not implemented for struct 'S'` |
| ct-ast：默认体互相派发成环、没有抽象叶子 | `error: trait 'T' has no non-default method to break the cycle` |
| ct-ast：默认体在某个采纳 struct 上不成立 | `error: trait T::m (declared at <path>:<line>) cannot be expanded for struct S: <reason>` |
| 大括号/圆括号必须配对 | `error: unterminated '{'` |
| `trait` / `impl` 头部必须完整（名字、`{`、`for`） | `error: expected trait name` / `expected '{' after trait 'X'` / `expected trait name after 'impl'` / `expected 'for' in impl of 'T'` |

**签名检查分入口**：`ct check` / `ct compile` 不比对 impl 方法签名（参数类型、个数、返回类型都原样搬运）；
`ct build` 在生成头之前比对，参数类型 / 个数 / 返回类型不一致按 L45-1 / L45-2 **硬错**（v0.45.0 起）。
普通函数调用实参的元数 / 类型：默认路径只报警告，`ct check --types` 才把类型不一致升为错误（§4.53）。
**v0.53.2 起例外**：至少一侧是**按值 `struct`** 的不一致（`char *` 传给 `Str` 形参、两个不同 struct 按值传递）
在默认路径就是**硬错**（`error: type mismatch: '<callee>' argument <n>: expected '<T>', got '<U>'`），
因为 C 无法转换、只会把同一条错误再报一次；`struct P *` ↔ `struct Q *` 这类指针不一致与算术类宽松规则保持不变。
trait / struct **重名**不是静默接受：ct-ast 报 `duplicate trait '<name>'` / `duplicate struct '<name>'`；
L0 / L2 仍取最先出现者，后者不可达、不报错。

#### 6.2 已知限制

- 变量表无类型信息；变量按**花括号块作用域**回滚（`{` 压栈、`}` 恢复），同一作用域内出现同名时取**最先**登记者（`find_var` 首命中）。
- **登记顺序 = 源码顺序**：在变量声明之前出现的方法调用不会被重写。
- **（仅 L2，行重写管线）**跨行的方法调用语句不重写（按行处理）；函数签名的**参数列表**跨多行时同样不识别。ct-ast 是 AST 管线，两者都不受限。
- **（仅 L2，行重写管线）**跨行的块注释 `/* … */` 只保护第一行：续行会被当作普通代码行处理，其中的 `self`、方法调用等照常改写（单行 `/* … */`、`//` 与字符串 / 字符字面量不受影响）。这是按行处理管线的固有限制，Phase 2–5 用 CT 重做特性时随实现一并保留（见 [roadmap](roadmap.md) 的「自举之后的恢复与新增」）。**ct-ast 不保留源码注释**：整段注释连同其中的代码一起丢弃，生成物只带溯源 banner（若要保留需单独立项）。
- **文件作用域的对象 / 数组**：ct-ast 把 vptr 写进静态初始化式，不生成 `__ct_init` 构造器；
  L0 / L2 才用 `__attribute__((constructor))` 在 `main` 前补写。
- 数组支持声明初值与变长数组（`int a[] = {…};`、`int a[n];`）；ct-ast 逐元素补 vptr。
- **堆对象自动初始化**（Phase 1，D1=A）：`T *p = malloc(sizeof(struct T));` / `calloc` 在声明后自动写 vptr（含嵌套字段）。
- **接口多态（ct-ast v0.53.1）**：接口**数组**支持（`T a[2]; a[0] = s;`、`T *p = a;` 按元素派发）；
  接口值 / 指针字段的**指定初始化**与语句赋值都会自动装箱；返回局部接口值已改堆复制（SH-75）。
  仍不支持的是：接口作接收者的 `into`（§4.52）、接口值元素的 `foreach` 拷贝（L29-15）、
  以及**右值表达式直接装箱**——`T t = mk();` 现在是编译期硬错（v0.53.1），
  提示 `cannot box an rvalue struct; assign it to a variable first`；不再静默发射坏 C。
- **（仅 L2）**单行函数体（`int f() { … }` 与函数头写在同一行）不处理，与 Phase 0 的按行改写一致。同理，与构造**同处一行**的语句也不会被重写：一行接口装箱、一行右值接收者均按原样透传。（`impl` 构造是例外：它的方法体由块匹配整体抽取，即使与方法头同处一行也会走重写管线。）ct-ast 没有这些限制，跨行语句与单行函数体都照常回写。
- 不完整的 `struct` 头部（缺 `{`）不作为构造，按原样透传。`trait` / `impl` 是 ct 独有关键字：行首出现且其后紧跟标识符或 `{` 即视为构造声明，头部畸形一律报错（其后是其它 token 的行，如 `impl[n] = 0;`，仍透传）。
- 顶层构造不支持嵌套。
- **生成物里「声明了但没用到」的 `static` 实体**：一个 `impl` 总会发射 `<S>_<T>_vtable`，一个
  `use Drop` 的 struct 总会发射 `<S>_Drop_drop`，即使本单元从不调用该 trait 的方法、也不 `delete`
  （ct-ast 不做跨过程可达性分析）。compile 模式下这些符号带 `__attribute__((unused))` 的 `static`
  形态；PH-48 起 build 模式的 Drop 体由 owner 单元以非 `static` 发出（头文件带真原型），因此不会
  因「未使用」告警。属性与既有的 `__ct_init` 的 `__attribute__((constructor))` 同源，需要
  GCC / clang。它们**不影响**语义与运行。
- **闭包**（Phase 21，仅 ct-ast）的限制是语言规则，不是实现缺口：不能进 `.h.ct`、不能作返回值 /
  字段 / 元素、闭包变量只能调用不能搬走、`qsort` 类无 env 槽的 C API 接不了；另有 E8 / E9
  两个未防护面。见 §4.44 与 [closure-conventions.md](closure-conventions.md)。
- **「方法调用当接收者」两侧不一致**（原记「留待 Phase 24」；Phase 24 已定为**数组 range 初值**，
  本项改记「留待后续未编号阶段」）：类型宿主（§4.10）接受任意静态类型已知的
  接收者，包括方法调用结果（`s.trim().len()`）；动态派发（impl）当前拒绝接收者本身是方法调用的
  形态（`a.m().n()`），只接受变量 / 元素 / 调用 / 字段链。这是两条 lowering 的差异，不是设计意图；
  本轮只收紧类型宿主侧的误判，未放宽 impl 侧。
- **AutoDrop 的 `break` / `continue` 出口（仅 ct-ast）**：ct-ast 在 `break` / `continue` 前释放
  循环体（含嵌套块）登记的 `own`，`case … break` 只作用到 switch 基线；冻结的 L2 仍只在块尾与
  `return` 前注入。同样的源码在 L2 下会漏释放，这是 ct-ast **比 L2 多释放**的能力差，不是行为回归。

#### 4.45 `loop(n)` 计数循环（Phase 22，仅 ct-ast）

`loop(<count>) { … }` 是原生 `for` 的语法糖，展开恰好是：

```c
for (int i = 0, __ct_loop_n_K = (<count>); i < __ct_loop_n_K; i++) { … }
```

- **`loop` 是上下文关键字**（D22-4）：它不进关键字表，只有语句位置、且紧跟 `(` 时才特殊。
  `int loop = 3;`、`loop:` 标签、`goto loop;`、`x = loop + 1;` 仍是普通标识符。
- **计数只求值一次**：表达式绑定到私有临时量 `__ct_loop_n_K`（`K` 是发射器进程级单调的计数器），
  条件读该临时量，不会重复求值。`loop(0)` 与 `loop(-2)` 都零次迭代，不报错。
- **隐式计数器是 `int i`**：`loop` 体自成一个作用域，`i` 在解析期进入符号表，所以名字解析、
  闭包按值捕获（每轮一个快照）与遮蔽判定都和手写 `for` 一致。体内可以 `break` / `continue`、
  读或写 `i`、`i++`；体内声明的 `own` 变量在块尾、`break` 与 `continue` 前释放——正常走完
  一轮和提前跳出都会释放（与原生 `for` / `while` 相同）。
- **边界是硬错误**：`loop()` 报 `loop needs a count expression`；`loop(3) printf("x");` 报
  `loop body must be a block`；`loop(3, x)` 报
  `loop takes exactly one count; use a native for to name the counter`。
- **遮蔽只判 `loop` 套 `loop`**（D22-5）：内层 `loop` 遮蔽外层隐式 `i` 时，编译模式打印
  `warning: loop shadows the outer 'i'; use a native for to name the inner counter`，
  `ct check` 下记为 `loop_shadow` 错误。体内手写 `int i` 或原生 `for` 是普通 C 遮蔽，不诊断。
- **静态可判定的非整数计数**按实参类型规则（kind 5）告警：编译模式
  `warning: type mismatch: 'loop' count must be an integer (got 'double'); the value is converted to int`，
  `ct check` 下为错误；仍然按 C 规则转成 `int` 运行。类型判不准时保持沉默。
- 生成物是**单行** `for`，不新增逐语句 `#line`，因此生成行号与源行号不保证逐行对齐。
- 双界形式 `loop(a..b)` 见 §4.46（Phase 23）；AST 里 `b == -1` 是单界哨兵。

#### 4.46 `loop(a..b)` 半开区间循环（Phase 23，仅 ct-ast）

`loop(<start>..<stop>) { … }` 是显式起点的计数循环，展开恰好是：

```c
for (int __ct_loop_n_K, __ct_loop_hi_K,
         i = ((__ct_loop_n_K = (<start>)), (__ct_loop_hi_K = (<stop>)), __ct_loop_n_K);
     i < __ct_loop_hi_K; i++) { … }
```

- **区间左闭右开** `[a, b)`：`i` 从 `a` 起、取到 `b - 1`。`b <= a` 零次迭代，不报错、不告警。
  不做反向、不做步长、不做闭区间。
- **两个边界各求值一次，先 `a` 后 `b`**。两个赋值写在 `i` 的**同一个**初始化器里，由逗号运算符
  保证从左到右求值（C99 §6.5.17）；上界存进私有临时量 `__ct_loop_hi_K`，循环中改 `a` / `b`
  读的变量不影响本轮次数。这里**不依赖**同一声明内多个声明符初始化器的求值次序——C99 §6.7.8
  并未规定该次序。
- **`i` 仍是单个可写 `int`**，作用域、`break` / `continue` / `return`、`i--` / `++i`、`own` 的
  释放（块尾、`break` / `continue` 前）全部与 `loop(n)` 相同。闭包在体内按值
  捕获 `i`，每轮一个快照。
- **`loop(0..b)` 与 `loop(b)` 等价**（D23-2）：下界是字面量 `0` 时在解析期折成单界形态，
  生成物逐字节相同。折叠只看 `N_NUM == 0`，不看后缀：`0L..n`、`0x0..n` 也会折叠；
  `-0..n` 与 `0+0..n` **不**折叠（等价于前者，但规则是纯语法的，不做常量折叠）。
- **`..` 是单个 token**：`2..8` 不会被切成浮点 `2.` + `.8`；`...` 仍是三连点 token。
  `loop` 仍是上下文关键字，`int loop = 3;`、`loop:`、`goto loop;` 不受影响。
- **边界必须是整数**：`loop(..b)` / `loop(a..)` 报 `a loop range needs both bounds`；
  `loop(1..2..3)` 报语法错误；指针、数组、`struct` / `union` 值、函数指针作为边界是硬错误
  （`a loop bound must be an integer (got 'int *')`，数组变量为 `(got the array 'a')`，
  数组字段等其他数组形式给出类型串，例如 `(got 'int[2][3]')`）。
  这条对 `loop(n)` 同样生效——Phase 22 里 `loop(arr)` 曾静默通过。
- **静态可判定的非整数标量**（`float` / `double` / `void`）沿用 L22-5：编译模式一条
  `type mismatch` 警告、`ct check` 下为错误，仍按 C 规则转成 `int` 运行。两条边界各报一次。
- **边界存进 `int`（D23-7）**：`i` 与临时量都是 `int`，`size_t` / `long` 超出 `INT_MAX` 的边界
  按 C 的转换规则截断，属已发布语义，本相不改；需要大范围计数的场景请写原生 `for`。
- 生成物是**单行** `for`，不新增逐语句 `#line`。

#### 4.47 数组 range 初值 `a..b($)`（Phase 24，仅 ct-ast）

`int a[] = <start>..<stop>(<表达式>)` 把半开区间按元素表达式展开成花括号初始化列表，
展开**恰好**是把 `$` 依次换成 `((int)k)`：

```c
/* 输入 */  int odd[] = 0..3($ * 2 + 1);
/* 输出 */  int odd[] = { ((((int)0) * 2) + 1), ((((int)1) * 2) + 1), ((((int)2) * 2) + 1) };
```

括号形态由既有 `emit_expr` 决定（每个二元 / 一元运算各加一层括号），本相不另立规则。

- **区间左闭右开** `[start, stop)`：元素个数 = `stop - start`。`stop <= start` 报
  `an empty range has no elements`；个数超过 1024 报 `too many range elements (limit 1024)`。
- **边界只收整数字面量**（可带一元 `-`，十进制 / `0x` / 八进制，后缀仅 `U` / `L`）：
  `0..n($)` 报 `a range bound must be an integer literal (got 'n')`，`0..0x($)` 的文案带
  `got '0x'`（不静默按 0 处理），超出 `long` 报 `a range bound is out of range`，
  `..` 之后直接 `(` 报 `a range initializer needs both bounds`。因为边界是字面量，表达式解析器
  根本不参与边界，`0..13(` 不会被读成函数调用。
- **`$` 是当前成员的占位，不是下标**：在 `a..b(expr)` 里，`$` 绑定为当前序列成员的值 `k`
  （`k` 从 `a` 起，不是 0 起偏移），按元素展开成 `((int)k)`。因此 `2..5($)` 产出 `2 3 4`，
  `1..6($ * $)` 产出 `1 4 9 16 25`；只有 `0..b` 这类从 0 开始的区间，成员值才恰好等于
  0 起偏移。出现在数组维度里
  （`int a[$];`）报 `'$' cannot be used in an array dimension`；被取地址或自增（`&$`、`$++`、`++$`）
  报 `the range index '$' is not a variable`——这是 Phase 24 发布时的**历史措辞**，`$` 并非标识符，
  文案已发布且被精确断言，本文不改诊断文案。在 range/into 之外的表达式位置（`int x = $;`）仍走既有的
  `unexpected token`；语句首的 `$ = …` 按 Phase 40 的 L40-10 报 `'$' is read-only and only valid in
  the trailing block`。**`$` 不是标识符**：不进符号表，也不会与 `loop` 的隐式 `i` 撞名。
  尾随声明块里的 `$` 是声明名的只读别名（§4.58），与 range 的 `$` 按上下文区分。
- **声明必须带 `[]`**：`int x = 0..3($);` 报 `a range initializer declares an array`；
  写了字面量维度就必须等于元素个数（`int a[4] = 0..3($);` 报
  `the array size '4' does not match the range (3 elements)`）。
- **元素限标量**：`struct` / `union` / 接口值 / 数组元素报
  `a range initializer cannot initialize '<type>' elements`。数组元素、接口值的判定与既有
  「可作初值」的规则一致，不走 boxing / vptr 分支。
- **不求值、不循环、不留 `$`**：产物是初始化列表，没有 `for`、没有临时量、没有逐元素节点，
  所以可以用在文件作用域的 `static const` 表上——这是本相的核心收益。
- **元素表达式里不要写副作用**：C99 §6.7.8 不规定同一初始化列表内各初始化器的求值次序，
  本相按元素顺序写出，但不保证运行时求值次序，编译器不诊断。
- **只加这一种初值形态**：不是新类型、不是新表达式、不是新关键字；`ct check` 的 kind 表与
  `--diagnostics=json` 的形状都不变（L24-8「内层 `$` 遮蔽」随 `$` 的引入而撤销，编号不复用）。

#### 4.48 泛型函数（Phase 26，仅 ct-ast）

本节只记述**泛型函数**（Phase 26）的形态；泛型 struct、有界泛型、泛型 trait 与类型参数上的 bound
分别见 §4.51、§4.54、§4.55、§4.50：

```c
T id<T>(T x) {
    return x;
}

int main(void) {
    int a = id<int>(42);
    char *p;
    p = id<char *>("hi");
    printf("%d %s\n", a, p);
    return 0;
}
```

- 声明写作 `T name<T>(形参列表) { 体 }`：返回类型与形参里的 `T` 是占位符，不是注册过的类型名。
- 调用必须在 `< >` 里给出具体类型：`name<int>(...)`。类型实参按 `parse_type` 读取；`void` 以及在
  非泛型上下文把 `T` 自身当类型实参会被拒绝（`'<type>' cannot be a generic type argument`）。
  函数指针与数组类型实参由类型解析先拒绝（分别报 `expected a name in the function-pointer declarator`
  与 `expected '>' after the generic type argument`），不会伪装成 L26-4。
- 同一 `(模板, 具体类型)` 只登记一份实例，C 名为 `<name>__ct<N>`（`N` 从 1 起，按源码中首次出现的
  次序编号）。实例是 `static`，不进入生成的头文件，也不跨单元可见。
- 模板本身**不生成任何 C 符号**：生成物只含实例。实例体内的返回类型、形参、局部声明、`(T)` 转型、
  `sizeof(T)` / `_Alignof(T)`、`sizeof T` / `_Alignof T` / `alignof(T)`、`offsetof(T, ...)`、
  `va_arg(ap, T)` 都按实例的具体类型写出；无括号的类型操作数只吃一个类型名（`sizeof T * 2` 是
  `(sizeof T) * 2`，不是 `sizeof(T *)`）。`struct T` / `union T` / `enum T` 里的 `T` 是标签名，
  不随类型参数替换。
- 只有名字已经是符号表里的模板时，`<` 才被当作类型实参的开头；变量的 `a < b` 仍是比较。
- 诊断：`L26-1` 忘记类型实参 `generic function '<name>' needs a type argument`；`L26-2` 已于 Phase 34
  解禁（`pub T f<T>(T)` 合法，模板体须写在 `.h.ct` 中；旧文案 `generic functions cannot be pub` 仅作历史）；
  `L26-3` 多个类型参数 `only one type parameter is supported`
  （空列表 `<>` 由类型参数解析报 `expected a type parameter name`）；`L26-4` 非法类型实参
  `'<type>' cannot be a generic type argument`；`L26-5` 泛型体内调用泛型
  `recursive generic calls are not supported`。
- 不支持：泛型 union / enum、类型推导（`id(42)` 不会推成 `int`）、泛型函数多个类型参数、递归或嵌套
  泛型调用、跨单元实例共享、类型参数用于数组维度。这些都在源码处硬报错，不静默降级；被替换的类型
  位置（上一条）若拼写不完整，同样在解析期报错而不是原样发射。
  `_Generic(...)` 的选择体是原样透传，因此模板体内 `_Generic` 出现裸类型参数会硬报错
  `type parameter cannot be used inside _Generic`，绝不把它发射成未声明的名字；紧邻 `struct` / `union` /
  `enum` 的标签选择器（`_Generic(x, struct T: 1, default: 0)`）是合法标签，放行。类型参数是类型而非值：
  `return T;`、`h(T)`、`sizeof T * T`、`sizeof T + T` 等值位置一律硬错
  `type parameter 'T' cannot be used as a value`，不会退出 0 发射裸 `T`。数组维度不参与替换，
  维度里出现类型参数一律硬错 `type parameter 'T' cannot be used in an array dimension`；
  模板名离开 `<type>` 作值使用（`int (*p)(int) = id;`）报与 L26-1 相同的
  `generic function '<name>' needs a type argument`，不发射没有 C 符号的名字。

### 7. 容量上限

> 下表是 **L0**（冻结种子）的上限。**ct-ast**（安装入口）把用户可见的上限整体抬高：`MAX_NODES` 262144、
> `MAX_TRAITS` 64、`MAX_STRUCTS` 128、`MAX_METHODS` 64、`MAX_FIELDS` 64、`MAX_FUNCS` 512、
> `MAX_PARAMS` 16、`MAX_VARS` 4096、`MAX_TYPES` 256、`MAX_CALLS` 1024；其余（`MAX_TEXT` / `MAX_PATH` /
> `MAX_SCOPE` / `MAX_UNITS` / `MAX_IMPORTS` / `MAX_MAPS`）不变。策略仍是「固定上限 + 越界硬报错」，未改成动态分配。
>
> `MAX_FUNCS` 是**整个程序**的累计预算：`build` 模式共用一张符号表，`nfunc` 跨单元累加
> （builtin 层经 `nfunc_base` 扣除），不是「每个单元各有一份配额」。越界文案为
> `too many functions (limit 512, whole program)`（依据：`frontend/parse/ParseSupport.h.ct` 的判界点）。
>
> 实现细节（ct-ast）：`MAX_NODES` 是 `selfhost/ct-ast/runtime/arena/Arena.h.ct` 里的宏，只在 `alloc` 判界时使用；
> 而节点数组会随 `pub struct Arena` 进入生成的 `Arena.h`，**宏不跨翻译单元**，所以该字段写的是字面量
> `262144`。两者必须相等，改一处就要同步改另一处。
>
> 契约测试范围（TEST-9）：只对已有生成式夹具的上限把越界文案钉成契约——`MAX_PARAMS` / `MAX_METHODS` /

### 8. 明确不支持

可见性修饰符的完整集合（`pub readonly` / `setter`）、继承、默认编译路径上的全量类型检查、嵌套定义、
模板参数推导、单参数多约束与 supertrait。泛型**函数**（§4.48）、**约束泛型**（§4.50）、
**泛型 struct**（§4.51）、**有界泛型 struct**（§4.54）与**泛型 trait**（§4.55）均已落地，
类型参数最多两个（泛型函数只支持一个），但都不做推导。

另有三类已知边界，写代码时按此规避：

- **自定义下标只做单层、只按名字 + 参数个数匹配**（§4.64）。多级连写 `v["a"]["b"]` 会被当作
  C 指针算术，可能静默得错值；数字下标 `v[0]` 在 `get(char *)` 类型上会展开成 `get(0)`（C 里是
  空指针常量）：`ct compile` / `ct build` 只给 warning（rc=0，产物仍是错调用），`ct check` 给
  error（rc=1，L32-6 / PH-72）。**按键类型分派仍待 `REQ-JSACCESS-1`**（同类型并存 `get(char *)` /
  `get(int)` 各选其版）；JSON 数字下标请继续用包层 `get_idx`，或等 `REQ-JSACCESS-1` 与
  `REQ-INDEX-1`（[设计草案](proposals/user-index-operator.md)）落地。
- **表达式位置的超长字符串**（>158 字节）在 v0.53.1 起是编译期硬错，拆成相邻字面量或写入初始化器；
  不再静默截断。
- **`?.` / `?[` 只接受指针接收者**，结果必须有 `0` 表示（struct 值 / 含 Drop 的值拒绝，L53-3/4）；
  不支持 `T?` / `Maybe<T>`、可选方法调用与 `p?.b = 1`。
（错误恢复是 L0 的边界；CT 线会先收集多个错误再报告，见 §10。）

### 9. 诊断与退出码

- **错误**：格式 `<file>:<line>:<col>: error: <message>`，输出到 `stderr`；L0 **遇错即 `exit(1)`**，
  CT 线则先收集多个错误（§10）。
- **L0 不产生任何警告**；CT 线会输出泄漏警告与签名不一致告警，`--diagnostics` 可切 JSON（§10）。
- **语义类记录的严重级**：调用点 arity / 实参类型 / trait 方法歧义 / impl 签名漂移中，
  `ct build` 只把 **impl 签名漂移**当硬错（退出 `1`、不写 `.c`），其余记录仍是 `warning:`、不改变退出码；
  `ct compile` 全部保持 `warning:`；`ct check` 把同一批记录升为 `error:`，有任何一条即退出 `1`。
  **例外**：静态映射调用点的实参类型（SH-60）是硬错——
  映射单元通常被 `import`，而 `ct check` 只吃单单元，看不到这些调用点；recipe 又会把实参直接拼进
  生成的 C 调用，放行等于把类型错误留给 C 或运行期。
- **运行期契约（Phase 37）**：`ct build --runtime-checks` 在接口派发前检查 vtable；空则带
  `<file>:<line>: runtime check: null vtable in call to '<method>'` abort。默认关闭，关闭时产物不变。
  guard 要求接收者稳定：`--runtime-checks` 下，索引/基址子树含 call/post/pre/assign 或接收者为未物化 call 时，
  编译器以 `error: runtime checks need a stable receiver; bind it to a local first` 拒绝（`arr[0]` / `arr[i]` /
  已 hoist 的 `make()` 放行）；列号沿用 `fail_from` 的 1。详见 [D-003](decisions/D-003.md)。
- 退出码：`0` 成功；`1` 语法 / I/O 错误、`ct check` 下的语义发现，或 `ct build` 的 impl 签名漂移。

### 10. L2 独有：模块系统与诊断（本文不描述其语法）

#### 4.49 `foreach` 语句形态（Phase 27，仅 ct-ast）

`foreach (<数组>) { … item … }` 在一维数组上迭代，块内隐式绑定 `item` 为当前元素的**值拷贝**；
展开恰好是一个普通 `for`，零运行时对象：

```c
/* 输入 */  foreach (nums) { total += item; }
/* 输出 */
{
    int __ct_foreach_n_0 = (int)(sizeof(nums) / sizeof((nums)[0]));
    for (int __ct_foreach_i_0 = 0; __ct_foreach_i_0 < __ct_foreach_n_0; __ct_foreach_i_0++) {
        int item = (nums)[__ct_foreach_i_0];
        (void)item;   /* keeps -Wall -Wextra clean when the body ignores item */
        total += item;
    }
}
```

- **`foreach` 是上下文关键字**（D27-1）：不进关键字表；只有语句位置、且紧跟 `(` 时才特殊。
  `int foreach = 3;`、`foreach:` 标签、`goto foreach;`、`x = foreach + 1;` 仍是普通标识符。
- **集合只收一维数组变量**（D27-3 / D27-11）：元素类型取声明时的元素类型，`item` 按值初始化，
  写 `item` 不回写容器（D27-5）。`item` 在解析期进入符号表，所以名字解析、闭包捕获、遮蔽都看得见它；
  它在集合表达式求值之后才入作用域，`foreach (item)` 引用的是外层同名绑定。
- **长度只求值一次**（D27-7 / D27-9）：`sizeof(x) / sizeof((x)[0])` 赋给私有临时量
  `__ct_foreach_n_K`（`K` 是发射器进程级单调计数器，嵌套天然是 `_1`、`_2`），
  `[5]`、`[]`（初值推导）、`[MAX]`、VLA 都成立；外层加块，两个临时量不泄漏。
- **`break` / `continue` / `return`** 是普通 C 跳转；`break` / `continue` 前释放体内登记的
  autodrop 变量，与 `loop` 同一套机制。
- **遮蔽只判 `foreach` 套 `foreach`**（D27-10）：内层遮蔽外层 `item` 时编译模式打印
  `warning: foreach shadows the outer 'item'; use a native for to name the binding`，
  `ct check` 下升为错误。体内手写同名局部变量与原生 `for` 是普通 C 遮蔽，不诊断。
- **不可迭代形态一律硬错，绝不发射坏 C**：裸指针 / 非数组值报
  `foreach needs an array; '<name>' is not iterable`；多维数组（含 typedef 隐藏的数组元素）报
  `foreach does not support multidimensional arrays ('<name>')`；数组形参在 C 里已是指针、
  长度已丢失，报 `foreach cannot iterate the array parameter '<name>' (its length is lost)`；
  未定长的文件作用域数组报 `foreach needs an array with a known length ('<name>')`；
  数组成员与非标识符集合报 `foreach needs a plain array variable`；函数指针数组等非朴素声明符报
  `foreach cannot iterate '<name>'; its declarator is not a plain array`；接口值元素报
  `foreach cannot copy interface values ('<name>')`。
- **边界**：`foreach ()` 报 `foreach needs a collection expression`；两个集合报
  `foreach takes exactly one collection`；`foreach (a) printf(…);` 报 `foreach body must be a block`。
  `item` 只在该块内可见，块外引用走普通的未声明标识符诊断。
- **不做**（D27-4）：`in` 形式、显式绑定名、迭代器、容器协议（`len()` + `get(int)`）——
  本仓没有 std 容器，协议留给有真实消费者的阶段；非数组容器按上面的 L27-2 拒绝。

#### 4.50 约束泛型（Phase 28，仅 ct-ast）

在 §4.48 的单类型参数上可以写**一个 trait 约束**，模板体内即可直接调用该 trait 的方法：

```c
trait Compare { int cmp(void *other); }

T max2<T: Compare>(T a, T b) {
    if (a.cmp(&b) > 0) { return a; }
    return b;
}

struct Point { int x; } use Compare;
/* impl Compare for Point … */
max2<struct Point>(p, q);     /* → Point_Compare_vtable.cmp(&a, (&b)) */
```

- 语法 `T name<T: Trait>(…)`：单类型参数、单约束、显式实例化；`T: A + B` 报
  `only one trait bound is supported`。约束必须是真实的 `.ct` trait：未声明报
  `unknown trait '<x>' in a generic bound`，`.m.ct` 静态 trait 与内建 `Drop` / `Handback` 报
  `trait '<x>' cannot bound a type parameter`。
- **模板体内派发**：接收者类型等于类型参数时（`x.m(…)`、`p->m(…)`、`arr[i].m(…)`，含 trait 默认方法），
  按约束的方法表解析，arity / 实参按该方法签名检查；约束里没有该方法报
  `trait '<t>' has no method '<m>'`。节点记为「约束调用」，发射期不复制 AST。
- **实例化**：`T` 必须是 struct 或指向 struct 的指针（`struct Point` / `struct Point *`）；
  `int`、`void`、接口等报 `type argument '<x>' cannot satisfy trait '<t>' (not a struct)`；
  没有 `use Trait` 也没有 `impl Trait for S` 报
  `type argument '<s>' does not implement trait '<t>'`。检查在单元解析完成后做，因此 `impl`
  写在调用点之后也算数；`ct check` 与 `ct build` 同文案。
- **落码**：约束调用发成 `<S>_<Trait>_vtable.<m>(&recv, …)`（值接收者）或
  `<S>_<Trait>_vtable.<m>(recv, …)`（指针接收者）——裸 C 调用，不读 `__<trait>_vptr`、不装箱、
  不改结构体布局。实例仍是 `static`，与 §4.48 的命名与可见性一致；跨单元时依赖单元的生成头只新增
  `extern struct <Trait>_vtbl <S>_<Trait>_vtable;`。
- 不支持：多约束、`Self`、约束方法签名里出现类型参数、泛型函数 `pub`、跨单元实例共享、装箱；
  参数化 trait 作约束由 §4.55 承接。**`char *` 不能直接满足约束**（`impl` 只对 struct 生效）；
  需要字符串语义时用一个 `struct` 包住指针，见 `examples/21_generic_bound` 的 `Word`。
  泛型 struct 见 §4.51。

### 4.51 泛型 struct、固有方法与内置容器（Phase 29）

- **声明**：`struct Name<T, U> { … }`，最多两个类型参数。类型参数可以出现在字段类型的任意位置
  （裸 `T`、`T *`、`T items[N]`）。
- **实例化**：使用点写 `Name<Arg[, Arg]>`（`struct` 前缀可有可无）。每个 `(模板, 实参组合)`
  生成一个独立的 C struct，标签是编码拼写 `<Name>_<arg1>[_<arg2>]`：`*`→`_p`、空格→`_`、
  `_`→`__`、`<`→`_l`、`>`→`_r`、`,`→`_c`。类型位里的 `>>` 自动拆成两个闭合
  （`Box<Box<int>>` 合法）。只发射**可达**实例：源文件里出现过的实例才落码；同一实例在整个
  构建里只有一份定义，由**模板所在单元**发布到生成头，其他单元只引用。
- **固有方法**：`impl<T> Name<Args> { … }` 给实例加方法，落码 `<Instance>_<method>`，调用点
  **静态派发**（`v.push(3)` → `Vec_int_push(&v, 3)`），不生成 vtable、不装箱；同一实例可同时有
  多个 `impl` 块。实参默认只检查元数；`ct check --types` 会额外检查类型（L32-6），
  `ct build` / `ct compile` 仍不检查（`docs/history/design/phase29.md` §10.2）。
- **`.` 与 `->`（PH-51，仅 ct-ast）**：结构体指针作为方法接收者必须用 `->`；`.` 是硬错 L51-1
  （`'.' cannot call method 'f' through a pointer receiver; use '->f()'`），不会再发射 `S_f(&p)` /
  `Vec_int_push(&p, …)`。值接收者的 `.`、接口指针的 `.`（`Show *p; p.m()`，按接口值派发）与
  类型宿主（`map … for type`，含 `char *`）的 `.` 都不受影响。
- **带 `use` 的泛型 impl**：`impl<T> Stack<T> use Show { … }` 落码 `<Instance>_<Trait>_<method>`
  与 `<Instance>_<Trait>_vtable`，沿用既有 trait / vptr 路径；固有方法优先于 trait 方法。
- **静态固有方法与 range 初值构造（Phase 29 P29 补丁）**：`impl` 体内可写
  `static Ret name(params)`，落码 `<Instance>_<name>` 且**没有** `self` 参数，泛型实例的调用面是
  `Type<Args>::name(args)`；**非泛型 struct 的静态方法用 `Type.name(args)`**（`Counter.make()`），
  写 `Counter::make()` 会报 `no function`。`static` 只能进固有 impl，带 `use` 的泛型 impl 与经典
  `impl Trait for Struct` 里都是硬错（vtable 槽位没有接收者）。
  **v0.53.2 起**接收者按与类型解析相同的规则解析：`namespace lib;` 里声明的 `Box` 在单元内写
  `Box.make(...)` 即可，跨单元 `import lib::lib;` 后同样写裸名 `Box.make(...)`（落码
  `lib_Box_make`），不再报 `use of an undeclared variable`；不存在的类型名仍是硬错。
  `Vec<T>` 因此有 `Vec<T>::from(T *items, int n)`（复制 `n` 个元素）。声明初值
  `a..b { expr }` 与 Phase 24 的 `a..b(expr)` 同义；当声明类型是 `Vec<T>` 时，range 是
  「产物为静态数组」的表达式，降级为 `Vec_<enc>_from((T[n]){ … }, n)`，因此
  `Vec<int> v = 4..8 { $ * $ };` 合法。编译器只知道入口名与元素 C 类型，**不认识 `Vec` 的字段**
  （`docs/history/design/phase29.md` §11）。
- **内置容器下标与字面量（Phase 31 起）**：`v[i]` 发射为 `v.get(i)`、`v[i] = x` 发射为
  `v.set(i, x)`；`m["k"]` 发射为 `m.get("k")`（取元素值，越界/缺键得零值或空指针），
  `m["k"] = x` 发射为 `m.put("k", x)`；`Map<K,V> m = { "a": 1, "b": 2 };` 发射为
  `Map_<enc>_from((struct MapEntry_<enc>[2]){ … }, 2)`。三者都受上面的容器语义约束；
  不再有「Vec/Map 不可下标」的硬错。
- **自定义类型的 `[]`**：见 §4.64（PH-52，单层字符串键）；按键类型分派（同一类型并存
  `get(char *)` / `get(int)`）**尚未实现**，登记为 REQ-JSACCESS-1，不属于本节的容器下标糖。
  实参类型与唯一 `get` 不匹配时，`ct check` 已是硬错（PH-72 / LANG-4），`ct build` 仍只告警并
  发射 `get(0)`，因此不要把 `v[0]` 用在 `char *get(char *)` 上。
- **内置层**：`Vec<T>`、`Map<K,V>`、`MapEntry<K,V>` 写在 `lib/std/Vec.h.ct`，编译模式在输入前
  自动预解析，`ct build` 也把它作为一个单元自动加载，**两种模式都不需要 `import`、不需要 `-I`**。
  三个拼写是保留名，用户不能再声明同名 struct；旧项目里 `import std::vec` 带来的 `Vec` 定义会与
  内置名冲突（`'Vec' is a built-in type and cannot be redeclared`），须升级 `std` 包或删掉该 import。
- **`pub` 泛型函数（Phase 34）**：`pub T f<T>(T x)` 合法（L26-2 已解禁），模板体必须写在 `.h.ct`
  头单元里；消费方的每个 `f<int>(…)` 在本单元发一个 `static` 实例（`f__ct<N>`），生成 `.h`
  只放类型、不放函数原型。`.ct` 单元里的 `pub` 声明仍不可被 import（`only a .h.ct unit can be
  imported`）。
- **非泛型固有 `impl Name { … }`（Phase 34）**：`impl` 后面既没有类型参数、也没有 `for`，就是给
  非泛型 struct 加固有方法；方法落码 `<Struct>_<method>`、调用点静态派发。属主单元发一次定义
  （外部链接），消费方从生成的 `.h` 取 `int Counter_get(struct Counter *);` 原型，自己不重复定义。
  跨单元重复定义不在解析期检测，落到链接期的重复符号（R34-4）。
- **`Option` / `Result`（Phase 34）**：`lib/std/Option.h.ct` 提供 `Option<T>`（`int has; T value;`），
  `lib/std/Result.h.ct` 提供 `Result<T, E>`（`int ok; T value; E err;`）；两者都是普通泛型 struct，
  编译器没有专门分支。构造用字面量：`{ 1, v }` / `{ 0 }`（`Result` 是 `{ 1, v, 0 }` / `{ 0, 0, e }`）。
  `Option` 的方法是 `is_some` / `is_none` / `unwrap_or` / `unwrap` / `set` / `clear` / `release`；
  `Result` 是 `is_ok` / `is_err` / `unwrap_or` / `unwrap_err_or` / `unwrap` / `unwrap_err` /
  `set_ok` / `set_err` / `release`。`unwrap` / `unwrap_err` 在错误一侧 `abort`，不返回零值。
  当实参是消费方单元里的 struct 时，`Option<X>` / `Result<X, …>` 的布局与方法都在消费方发射
  （层头文件里字段不完整，只留前向声明）；标量实参的实例仍定义在层头文件里。payload 按值拷贝，
  `release` 是 no-op；自动释放与 pattern matching 属后续阶段（D34-8 / T34-1）。
- **`Map` 的键**：只接受 `int` / `long` / `char *` / `Str`，其他类型在类型实参处硬错（L29-8 / L47-1，
  文案列出四类键）。`int` / `long` 按键的字节比较，`char *` 走 `strcmp`（**借用**调用方指针），
  `Str` 按 `len` 加 `memcmp` 比较恰好 `len` 字节（内嵌 `\0` 不截断、不碰撞），并在 `put` 时
  **深拷贝**键、在覆盖写 / `remove` / `release` 时各释放一次；三份实现是
  `lib/std/Vec.h.ct` 里的三个 `impl` 块，不靠 `sizeof` 猜测键的类别。`foreach` 暴露的 `Str` 键是
  **借用**，**不得 release 键**（条目仍拥有它，D47-6）。
- **容器语义**：`Vec` / `Map` 是引用计数的句柄（共享 `ct_buf`），`retain` 增加、`release` 减少并
  返回剩余计数，归零时释放。`release` 之后该句柄即失效：对同一句柄再次 `release` 是硬错（`abort`），
  即使共享缓冲还被 `retain` 出的兄弟句柄持有，也不会把计数再减一次。`Vec.get` / `Map.get`
  越界或未命中返回零值 / 空指针，`set` 越界是 no-op。`Map` 按**插入序**遍历，重复键原位改值，
  `remove` 让后继条目左移。
- **`has` / `at`（Phase 50，D50-1/2/3）**：`Vec<T>::has(i) -> int` 与
  `Vec<T>::at(i) -> T *`，`Map<K,V>::has(k) -> int`（`int` / `char *` / `Str` 三份键实现）。
  `has` 只判存在（`at` 是否非 `0` 与它一致）；`at` 命中返回**借用指针**，未命中返回 `0`，
  不用零值哨兵——因此「元素值恰好是 0」与「越界/缺键」可区分。**`get` 的签名与语义不变**。
  借用指针不复制元素、不增加引用，在容器被修改或 `release` 后失效；调用方不得 `release` 它，
  容器只认元素自己的 `retain`/`release` 协议，`release` 不额外递归释放元素。
- **`foreach` 容器协议**：数组与 `Vec` 同时绑定 `item`（元素的值拷贝）与只读 `i`；`Map` 只绑定
  `item`，它是 `MapEntry`，用 `item.key` / `item.value` 读写。长度在循环开始前取一次。对 `i`
  赋值 / 自增 / 取地址是硬错（L29-16），循环体内重声明 `item` 或 `i` 是硬错（L29-17），
  在 `Map` 体内使用 `i` 是硬错（L29-18）；容器元素与接口值不能按值拷贝（L29-15）。
- **本节不涉及**：默认类型实参、显式实例列表；参数化 trait 见 §4.55，类型参数上的 bound 见 §4.54。
  已知偏差（`Map` 线性扫描、无哈希
  索引）见 `docs/history/design/phase29.md` §10.2。

### 4.52 接收者上下文块 `expr into { … }`（Phase 30，仅 ct-ast）

`into` 是**上下文关键字**：`int into = 1;` 仍是普通变量，只有「表达式 + `into {`」才起块。

```c
struct ServerConfig *cfg = config_new();
cfg into {
    .host = "0.0.0.0";
    .port = 8080;
    report($);              /* $ = 接收者 */
};
int port = cfg into { .backlog = 64; } ->port;   /* 后缀属于整个表达式 */
struct ServerConfig copy = live into { .port = 9090; };  /* 左值：直接改 live，再把结果赋给 copy */
```

- **接收者**：任意值或指针表达式；块内 `.field = expr;` 是字段赋值，`$` 指代接收者本身。
- **指针接收者**：直接修改原对象，块的值仍是指针；`cfg into { … }` 之后 `cfg->port` 已变。
- **值接收者**：若接收者是**左值**（变量 / 字段 / 元素），`into` 直接改这个左值本身，结果是它，
  因此 `live` 与 `copy` 都会变成 9090；若接收者是**右值**（函数返回、字面量），ct-ast 先落
  `__ct_recvN` 临时量再改，原对象不受影响。需要保留原值时先显式复制一份再 `into`。
- **后缀**：`into { … }` 后可接 `.field`、`->field`、`[i]`、`(args)`、`++`、`--`，作用于整个块的结果。
- **字段检查**：`.name` 必须是接收者类型的直接字段；拼错报 L30-5。嵌套字段请写后缀链
  （`.a` 后再 `->b`），块内不写 `.a.b`。
- **禁止**：接口值或 `own` 变量作接收者（L30-4）；同一块内再写 `into`（L30-7）；
  `a + b into { … }` 只有紧邻的那个表达式能作接收者（L30-2）；`f(x into { … })` 需给接收者加括号（L30-1）。
- 空块合法，返回接收者本身（左值即该对象；右值即临时量）。

### 4.52.1 内置容器方法速查

| 容器 | 方法（`Type<Args>::` 为静态调用；其余为实例方法） |
| --- | --- |
| `Vec<T>` | `Vec<T>::from(T *items, int n)`、`len()`、`get(int) -> T`、`has(int) -> int`、`at(int) -> T *`、`set(int, T)`、`push(T) -> int`、`pop() -> T`、`clear()`、`retain() -> Vec<T>`、`release() -> int` |
| `Map<K,V>` | `Map<K,V>::from(MapEntry<K,V> *items, int n)`、`len()`、`put(K, V) -> int`、`get(K) -> V *`、`has(K) -> int`、`remove(K) -> int`、`entry(int) -> MapEntry<K,V>`、`clear()`、`retain() -> Map<K,V>`、`release() -> int` |

`get` 返回指针（未命中为 `0`）；下标糖 `v[i]` / `m[k]` 取的是元素值，越界 / 缺键得零值。

### 4.53 可选类型检查 `ct check --types`（Phase 32）

- **开关**：`ct check --types` 只在三处做粗粒度类型校验——声明初值 / 赋值（含 `into` 块里的
  `.field = expr`）、`return`、容器与泛型固有方法的实参。不带 `--types` 的 `ct check`、以及
  `ct build` / `ct compile` 的输出、诊断和 golden 逐字节不变。`--types` 与别的子命令组合报
  `ctc: --types is only valid with 'ct check'` 并退出 1；这是 CLI 诊断（L32-7），不是源码诊断。
- **判定内核**：复用 19.2 的 `arg_class`。两侧都是指针时比较**基类型与层数**：同层不同基类型、
  不同星数是硬错；`void *` ↔ 任意对象指针、裸 `0`、typedef、数组、闭包、函数指针仍跳过。
  算术类内部一律兼容（`int x = 1.5`、`long n = 1` 不报）；接口槽仍走既有装箱路径；
  不同 struct 之间、算术类与实际为指针之间是硬错。
- **判不出就跳过**：数组、函数指针、`void` 实际值，以及 `sizeof` / `_Generic` / 宏等
  静态类型判不出的位置一律静默；闭包块体内的 `return` 按 §4.53 契约静默（闭包没有自己的
  `ret_type`，不按外层函数判）；跨单元函数体与 `import` 单元不检查。
- **文案**（统一 `file:line:col`，列指向表达式起点；L32-6 指向出错实参的起点）：

  | 编号 | 文案 |
  | --- | --- |
  | L32-1 | `initializer: expected '<T>', got '<U>'` |
  | L32-2 | `assignment: expected '<T>', got '<U>'` |
  | L32-3 | `return: expected '<T>', got '<U>'` |
  | L32-4 | `return: missing a value (function returns '<T>')` |
  | L32-5 | `return: a value is not allowed in a void function` |
  | L32-6 | `argument <n>: expected '<T>', got '<U>'` |

- **容器实参**：固有方法调用先按接收者实例行把 impl 的类型参数绑定到具体 C 实参，再对形参做
  受限替换（裸 `T` / `U` 与 `T *` / `U *`），不按 `Vec` / `Map` 名字分支；用户泛型
  `Pair<A, B>` 走同一条路径。
- **严格模式**：新诊断经 `ct_type_warn` 记录，`ct check` 的 strict 模式把 warning 升级为
  `error` 并让退出码非 0；`ct build` / `ct compile` 不进入这些判定。

### 4.54 有界泛型 struct 与嵌套 impl pattern（Phase 33）

- **声明**：`struct Box<T: Show> { … }` 给类型参数一个 trait 约束，约束与参数按位置对齐；每个参数
  最多一个，`T: A + B` 报 `a struct type parameter cannot carry more than one bound`。约束名在声明期
  只是拼写，不要求本单元可见；`Drop` / `Handback` 与 `.m.ct` 静态 trait 按名拒绝（沿用
  `trait '<x>' cannot bound a type parameter`）。
- **实例化校验**：写出实例的单元在解析完整单元后逐实例校验。实参要么在 `use` 列表里，要么有
  `impl Trait for <实参>`（`impl` 写在实例之后也算数）；实参本身是模板实例时，其模板 tag 上的
  `impl` 同样算数。不满足报一条 `instance argument '<arg>' does not satisfy the bound '<trait>'`，
  位置指向实例化处的实参。
- **约束可见性**：实例创建单元看不到约束 trait 时报 `unknown trait '<trait>' in a generic bound`，
  不静默通过、不落到链接错；只声明不实例化的 `struct Box<T: Nope>` 仍退出 0。
- **impl 继承约束**：`impl<T> Box<T>` 的方法体按位置继承 struct 的约束，`self->v.show()` 在编译期
  静态派发为 `<实参>_<Trait>_vtable.show(…)`；约束不引入 vptr、不装箱、不改结构体布局。impl 上
  再写 `impl<T: Show> Box<T>` 报 `impl type parameter 'T' cannot repeat the bound 'Show'`。
- **嵌套 impl pattern**：`impl<T> Box<Box<T>>`、`impl<T> Pair<int, Box<T>>`、
  `impl<T> Pair<T, Box<T>>` 按结构递归匹配，自内向外绑定；同名类型参数在 pattern 里出现两次必须
  绑到同一实参（`Pair<int, Box<long>>` 不匹配）。pattern 里的裸类型参数不经过 `parse_type`、不登记
  伪实例：`Box<Box<T>>` 不会产生 `struct Box_T`。
- **深度与形态**：depth = pattern 里 `Box` 的个数 − 1；`depth > 4` 报
  `impl pattern nesting exceeds 4 levels`，位置指向最内层 `<`。通配 `_`、数组 `T[2]`、指针尾缀
  `T *`、函数指针与 `&` 实参报 `unsupported impl pattern '<pat>'`；具体指针实参（既有的
  `impl<V> Map<char *, V>`）不受影响。`depth ≤ 4` 的 pattern 只在 impl 语法里成立，不是可实例化的
  具体类型（`type_depth > 4` 仍拒绝）。
- **跨单元单态化（Phase 31 T31-2）**：消费方单元实例化 `Vec<T>` / `Map<K, V>` 且元素 owner 与容器
  模板 owner 不同时，该单元的 `.c` 发射私有的 `static` 元素 helper 与实例方法副本；`.h` 只保留类型，
  vtable 与实例数据留在 owner 单元，所以两个消费方不会在链接期撞名。
- **元素完整性（Phase 46）**：`Map<K, V>` 的 `V` 是用户 struct 时，嵌套的
  `struct MapEntry_<K,V>` 完整定义下沉到实际使用该 `Map` 的翻译单元；层头只留
  `struct MapEntry_<K,V>;` 前置声明，`ct build` 不再因 incomplete type 失败。`Map` API、
  `MapEntry` 字段与布局不变，且不产生新的链接符号。
- 泛型 trait 由 §4.55 承接；本相只支持非泛型 trait 作约束。

### 4.55 泛型 trait（Phase 35，仅 ct-ast）

- **声明**：`trait Iter<T> { T next(void); }` 最多两个类型参数，参数可各带一个 bound（`trait Seq<T: Show>`）；一个参数写多个 bound 报 `a type parameter supports one trait bound`。泛型 trait 不支持默认方法体，报 `a generic trait cannot carry a default method body`。
- **单态化命名**：实例名一律 `<Trait>_<ct_inst_encode 输出>`，产物随之变成 `Iter<int>` → `Iter_int_vtbl` / `Iter_int_iface` / `__iter_int_vptr` / `Circle_Iter_int_next` / `Circle_Iter_int_vtable`；`Iter<char *>` → `Iter_char_p_*`；嵌套实参按转义（`Iter<Vec<int>>` → `Iter_Vec_lint_r_*`）；编码达到 64 字符时退化为 40 字符前缀 + 8 位哈希。非泛型 trait 的产物命名与布局逐字节不变。
- **impl 与使用**：`impl Iter<int> for Circle { … }`；接口值、字段、形参与 `T: Iter<int>` 约束都按实例行处理，实例的方法签名在创建实例时把 `T` 换成实参的 C 拼写，派发仍走既有 vtable 槽。
- **约束**：`trait Seq<T: Show>` 在实例创建单元校验实参的 `use` / `impl`（与 §4.54 同一套判据），不满足报 `'int' does not satisfy the bound 'Show' of 'Seq'`。
- **泛型 trait × 泛型 struct**：只支持参数一一对应的 `impl<T> MyVec<T> use Iter<T>`，其它形态报 `unsupported generic trait implementation shape`。
- **跨单元边界**：泛型 trait 实例只能在模板属主单元创建；消费方可以命名该类型，但创建实例即报 `a generic trait instance must be created in its owner unit`（L35-4）。
- **冲突与容量**：编码名与已声明的 trait、`struct <I>_vtbl` 或 `struct <I>_iface` 撞名时报 `trait instance name '<I>' collides with a declared type`；模板行与实例行共用 `MAX_TRAITS = 64`，第 65 条报 `too many traits`。
- **不做**：supertrait / 接口组合（开放项与触发条件见 [phase35 卡](history/design/phase35.md) §10.2 / §10.3）、默认方法体、多 bound、关联类型、`Self`、方法级泛型与泛型 enum。

### 4.56 `Drop` 与长度前缀字符串 `Str`（Phase 36，仅 ct-ast）

- **`Drop` trait**：`use Drop` 只置位、不进 `use[]` 列表；`delete p` 调用 `<S>_Drop_drop(p)`，无 vtable/vptr。无显式 `impl Drop` 时，编译器按字段**声明顺序**为每个 `uses_drop` 字段递归生成释放胶水；写了显式 `impl Drop for S`（或 `impl<T> Drop for Box<T>`）即**自负全责**，不再生成字段胶水，需在体里手动释放资源。
- **指针字段胶水（PH-48）**：自动胶水对指针字段写 `if (_self->f) Child_Drop_drop(_self->f);`——判空、把子对象传给它的 Drop，**不取字段地址、也不 `free` 子指针**；所有权仍归显式 `impl Drop`。值字段仍是 `Child_Drop_drop(&_self->f)`。多星指针与带维度的指针数组不递归（没有单一子对象可传），由显式 impl 负责。
- **跨单元 `Drop`（PH-48，D48-2 / U-2 A）**：Drop 体只由**声明该 struct 的单元**发射一次，链接性独立于 `pub`（默认可见）；该单元的生成头文件发布真原型 `void <S>_Drop_drop(void *);`，消费单元只发 `extern` 声明并调用它。`impl Drop for S` 必须写在 struct 的同一单元：写在别的单元时类型头没有原型，构建在写任何 `.c` 之前硬错 L48-2（`Drop body for 'struct Res' is not visible through its header`），不再生成静默空桩。显式 `impl` 仍负责释放子指针。
- **泛型 Drop**：`impl<T> Drop for Box<T>` 每实例单态化出一个 `Box_int_Drop_drop` / `Box_Str_Drop_drop`，不产生模板态 `Box_Drop_drop`；声明在首次使用之后仍生效（impl 在 emit 阶段解析）。容器元素协议（Phase 31）对普通 struct 同样生效：`Vec<Str>` / `Vec<Probe>` 的 `release()` 会调用元素的 `release()`。
- **重复释放诊断**：`drop()` 体内同一 `self` 字段不得 `release()` 两次，报 `field 'X' is released more than once in drop()`。
- **`Str`**：内建于 `lib/std/Str.h.ct`，布局 `{ char *data; int len; }`，`len` 是契约（保留内嵌 `\0`，不依赖结尾 NUL）。API：`str_from(s)` / `str_from_len(p, n)` / `str_len(s)` / `str_slice(s, start, n)` / `str_concat(a, b)` / `str_compare(a, b)` / `str_c_str(s)`；方法 `retain()` 深拷贝、`release()` 释放并置 `data=0,len=-1`。`impl Drop for Str` 释放 buffer；`free(0)` 是 no-op，故零值 `Str` 可安全 drop。
- **所有权形态**：`Str` 是值句柄，按值传递浅拷贝指针（不自动深拷贝，需显式 `retain()`）；`own Str *p = malloc(sizeof(struct Str)); ...; delete p;` 由 `Drop` 释放 buffer 再 free 结构体并置空指针。`Option<T>` / `Result<T,E>` 已加 `use Drop`，其 `none()` / `ok()` / `err()` 工厂零初始化未使用的 payload，使无条件胶水安全释放。
- **与 std 包 `String` 的关系**：`std::str::String` 是挂在 `char *` 上的方法层 trait（由外部 `std` 包提供 `String.m.ct`），
  不是 `Str` 的子类型、别名或构造器；本仓内建 `Str` 是长度前缀的低层值句柄，二者不重复、无继承关系。
  `String` 改名为 `CStrOps` 归 ct-pkg `std` 侧处置，CT 侧只在包发版后同步 §5.1 的保留名，不改 `Str`。

### 4.57 C ABI 静态库（`ct build --lib`，Phase 39，仅 ct-ast）

- **入口**：`ct build --lib [-o <archive>] [--outdir <dir>] <root.h.ct>`；`--lib` 只允许 `build`，与 `--emit-c` 互斥，`compile` / `check` 下报 usage 错误。
- **导出面**：只取根 `.h.ct` 单元内有定义、带 `pub` 的函数。签名只允许内建标量、`void`、指针（含具名 struct 指针 / 函数指针）、数组参数（decay 成指针）；按值 struct/union、trait/接口值、`Vec`/`Map`/`Option`/`Result`/`Str`、`own` 报 `'<name>' cannot be exported: <reason>`（L39-1）。泛型模板不导出，报 `'<name>' not exported: generic template has no external symbol`（L39-1w），构建继续。
- **硬错**：根不是 `.h.ct` 或没有候选（L39-2）；含 `main`（L39-3）；含 `pub` 全局（L39-4）；含带 C shim 的 `.m.ct`（L39-5）。L39-1/2/3/4/5 都带 `文件:行:列`，不写 `.a` / `.abi.h`。
- **非根 `pub`**：被 import 单元的 `pub` 与根内 `pub extern` 不进入 ABI，只给 `<n> pub function(s) are not part of the ABI surface (imported or extern)` 汇总警告（L39-6）。
- **产物**：`<outdir>/<base>.abi.h` 含 banner、`<BASE>_ABI_VERSION 1`、导出名排序后的 FNV-1a `<BASE>_ABI_HASH`、导出签名用到的 `struct X;` 前置声明与 C 符号原型；`-o` 指定归档，缺省 `<outdir>/lib<base>.a`。ABI 头不出现 `_iface` / `_vtbl` / `Vec_` / `Map_` / `Str_`。
- **可见性**：`--lib` 下非 `pub` 顶层函数/全局发 `static`；根导出定义前恰一个 `__attribute__((visibility("default")))`；中间对象以 `-fvisibility=hidden` 编译。
- **契约边界**：归档 `nm -g` 面可能大于导出面（内建 `Str_*`、vtable 等内部符号）；**只有 `.abi.h` 的声明是 ABI**。归档确定性由 `ar rcsD` / `ZERO_AR_DATE=1 ar rcs` 回退保证。

### 4.58 `errdefer`、`err:` 错误出口与尾随声明（Phase 40，仅 ct-ast）

- **错误出口**：`return err: expr;` / `return err:;`（仅 void）/ `break err:;` / `continue err:;`。`err:` 只在 `return` / `break` / `continue` 之后识别；其它位置 `err` 仍是普通标识符。非 void 写 `return err:;` 报 `an error return needs a value`（L40-1），void 写值报 `a void function cannot return a value`（L40-2），循环外报 L40-3，`switch` 内 `break err:` 报 L40-4。
- **errdefer**：`errdefer { … }` 与 `defer` 共用同一条块栈；条目带 `on_error`，只在错误出口执行。普通 `return` / `break` / `continue` / 落出只跑 `defer`，丢弃 `errdefer`。`return err` 跑函数内全部活跃条目，`break err` / `continue err` 只跑退出到的那层块；单栈 LIFO（不按种类分段）。**触发只看出口形态，不看返回值**：`return err: 7;` 触发，`return 7;`（Ok 路径）与 `return -1;`（普通返回）都不触发——后者不是错误出口。
- **边界**：`switch`、文件作用域禁止 errdefer（L40-5）；errdefer 内禁止控制转移和嵌套 `defer` / `errdefer`（L40-6）；`own` 变量出现在 errdefer 或 errdefer 内声明 `own` 都报 L40-7；`goto` 跨带 errdefer 的块报 L40-8。**v0.53.2 起** `.h.ct` 单元的函数体内允许 `errdefer`（原 L40-5 的后缀限制已撤销，见 §4.9）。
- **尾随声明**：`Type name = expr defer { … };` / `errdefer { … };` 只允许单声明符；`$` 是 `name` 的只读别名，块内可直接写名字。赋值形式、多声明符、`for` 初始化报 L40-9；语句首 `$ = …` 或对 `$` 赋值报 L40-10，range/into 之外的其它表达式位置仍沿用既有 `unexpected token`。尾随块在初始值之后注册，初始值可能失败时由作者在块内 guard（如 `if ($) …`）；尾随块内声明与 `$` 同名变量会报 `a trailing block cannot shadow the '$' name`。
- **不做**：`Result` / `?` / 异常、`goto err:`、错误传播、函数级错误标志、赋值形式尾随、多声明符尾随（开放项 T40-1…T40-5）。

### 4.59 `atomic` 原子修饰符与 `ct_atomic_*`（Phase 41，仅 ct-ast）

`atomic` 是**上下文类型修饰**：只有后跟 `int` / `long` / `void *` / `bool` 时才是类型；`int atomic = 1;`
和单独的 `atomic;` 仍是普通标识符。四种写法映射到 C11 `_Atomic(T)`：

| CT | 生成 C |
| --- | --- |
| `atomic int` | `_Atomic(int)` |
| `atomic long` | `_Atomic(long)` |
| `atomic bool` | `_Atomic(_Bool)` |
| `atomic void *` | `_Atomic(void *)` |
| `atomic int *` | `_Atomic(int) *`（指向原子 int 的普通指针） |

原子操作是内建名 `ct_atomic_load` / `ct_atomic_store` / `ct_atomic_cas`，一律 seq_cst：

```ct
atomic int hits = 0;
int expected = 0;

ct_atomic_store(&hits, 1);
int v = ct_atomic_load(&hits);
if (!ct_atomic_cas(&hits, &expected, v + 1))
    return 1;
```

- 第一实参的静态类型必须是 `_Atomic(T) *`；`&x` 与 `_Atomic(T) *p` 都接受。
- `ct_atomic_cas(&x, &expected, desired)` 的 `expected` 必须按地址传入；失败时写回实际值。
- 生成物带 CT 自带的 12 个 `static inline` 助手（仅在实际用到原子操作时发射），内部调用
  `__atomic_*`；不注入 `<stdatomic.h>`。
- **C11 要求**：`_Atomic` 是 C11 类型。`ct build` 在存在原子单元时使用 `-std=c11`；`ct compile`
  的用户需自行以 `-std=c11` 编译生成的 C。
- `atomic_load` / `atomic_store` / `<stdatomic.h>` 仍按普通 C 调用直通，不被占用；`atomic` 不是
  无条件关键字，`atomic char` 报 L41-1，`atomic _Atomic(int)` 报 L41-8，原子返回类型 / typedef
  目标报 L41-6，`own atomic` 报 L41-3，by-value CAS 报 L41-5。
- 原子类型只支持上述四种基类型；`atomic struct` / 原子容器元素 / 原子返回类型是开放项。

### 4.60 `impl` 方法可见性：方法级 `pub`，默认私有（Phase 42，仅 ct-ast）

`impl` 块里的固有方法默认**私有**；写 `pub` 才进 `.h`、才有外部链接、才允许跨单元调用：

```ct
pub struct Counter {
    int n;
}
impl Counter {
    pub int get() { return self.n; }
    pub static Counter make(int n) { Counter c; c.n = n; return c; }
    static pub int zero() { return 0; }
    int secret() { return self.n; }       /* 私有：同单元可调 */
}
```

- `pub` 只允许在 `.h.ct` 单元的 `pub struct` 固有 `impl` 方法上；`.ct` 单元 / 私有 struct 报 L42-1。
- trait impl（`impl Trait for S`）的方法写 `pub` 报 L42-2；块级 `pub impl` 报 L42-3。
- 私有方法：不进 `.h`，定义发 `static __attribute__((unused))`；同单元调用允许，跨单元调用 L42-4（实例）/ L42-5（静态）。
- 模板固有方法同规则：`exported = 模板 pub && 属主 .h.ct && 方法 pub`；foreign-element 副本恒 `static`。
- 元素协议 `retain` / `release` 不按名字自动公开；跨单元/foreign 元素调用未 `pub` 的方法报 L42-6。
- `drop` / `handback` 是 trait impl / static，不参与方法可见性；字段可见性仍随 struct。

### 4.61 `return err:` 载荷类型契约（Phase 43，仅 ct-ast）

`return err: expr;` 的 `expr` 必须可赋给当前函数的返回类型；不一致是 **L43-1 硬错**，
`ct build` / `ct compile` / `ct check` / `ct check --types` 四入口一致，且 `ct compile` 不写 `.c`：

```ct
Result<int, char *> f(int n)
{
    if (n < 0) return err: 1;              /* L43-1: expected struct Result_int_char_p, got int */
    return (Result<int, char *>){ 1, n, 0 };
}
```

- 文案：`return: expected '<T>', got '<U>'`，位置在载荷表达式起点。
- 只判 `err:` 分支；普通 `return` 仍只在 `--types` 下检查（避免闭包 `ret_type` 的既有假阳性）。
- 复用 PH-32 的豁免：接口槽、裸 `0` 填指针；指针基类型/层数按 §4.53 判（PH-45 起）。
- 判不出的形态（数组 / 闭包 / 函数指针 / `sizeof` / `_Generic` / 宏）仍交 `cc`；闭包体
  `return err:` 的 `ret_type` 缺陷按 PH-43 §0.2 另案记录。
- 发射与清理不变：仍走 PH-40 的临时量、errdefer/defer 单栈 LIFO。

### 4.62 后缀 `?` 错误传播（Phase 44，仅 ct-ast）

`expr?` 要求 `expr` 是 `Result<T, E>`；外层函数必须返回 `Result<U, E>`（或 `void`）。
成功时表达式类型是 `T`，失败时立即以 `Outer::err(inner.err)` 返回：

```ct
Result<int, char *> parse(int n)
{
    if (n < 0) return err: (Result<int, char *>){ 0, 0, "negative" };
    return (Result<int, char *>){ 1, n, 0 };
}

Result<long, char *> twice(int n)
{
    long v = parse(n)?;                    /* 失败时返回 Outer::err */
    return (Result<long, char *>){ 1, v + 1, 0 };
}
```

- 消歧：`?` 后不能开始表达式（`;` `)` `,` `]` `->` 等）才是后缀；`a ? b : c` 仍是三目。
- 诊断：L44-1 外层不是 `Result`；L44-2 `E` 不同；L44-3 操作数不是 `Result`。
- 禁止位置：`if`/`while`/`for`/`switch` 条件、`&&`/`||` 右操作数、三目两侧、闭包体、`defer`/`errdefer` 块、文件作用域（L44-4）。
- 失败分支走既有清理链：`errdefer` → `defer` → `own` release；临时量 move 后清零，丢弃的 payload 调 `release`/Drop glue（ASAN 夹具 `p44_try_drop.sh`）。同一表达式多个 `?` 各求值一次，但顺序仍受 C 操作数顺序约束（PH-44 §9 记录）。

### 4.63 类型契约一致性（Phase 45，仅 ct-ast）

- 闭包块体内的 `return` 不再读外层 `ret_type`；`ct check --types` 对闭包体保持静默
  （闭包返回类型推断仍是独立缺陷，见 PH-43 §0.2）。
- 指针初值 / 赋值 / `return` / 容器实参与普通实参共用同一条判据：**结构体指针**同层不同基类型、
  不同星数报 L45-1 / L45-2；标量指针（`int *` ↔ `char *`）不同基类型仍跳过，`void *` ↔ 任意对象指针、
  裸 `0`、typedef、数组、闭包、函数指针也跳过。
- 文案沿用 `initializer:` / `assignment:` / `return:` / `argument <n>:`。

### 4.64 自定义类型下标（Phase 52，仅 ct-ast）

- **读形态**：非指针的 `struct` 值接收者、且类型在 `impl` 里有固有 `get` 时，`obj[k]`
  展开为 `obj.get(k)`（复用 `N_MCALL` / `aux = 9`，与容器下标同形）。**方案 A**：只匹配
  名字 + 参数个数（1）+ 非 `static`，**不看参数类型**（D52-2）。
- **写形态**：语句 `obj[k] = v;` 展开为 `obj.set(k, v)`；`set` 同样只按名字 + 参数个数（2）
  + 非 `static` 匹配。只支持普通 `=`、且接收者必须是可回溯到变量的左值（D52-4）。
- **诊断**（位置一律指向 `[`；一次只报一条）：
  - L52-1 缺 `get`：`type 'X' has no subscript: declare 'V get(K)' in impl X`
  - L52-2 缺 `set`（只读）：`type 'X' has a read-only subscript: declare 'void set(K, V)' in impl X`
  - L52-3 `get` 参数个数不是 1；L52-4 `set` 参数个数不是 2
  - L52-5 `get` / `set` 是 `static`
  - L52-6 `+=` / `++` / `--`：`a custom subscript supports only '='; use set(k, v)`
  - L52-7 `&obj[k]`：`cannot take the address of a custom subscript; bind it to a local first`
  - L52-8 写形态不是语句或接收者非左值
  - L52-9 右值是 `own` / `borrow` 变量
  - L52-10 `get` / `set` 在定义单元私有、消费单元不可见
- **不进入协议**：`struct X *p` 的 `p[k]` 保持 C 指针算术；C 数组 / `int *` / 指针到 struct 的
  `[]` 逐字节不变；`Vec` / `Map` 的下标糖与 L31-3 / L31-4 写保护不变；trait 提供的 `get` 不算
  （只认固有 `impl`）。
- **已知洞（D52-6）**：数字下标 `v[0]` 会按方案 A 展开成 `get(0)`；若 `get` 只接受
  `char *`，实参类型不匹配会由 `custom_index_method` 的键类型判定报出——`ct check` 是
  `error:`（rc=1），`ct compile` / `ct build` 是 `warning:`（rc=0，产物仍发射 `get(0)`）。
  完整的按键类型分派（同类型并存 `get(char *)` / `get(int)` 各选其版）**尚未实现**，由
  `REQ-JSACCESS-1` 承接；在此之前 JSON 数字下标请用 `get_idx`，不要写 `v[0]`。
- **范围外**：`x[k].field = v`、`x[k].m()` 在编译期报错（不落 `cc`）；连写 `v["a"]["b"]`
  会被当成 C 指针算术，可能静默得错值，必须由包层（如 `JsonRef`）提供多级访问。

### 4.65 可选链 `?.` / `?[`（Phase 53，仅 ct-ast）

- **读形态**：指针接收者的字段/下标访问可写成 `p?.f`、`p?[i]`，展开为
  `(p ? p->f : 0)` / `(p ? p[i] : 0)`；接收者为 `Map<K,V> *` 时 `m?["k"]` 展开为
  `(m ? <Map>_get(m, k) : 0)`。`m["k"]?.c` 的单次 `get` 结果先落临时量再判空。
- **单次求值**：简单标识符直接使用；字段链、调用、map 查找等复杂接收者先落一个
  `__ct_optN` 临时量，赋值在三目条件里，前跳为 0 时后续字段/下标/`get` 都不求值。
  条件位置的临时量声明写在 `if`/`while`/`for`/`switch`/`do` 之前。
- **结果**：指针/函数指针/标量/枚举/数组退化为 `0`；struct/union/含 Drop 的值拒绝
  （L53-3/L53-4）。`Map<K,V>` 的 `V` 必须为值类型（L53-5）。
- **诊断**：L53-1 值接收者 `?.`；L53-2 值接收者 `?[`；L53-3 / L53-4 结果无 NULL 表示；
  L53-5 map 值类型为指针；L53-6 赋值/取址；L53-7 可选方法调用。位置一律在 `?`。
- **切词**：`?.` / `?[` 是 parser 组合，不新增词法 token；`?` 后是 `T_NUM` 且以 `.`
  开头时仍按三目（`c?.5 : 1.0` → `(c ? .5 : 1.0)`），`a?.5` 是不完整三目语法错误。
- **范围外**：`T?` / `Maybe<T>`、struct 值接收者、可选方法调用、`p?.b = 1` / `&p?.b`、
  用户类型 `get` 的指针接收者协议；`struct X *p` 的 `p?.f` 之外的 `.` 规则仍按 PH-51。

### 4.66 C 边界：`c-boundary` 与 shim（Phase 65，仅 ct-ast）

默认只有 CT 树（`selfhost/**`、`lib/std/**`、`test/**`、`examples/**`）与 `--c-boundary=allow`
的构建可以直接和 C 打交道；**外部代码默认 strict**。

| 形态 | strict 下 | 出口 |
| --- | --- | --- |
| `.ct` / `.h.ct` 的 `#include` | 硬错 | `#include "<base>.shim.h"`（本单元的 shim） |
| `#ct-raw` | 硬错 | 放进 `.shim.c` 或 `.m.ct` |
| `extern` 原型 / 裸 C 声明 | 硬错 | `<base>.shim.h` 声明、`.m.ct` 映射 |
| 函数式 `#define` | 硬错 | 对象式常量宏，或 shim |
| `.m.ct` | 允许 `#include` 与对象式宏；函数式宏硬错 | `.shim.h` |

开关：`ct build --c-boundary=strict|allow` / `ct --c-boundary=...`；
包在 `ct.pkg` 写 `c-boundary = strict|allow`（缺省按外部 strict；**有 manifest 但没这个键**
的旧包保留 allow 窗口）。`.h.ct` 的姊妹 `<base>.shim.h` 会自动进公开头并加入 `ct build` 的 `-I`；
两个同名 shim 同时入构建是硬错。

strict 是**护栏**不是沙箱：shim 的内容、`--ldflags` 外链的 `.c` 仍能绕过文件边界（D65-8）。

### 4.67 libc I/O 内置例外：按直接调用补头（Phase 66，仅 ct-ast）

`printf` 这一族**不需要 `#include`，也不需要 `import`**：编译器按**直接调用**补头，
没有调用就不补（D-008）。

| 组 | 名字 | 补的头 |
| --- | --- | --- |
| 格式化/标准 I/O | `printf`、`fprintf`、`sprintf`、`snprintf`、`scanf`、`fscanf`、`sscanf`、`puts`、`putchar`、`fputs`、`fputc`、`fflush`、`perror` | `<stdio.h>` |
| 宽字符 | `wprintf`、`fwprintf`、`swprintf`、`wscanf`、`fwscanf`、`swscanf` | `<wchar.h>` |

边界：

- 只认**直接调用**；名字出现在字符串/注释里不算。取地址不是调用（但 CT 目前不允许引用未声明函数）。
- 用户自己定义了同名函数（或宏）时**不抢**：按用户的声明处理，不补头。
- 集合外的名字（`syslog`、`open`、`fcntl`、`exec*`、`ioctl` …）**不补头**：走 `.m.ct`/shim 或显式声明。
- `vprintf`/`vsnprintf` 等接收 `va_list`，不是可变参数函数，不因前缀补头。
- 每个头只补一次，位置在 banner 之后、内置层 prologue 之前。
- `--freestanding` 下**不补头**；调用未由 shim 声明时报错（`'printf' is not declared in a freestanding build`）。

这是**显式 libc 例外**，不是"C 库已被封装"：格式串与实参类型不检查，与 C 一致。

### 4.68 `ref` / `out` 参数（Phase 78，仅 ct-ast）

```ct
void inc(ref int x) { x = x + 1; }
bool parse(Str s, out int len) { len = s.len; return len != 0; }

int v = 1;
int n;
inc(v);          /* 调用点不写 & */
parse("ab", n);  /* 调用点不写 out */
```

- **上下文关键字**：`ref` / `out` 只在**形参表的第一 token** 是注解；出了形参表仍是普通标识符，
  `int out;`、`time_t *ref;`、`void f(int out)` 全部合法。`ref` / `out` 不能与 `borrow` 同时写。
- **发射**：形参声明、原型、trait vtable 槽、实现定义、`--lib` 的 ABI 头一律发射 `T *`；
  函数体里对 ref/out 参数的读写发射 `(*name)`；调用点自动取地址 `&place`（Vec 元素见下）。
- **类型**：`ref int` / `out int` 的形参基类型仍是 `int`；调用点的实际实参按基类型比较，
  因此 `ref int` 接到 `struct P` 报 `type mismatch`，不靠 C 的隐式转换蒙混。
- **调用点 lvalue 白名单**：
  - 变量（不是常量、不是函数名）、字段 `s.f`、`*p`、数组元素 `a[i]`（`N_INDEX`）；
  - `Vec<T>` 元素 `v[i]`：发射为 `Vec_*_at(&v, i)`（`get` 改 `at`），不再加一层 `&`；
  - `Map<K,V>` 元素在语言里的静态类型是 `V *`（`get` 返回元素指针），因此可写的书写是
    `*m[k]`（`N_DEREF`）；裸 `m[k]` 是**指针值**，不是 `ref V` 的 place，会被拒绝；
  - 字面量、算术/比较表达式、调用结果、cast、自定义下标（`Phase 52` 的 `get/set` 协议）
    一律硬错：`ref/out argument must be an assignable place`。
- **`out` 调用方初始化**：trivial（标量、无 `Drop` 的 struct、指针）可以未初始化；owning
  （`String` / `Str`、`box<T>`、`Vec<T>`、`Map<K,V>`、任何 `use Drop` 的 struct）必须已有值——
  声明初始化式、后续赋值、普通/`ref` 形参、文件作用域变量与 `static` 局部都算已初始化；
  未初始化的 owning 实参报 `out owning argument must be initialized`。字段/数组/容器元素作为
  实参时按"已初始化"处理（L1 不做逐字段定值，见边界）。
- **`out` 定值（L1）**：`ct build` 与 `ct check` 默认硬错，`ct check --types` 不改变这条规则。
  - 顺序语句精确；`if` / `if/else` 精确（条件里的赋值也算，因为条件一定求值）；
    两边都 `return` 时后续语句不再检查；
  - 每个 `return` 在求值返回表达式后检查；函数末尾也检查；
  - `while` / `for` / `do-while` / `loop` / `foreach` 保守：循环体内的赋值**不**证明循环之后有值，
    但循环体内的 `return` 仍按进入集合检查；
  - `switch` 保守：每个 `case` 是独立入口，`break` 不掩盖后续 case 的 `return`，但 case 内的赋值
    不流到 switch 之后；
  - `goto` 保守：跳到该语句时所有 out 参数必须已赋值（线性分析看不到跳转之后再做赋值的路径）；
  - 赋值一个同名 **shadow** 局部不算给形参赋值（按符号表身份，不按名字）。
- **方法 / trait（S2b）**：trait 方法、trait 默认体、trait impl、固有方法、泛型 impl 与静态
  固有方法走同一规则；vtable 槽与 impl 定义发射 `T *`，调用点取地址。impl 的 ref/out 注解必须
  与 trait 声明一致（`ref/out annotation does not match the trait's`），否则 vtable 槽与实现
  的函数指针类型不同；调用点的 lvalue/owning 规则与自由函数一致。
- **既有语义不变**：`ref` / `out` 不改变指针、`own`、`borrow`、`defer` / `errdefer` 与 AutoDrop
  的规则；生成的只是普通 C 指针和 `(*name)`。`ref` 可以被存储或传给更长寿命的位置，语言不做
  借用检查（契约 + 直接 lint，J-4b）。
- **边界**：数组与函数指针形态的 ref/out 参数报
  `ref/out parameters cannot be arrays or function pointers`；闭包、`ref` 的跨单元高阶形态、
  Map 的自定义下标协议不作为 place；`out` 的 L1 不建模短路表达式、三元分支之外的控制流与
  跨过程定值；owning 实参是字段/元素时按已初始化处理。

### 4.69 切片 `T[]`（Phase 79，仅 ct-ast）

- **拼写**：`T[]` 是唯一切片拼写；`T a[N]` 是 C 数组；`T a[] = {...}` 保留为推断长度 C 数组。
  `T a[]` 作为形参、字段或无初始化器的声明告警：`'T a[]' is deprecated; write 'T[]' for a slice
  or 'T a[N]' for an array`；v1 起改为硬错。`ct check` 按既有 strict 规则把该告警升为 error，
  迁移期请用 `ct build` 或先把形参/声明改成 `T *`、`T[]` 或 `T a[N]`。
- **表示**：切片是 `{ptr,len}` 视图；空切片 `{0,0}`；数组→切片自动补长度；子切片 `a[lo..hi]`
  为半开区间，越界在编译期可判定时硬错，否则运行期 trap。
- **下标**：`s[i]` 是带边界检查的 place，读、写、借用都作用于底层元素；越界 trap（stderr + 非零退出）。
  `s.get(i)` 是软访问，越界返回 0 指针；调用者负责判空。
- **只读**：`const T[]` 的元素写硬错（`cannot write to an element of a const slice`）；
  C 数组 `T[N]` 保持 C 下标，不做边界检查。
- **位置白名单**：切片只允许出现在参数、局部变量、表达式临时量与返回值；字段、全局、接口值、
  `box<T>`、`Option`/`Result`、容器、数组元素、泛型实参、闭包捕获一律硬错。
- **返回**：返回局部数组或局部 owning 视图触发 lint；透传路径由作者负责。
- **边界**：`Vec.as_slice`、`s.field[i]`、`f().get(i)`、`int[] s; s = a;` 不在首轮范围。

### 4.70 `String` / `Str`：UTF-8 owning 与借用（Phase 80，仅 ct-ast）

- **类型**：`String` 是 owning 句柄（`char *ptr` + `int len`，16 字节 LP64），`Str` 是同一布局的
  borrowed 视图（无 Drop）；`U16String` / `U16Str` 是 UTF-16 对（`uint16_t *ptr` + `int len`）。
  五个句柄之前都有 8 字节头 `struct ct_str_hdr { int refs; int aux; }`：`ptr - 8` 即头；
  `refs = -1` 为 immortal（字面量 / 空串），`release` 首行直接返回。refcount 是普通 `int`，
  非原子、非线程安全，作者负责同步。
- **字面量**：`String s = "x"` 绑定编译器发射的 L1 immortal 静态块（只读区，Drop 不释放）；
  `Str v = "x"` 绑定同一段只读字节的借用视图；文件作用域初始化器与 `return "x"` 同规则。
  裸字符串字面量的值类型仍是 `char *`；把字面量直接当作工厂实参（如
  `U16String.from_utf8("abc")`）本轮不做隐式绑定，先绑定到 `Str` 变量再传。
- **转换**：`String.as_str() -> Str`（借用）；`Str.to_string() -> String`（独立副本）；
  `String.to_string()` / `String.slice(start,n) -> String`（新 owning）；
  `Str.slice(start,n) -> Str`（视图）。跨编码只走显式工厂：`U16String.from_utf8(Str)`、
  `U16String.from_utf16(U16Str)`、`String.from_utf16(U16Str)`、`to_utf8()`、`to_utf16()`；
  UTF-16 没有隐式字面量（`U16String x = "abc"` 硬错：`a UTF-16 string literal is not implicit`）。
- **方法**：UTF-8 用码点下标 + 字节 API：`len`（字节数）、`char_len`（码点数）、`byte_at(i)`（O(1)）、
  `codepoint_at(i)`（O(n)）、`get(i)`、`s[i]`、`char_at(i)`、`byte_slice(start,n)`、
  `byte_index_of(_from)`、`slice`、`as_str`、`to_string`、`cstr`。UTF-16 只用 JS 核心子集并统一
  snake_case：`len`（code unit 数）、`char_code_at`、`char_at`、`get` / `at` / `u[i]`、
  `code_point_at`、`index_of(_from)`、`last_index_of`、`includes`、`starts_with`、`ends_with`、
  `slice` / `substring`、`concat`、`replace` / `replace_all`、`to_upper_case` / `to_lower_case`、
  `trim` / `trim_start` / `trim_end`、`repeat`、`pad_start` / `pad_end`、`split`、`to_utf8`、
  `to_utf16`、`to_string`。`match` / `locale` / `normalize` 不在内建，走包 + shim。
- **不可变与下标**：`String` 不可变，`s[i] = ...`、`u[i] = ...` 硬错；`s[i]` 是只读单码点 `Str`
  视图（越界为空视图），`u[i]` 是只读单 code unit `U16Str` 视图。
- **C 边界**：`.data` 是只读原始视图，静态类型 `const char *`（UTF-8）/ `const uint16_t *`（U16），
  **不保证 NUL 结尾**；它只能下标（`s.data[i]`），不能作为值传出、不能传给任何被调方
  （`printf("%s", s.data)` 硬错：`'.data' is a read-only raw view without a NUL guarantee; index it
  byte by byte or use cstr() at the C boundary`）。`cstr()` 是唯一 C 边界出口，返回独立的
  NUL 结尾副本，调用方负责 `free`。`.ptr` 是实现字段，用户读写一律硬错。
- **复制 / retain**：显式协议 `copy()` / `retain()`（共享缓冲、`refs + 1`）与 `release()`
  （`refs - 1`，归零时释放）；`Vec` / `Map` 插入按容器元素 glue 自动 `retain`。
  D-013 §3 的自动半部自 v0.80.1（SH-102）起生效：按值传参在入口 `retain`、由被调方在所有
  出口 `release`；字段赋值与非局部 owning `return` `retain`；局部句柄 `return` 按 move；
  重新赋值先 `retain` 右值再 `release` 旧值；作用域结束释放 owning 局部。局部绑定若是借用
  视图（`Vec.get` / `Map.get` 结果）则不 `retain` 也不 `release`；`refs = -1` 的 immortal
  字面量 / 空串在所有位置都跳过。
- **旧类型已删除（S5b）**：`lib/std/StrLegacy.h.ct` 与 `namespace std::str` 兼容单元已移除，
  `std::str::Str` 不再解析；仓内消费者已迁到 `String` / `Str` 新 API，外部消费者的 dry-run
  见 phase80 卡 §7。
- **边界**：`box<String>` 已由 PH-81 的 `box<String>::of` 回填；`Map<Str,V>` 存储位置（借用类型不能作为容器键，用
  `Map<String,V>`）、字段/全局位置的 `String`（无自动 Drop）、跨仓外部工程迁移只做 dry-run。

### 4.71 `box<T>` / `new`：单对象句柄（Phase 81，仅 ct-ast）

- **类型**：`box<T>` 是单元素 owning 句柄，布局 `{ struct ct_box_hdr *h; T *ptr; }`
  （LP64 16 字节）；8 字节头 `struct ct_box_hdr { int refs; int aux; }` 在 payload 前，
  偏移 `header_size(T) = round_up(8, _Alignof(T))`。`refs` 从 1 起；box 不使用
  `refs = -1` immortal（那是 `String` 字面量 / 空串专用）。refcount 非原子、非线程安全。
- **构造**：`new T { ... }` 是 move 构造，`T` 只能是**具名、非泛型 struct**；花括号与
  `T x = { ... }` 共享解析（位置式、指定式 `.f = e`、嵌套）。`box<T>::of(v)` 是复制构造：
  payload 的 owning 叶各自 `retain`，`String` 参数在调用侧按值 retain、被调方出口 release，
  因此 `box<String>` 由 `box<String>::of(s)` 得到。`new String` / `new Str` / 标量 / 指针 /
  数组 / 容器 / 其他内建句柄一律硬错；`new` 不能出现在文件作用域或 `static` 局部的初始化器
  （运行时分配，直接报错）。
- **上下文关键字**：`new` 只在后接类型名（或错误形态 `new {`）时才是构造；`int new;`、
  `r.new`、形参 `new`、`new = ...`、`new + 1` 继续是标识符。
- **解引用**：`b.f` / `b.f = ...` 自动改写为 `b.ptr->f`（`box<T> *p` 时为 `p->ptr->f`）；
  `.h` / `.ptr` 是实现字段，用户读写硬错。
- **生命周期**：`retain()` 共享并 `refs + 1`，`release()` 归零时按静态类型释放 payload：
  `String` / `U16String` 字段走其 Drop，容器 / 嵌套 box 字段走 `release`，普通 struct 递归
  其 owning 字段；`use Drop` 宿主 struct 的字段 glue 调 box Drop。采用 `Vec` 的显式协议：
  按值传参、字段赋值、容器插入不会自动 retain；容器元素 glue 会 retain。locally owned
  `box<T>` 的 `release()` 由作者显式调用。
- **借用视图 / 失效**：`b.at()` 返回 `T *` 借用视图，不 retain；`release()` 使该视图失效
  （与 `Vec.at` 的失效契约同构）。失效后的读取由 ASan 抓，不做运行期检查。
- **边界**：`box<Str>` / `box<U16Str>` / `box<T[]>` 硬错；`struct Bad { Str tag; }` 在声明层
  硬错（借用字段会活过其底层数据）。引用环是作者责任：`retain()` 成环后释放句柄仍保留
  `refs >= 1`；v0.82.0 起对 `box<X>` 字段的直接环做**编译期告警**（§4.72），运行期仍不做
  环检测/回收；`--debug-leaks`（若将来实现）只报未配对 alloc/release 计数，不叫环检测。
  `ct build` 跨单元 `box<T>` 在 v0.81.0 不支持（实例/助手写在命名它的单元里，导出签名只有
  前向声明）；单文件 compile 模式与单单元 build 可用。
- **C 边界 / ABI**：`box<T>` 是编译器生成的 nominal 句柄，不是 C ABI 导出类型；C 侧只用
  `T *` / 普通 struct / `void *`。句柄 16 字节、头 8 字节是 golden 断言，不是跨编译器 ABI
  承诺。

### 4.72 泄漏防护：`leaks` 与直接环检测（Phase 82，仅 ct-ast）

`box<T>` 的引用环是作者责任（§4.71）；本节把**直接环**从无声事故变成可见风险，不引入 GC /
weak / 跨过程分析（D-012）。

- **配置**：`ct.pkg` 新增窄键 `leaks = warn|error`，缺省 `warn`。`error` 把现有的
  `potential leak` 诊断与本节的直接环告警升为 **error**，并让 `ct build` / `ct compile`
  在写任何产物之前失败；`ct check` 仍按既有策略把所有 finding 当 error。键从输入所属包读取：
  `ct build` 取 `-I` 根的 manifest（无则入口单元目录），`ct compile` / `ct check` 取单元
  自身目录（这两种模式忽略 `-I`）。缺键、未知值与旧包一律 `warn`，存量包行为不变。`leaks`
  与 `c-boundary = strict`（§4.66）互不影响，也不改 `--debug-leaks` 的计数契约（D-011 J-4c）。
- **检测范围**：只展开 struct 的 **`box<X>` 字段**（相邻边计 1），限深 **3 条边**：自环
  `A -> A`、`A -> B -> A`、`A -> B -> C -> A` 命中；同一环只报一次（重复的载荷字段算一条边）。
  4 条边以上的环、经 `Vec<box<T>>` / 泛型参数 / 接口字段 / typedef 别名的间接环、泛型 struct
  与其实例、跨过程转手**不在检测范围**——不报不代表没有泄漏（R82-2）。
- **文案**：`file:line: warning: potential reference cycle: A -> B -> A; instances may leak
  unless the cycle is broken by hand`。写「可能泄漏，除非手工破环」，不写「会泄漏」；位置指向
  环里行号最小的那个 struct 声明。
- **豁免**：`/* ct: allow-cycle */` 必须与 `struct` 声明**同一行**；标记在环的任一参与者上即
  抑制该环。`ct check` 仍以 `note: reference cycle suppressed by 'ct: allow-cycle': …` 报出
  被抑制点（审计用），`ct compile` / `ct build` 静默。标记在上一行或字段行不生效；注释被
  refactor 删掉后告警重新出现是可接受代价。
- **树模式**：标准的父子结构见 [patterns §5](patterns.md#5-父子结构树)。
- **非目标**：运行期环检测/回收、`weak` 引用、句柄运行期泄漏分析；`--debug-leaks` 仍只报
  未配对 alloc/release 计数，不叫环检测。
