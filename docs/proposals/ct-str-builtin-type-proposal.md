## 0. 已定前提（负责人已拍板，不作为待议项）

### P1 字面量属性不变

双引号字面量本身就是 `char *`，这一点不改。只有当目标类型是 `Str` 时（声明、赋值、传参等位置），
由隐式转换把该 `char *` 构造成 `Str`。这类隐式转换与其它声明场合是同一套机制。

因此不存在「字面量类型随上下文变化」，也不需要「无上下文时默认类型」这类补充规则。

### P2 值语义取拷贝

- `Str a = b;` 深拷贝；
- 右值是临时值（如运算结果）时直接转移，不再额外拷贝；
- 文档必须把开销写清楚、写得详细：该赋值是**一次分配加一次拷贝**，高频路径应改用 `char *` 视图。

这条是正文规定，不是脚注。

### P3 内存布局是语言承诺

- 两个字段、顺序固定、名字固定：`data` 指针 + `len` 长度；
- 同形的 C struct 可直接对传；
- 调试器所见与文档一致；
- 新增字段即破坏性变更；
- 需要可变字符串时不通过给 `Str` 加字段实现。

## 1. 事实：现状与差距

### 1.1 `Str` 目前是什么

- 规范称 `Str` 为「内建」，但定义在 `lib/std/Str.h.ct` 的源码里：
  `pub struct Str { char *data; int len; }`，并带 `impl Drop`（[Str.h.ct:18-29](../../lib/std/Str.h.ct#L18-L29)）。
- `ct build` 自动加载 `Str`，不需要 `import`（[language-spec.md:47](../language-spec.md#L47)）。
- 布局与 `len` 契约已按「保留内嵌 `\0`、不依赖结尾 NUL」写明
  （[language-spec.md:2559](../language-spec.md#L2559)）。
- 现行所有权语义是**浅拷贝句柄**：按值传递只拷贝指针，不自动深拷贝，需要显式 `retain()`
  （[language-spec.md:2560](../language-spec.md#L2560)；`retain()` 见 [Str.h.ct:132-134](../../lib/std/Str.h.ct#L132-L134)）。

### 1.2 与三条前提的差距

| 前提 | 现状 | 差距性质 |
| --- | --- | --- |
| P1 字面量 `char *`，目标 `Str` 时隐式转换 | `char *` 传给 `Str` 形参在默认路径是**硬错**（[language-spec.md:2000-2005](../language-spec.md#L2000-L2005)） | 需要把该硬错改为按目标类型的转换 |
| P2 `Str a = b;` 深拷贝 | 现行 §4.56 明确「按值传递浅拷贝指针，不自动深拷贝」 | **改变已发布语义**，不是补文档 |
| P2 临时值直接转移 | 现行规范没有 `Str` 的移动/转移规则；只有 `own` 与 AutoDrop 的语句级记账 | 需要新的转移规则与判定 |
| P3 布局两字段固定 | 源码布局已一致，但「内建」地位靠 `lib/std` + 自动加载 | 需要把布局写成语言契约，并防止用户重定义 |
| P3 同形 C struct 直接对传 | 不同具名 struct 按值互传是硬错（[language-spec.md:2003](../language-spec.md#L2003-L2005)） | 需要 FFI 兼容规则；当前规范没有 |

**关键事实（必须写进正文）**：P2 把 `Str` 从「浅拷贝句柄」改为「拷贝即深拷贝」，会与既有
`retain()` 的用法、按值传参的开销、以及所有依赖浅拷贝的调用点发生冲突。这不是语义澄清，
是一次**破坏性语义变更**，必须有迁移与兼容说明。

## 2. 提案：内置化的边界

### 2.1 「内置」指什么

本提案把「内置」限定为三件事，不新增语法、不改类型名：

1. 编译器承认 `Str` 的身份：类型名、两字段布局、`Drop` 行为、拷贝语义由语言规范定义；
2. 编译器在 P1 的目标位置插入公开的转换函数调用；
3. 布局与字段名成为对外承诺，新增字段按破坏性变更处理。

`Str` 仍是值类型，不引入引用计数、不引入可变长度头、不把方法搬进编译器。

### 2.2 与现有声明的关系

现状的 `pub struct Str` 与 `impl Drop` 可以继续作为**唯一源码定义**；编译器只增加身份识别与
P1/P2 的代码生成，不复制一份平行声明。是否最终迁到编译器 prelude / 语言层，见 §3 待定项。

### 2.3 方法层

`retain()` / `release()` 与自由函数（`str_from` / `str_len` / `str_compare` 等）继续留在
`lib/std/Str.h.ct` 的 `impl Str` 与自由函数中；编译器不接管方法体。P2 生效后 `retain()` 的定位
需要重新说明（自动深拷贝已覆盖的场景不必再手写 `retain()`），但函数本身保留。

## 3. 待项目组决定的部分

以下各项不由本提案替项目组拍板；每项给出可选路径与代价，供评审对抗。

### 3.1 内置类型定义落在哪一层

- **A：源码定义 + 编译器身份识别**：`Str` 仍在 `lib/std/Str.h.ct`，编译器按名字/布局识别。
  迁移成本最小，自举链不变；缺点是「内置」仍依赖一个可被修改的源码文件。
- **B：编译器 prelude / 语言层定义**：`Str` 由编译器内置，源码不再声明。
  承诺最强；缺点是要处理自举、旧产物、以及 `Drop` / 方法层的迁移。

### 3.2 与现有 `Str` 声明的关系与迁移路径

- 一次性切换：旧代码依赖浅拷贝的调用点会直接改变行为；
- 分阶段：先加诊断/警告（`Str a = b;` 当前是浅拷贝），再切深拷贝，最后移除旧语义。
  需要定义兼容窗口与回退方式。

### 3.3 方法层归属

- 方法继续留在 `lib/std`（A 路线的自然结果）；
- 或随内置化迁入编译器 prelude（B 路线），但 `Drop`、`retain`、`release` 的实现位置要一起搬。

### 3.4 与 `char *` 的隐式转换边界

P1 只说明「目标类型是 `Str` 时转换」。仍需定：

- 只允许声明、赋值、传参，还是也允许返回、字段初值、容器字面量、三目；
- 是否允许 `Str` → `char *` 的隐式借用（涉及生命周期）；
- 重载/二义时精确匹配与转换的优先级。

### 3.5 内嵌 `\0` 的表示与比较

- 表示：`data` + `len` 已支持内嵌 `\0`（[language-spec.md:2559](../language-spec.md#L2559)）；
- 比较：必须按 `len` + `memcmp`，不能只用 NUL 结尾视图（`Map` 的 `Str` 键已按此实现，
  [language-spec.md:2419](../language-spec.md#L2419)）；
- 与 C 侧对传时，C 读者会在第一个 `\0` 截断；这是布局承诺的已知边界，需要写进文档。

### 3.6 `NULL` 语义

- `char *` 的 `NULL` 转 `Str`：拒绝（要求显式 `str_from`）、当空串、还是终止；
- 现状 `str_from(0)` 返回一个空串（`len = 0` 的拥有型值），不是 `{0,-1}` 的释放态
  （[Str.h.ct:51-60](../../lib/std/Str.h.ct#L51-L60)）；
- 若隐式转换接受 `NULL`，会把「缺失/错误」与「空串」压成同一个值。

### 3.7 OOM 政策

- 隐式深拷贝没有返回值通道；分配失败是终止、返回释放态，还是要求显式 `str_from`；
- 现行 `str_from_len` 失败返回 `len = -1` 的释放态（[Str.h.ct:40-43](../../lib/std/Str.h.ct#L40-L43)）；
- P2 的「一次分配加一次拷贝」把该失败点带到每个赋值/传参位置，需要统一政策。

## 4. 影响面

### 4.1 会改变的既有写法

- `Str a = b;`：从浅拷贝句柄变为深拷贝；原来靠 `retain()` 的调用点会多一次拷贝。
- `Str s = p;` / `f(p)`：从硬错变为隐式转换（P1）。
- 按值传参与返回 `Str`：拷贝开销从 O(1) 变为 O(n)，热点路径需要改用 `char *` 视图。
- 依赖「两个 `Str` 共享同一 buffer」的代码：语义不再成立。

### 4.2 不变的部分

- `Str` 的字段名、顺序、`len` 契约不变；
- `str_from` / `str_from_len` / `str_len` / `str_slice` / `str_concat` / `str_compare` / `str_c_str`
  的公开性不变；
- `Drop` 仍负责释放；`free(0)` 仍是 no-op；
- `Map` 的 `Str` 键比较仍按 `len` + `memcmp`。

### 4.3 需要同步的文档与诊断

- §4.56 的「浅拷贝句柄」表述需要按 P2 改写，并写清「一次分配加一次拷贝」；
- `char *` → `Str` 形参的硬错文案要改为按目标类型的转换；
- 布局承诺需要给出可验证的 `sizeof` / 字段偏移断言；
- C 对传的截断边界、`NULL`、OOM 三条要写进同一节。

---

## 5. 供评估的验收建议（不构成排期）

- 布局：C 侧 `offsetof(struct Str, data) == 0`、`offsetof(struct Str, len) == sizeof(char *)`、
  `sizeof(struct Str)` 与语言侧一致；新增字段的改动能被门禁识别为破坏性变更。
- P1：`Str s = p;`、`s = p;`、`f(p)` 三处生成转换调用；`char *p = s;`、返回、字段初值仍按
  最终裁定的边界处理。
- P2：`Str a = b;` 后修改 `b` 的内容不影响 `a`；ASAN 无 double-free / 泄漏；
  临时值 `Str a = f();` 的分配计数比「先构造再拷贝」少一次。
- 内嵌 `\0`：`Str` 与 `Str`、`Str` 与 `char *` 的比较按 `len` 判定，不被 NUL 截断。
- `NULL`、OOM：按 §3.6 / §3.7 的最终裁定给出固定行为与夹具。
- 既有显式 `retain()` / `release()` 调用零回归（若保留）。

本提案只处理 `Str` 的内置身份、P1/P2/P3 三条前提与布局承诺；`char *` / `Str` 转换的
适用位置、借用生命周期、目标类型归属等细节，另见
