## 0. 已定前提（负责人已拍板，不作为待议项）

### P1 字面量属性不变

双引号字面量本身就是 `char *`，这一点不改。只有当目标类型是 `Str` 时（声明、赋值、传参等位置），
由隐式转换把该 `char *` 构造成 `Str`。这类隐式转换与其它声明场合是同一套机制。

因此不存在「字面量类型随上下文变化」，也不需要「无上下文时默认类型」这类补充规则。

### P2 值语义取拷贝

- `Str a = b;` 深拷贝；
- 右值是临时值（如运算结果）时直接转移，不再额外拷贝；
- 文档必须把开销写清楚、写得详细：该赋值是**一次分配加一次拷贝**，高频路径应改用 `char *` 视图。

这条是正文规定，不是脚注。

### P3 内存布局是语言承诺

- 两个字段、顺序固定、名字固定：`data`（`const char *`） + `len` 长度；
- 同形的 C struct 可直接对传；
- 调试器所见与文档一致；
- 新增字段即破坏性变更；
- 需要可变字符串时不通过给 `Str` 加字段实现。

### P4 方法层是映射，不是另一套实现

除 §2.4.6 的子串查找（P10，归便利层）外，`Str` 的方法不做独立实现：每个方法在编译期展开为对
**与 `char *` 方法同一族底层 C 函数**的直接调用，唯一差别是实参取 `struct` 的成员 `data`，
需要长度的位置再传 `len`。不新增实现层、不引入间接调用、不做动态派发；展开后与直接调用该
C 函数等价。两宿主的映射表各自独立，不共用（P8）。

- **同名同义**：`char *` 侧已有的方法名与语义，`Str` 侧逐一对应，不得为同一件事用两套名字。
  两宿主各维护一份映射，不共用表（P8）。
- **选变体**：同一能力在 C 里同时有带长度参数的版本与依赖 NUL 结尾的版本时，`Str` 侧取带长度的那个
  （`Str` 允许内嵌 `\0`，依赖 NUL 的版本会在 `\0` 处截断）。长度方法 `length()` 直接读字段 `len`，是 O(1)。
- **便利层**：子串查找没有标准 C 的带长度函数，用标准 C 的 `memchr` 循环实现一次，不加平台条件编译（P10 / §2.4.6）。
- **显式边界**：C 函数自身强制要求 NUL 结尾（解析类、路径类、系统调用参数类）时，必须由调用方
  显式转换，不能隐式完成；单列于 §2.5。这不是实现层例外，是调用边界。

### P5 归属

`Str` 的签名与语义全部归语言侧；使用方不再定义、不再重复提供，只消费。`Str` 从 std 侧完全移除，
迁到语言侧。内置化的落点、与现有 `lib/std/Str.h.ct` 的关系、迁移路径与可用版本见 §2.3、§3.1–§3.2、§3.8。

### P6 借用指针可存变量，随 `Str` 失效

从 `Str` 借出的指针（类型为 `const char *`）允许赋给变量，不做「只限立即实参」的限制。
借用不延长 `Str` 的寿命：

- `s = other;` 会释放 `s` 的旧 buffer，此前从 `s` 借出的所有指针立即失效，再读即未定义；
- `s2 = s;` 是深拷贝，`s` 的 buffer 不变，此前从 `s` 借出的指针仍然有效；
- `s` 被 `release()` 或离开作用域时，借用指针同样失效；
- 语言侧没有借用检查器，编译器不拦；这条靠规范与文档约束，越界读是未定义行为。

### P7 `data` 只读，`Str` 内容不可变

`data` 是 `const char *`，通过 `data` 不允许写。要改内容只能产出一个新值。职责划分：

- 只读的定形内容归 `Str`；
- 构造与逐字节修改走可变缓冲区（`char` 数组或既有 `Buf`），完成后再转成 `Str`；
- `len` 是构造时的快照，不讨论「可写范围」。

理由：值语义只有在内容不可变时才成立；可写会让借用指针绕过深拷贝、直接改回原件。

### P8 静态映射按宿主各自定义

静态映射只是定义与声明层面的设置，不产生新函数。`char *` 与 `Str` 各有一份映射，各自维护；
不同宿主的方法实参形态本来就不同，不共用一张表。

- 跨宿主不靠隐式转换去调用对方的方法，各认各的；
- 确实需要跨侧时显式转换；
- 方法名在两宿主间同名同义是**命名约定**，不是共用一张表。

### P9 内嵌 `\0` 只在产出 NUL 形态时诊断

`Str` 允许内嵌 `\0`；构造时不扫描、不禁止。诊断只发生在**产出 NUL 形态**的那一步：
`to_c_str()`、`copy_to()` 一类转换在运行期检查内容是否含内嵌 `\0`，含则报错，不产出副本、
不写入。借用视图（`data` 指针配 `len`）不做诊断，调用方自己按长度处理。

### P10 子串查找归便利层

标准 C 与 POSIX 都没有带长度的子串搜索函数（`memmem` 属 GNU/BSD 扩展，glibc 还要额外宏），
因此子串查找不列入零实现映射：`find` 归**便利层**，用标准 C 的 `memchr` 循环实现，
不加编译期探测分支、不引入平台条件编译。单字节查找仍直调 `memchr`，保持零实现。

## 1. 事实：现状与差距

### 1.1 `Str` 目前是什么

- 规范称 `Str` 为「内建」，但定义在 `lib/std/Str.h.ct` 的源码里：
  `pub struct Str { char *data; int len; }`，并带 `impl Drop`（[Str.h.ct:18-29](../../lib/core/Str.h.ct#L18-L29)）。
  本提案把 `data` 定为 `const char *`：布局大小与字段顺序不变，写权限收窄。
- `ct build` 自动加载 `Str`，不需要 `import`（[language-spec.md:47](../language-spec.md#L47)）。
- 布局与 `len` 契约已按「保留内嵌 `\0`、不依赖结尾 NUL」写明
  （[language-spec.md:2559](../language-spec.md#L2559)）。
- 现行所有权语义是**浅拷贝句柄**：按值传递只拷贝指针，不自动深拷贝，需要显式 `retain()`
  （[language-spec.md:2560](../language-spec.md#L2560)；`retain()` 见 [Str.h.ct:132-134](../../lib/core/Str.h.ct#L132-L134)）。

### 1.2 与三条前提的差距

| 前提 | 现状 | 差距性质 |
| --- | --- | --- |
| P1 字面量 `char *`，目标 `Str` 时隐式转换 | `char *` 传给 `Str` 形参在默认路径是**硬错**（[language-spec.md:2000-2005](../language-spec.md#L2000-L2005)） | 需要把该硬错改为按目标类型的转换 |
| P2 `Str a = b;` 深拷贝 | 现行 §4.56 明确「按值传递浅拷贝指针，不自动深拷贝」 | **改变已发布语义**，不是补文档 |
| P2 临时值直接转移 | 现行规范没有 `Str` 的移动/转移规则；只有 `own` 与 AutoDrop 的语句级记账 | 需要新的转移规则与判定 |
| P3 布局两字段固定 | 源码布局名义一致；`const` 限定是本提案新增 | 需要把布局写成语言契约，并防止用户重定义 |
| P3 同形 C struct 直接对传 | 不同具名 struct 按值互传是硬错（[language-spec.md:2003](../language-spec.md#L2003-L2005)） | 需要 FFI 兼容规则；当前规范没有 |

**关键事实（必须写进正文）**：P2 把 `Str` 从「浅拷贝句柄」改为「拷贝即深拷贝」，会与既有
`retain()` 的用法、按值传参的开销、以及所有依赖浅拷贝的调用点发生冲突。这不是语义澄清，
是一次**破坏性语义变更**，必须有迁移与兼容说明。

## 2. 提案：内置化的边界

### 2.1 「内置」指什么

本提案把「内置」限定为三件事，不新增语法、不改类型名：

1. 编译器承认 `Str` 的身份：类型名、两字段布局、`Drop` 行为、拷贝语义由语言规范定义；
2. 编译器在 P1 的目标位置插入公开的转换函数调用；
3. 布局与字段名成为对外承诺，新增字段按破坏性变更处理。

`Str` 仍是值类型，不引入引用计数、不引入可变长度头；方法层是映射，不是把算法搬进编译器。
`data` 只读，`Str` 内容不可变（P7）；`Str` 不表示「没有值」，空串是 `len == 0` 的合法值，
方法层不判空（§3.6）。

### 2.2 与现有声明的关系

`Str` 的定义迁到语言层 prelude；现有 `lib/std/Str.h.ct` 在语言侧可用的那个 MINOR 降为不含定义的
兼容 shim，其后的那个 MINOR 删除。编译器只增加身份识别、P1/P2 代码生成与方法映射，不复制一份
平行声明；落点与迁移见 §3.1、§3.2、§3.8。

### 2.3 方法层

`Str` 的方法层是**映射层**，不是实现层：方法签名与语义归语言侧，编译期展开为对与 `char *` 方法
同一族底层 C 函数的直调，实参取 `data`（需要长度的位置再传 `len`）。std 侧不再保留独立定义，
也不存在 `Str` 专用的算法实现。

`char *` 与 `Str` **各有一份映射，各自维护，不共用一张表**（P8）。完整清单与变体规则见 §2.4；
唯一显式转换例外见 §2.5。

`retain()` / `release()` 保留，位置随 `Str` 迁移；`Drop` 仍由语言侧保证。

### 2.4 方法映射清单

#### 2.4.1 同名方法与底层 C 函数

下表是 **`Str` 宿主自己的映射**；`char *` 宿主另有一份映射。两表的目标可以是同一族 C 函数，
但表不共用、各自维护（P8）。

| 语义 | 方法（两端同名） | `char *` 侧底层 | `Str` 侧展开 | 说明 |
| --- | --- | --- | --- | --- |
| 长度 | `length()` | `strlen` | 读 `len` 字段 | `Str` 为 O(1)，`char *` 为 O(n) |
| 空判断 | `is_empty()` | `strlen(...) == 0` | `len == 0` | 同上 |
| 相等 | `equals(other)` | `strcmp` | 带长度版本：先比 `len`，再按字节比较 | 内嵌 `\0` 不截断 |
| 比较 | `compare(other)` | `strcmp` | 带长度版本：按字节比较 + 长度次序 | 返回负数 / 0 / 正数 |
| 前缀 | `starts_with(prefix)` | `strncmp` | 带长度版本：按字节比较 | 不依赖 NUL |
| 后缀 | `ends_with(suffix)` | 指针偏移 + `strcmp` | 指针偏移 + 按字节比较 | 不依赖 NUL |
| 查找（子串） | `find(needle)` | `strstr` | **便利层**：标准 C 的 `memchr` 循环（§2.4.6） | 不在零实现映射内；返回形态见 §2.4.5 |
| 切片 | `slice(start, n)` | `memcpy` 到新缓冲 | 同一 `memcpy`，源为 `data + start` | 产出新 `Str`；分配属底层调用成本 |
| 拼接 | `concat(other)` | 两次 `memcpy` | 同一 `memcpy`，长度用 `len` | 产出新 `Str`；分配属底层调用成本 |
| 取字符 | `char_at(i)` | `p[i]` | `data[i]` | 返回字节值；越界 `-1` |
| 切分 | `split(sep)` | 扫描 + `memcpy` | 同一扫描 + `memcpy`，长度用 `len` | 产出 `Vec<Str>`；空段处理需定 |

「展开后与直接调用 C 函数等价」指**不新增间接层**：没有 vtable、没有运行时方法表、没有分发查找。
底层 C 函数自身的扫描、分配、拷贝成本仍然存在，按上表写进文档，不称为「映射开销」。
表中 `find` 是唯一不在零实现映射内的一项，归便利层（§2.4.6）；其余各行都是零实现映射。

#### 2.4.2 变体选择规则

同一能力同时存在「带长度参数」与「依赖 NUL 结尾」两个 C 版本时，`Str` 侧一律取带长度版本：

- 相等、比较、前后缀走带长度的字节版本，不走依赖 NUL 结尾的版本；
- 子串查找走 §2.4.6 的便利层，不依赖 `memmem`，也不拿 `strstr` 顶替（`strstr` 会在内嵌 `\0` 处停）；
- 单字节查找直调 `memchr`，保持零实现；
- 切片、拼接、切分用显式长度，不扫描 NUL；
- 长度方法直接读字段，不调用 C 的长度函数。

理由是 `Str` 的 `len` 是契约，内嵌 `\0` 必须保留；`str*` 系列会在第一个 `\0` 处截断，丢数据。

#### 2.4.3 同名同义

同一语义在 `char *` 与 `Str` 两个宿主上使用同一个方法名、同一套字节语义；差异只在复杂度与
结果的归属（`Str` 由 `Drop` 回收，`char *` 结果由调用方释放）。不得为同一件事提供两套名字。

这是**命名约定**，不是共用一张映射表：两宿主各有一份映射（P8）。跨宿主调用对方的方法不靠隐式转换；
确实需要跨侧时显式转换。

#### 2.4.4 字段名与方法名

**结论：字段保持 `len`，方法叫 `length()`；两个宿主都只提供 `length()`，不提供 `len()` 方法。**

- `s.len` 是字段读取，`s.length()` 是方法调用，语法位置不同，不构成同名冲突；
- `char *` 没有字段，但同样提供 `length()`，保持两宿主同名同义；
- 方法名一律 snake_case，调用一律对象式 `receiver.method()`；
- C 函数名只出现在 §2.4.1 的映射表内，不出现在示例或调用点。

#### 2.4.5 `find` 的返回形态

**结论：`find` 的语义固定为「首次出现的位置」，返回形态由目标类型决定，两个宿主同一规则。**

- 目标为 `int`：返回字节下标，未找到 `-1`；
- 目标为 `const char *`：返回首次出现的借用指针，未找到 `NULL`；`Str` 侧指针只在
  该 `Str` 存活且未 `release()` 时有效；
- 目标为 `char *`：只在 `char *` 宿主可用；`Str` 宿主拒绝（`data` 是 `const char *`，不能去 `const`）；
- 不得一侧固定返回指针、另一侧固定返回下标；两侧必须按同一目标类型规则；
- `find` 不单独作为无目标表达式；必须由声明、赋值或实参给出目标类型。

示例（对象式调用、snake_case；C 函数名不出现）：

```c
char *p = "abc";
int   n = p.length();
int   i = p.find("bc");        /* 下标：2 */
char *q = p.find("bc");        /* 指针：指向 "bc" */

Str   s = "abc";
int   m = s.length();
int   j = s.find("bc");        /* 下标：2 */
const char *r = s.find("bc");  /* 借用：指向 s 内部，s 存活期内有效 */
Str   t = s.concat(s);
```

#### 2.4.6 便利层：子串查找

`find` 是方法表里唯一不在零实现映射内的一项（P10）：

- 标准 C 与 POSIX 都没有带长度的子串搜索函数；`memmem` 属 GNU/BSD 扩展，glibc 还需要额外宏；
- 实现方式：循环调用 `memchr` 找首字节，命中后按 `len` 做字节比较；只用标准 C；
- 不加编译期探测分支，不引入平台条件编译，不按平台切换实现；没有 `memmem` 也走同一条路径；
- 复杂度最坏 O(n·m)，写进文档；`char *` 侧的 `strstr` 复杂度由 C 库决定，两宿主不承诺同复杂度；
- 单字节查找直调 `memchr`，保持零实现，不为此新增方法名；
- 方法名与返回形态不变：仍叫 `find`，目标类型规则按 §2.4.5。

### 2.5 唯一显式转换例外：C 函数强制要求 NUL 结尾

有些 C 函数没有长度参数，只接受 NUL 结尾的 `char *`：解析类、路径类、系统调用参数类等。
这类边界**必须由调用方显式转换**，不能由 `Str` 方法或隐式转换代劳，因为 `Str` 允许内嵌 `\0`，
隐式转换会在第一个 `\0` 处截断并丢数据。

| 场景 | 显式方法 | 行为 |
| --- | --- | --- |
| 需要一份 NUL 结尾副本 | `to_c_str()` | 先检查 `data[0..len)` 是否含内嵌 `\0`：含则报错并返回失败，不产出副本；不含则分配 `len + 1` 字节、复制并补 `\0`，调用方释放 |
| 写入调用方缓冲 | `copy_to(buf, cap)` | 同样先检查内嵌 `\0`：含则报错且不写入；不含则最多写 `cap - 1` 字节并补 `\0`，返回实际写入长度 |

规则：

- 调用点必须显式写出上述方法，不得由方法映射或隐式转换自动插入；
- 诊断只在**产出 NUL 形态**这一步发生（P9）：构造时不扫描、不禁止内嵌 `\0`；借用视图
  （`data` 指针配 `len`）不诊断，调用方自己按长度处理；
- 含内嵌 `\0` 的内容不得静默截断后交给 C：报错，由调用方决定截断还是改写；
- 解析、路径、系统调用等函数如果只有 NUL 版本，`Str` 侧不提供同名映射，避免误用；
- 如果该 C 函数另有带长度的版本，优先用长度版（§2.4.2），不走本节的显式转换。

### 2.6 借用指针的存放与失效

从 `Str` 借出的指针类型是 `const char *`，允许赋给变量；它不是副本，不延长 `Str` 的寿命。
失效矩阵：

| 操作 | 旧借用指针 | 说明 |
| --- | --- | --- |
| `s = other;` | **立即失效** | 赋值释放 `s` 的旧 buffer，再读即未定义 |
| `s2 = s;` | 从 `s` 借出的仍有效 | `s2` 是深拷贝，`s` 的 buffer 没有被释放 |
| `release(s)` | 失效 | 显式释放 |
| `s` 离开作用域 | 失效 | `Drop` 释放 |

语言侧没有借用检查器，编译器不拦「借用指针活得比 `Str` 长」；这条靠规范、文档与使用方自查约束。
读取失效指针是未定义行为，语言不保证诊断。

### 2.7 `data` 只读与可变缓冲区职责

`data` 是 `const char *`，通过 `data` 写内容在编译期即被拒绝。`Str` 的内容不可变：

- 只读的定形内容归 `Str`；
- 构造、拼接、逐字节修改走可变缓冲区（`char` 数组或既有 `Buf`），完成后再转成 `Str`；
- `len` 是构造时的快照，不讨论「可写范围」；
- 需要 NUL 副本或写入调用方缓冲时走 §2.5 的显式方法，不通过 `data` 写。

理由：值语义只有在内容不可变时才成立；若 `data` 可写，借用指针就能绕过深拷贝直接改回原 `Str`，
P2 的拷贝独立性失效。

## 3. 落点、待定项与版本门

以下各项中，落点与归属已由负责人裁定；其余仍需项目组决定。

### 3.1 落点：语言层（负责人裁定 B）

- `Str` 的定义放在**语言层 prelude / 编译器内置声明**，不再由 `lib/std/Str.h.ct` 声明；
- 类型身份、两字段布局、`Drop`、P1/P2 的拷贝语义、方法映射由语言侧拥有；
- `lib/std/Str.h.ct` 不再是定义源；迁移期的兼容形态见 §3.2；
- A 路线（源码定义 + 编译器身份识别）只可作为迁移期的临时形态，不作为最终落点。

### 3.2 与现有 `Str` 声明的关系与迁移路径

- **语言侧可用的那个 MINOR**：语言侧 prelude 提供 `Str`；`lib/std/Str.h.ct` 降为兼容 shim，不再包含
  `pub struct Str` / `impl Drop` / 方法实现，只做转发或留空；编译器开始拒绝用户重复定义 `Str`。
- **其后的那个 MINOR**：删除 std 侧 shim，`Str` 只存在于语言侧；P2 的深拷贝语义在同一版本成为默认。
- 语言侧可用的那个 MINOR 先对 `Str a = b;` 的浅拷贝发弃用警告，给使用方一个 MINOR 的迁移窗口；
  警告文案、回退方式与最终版本位由项目组钉定。

### 3.3 方法层归属

- 方法签名与语义归语言侧；实现以零实现映射为主，子串查找归便利层（§2.4.6）并在本侧只实现一次，
  不引入第二套方法名；
- std 侧不再保留 `Str` 的方法实现；
- `retain()` / `release()` 随 `Str` 迁到语言侧，`Drop` 由语言侧保证；
- `char *` 侧已有方法名与语义，`Str` 侧逐一对应，不另起名字。

### 3.4 与 `char *` 的隐式转换边界

P1 只规定 `char *` → `Str` 的目标类型转换。已定：从 `Str` 借出的 `const char *` 允许存变量，
随 `Str` 失效（P6）；不把 `Str` 隐式转换成 `char *`，借用通过显式视图 / `find` / 方法获得。
跨宿主不靠隐式转换去调用对方的方法，各认各的；确实需要跨侧时显式转换（P8）。

仍需项目组定：

- `char *` → `Str` 是否只允许声明、赋值、传参，还是也允许返回、字段初值、容器字面量、三目；
- 重载/二义时精确匹配与转换的优先级。

### 3.5 内嵌 `\0` 的表示与比较

- 表示：`data` + `len` 已支持内嵌 `\0`（[language-spec.md:2559](../language-spec.md#L2559)）；
- 比较：必须按 `len` 做字节比较，不能只用 NUL 结尾视图（`Map` 的 `Str` 键已按此实现，
  [language-spec.md:2419](../language-spec.md#L2419)）；
- 诊断边界：构造不扫描、不禁止内嵌 `\0`；借用视图不诊断；只有产出 NUL 形态的 `to_c_str()` /
  `copy_to()` 在运行期检查并报错（P9）；
- 与 C 侧对传时，C 读者按 NUL 解释借用视图会在第一个 `\0` 截断；这是借用视图的已知边界；
  产出 NUL 形态的转换不静默截断，而是报错（P9）。

### 3.6 空状态：不表示「没有值」

**结论：`Str` 不表示「没有值」。** 存活且构造成功的 `Str` 满足不变量：`data != NULL`、`len >= 0`，
缓冲区至少 `len + 1` 字节且末尾为 `\0`；空串是 `len == 0` 的合法值。方法层不判空：
`length()` / `is_empty()` 直接读字段，其余方法走 §2.4 的长度版，映射表里没有 `data == 0` 分支。

`NULL` 来源只在**构造点**处理，且必须显式：

- `Str s = NULL;` / `Str s = 0;` 这类编译期可判定的，直接拒绝；
- 运行期才知为 `NULL` 的 `char *`，隐式转换不接受：先判空，或走显式可失败构造；
- 需要表达「可能没有值」时，用可失败构造（`bool` + 出参，或等价结果形态），失败时不产出 `Str`；
  忽略返回值按诊断处理；
- `str_from(NULL)` 仍返回空串（[Str.h.ct:51-60](../../lib/core/Str.h.ct#L51-L60)），这是**显式调用**
  的既定语义，不作为隐式转换的 `NULL` 路径。

不采纳的两条：

1. **`{NULL, 0}` 作为无值状态**。它要求每个方法先判空（`equals` / `compare` / `find` / `slice` /
   `concat` / `split` 都要加前置分支），破坏 P4「展开后与直接调用 C 函数等价」；与 `char *` 宿主
   无法同名同义（P8）；`is_empty()` 与 `length()` 也区分不出空串与无值；`Map` 的 `Str` 键按 `len`
   比较，无值键与空串键会落进同一个桶。要让空串与无值可区分，空串的 `data` 必须非 NULL，
   于是每次空串要么分配 1 字节，要么共享静态缓冲——后者与 `Drop` 的 `free` 冲突，规避需加第三个字段，
   违背 P3。
2. **把 `NULL` 静默转成空串**。`strstr` / `strchr` / `getenv` 一类以 `NULL` 表示未找到或缺失的
   返回值，一旦静默变成 `len == 0`，错误会沿返回值、字段、容器一路传播，而在 §3.6 的不变量下
   没有任何可观测点能发现它。

成立条件：§3.7 已裁定失败取显式失败返回，构造失败不产出 `Str`，`len = -1` 不再作为失败信号，
不变量所需的这一前提已关闭；仍待 §3.4 的 FFI 规则处理 C 侧可以传入 `{NULL, 0}` 的情况，否则
不变量只覆盖语言侧构造的值。完整对抗与逐项依据见
[ct-str-null-state-battle.md](../reviews/ct-str-null-state-battle.md)。

### 3.7 失败政策：显式失败返回（负责人裁定）

**结论：产出型操作在分配失败时通过可判定的返回值报告失败，不终止进程，不返回半成品。**
（2026-11-16 负责人裁定，替换此前「终止 / 释放态」两种待议形态。）

- 适用范围：拼接、切片、转 C 字符串，以及任何「改一个字符产新值」的产出型操作；
- 失败形态：`bool` 加出参（或等价的结果形态），同时设置错误码，由调用方判断；
- 不采用「返回空值」：那依赖 `Str` 能否表示空状态（§3.6 已判不表示无值），且会把「失败」与
  「空串」压成同一个值；
- 不返回半成品：失败时调用方不得收到部分构造或部分写入的值；
- 库不替宿主决定终止：失败必须可被调用方观察到。这是这条裁定的理由。

与 §3.6 的关系：§3.6 的不变量要求「构造失败不产出 `Str`」，本裁定给出它的具体形态；已释放值
（`len = -1`）不是失败信号，也不是「没有值」。

现状差距（按此裁定都要改，本轮不动实现）：

- `str_from_len` 失败返回 `len = -1` 的释放态（[Str.h.ct:39-43](../../lib/core/Str.h.ct#L39-L43)），
  既没有可判定返回值，也没有错误码；
- `str_c_str` 失败返回 `NULL`（[Str.h.ct:117-127](../../lib/core/Str.h.ct#L117-L127)），属「返回空值」形态；
- P2 的「一次分配加一次拷贝」把失败点带到每个赋值/传参位置；隐式转换位置没有返回值通道，
  与「失败必须可观察」存在张力——该位置要么不实施隐式拷贝，要么由项目组另定可观察机制
  （错误码 + 状态检查之类）。本轮不预设。

### 3.8 可用版本与使用方迁移窗口

| 位次 | 语言侧 | std 侧 | P2 拷贝语义 | 使用方 |
| --- | --- | --- | --- | --- |
| 语言侧可用的 MINOR | `Str` 可用；`char *` → `Str` 按 P1 转换 | 仅兼容 shim，无定义 | 浅拷贝 + 弃用警告 | 可停止自行定义/重复提供，改为只消费 |
| 其后的 MINOR | `Str` 唯一来源 | shim 删除 | 深拷贝成为默认 | 不得再依赖 std 侧文件 |

**承诺写相对位次，不写绝对版本号：语言侧可用落在下一个 MINOR，删除落到其后的那个 MINOR。**
这条承诺的实质是顺序与间隔；绝对版本号会被后续变更挤占，一旦挪期就要改承诺。
仅作内部排期参考（非承诺）：按当前节奏大致对应下两个 MINOR。

## 4. 影响面

### 4.1 会改变的既有写法

- `Str a = b;`：从浅拷贝句柄变为深拷贝；原来靠 `retain()` 的调用点会多一次拷贝。
- `Str s = p;` / `f(p)`：从硬错变为隐式转换（P1）。
- 按值传参与返回 `Str`：拷贝开销从 O(1) 变为 O(n)，热点路径需要改用 `char *` 视图。
- 依赖「两个 `Str` 共享同一 buffer」的代码：语义不再成立。
- `s.data[0] = ...` 一类写法变为编译错误；要改内容必须走可变缓冲区再转 `Str`（P7）。
- 借用指针可以存变量，但 `s = other;` / `release(s)` / 离开作用域后立即失效；`s2 = s;` 不影响
  从 `s` 借出的指针（P6）。
- `Str s = p;`（`p == NULL`）不再得到静默空串：字面 `NULL` 编译期拒绝，运行期先判空或走可失败
  构造（§3.6）。
- 产出型操作的失败形态从「`len = -1` 释放态 / 返回 `NULL`」改为显式失败返回（`bool` + 出参 +
  错误码，§3.7）；调用方需要检查返回值。
- std 侧不再提供 `Str` 定义；使用方自行定义或重复提供的 `Str` 会被拒绝。
- 方法层改为语言侧映射：方法名与 `char *` 侧对齐；同一能力不再有独立实现或第二套名字；
  两宿主各维护一份映射，不共用表（P8）。
- 需要 NUL 结尾的调用点必须显式 `to_c_str()` / `copy_to()`；含内嵌 `\0` 时这一步报错，
  不再静默截断。
- `find` 从零实现映射移到便利层：`Str` 侧用标准 C 的 `memchr` 循环实现，最坏 O(n·m)；
  `char *` 侧仍由 C 库 `strstr` 决定；不依赖 `memmem`，无平台条件编译（P10）。

### 4.2 不变的部分

- `Str` 的字段名、顺序、`len` 契约不变；`data` 改为 `const char *`，布局大小不变，写权限收窄；
- `str_from` / `str_from_len` / `str_len` / `str_slice` / `str_concat` / `str_compare` / `str_c_str`
  的公开性不变（改由语言侧提供）；
- `Drop` 仍负责释放；`free(0)` 仍是 no-op；
- `Map` 的 `Str` 键比较仍按 `len` 做字节比较。

### 4.3 需要同步的文档与诊断

- §4.56 的「浅拷贝句柄」表述需要按 P2 改写，并写清「一次分配加一次拷贝」；
- `char *` → `Str` 形参的硬错文案要改为按目标类型的转换；
- 布局承诺需要给出可验证的 `sizeof` / 字段偏移断言；
- 方法映射表（§2.4）与 NUL 例外（§2.5）要写进同一节，注明「无派发开销，底层调用成本仍在」；
- C 对传的可见边界与内嵌 `\0` 诊断（P9、§3.5）、空状态与 `NULL`（§3.6）、失败返回（§3.7）
  要写进同一节；
- 版本门（§3.8）要写清「下一个 MINOR 可用、其后的 MINOR 移除 std」这一相对位次；
  使用方据此安排自己的删除。

## 5. 供评估的验收建议（不构成排期）

- 布局：C 侧 `offsetof(struct Str, data) == 0`、`offsetof(struct Str, len) == sizeof(char *)`、
  `sizeof(struct Str)` 与语言侧一致；`data` 类型为 `const char *`；新增字段的改动能被门禁识别为破坏性变更。
- 只读：`s.data[0] = 'x';` 编译期失败；`s.data` 可赋给 `const char *`，不可赋给 `char *` 而不报警。
- 借用失效：`const char *p = s.data; s = other;` 后再读 `p` 属未定义（文档与夹具标注，不做运行时检查）；
  `const char *q = s.data; Str s2 = s;` 后 `q` 仍有效。
- 借用可存变量：`const char *p = s.find("bc");` 合法；语言侧不拦越界生存期，文档写明。
- 映射独立：`Str` 只命中的方法不会通过隐式转换去调用 `char *` 侧方法；反向亦然；跨侧必须先显式转换。
- 方法名同义：`s.length()` 与 `p.length()` 同名同义，但分别由两份映射各自展开，不共用表。
- P1：`Str s = p;`、`s = p;`、`f(p)` 三处生成转换调用；`char *p = s;`、返回、字段初值仍按
  最终裁定的边界处理。
- P2：`Str a = b;` 后修改 `b` 的内容不影响 `a`；ASAN 无 double-free / 泄漏；
  临时值 `Str a = f();` 的分配计数比「先构造再拷贝」少一次。
- 内嵌 `\0`：`Str` 与 `Str`、`Str` 与 `char *` 的比较按 `len` 判定，不被 NUL 截断。
- 空状态：`{NULL, 0}` 不是合法的 `Str` 值；任何方法都不判空；空串 `len == 0` 与其它值走同一路径。
- `NULL`：`Str s = NULL;` 编译期拒绝；运行期 `NULL` 走可失败构造，失败不产出 `Str`；忽略
  可失败构造的返回值有诊断；显式 `str_from(NULL)` 仍得到空串。
- 失败返回：注入分配失败的夹具下，拼接 / 切片 / `to_c_str` / 「改一字符产新值」均返回可判定的
  失败（`bool` + 出参或等价形态）并设置错误码；进程不终止；调用方拿不到半成品；已释放值
  `len = -1` 不作为失败信号出现。
- 方法映射：`s.length()` 展开为字段读；`equals` / `compare` 用带长度版本；调用点无 vtable、
  无运行时方法表；`to_c_str()` / `copy_to()` 只在显式调用处出现。
- 子串查找：`find` 只由标准 C 的 `memchr` 循环实现，构建里没有 `memmem` 探测分支与平台条件编译；
  单字节查找直调 `memchr`；内嵌 `\0` 的内容可被找到，不在 `\0` 处停。
- 同名同义：同一语义在 `char *` 与 `Str` 两个宿主上方法名一致；`len` 的 O(1) / O(n) 差异写进文档。
- NUL 例外：含内嵌 `\0` 的 `Str` 调 `to_c_str()` / `copy_to()` 报错，不产出副本、不写入；
  借用视图不诊断，调用方按 `len` 处理；构造不扫描、不禁止内嵌 `\0`。
- 版本门：语言侧可用的那个 MINOR 起 std 仅 shim；其后的 MINOR 起 std 侧无 `Str`；重复定义被拒绝。
- 既有显式 `retain()` / `release()` 调用零回归（若保留）。

## 6. 与既有转换提案的关系

本提案处理 `Str` 的内置身份、P1/P2/P3 三条前提、布局承诺、方法映射（含 P10 的便利层）、
P6/P7 的借用与只读规则、P9 的 `\0` 诊断边界；
`char *` / `Str` 转换的适用位置、目标类型归属等细节，另见
[ct-str-char-conversion-proposal.md](ct-str-char-conversion-proposal.md) 及其评审记录。
两份提案的对象不同，评审结论不互相代替；P6 关于「借用可存变量」的裁定覆盖转换提案中「只限立即实参」
的旧口径。
