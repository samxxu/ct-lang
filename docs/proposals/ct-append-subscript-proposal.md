# 提案 · 容器末尾追加的空下标语法（`v[] = x`）

| 项 | 值 |
| --- | --- |
| 状态 | **已被 PH-62 吸收**；保留作 S1 切片参考，不单独排期、不排 phase 卡 |
| 来源 | 负责人语言需求（2026-11-15）：`fields[] = 32;` 表示在末尾追加一个元素 |
| 拟占 | 并入 **PH-62**（`v[] = x` 作为 S1 切片），不再单独占号 |
| 关联 | `Vec::push` / `Vec::set` / `Vec::at` / `Vec::has`、SH-79（模型导出）、PH-58 |
| 定性 | **语法糖**（能力已存在：`v.push(x)`）；新语法形态 → 走提案，不走 patch |

## 1 要解决什么

让「在 `Vec` 末尾追加一个元素」有一个和读下标对称的语句写法：

```ct
fields[] = 32;   // 等价于 fields.push(32);
```

目标是语句层面的可读性，不引入新的容器语义、不改容量策略、不改 ABI。

## 2 现状与证据（HEAD `v0.53.1` 重建）

### 2.1 能力已经存在，只是方法式

[Vec.h.ct:145](../../lib/std/Vec.h.ct#L145)：

```ct
pub int push(T v)   // 成功返回 1；realloc 失败返回 0，容器不变
```

实测：

```ct
Vec<int> v = {1, 2};
v.push(32);         // rc=0；len=3，v[2]=32
```

### 2.2 下标只读，赋值一律被拒

| 写法 | 实测原文 |
| --- | --- |
| `v[0] = 9;` | `c.ct:1:40: error: a Vec subscript is read-only; use set(i, v)` |
| `m["a"] = 1;` | `e.ct:1:39: error: a Map subscript is read-only; use put(k, v)` |
| `v[] = 32;` | `b.ct:1:41: error: expected an expression` |
| `int x = v[];` | `d.ct:1:48: error: expected an expression` |
| `int a[2]; a[] = 1;` | `f.ct:1:30: error: expected an expression` |

`Vec::set(i, v)` 是写入口，但越界是 **no-op**（D50-1 的取用契约），因此现有 `v[i] = x` 被
刻意拒绝，避免「静默不写」。

### 2.3 字面量展开不是追加

`Vec<int> v = {1, 2};` 走 `Vec::from(items, n)`（构造），不能在已有容器上追加。

### 2.4 定性

- **能力**：已有，`push` 就是追加；
- **语法**：没有，空下标目前是解析错误；
- 因此本条是**语法糖 + 新语法形态**（B 类），不是 bug；按既定链条出提案，不进 patch。

## 3 候选写法与取舍

| 方案 | 写法 | 优点 | 代价 / 风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A 空下标赋值**（需求） | `v[] = x;` | 与读下标对称；最短；一眼看出「追加」 | 读 `v[]` 不合法，读写不对称；返回值/失败语义要定；易被误推成 `v[i] = x` 也可写 | **推荐（附条件）** |
| **B 复合赋值** | `v += x;` / `v <<= x;` | 复用运算符 | `+=` 在 C 语境里是数值/字符串拼接，容器上含义歧义；等于开运算符重载口子 | 不采纳 |
| **C 方法式** | 维持 `v.push(x)`，或加 `append` 别名 | 零语法、零解析风险；失败可检查返回值 | 没有满足「下标追加」的写法需求；`append` 只是改名 | 作为兜底 |
| **D 字面量展开赋值** | `v = { ...v, x };` | 无新语法 | 需要展开语法与移动语义，代价远大于收益 | 不采纳 |

推荐 A，但只在下列语义全部写死时成立；否则退回 C。

## 4 语义与边界（必须讲清）

### 4.1 解析：空下标与 `[expr]` 不冲突

- `v[` 后**紧跟 `]`** 且 `]` 后紧跟 `=`，才是追加形态；`v[expr]` 走现有下标解析。
- `v[]` 出现在**读位置**（表达式、初始化、参数）→ 继续报 `expected an expression`，
  可改为更明确的 `empty subscript is only allowed on the left of '='`。
- `v[] += 1`、`v[] == x`、`v[][]= x`、`v[] = {1,2}` → 全部硬错，不猜。
- `v[i] = x` **保持现状**：`a Vec subscript is read-only; use set(i, v)`。本提案不放开带下标赋值。

### 4.2 只对 `Vec<T>` 生效

| 接收者 | 行为 |
| --- | --- |
| `Vec<T>` | 追加，RHS 类型必须可赋给 `T` |
| `Map<K,V>` | 硬错：`Map needs a key; use put(k, v)`（`m[] = v` 没有键，语义不成立） |
| C 数组 / `Str` | 硬错：`C arrays cannot grow` / `Str has no append subscript` |
| 临时值 / 非 lvalue | 硬错：`append target must be a variable, field or element` |

### 4.3 容量与越界

- 容量策略**完全复用 `push`**：满了翻倍，`realloc` 失败返回 0、容器不变；
- 追加没有「越界」概念，`has(i)` / `at(i)` 语义不变；
- 追加后，之前由 `at(i)` 拿到的借用指针失效（与 `push` 相同，需在文档写明）。

### 4.4 失败语义（必须先定）

`push` 的返回值在赋值语句里无处安放，因此三选一：

1. **失败即 abort**（推荐）：降级为 `if (!Vec_push(&v, x)) abort_with("Vec: append failed");`，
   与 `Vec::from` 分配失败 abort 的口径一致；
2. 静默忽略返回值：不推荐，等于掩盖 OOM；
3. 只允许 `push` 处理失败：语法存在但失败即 UB，不可接受。

本提案推荐 1；若研判选 2，则提案不通过。

### 4.5 求值顺序与别名

- LHS 容器只求值一次；RHS 只求值一次；
- 先算 RHS，再 `push`（`v[] = v[0]` 读到的是追加前的值）；
- `v[] = v.at(0)` 类型不匹配（`T*` vs `T`），按类型错误处理；
- `Vec<Vec<int>>` 追加的是句柄值，引用计数仍按 `push` 的 `__ct_elem_retain` 规则处理。

### 4.6 与 `at` / `has` 的关系

- `at` / `has` 是**读/查询**入口，不因本语法改变；
- 追加后 `len` +1，`at(len-1)` 可取到新元素；
- 不提供 `insert(i, x)`、`reserve`、`resize`。

## 5 代价与风险

| 项 | 估计 |
| --- | --- |
| 解析器 | 空下标 LHS 识别 + 诊断，约 **S** |
| 类型检查 | RHS 与 `T` 的赋值兼容、接收者 lvalue，约 **S** |
| 代码生成 | 降级到 `Vec_<enc>_push` + abort 包装，约 **S** |
| 测试 | 正例 4 + 负例 7 + golden 1，约 **S** |
| 风险 1 | 读写不对称引起「为什么 `v[i] = x` 不行」的重复提问 → 诊断文案与文档写死 |
| 风险 2 | 失败语义被实现成静默忽略 → 评审卡住 |
| 风险 3 | 语法面扩张带来 `v[i] = x` 的持续压力 → 非目标写死，另案处理 |
| 风险 4 | 与 C 数组的 `a[]` 混淆 → 对 C 数组给专门诊断 |

## 6 非目标

- 原「不放开 `v[i] = x`」**已废止**：由 PH-62 接管（越界硬错 + 常量折叠）；
  本提案只保留 `v[] = x` 切片，不再作为独立非目标；
- 不支持 `Map` / C 数组 / `Str` 的空下标；
- 不做 `insert(i, x)` / `reserve` / `resize` / 拼接；
- 不做运算符重载（`+=` 等）；
- 不让该形态出现在表达式位置（无返回值）；
- 不改 `push` 的签名与返回值。

## 7 ABI / 兼容性

- **零 ABI**：降级为既有 `Vec_push` 调用，不新增 C 符号、不改 `.h` / `.abi.h`；
- **兼容**：`v[] = x` 今天本来就是解析错误，不存在「合法程序改义」；
- `v[i] = x`、`m[k] = v`、C 数组的行为逐字节不变；
- 模型导出 / `--emit-map`：新语法不影响模型，AST 只是多一种赋值形态。

## 8 验收判据草案

| ID | 判据 |
| --- | --- |
| A1 | `Vec<int> v={1,2}; v[]=32;` → `len=3`、`v[2]=32`，等价 `push(32)` |
| A2 | 空 `Vec<int> v={}; v[]=1;` → `len=1`（`push` 自建 header） |
| A3 | `v[] = v[0]` 取追加前的值（先算 RHS） |
| A4 | 读 `v[]`、`v[] += 1`、`v[] == x`、`v[][]`、`v[]={1,2}` 全部硬错，诊断含「只能出现在 `=` 左侧」 |
| A5 | `Map<char*,int> m; m[]=1;` → 硬错，提示用 `put(k, v)` |
| A6 | `int a[2]; a[]=1;` → 硬错，提示 C 数组不能增长 |
| A7 | 原「`v[0]=9;` 仍报 read-only」**已废止**：由 PH-62 改为可写 + 越界硬错，见 [可写下标提案](ct-writable-subscript-proposal.md) |
| A8 | RHS 类型不匹配 → 与 `push` 相同的类型错误，不写 `.c` |
| A9 | `make_vec()[] = 1;` → 硬错（接收者必须是 lvalue） |
| A10 | 生成 C 只含 `Vec_<enc>_push` + abort 包装；`.abi.h` 逐字节不变 |
| A11 | 追加 N 次后 `len=N`；`at(N-1)` 指向最后元素（借用语义不变） |

## 9 排位与后续

- 位置：**并入 PH-62**（[容器下标可写与嵌套链](ct-writable-subscript-proposal.md)），作为其 S1 切片；
  不再单独占 PH-61，也不单独排期；
- 理由：PH-62 要放开 `v[i] = x`，与本提案原「不放开」非目标直接冲突；先发会造成同一处语法/发射返工；
- 依赖：无语言依赖；改 `frontend/parse/Expr.h.ct` 与 `Emitter`，与 TypeCheck/Expr 族**串行**；
- 研判记录见 [ct-append-subscript-proposal-review](../review/ct-append-subscript-proposal-review.md)；
  该记录的「不放开 `v[i] = x`」结论已被 PH-62 取代；
- 提案阶段不改 `selfhost/**`、不排 phase 卡。
