# 记录：Phase 53 — `?.` 可选链（待商定）

> **状态：已定稿为 PH-53 施工（2026-11-15）**；施工卡见 [history/design/phase53.md](../history/design/phase53.md)。
> 本文保留语义、切词策略与 battle 结论；不单独承诺实现、不 bump。
> **定性**：`?.` 是**纯语法糖**，编译期展开成条件判断，零运行时开销、不改 ABI，目的是避免空指针。
> **关联**：[裁决记录 U-5](../reviews/phase46-52-freeze-verdict.md)、[REQ-JSACCESS-1](../planning/requirements-pool.md)、
> [第二轮 battle 记录](../reviews/phase53-optional-chain-battle.md)。
> **纪律**：本文只记录结论与判据，不写实现落点；实现细节留在卡面。

## 1 一句话定性

`?.` 不引入运行时设施：编译器把 `a?.b` 展开成 `(a ? a->b : 0)` 一类的条件表达式，生成的就是等价 C；
不引入 helper、不改 vtable / 接口 struct / ABI。

## 2 最小版本（只这一格）

- **只收指针接收者**，**只覆盖字段访问**：`a?.b` → `(a ? a->b : 0)`；
- **值上取到的一跳允许继续 `?.`**：`a.b?.c` 中 `b` 是指针时，`?.` 的接收者是 `a.b`（指针），
  不是 `a`；map 形态 `a.m["k"]?.c` 要求 `Map<K, V>` 的 `V` 是值类型（`get` 返回 `V*`）；
  `V` 为指针时 `get` 返回 `V**`，直接 `?.c` 不成立。接收者表达式只求值一次（先落临时量）；
- 结果只允许指针或标量；值类型/带 Drop 的 struct 结果不在本格；
- JSON 的 `JsonRef *` 访问正好落在这格：`doc?.obj`、`node?.next` 这类 C 字段链。

## 3 后续格（只列名字与一句为什么难）

| 格 | 为什么难 |
| --- | --- |
| 值接收者 `a?.b` | 值类型没有「空」；已裁定不支持（§4.1）；除非另立显式可空类型 |
| 可选下标 `a?[k]` | 两种接收者下都不合法（值不能作条件、指针不能用 `.`），需按元素类型单独设计 |
| 可选方法调用 `a?.get(k)` | 依赖指针接收者 `.` 的发射缺陷先修（PH-51），且接收者求值次数要定义 |

## 4 两条语义卡点与一条切词策略

### 4.1 普通 struct 值接收者：不支持（2026-11-15 battle 裁定）

值类型没有「不存在」这个状态。实测（探针与命令见
[第二轮 battle 记录](../reviews/phase53-optional-chain-battle.md) §5）：

- 值不能作三目条件：`s ? s.b : 0` → `cc` rc=1；`s` 为 `struct S`，`cc` 报
  `used type 'struct S' where arithmetic or pointer type is required`。
- 零值/哨兵不可判定：`s.present ? s.b : 0` 与 `MaybeS` 包装都能编译，但「缺失」与「值为 0」
  输出同一个 `0`。
- 含 Drop 字段不能浅拷贝：三元浅拷贝后双方 drop → ASAN `double-free`，rc=134；
  `Maybe<D>` 包装同样 rc=134。
- 零值不是合法的「空」：带 vptr 的 struct 零值 vptr 为 NULL，调用即段错误 rc=139。
- 值接收者的字段地址恒非空：`&a.b` 恒非空，`(p ? p->b : 0)` 的 false 分支不可达。

**结论**：普通 struct 值接收者的 `?.` 不支持；要支持只能引入显式可空类型（`Maybe<T>` / `T?`）
与 move/部分移动规则，那是新类型特性，不是本卡的语法糖。重新开启条件见 battle 记录 §2。

**2026-11-15 补充（不改结论）**：值接收者本身仍拒绝；但「值上取到的一跳」如果是**指针或 map**，
应当允许继续 `?.`，例如 `a.b?.c` 中 `b` 为 `struct B *`、或 `a.m["k"]?.c` 中 `m` 为
`Map<char *, B>`（`V` 是值类型）。这里的接收者是 `a.b` / `m["k"]`（指针），不是 `a`（值），
走的是指针规则。若 `Map` 的 `V` 本身是指针，`get` 返回 `V**`，`a.m["k"]?.c` 不成立
（需 `(*a.m["k"])?.c`，不属于本正例）。接收者必须只求值一次（`a.b` 先落临时量；实测 naive
展开会把 `make().b` 调两次）。**当前实现的事实**：`?.` 尚未实现，N1（`a?.b` 值接收者）与
P1/P2（值上取到的指针/map 跳）在 `ct v0.44.1` 上全部 rc=1，都报 `'?' needs a Result operand`；
现有实现没有这条接收者类型区分，正例目前走不通。同一语义用显式三目今天可编译
（`p3_field_ptr_manual` / `p5_map_value_manual`：`ct` rc=0、运行 rc=0），说明缺的是 `?.`
语法与单次求值，不是类型能力。判据见 battle 记录 §4 N1/P1/P2/P3。

### 4.2 切词策略（不再是阻塞或风险）

`?` 不合成独立 token，仍是 `?`；parser 在 `?` 之后按下一个 token 判定：

| `?` 后 | 判定 | 用例 |
| --- | --- | --- |
| `T_NUM` 且文本以 `.` 开头 | 三目 + 浮点字面量 | `c?.5 : 1.0` → `(c ? .5 : 1.0)` |
| `T_PUNCT "."`，再下一个是 `T_ID` | 可选链 | `a?.b` → `(a ? a->b : 0)` |
| 其他 | 维持 PH-44 的后缀 `?` / 三目规则 | `x?;`、`a ? b : c` |

现状实测（`ct v0.44.1`，`/tmp/ctgap/bin/ct`）：`c?.5 : 1.0` 为 `ct` rc=0，生成
`double d = (c ? .5 : 1.0);`，运行 rc=0；`a?.b` 为 rc=1，报 `'?' needs a Result operand`
（值接收者与指针接收者相同）。词法依据：`.5` 在 `Lexer.h.ct:244-271` 整体扫成 `T_NUM`，
`?` 在 `:356` 走单字符 `T_PUNCT`，两条路径不合并。

可执行判据（T1–T6）见 [battle 记录 §4](../reviews/phase53-optional-chain-battle.md)；
两席均不得再用「独立 `?.` token」或「`c?.5` 必然被破坏」作为论据。

### 4.3 `a?[k]` 在两种接收者下都不合法

- 值接收者：`a` 不能作三元条件（同 §4.1 的 `cc` 错误）；
- 指针接收者：展开里的 `a.get(k)` 用 `.`，对指针接收者不成立。

故 `a?[k]` 必须单列后续格，不能顺手并进 MVP。

## 5 结论

- **接收者范围**：只收指针（含 `Map::get` 返回的 `T*`）；`p?.field` 展开为 `(p ? p->field : 0)`，
  map 键缺失整链短路、结果 NULL，不引入新运行时。值上取到的指针/map 跳（`a.b?.c`）同属指针规则，
  允许继续 `?.`；值接收者本身（`a?.b`）仍拒绝。
- **普通 struct 值接收者不支持**：值类型没有「不存在」状态；零值、哨兵、`Maybe<T>` 包装都
  无法在不引入新类型/新所有权规则的前提下成立（见 §4.1 与 battle 记录）。
- **切词**：按 §4.2 的 parser 组合识别；`c?.5 : 1.0` 保持三目，`a?.b` 走可选链，非阻塞项。
- **`a?[k]`** 仍在两种接收者下都不合法，单列后续格；不并入本卡。
