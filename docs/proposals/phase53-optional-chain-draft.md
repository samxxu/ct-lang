> **定性**：`?.` 是**纯语法糖**，编译期展开成条件判断，零运行时开销、不改 ABI，目的是避免空指针。

## 1 一句话定性

`?.` 不引入运行时设施：编译器把 `a?.b` 展开成 `(a ? a->b : 0)` 一类的条件表达式，生成的就是等价 C；
不引入 helper、不改 vtable / 接口 struct / ABI。

## 2 最小版本（只这一格）

- **只收指针接收者**，**只覆盖字段访问**：`a?.b` → `(a ? a->b : 0)`；
- 结果只允许指针或标量；值类型/带 Drop 的 struct 结果不在本格；
- JSON 的 `JsonRef *` 访问正好落在这格：`doc?.obj`、`node?.next` 这类 C 字段链。

## 3 后续格（只列名字与一句为什么难）

| 格 | 为什么难 |
| --- | --- |
| 值接收者 `a?.b` | 值类型没有「空」；三元展开在值类型上过不了 `cc`（§4.1 实测），要临时量或改接收者规则 |
| 可选下标 `a?[k]` | 两种接收者下都不合法（值不能作条件、指针不能用 `.`），需按元素类型单独设计 |
| 可选方法调用 `a?.get(k)` | 依赖指针接收者 `.` 的发射缺陷先修（PH-51），且接收者求值次数要定义 |

## 4 三个已知卡点

### 4.1 值接收者下三元过不了 `cc`（实测）

```text
$ cc -Wall -Wextra -std=c99 opt_field_val.c -o opt_field_val
error: member reference type 'struct S' is not a pointer; did you mean to use '.'?
error: used type 'struct S' where arithmetic or pointer type is required
cc rc=1
```

同一展开在指针接收者上 `cc rc=0`、运行 rc=0。所以值接收者不是「补规则」，而是语义不成立。

### 4.2 `?.` 与三目 `c?.5 : 1.0` 的切词冲突

今天 `c?.5 : 1.0` 合法：`ct-ast` rc=0，生成 `(c ? .5 : 1.0)`（实测）。若把 `?.` 按最长匹配合成独立
token，`c?.5` 会被切成 `?.` + `5`，既有程序静默变错。解法方向是「词法不动、parser 组合识别，
`.` 后必须是标识符」，但细节留 battle。
另：`a?.b` 今天 rc=1，报 `'?' needs a Result operand`，没有历史语义要兼容。

### 4.3 `a?[k]` 在两种接收者下都不合法

- 值接收者：`a` 不能作三元条件（同 §4.1 的 `cc` 错误）；
- 指针接收者：展开里的 `a.get(k)` 用 `.`，对指针接收者不成立。

故 `a?[k]` 必须单列后续格，不能顺手并进 MVP。
