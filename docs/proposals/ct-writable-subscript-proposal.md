# 提案 · 容器下标可写与嵌套下标链（`m[k] = v` / `v[i] = x` / `m["a"]["b"]`）

| 项 | 值 |
| --- | --- |
| 状态 | **提案（待研判）**；不排 phase 卡、不改 `selfhost/**` |
| 来源 | 负责人判定为必须补的能力缺口：Map / Vec 只能读不能写，JSON 写回无法完成（2026-11-15） |
| 拟占 | **PH-62**；吸收 PH-61（`v[] = x` 作为其中一个切片），不另立两个 phase |
| 关联 | [PH-61 追加下标](ct-append-subscript-proposal.md)、LANG-13（三级链）、PH-53（`?.` / `?[`）、`Vec::get/set/at`、`Map::get/put` |
| 定性 | **新能力（B）**：可写下标与嵌套写是新语法/新语义；其中「朴素嵌套读发出坏 C」是 A 类 bug，可单独止血 |

## 1 要解决什么

让下面这段真实 JSON 写回代码成立：

```ct
doc["server"]["host"] = "192.168.0.6";
```

今天同时踩两条：

1. `m["server"] = x` 被前端拒绝：`a Map subscript is read-only; use put(k, v)`；
2. `m["server"]["host"]` 被发成 `Map_get(&m, "server")["host"]`，C 编译器报
   `array subscript is not an integer`。

需要覆盖：单层写（`m[k] = v`、`v[i] = x`）、嵌套读、嵌套写、越界语义、`Map` 指针值的
lvalue 规则，以及与 PH-61（`v[] = x`）的边界。

## 2 现状与证据（HEAD `v0.53.1` 重建）

### 2.1 单层写被拒

```ct
Map<char *, int> m; m.h = 0; m["a"] = 1;
// b.ct:1:-3788: error: a Map subscript is read-only; use put(k, v)

Vec<int> v = {1, 2}; v[0] = 9;
// c.ct:1:-3796: error: a Vec subscript is read-only; use set(i, v)
```

### 2.2 嵌套朴素写/读发出坏 C

```ct
Map<char *, Map<char *, char *> > doc; doc.h = 0;
doc["server"]["host"] = "192.168.0.6";
```

```text
a.ct:14:57: error: array subscript is not an integer
    Map_char_p_Map__char__p__char__p_get(&doc, "server")["host"] = "192.168.0.6";
                                                        ^~~~~~~
```

读也一样：

```ct
char **p = doc["server"]["host"];
// d.ct:14:70: error: array subscript is not an integer
//   char * * p = Map_..._get(&doc, "server")["host"];
```

`ct` 自身返回 0，只有 `cc` 报错——属于「静默坏 C」，按 D-005 是可单独止血的 A 类子项。

### 2.3 `?[` 不能写

```ct
doc["server"]?["host"] = "x";
// e.ct:1:-3755: error: optional chain/subscript is not an lvalue; it cannot be assigned or address-taken
```

可选链只解决读，不解决写。

### 2.4 Vec / Map 的取值形态不同

- `Vec<T>::get(int) -> T`（值；越界零值，D50-1）；`at(i) -> T*`；`set(i, v)` 越界 **no-op**
  （[Vec.h.ct:97](../../lib/std/Vec.h.ct#L97)、[Vec.h.ct:121](../../lib/std/Vec.h.ct#L121)、
  [Vec.h.ct:132](../../lib/std/Vec.h.ct#L132)）。
- `Map<K,V>::get(K) -> V*`（缺键 0）；`put(K,V)` 插入/覆盖；`char *` 键借用，`Str` 键深拷贝。

嵌套写 `Map<char *, Vec<int> > m; m["a"][0] = 1;` 当前生成：

```c
Map_char_p_Vec__int_get(&m, "a")[0] = 1;
// error: assigning to 'struct Vec_int' from incompatible type 'int'
```

即 `Map_get` 返回的是 `Vec<int> *`，`[0]` 落到指针上得到 `Vec<int>` 值，不是 `int` 槽位。
嵌套物化必须按「Map 步取指针、Vec 步用 `at` 取指针」展开，不能照抄 C 的下标链。

## 3 定性

| 子项 | 定性 | 理由 |
| --- | --- | --- |
| `m[k] = v` / `v[i] = x` | **B 新能力** | 新语法 + 新写语义；今天硬错，不是既有承诺 |
| 嵌套读 `m["a"]["b"]` | **A 子项**（可独立止血） | ct 放行、发出坏 C；最小止血是硬错，完整修复在 PH-62 |
| 嵌套写 `m["a"]["b"] = v` | **B 新能力** | 需要物化、自动创建、所有权规则 |
| `?[` 写 | 保持拒绝 | PH-53 明确可选链只读 |
| `v[] = x`（PH-61） | **B 语法糖**，并入本 phase | 与可写下标共用语法/发射路径，分开做会重复改同一处 |

## 4 候选与取舍

### 4.1 总体写法

| 方案 | 做法 | 优点 | 代价 / 风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A 下标可写 + 嵌套链**（推荐） | `m[k] = v`、`v[i] = x`、`m["a"]["b"] = v` 统一走赋值路径 | 满足 JSON 写回；读写形态对称；不改变读表达式类型 | 解析/类型检查/发射都要改；嵌套物化与所有权复杂 | **推荐** |
| B 只加方法/辅助函数 | 保留只读下标，新增 `Map::at` / `Vec::at` + `put`/`set` 组合 | 零语法风险 | `doc["server"]["host"] = ...` 仍写不出来；用户要的形态没解决 | 兜底 |
| C 把下标读改成真 lvalue | `m[k]` 读类型从 `V*` 改为 `V`，`v[i]` 为 `T` 左值 | C 式写法自然 | 破坏 `*m["a"]`、`m["a"] == 0`、`get` 指针契约；既有代码大面积失效 | 不采纳 |

### 4.2 `v[i] = x` 越界语义（必须正面解决）

| 方案 | 语义 | 取舍 |
| --- | --- | --- |
| **A1 硬错 + 常量折叠**（推荐） | 常量下标越界 → 编译错误；运行时越界 → `abort` 并打印 index/len | 不静默；与 `set` 的 no-op 明确区分；读写不对称（读仍零值）需文档写明 |
| A2 自动扩展 | `i >= len` 时补零到 `i` 再写 | 稀疏数组方便，但会掩盖下标 bug、内存可被放大；与 `push` 语义冲突 | 不采纳 |
| A3 沿用 `set` 的 no-op | 越界静默不写 | 正是负责人要求正面解决的问题；不采纳 | 不采纳 |

推荐 **A1**：新增语法不复用 `set` 的越界 no-op，而是在发射时插入边界检查；`set` 本身签名与
行为不变，既有调用者不受影响。

### 4.3 嵌套读的缺席语义

| 方案 | 语义 | 取舍 |
| --- | --- | --- |
| **R1 零值传播**（推荐） | 任一层 `Map` 缺键 → 最终结果为零值（`V*` 为 0）；不崩溃 | 与单层 `Map::get` 缺键返回 0 一致；`?[` 仍可用于混合指针链 |
| R2 硬错 | 任一层缺键 → abort，提示用 `?[` | 更严格，但与单层 `m["k"]` 返回 0 不一致 |
| R3 读时自动创建 | 缺键就建空 Map | 读操作产生副作用，拒绝 |

推荐 **R1**：嵌套读只是把既有的「缺键 → 0」传播到链上；写才自动创建。

### 4.4 嵌套写的中间缺失

| 方案 | 语义 | 取舍 |
| --- | --- | --- |
| **W1 写时自动建 Map**（推荐） | 中间槽是 `Map` 且缺键 → 建空 Map、`put` 进上层、继续写；`Vec` 越界仍 abort | `doc["server"]["host"] = ...` 直接成立；需要正确 release 临时句柄 |
| W2 硬错 | 中间缺失 → abort，要求先显式 `put` 空 Map | 简单，但 JSON 写回要写一堆样板 |
| W3 Map / Vec 都自动建 | Vec 缺位补零 | Vec 空洞语义危险，且与 A1 冲突 | 不采纳 |

推荐 **W1**：只自动创建 `Map` 中间层，不自动扩展 `Vec`；中间是 `Vec` 时按 A1 处理。

## 5 推荐语义（组合后）

### 5.1 语句形态与 lvalue

- `m[k] = v;`、`v[i] = x;`、`m["a"]["b"] = v;` 都是**语句级赋值形态**，返回 `void`；
  不能出现在表达式里，不能取地址，不做 `+=` / `++`（第一版）。
- `m[k]` 的**读**类型仍是 `V*`；`v[i]` 的读类型仍是 `T`。既有 `*m["a"]`、`v[0]` 不变。
- `&m["a"]`、`m["a"] += 1`、`v[0] += 1`、`(m["a"] = 1) + 1` 全部硬错。
- RHS 按普通表达式类型求值，**不做隐式解引用**：`m["a"] = m["b"]` 不成立（`m["b"]` 是 `V*`），
  要复制值写 `*m["b"]`；`v[0] = v[1]` 是值拷贝，可直接写。
- `?[` / `?.` 仍只读；赋值报既有的 `optional chain/subscript is not an lvalue`。

### 5.2 降级规则（物化）

| 步骤 | 读 | 写 |
| --- | --- | --- |
| Map 键 | `V *p = Map_get(parent, k)`；`p == 0` 时按 R1 返回零 | 最终步 `Map_put(parent, k, rhs)`；中间步缺键按 W1 建空 Map 后重取 |
| Vec 下标 | `T v = Vec_get(parent, i)`（值为零值语义） | 中间步 `T *p = Vec_at(parent, i)`，`p == 0` → abort；最终步 `Vec_set(parent, i, rhs)` |
| 根 | 变量地址 `&root` | 同左 |

- 嵌套写必须用 `Vec_at` 取中间 `Vec` 槽的指针，不能用 `Vec_get` 的值拷贝；
  否则会写出「改副本」的 bug。
- 求值顺序：先算 RHS，再逐层物化并写入；中间自动创建的 Map 句柄在写入后 `release`，
  避免引用计数泄漏。
- 常量下标在类型检查期折叠：`v[5] = 1` 且已知 `len == 2` 时直接编译错误；
  动态下标走运行时 abort。

### 5.3 自动创建与所有权

- 只对 `Map` 中间层自动创建：新建 `Map<K,V>`（`h = 0`）→ `put` 进上层 → 取回指针 → 继续；
  写入结束后 `release` 本地句柄。
- `Map<char *, V>` 的键仍借用；`Map<Str, V>` 的键由 `put` 深拷贝。
- `Vec` 中间层不自动扩展；`Vec<T>` 元素按 `set` 的 retain/release 规则处理。
- 嵌套写 `m["a"]["b"] = m["x"]["y"]` 这类别名场景：先读完 RHS，再开始写入。

## 6 代价与风险

| 项 | 估计 |
| --- | --- |
| 解析器 | 下标赋值路径 + 空下标（PH-61）合并，约 **M** |
| 类型检查 | 写路径类型、lvalue 限制、常量越界折叠，约 **M** |
| 代码生成 | Map/Vec 指针物化、自动创建、临时句柄 release、诊断，约 **M–L** |
| 测试 | 正例 8 + 负例 8 + ASan/引用计数夹具 + golden，约 **M** |
| 风险 1 | 物化用错（`get` vs `at`）导致改副本 / 类型错 → 用 `m["a"][0] = 1` 夹住 |
| 风险 2 | 自动创建中间 Map 的临时句柄泄漏 → 引用计数/ASan 夹具 |
| 风险 3 | 读写语义不对称（读零值、写 abort/创建）引起误解 → 文档与诊断写死 |
| 风险 4 | 与 PH-61 的「不放开 `v[i] = x`」冲突 → 本提案吸收 PH-61，废止该非目标 |
| 风险 5 | 位置诊断已有负数行号（`1:-3788`）→ 顺手修诊断位置，避免新错误也带负号 |

## 7 非目标

- 不做 `+=` / `++` / 复合赋值；
- 不做 `Vec` 自动扩展、`insert` / `remove` / `resize`；
- 不改 `Map::get -> V*`、`Vec::get -> T`、`put` / `set` 的签名与越界 no-op；
- 不做 `Map` 点访问（`m.a`）、不改 `?.` / `?[` 的只读属性；
- 不做 `Vec` 元素 struct 的字段写（`v[i].f = x`），除非它自然落入同一物化路径；
- 不做 JSON 专用语义，全部按通用容器定义。

## 8 ABI / 兼容性

- **零 ABI**：降级为既有 `Map_get` / `Map_put` / `Vec_get` / `Vec_set` / `Vec_at` 调用；
  如需要辅助函数，只在生成的 `.c` 内以 `static` 形式出现，不新增导出符号，不改 `.h` / `.abi.h`。
- **兼容**：`m[k] = v`、`v[i] = x` 今天都是硬错；`m[k]` 读类型不变，`*m["a"]` 等既有写法不变。
- `set` 的越界 no-op 保持；只有新语法插入边界检查并 abort。
- 嵌套读今天发出坏 C，修复后变为合法 C；不改变任何已成功编译程序的行为。

## 9 验收判据草案

| ID | 判据 |
| --- | --- |
| W1 | `Map<char*,int> m; m["a"] = 1;` → `*m["a"] == 1`；重复写覆盖；缺键插入 |
| W2 | `Vec<int> v={1,2}; v[0]=9;` → `v[0]==9`，`len` 不变 |
| W3 | `v[2]=9`（len=2）→ 运行时 abort，消息含 index/len；常量 `v[5]=9` → 编译错误 |
| W4 | `doc["server"]["host"]="192.168.0.6";` → 中间 Map 自动创建，`*doc["server"]["host"]` 为原串 |
| W5 | 嵌套读缺键 → 零值（R1），不崩溃；`?[` 仍可读 |
| W6 | `Vec<Vec<int>> vv; vv[0][0]=1;` → 外层存在则写内层；外层越界 abort |
| W7 | `Map<char*,Vec<int>> m; m["a"][0]=1;` → 用 `Map_get` 指针 + `Vec_set`，不出现 `struct Vec_int` 赋值错误 |
| W8 | `m["a"]=1` 类型不匹配 → 编译错误，不写 `.c` |
| W9 | `&m["a"]`、`m["a"] += 1`、`v[0] += 1`、`(m["a"]=1)+1` → 硬错 |
| W10 | `?[` / `?.` 赋值仍报 `optional chain/subscript is not an lvalue` |
| W11 | 既有读 `*m["a"]`、`v[0]`、`vv[0][0]` 逐字节不变（golden） |
| W12 | 自动创建中间 Map 后引用计数归零（ASan/valgrind 或 release 断言） |
| W13 | `Map<Str,int>` 键写入深拷贝；`Map<char*,int>` 键借用（所有权夹具） |
| W14 | 无新语法的程序 `.c` / `.h` / `.abi.h` 零变化 |

## 10 排位与 PH-61 的关系

- **拟占 PH-62**，接替 PH-61 的排位；PH-61 的 `v[] = x` 作为 PH-62 的 **S1 切片**，
  不再单独占号。理由：PH-61 的非目标（不放开 `v[i] = x`）与本需求直接冲突，若先发 PH-61
  再改同一处语法/发射，会产生一次返工和自相矛盾的中间态。
- PH-61 的研判结论「失败即 abort、仅 Vec、语句级」保留；其中「不放开 `v[i] = x`」被本提案废止。
- 依赖：无语言依赖；与 PH-53 / PH-59 / PH-60 无依赖；改 `Expr` / TypeCheck / Emitter，
  与 TypeCheck/Expr 族**串行**。建议切片：
  S0 读物化 + 诊断位置；S1 `v[]=x`（吸收 PH-61）；S2 单层写 + 越界策略；
  S3 嵌套读；S4 嵌套写 + Map 自动创建；S5 所有权/ASan/golden。
- 本轮只到提案 + 研判，不排 phase 卡；先补 A 类止血（嵌套读硬错或修复）可另开 patch。

## 11 开放问题

1. 运行时越界 abort 的错误码与文案（建议 `Vec: write index out of range`）；
2. 自动创建中间 Map 时，是否允许键类型不是 `char *` / `Str` 的组合（按 `Map` 白名单即可）；
3. `Vec` 中间层是否允许自动 push 到 `i`（本提案拒绝，保持 A1）；
4. `v[i] = x` 是否允许常量折叠在 `len` 未知时只做运行时检查；
5. 是否顺手修 `1:-3788` 这类负行号诊断（建议单独 patch）。
