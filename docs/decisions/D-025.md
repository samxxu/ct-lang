# D-025 · std 0.20.0 的 `CharStr` 改名不保留旧名别名（PKG-22）

- 日期：2026-11-23
- 状态：**accepted（兼容裁定）**；执行随 PKG-22 的 pin + 消费者原子迁移，不单独 bump 版本
- 目标：`v1-PH-0` 开卡之前完成；不新增 phase
- 签收：REQ 2026-11-23（owner 交底授权 REQ 裁定，见 PKG-22 §裁定）
- 依据：[PKG-22](../../issues/packages/pkg-22-std-str-charstr-rename.md) 复核（REV 2026-11-22）
  与 §裁定（REQ 2026-11-22）；[language-spec §5.1](../language-spec.md#51-源码命名约定语言--标准库--ct-pkg稳定契约)
- 决策范围：只定 `std::str::String` → `std::str::CharStr` 的兼容策略，以及本仓内置 pin 与
  消费者/推荐写法的迁移；不改内置 `String` / `Str`、不复制 std 包源码、不动 `std::*` 其他单元

## 1. 裁定

**接受 std 0.20.0 包侧的既成决定：不保留旧名别名。** `std/str/` 只有
`CharStr.m.ct` / `CharStr.shim.h`，没有 `String.m.ct`，也没有 `import std::str::String;`
的兼容转出。本仓自内置 pin 升到 `0.20.0` 起：

- 推荐写法与可运行示例一律写 `import std::str::CharStr;`；
- `import std::str::String;` 必须失败（`cannot resolve import 'std/str/String'`），
  文档不再承诺兼容窗；
- 测试 pin、索引样例与安装示例同步到 `0.20.0` / `v0.20.0` / 发布索引的 digest。

本裁定**取代** PKG-22 原决策表的「兼容」行与验收 2、7：

| 原条目 | 原内容 | 现状态 |
| --- | --- | --- |
| 决策表「兼容」 | 旧 `String.m.ct` 作为薄兼容单元保留一个 MINOR | **废止**；旧名不保留，本仓不以任何形式要求包侧补别名 |
| 验收 2 | 旧 `import std::str::String;` 在兼容窗内仍可用，文件头有 deprecation | **取代**：旧导入必须失败，文档不承诺兼容窗 |
| 验收 7 | 一个 MINOR 后移除 `String.m.ct`，另立清理 issue | **不再需要**：一次原子迁移完成，不另立清理 issue |

验收 1、3、4、5、6 不变（新名可用；无 `CStrOps` 残留；包版本/索引/verify；消费者迁移；
内置 `String` / `Str` / `Vec` 等不受影响）。

## 2. 理由

1. **包侧事实先于本仓承诺。** std 0.20.0 已把单元与 trait 一起改为 `CharStr`；旧导入在
   0.20.0 上直接 `cannot resolve import 'std/str/String'`，`CHANGELOG` 明示不留兼容别名。
   本仓文档若继续写「旧名一个 MINOR」就是承诺一个包侧不存在的回退。
2. **本仓不代改、也不要求包侧改。** 按 AGENTS §9.8 DB-5 / §9.10 CF-1，跨仓问题只登记提案；
   std 包是否保留别名由包维护者决定。PKG-22 已复核并记录包侧决定，本仓只能选择跟随或继续
   pin `0.19.0`；继续 pin 与 `CharStr` 目标及 `v1-PH-0` 前的迁移触发条件冲突。
3. **项目尚未正式发布。** std 0.20.0 的 `CHANGELOG` 以「项目未正式发布」为不留别名的理由；
   本仓的示例与文档是仓内消费者，不是已发布 API，迁移成本可控。
4. **留别名会延长错误写法。** §5.1 的目标是消除 `String` 与内置 `String` 的混淆；保留旧名会让
   推荐写法继续分叉，且要在下一个 MINOR 再删一次。
5. **迁移必须原子。** pin 升到 0.20.0 后 0.19.0 的 `String.m.ct` 不在 store 中：只升 pin 不迁移
   示例会立刻编译失败，只迁移示例不升 pin 则 0.19.0 没有 `CharStr`。因此 pin、消费者与测试
   必须在同一次迁移内完成。

## 4. 回滚

- 回滚以「pin + 消费者 + 测试」的原子迁移为单位：`git revert` 迁移提交（连同其红证测试提交）
  后，pin 回到 `0.19.0`，示例/文档/测试同时回到 `std::str::String`。**不得只回滚 pin 或只回滚
  示例/文档**——两种半回滚都会留下不可编译或与包内容不一致的树。
- 回滚不恢复 `String.m.ct` 兼容承诺，也不改写包侧历史；D-025 作为已作出的裁定量保留，
  后续若重新评估须另立 decision。
- 若 std 包未来自行重新提供 `std::str::String` 别名，本裁定不自动失效；是否改回旧名需新的
  REQ 裁定，且不延长旧名承诺。
