# D-021 · JSON 树方案 B（无 arena）设计

- 日期：2026-11-23
- 状态：**accepted（设计）**；实现按 [LANG-28](../../issues/lang/lang-28-json-tree-b.md) 分阶段，LANG-27 为前置
- 目标：v1.1（容量与语言特性 ADR 复核后；不阻塞 v1.0）
- 签收：USER 2026-11-23（逐项裁定 B1–B8）；批准：EDITOR 2026-11-23
- 依据：所有者 2026-11-23 逐项裁定；[JSON v1.1 提案评估](../reviews/2026-11-23-json-v11-proposal-eval.md)
- 决策范围：仅“树存储与绑定体验”，不含外部 `ct/json` / `ct/tree` / `ct-gen` 的交付排期

## 1. 树表示与布局

- `JsonNode` 是递归 ADT，payload 直接存容器句柄：`Arr(Vec<JsonNode>)`、`Obj(Map<String,JsonNode>)`；
- 发射器在 ADT 之前**预发射具体实例壳**（如 `struct Vec_JsonNode { ct_buf *h; }`），方法体与
  `MapEntry_*` 仍在其后；递归实例按拓扑序、防环；
- `Bool` 统一发射 `_Bool`，不依赖 `<stdbool.h>`；
- 数字模型：`Int(long long v)` + `Double(double v)`；整数形态进 `Int`，带小数点/指数进 `Double`；
  绑定到 `int` / `float` 时做范围与精度检查；
- 解析错误：`Result<JsonNode, JsonError>`；`JsonError` 含 offset / line / column / message；
  `JsonNode.Null()` 只表示合法 JSON null，不表示失败。

## 2. ADT 方法与下标链

- 允许 enum ADT 的固有方法（`impl JsonNode { … }`），含 `pub`、跨单元、静态/实例方法，无 vtable；
- 自定义下标扩展到 ADT：固有 `get` / `set`，读写形态都支持；
- 多级链完整支持：`doc["user"]["age"]`、`doc["user"].field`、`doc["user"].method()`、
  `doc["user"].field = v`；每级临时量只求值一次、顺序固定，**不得落成 C 指针算术**；
- 这条是独立语言特性，按 B2 的完整范围实现，不做“自由函数 + 中间变量”的降级。

## 3. ADT 值语义与释放

- 采用 **retain/release 浅共享**：ADT 拷贝只增加顶层句柄计数，不递归复制；
- 编译器生成 `JsonNode_retain` / `JsonNode_release`（按 `tag` 只处理当前变体），
  并在声明初始化、赋值、实参、`return`、容器插入、`foreach` 元素、字段初始化处插入 retain；
- `release` 在作用域出口、`return`、容器级联、ADT 递归释放处插入；
- `match` 绑定对 payload 做 **retain 副本**（不改“源被 move 后置空”的旧提议），
  避免源 ADT 与绑定双重释放；
- `Str` 不作为 ADT payload；需要字符串时存 `String`，取值处 `as_str()`；
- 容器元素协议识别 ADT 的 retain/release；树按构造无环，引用环仍是作者责任。

## 4. 绑定点注册表（`map binding`）

- 作为 D-020 的第三查找源：源类型固有方法 → **binding 注册** → 已 import 的 `map trait`；
- 注册是编译期的 `(Source, Target) -> from` 表；只有已 import 的单元参与；未 import 给可行动诊断；
- 同 pair 多候选 → 硬错并列候选；只做一跳，不做 A→B→C 链；
- `Vec<T>` / `Option<T>` 由编译器按元素递归路由，注册表只负责叶子；
- 生成代码直接展开为 `from(x)`，无运行时注册表、无 vtable；未 import 零代码；
- 语言层不认识 JSON/XML；`json` / `xml` 只是注册者。

## 5. 表达式 `match`（A+B）

- 保留 A：ct-gen 生成代码可先改写为语句 `match` / `if`，不阻塞；
- 同时实现 B：`expr match { … }` 的臂为 `Pattern => expr` 或
  `Pattern => { …; yield expr; }`；`yield` 是上下文关键字，正常出口恰好一个；
- `return` / `break` / `continue` 允许，臂按“发散”处理；不做块尾表达式隐式取值；
- 语句 `match` 不变；主语求值一次、臂类型统一、穷尽规则与 `_` 末位不变。

## 6. 构建与生成物

- `ct-gen` 是外部工具；生成 `*.json.ct` 后由用户/CI **显式 import**；
- `ct build` 不自动 glob、不隐式调用 `ct-gen`、不读 `ct-gen.toml`；
- 生成物可 `.gitignore`，但 README/CI 必须写清“先 ct-gen 再 build”；缺文件时报可行动错误；
- 不从编译器核心下沉外部工具依赖。

## 7. 子树、可变性与性能

- 对外只暴露**只读视图**（`JsonArray` / `JsonObject`），内部仍用 `Vec/Map`；
  匹配绑定不直接给可变容器；建树走构造器/`to_node`；
- 子树可跨文档：retain 后 `root` 释放、子树仍有效；取代旧 arena 的“子树不跨文档”；
- 解析/释放设深度上限，释放用迭代或受控递归，防栈溢出；
- refcount 非原子，跨线程共享仍由作者同步；
- 与 arena 的基准对比作为回归/唤醒门禁，不在实现前承诺更快。

## 8. 容量与 ABI

- 新增 per-ADT retain/release/drop、`map binding` 包装、`from_node/to_node` 均占 `MAX_FUNCS`；
  但 **SH-109 已改判为当前 pre 窗口动态增长**（初始 512、65536 安全阀，待 DEV 落地）；
  B 实施前确认已落地即可，不再以 501/512 或 ≤11 为预算；
- `JsonNode` 布局 tag + union；`_Bool` / `double` 对齐写 `_Static_assert`；
- 包不承诺 C ABI 稳定性；若导出，另立 ABI 决策。

## 9. 实施阶段

1. LANG-27（容器级联）→ 2. B1 布局 + B3 ADT glue + B8 ABI/错误 →
3. B2 ADT 方法/下标链 + B4 注册表 + B5 表达式 match（各自 ADR）→
4. B7 只读视图/子树/深度与基准 → 5. 外部 `ct/json` / `ct/tree` / `ct-gen`。

## 10. 非目标

- 不回到 arena + 索引作为默认（若唤醒条件重评失败，再按 LANG-27 回退）；
- 不做 COW、可变树、运行时反射；
- 不把 `ct/json` / `ct-gen` 的排期写进 Ct 发布路线。
