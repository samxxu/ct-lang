## 1. 句柄布局

1. **句柄 16 字节**：`struct box<T> { struct ct_box_hdr *h; T *ptr; }`（LP64 两个指针）。
   `h` 是分配基址（也是 8 字节 `{refs, aux}` 头），`ptr` 是 payload。卡 E81-1 要求 16 字节
   句柄与共享头；这个形状同时保留「头在 payload 前」与「release 按静态类型」两项。
2. **payload 偏移** `header_size(T) = round_up(8, _Alignof(T))`；分配
   `header_size(T) + sizeof(T)`，`ptr = (char *)h + header_size(T)`。`_Static_assert` 与
   `payload_offset()` 在 `test/ast/p81_box/layout.ct` 钉住。
3. **refs 从 1 起；box 不使用 `refs = -1` immortal**。immortal 只属于 `String` 字面量 / 空串
   （D-013）；`box` 没有静态字面量形式。
4. **独立内建单元 `Box.h.ct`**（第 5 个）：不在 `Vec.h.ct` 里声明 `box` / `ct_box_hdr`，否则
   任何加载容器层的程序都会多出 `struct ct_box_hdr;` 前向声明，`p39 r8` 的 `--emit-c` 字节
   比较会红。`Driver` / `Module` 按源码（跳过注释与字符串）决定是否加载该单元。

## 2. `new` 是上下文关键字，不是完全保留字

卡 §1 写「完全关键字」，但本轮任务指令明确「`int new;` / `r.new` 仍合法（上下文关键字）」。
两者冲突，按更具体、更晚的指令取**上下文关键字**：

- `new` 只在后接类型名（或错误形态 `new {`）时是构造；`int new;`、`r.new`、形参 `new`、
  `new = ...`、`new + 1` 继续是标识符。
- 这是对 D-011 J-2a「完全关键字」的**有意偏离**；代价是 `new` 不能像 `if` 那样作为保留字
  参与语法消歧，收益是现有语料零迁移（`Box box;` 之类的标识符不必改名）。
- 证据：`test/ast/p81_box/ctx.ct`；`is_decl_start` 对裸 `box` 也按「是否后接 `<...>`」区分。

## 3. `new` 的类型边界

- 只接受**具名、非泛型 struct**；`new String` / `new Str` / 标量 / 指针 / 数组 / 容器 /
  其他内建句柄 / 泛型实例一律硬错。
- `new` 不能出现在文件作用域或 `static` 局部初始化器（运行时分配）；错误在解析/发射前给出。
- 花括号与 `T x = { ... }` 共享：位置式、指定式 `.f = e`、嵌套。局部 struct 初始化器中的
  `String` 字面量按 owning 处理（`str_dup_len`），因为 `String` 字段默认值不是 `char *`。

## 4. 复制协议：显式，不自动 retain

`box` 采用 `Vec` 的显式协议：

- `retain()` / `release()` / `refs()` / `at()` / `payload_offset()`；`use Drop` + 泛型
  `impl Drop for box<T>`；容器元素 glue 会对 `Vec<box<T>>` 的插入 retain。
- 按值传参、字段赋值、容器插入**不**自动 retain；容器 `get` 的复制需要调用方 `retain()`。
  理由：D-013 §3 的自动半部按 `String` 句柄实现，扩展到任意 owning 泛型会改动 PH-80 的
  emitter 记账；本轮 E81 不要求，且 `Vec` 的既有协议已给出一致语义。
- **`box<T>::of(v)` 是复制构造**：payload 的 owning 叶各自 retain。`box<String>` 由
  `box<String>::of(s)` 得到（D-013 的 `box<String>` 回填），`new String` 仍是硬错。
- **`new T { ... }` 是 move 构造**：把新构造的 payload（含已 retain 的 place 初始化项）
  移进 box。

## 5. release / Drop 的静态类型

- 每个 `box<T>` 实例发射 `box_X__payload_release(T *)`：`String` / `U16String` 字段走
  `<T>_Drop_drop`；`Vec_*` / `Map_*` / 嵌套 `box_*` 字段走 `<Inst>_release`；普通 struct
  递归其 owning 字段；单维 owning 数组逐元素释放，多维数组留给显式 Drop（与既有 Drop glue
  的规则一致）。
- `use Drop` 宿主的字段 glue 调 `box_X_Drop_drop`；`delete` 一个 `own box<T> *` 只释放句柄
  指针，不替 payload 释放——box 值本身是句柄，不是指针。
- 借用视图 `at()` 不 retain，`release()` 后失效；ASan 兜底，不做运行期失效检测。

## 6. 借用字段与环

- `box<Str>` / `box<U16Str>` / `box<T[]>` 在类型实参层硬错；`struct Bad { Str tag; }` 在
  struct 声明层硬错（`box<Bad>` 复用同一层）。
- 引用环是作者责任；`--debug-leaks` 在 ct-ast 仍未实现，将来也只报未配对 alloc/release
  计数，不叫环检测（D-011 J-4c）。E81-5 的探针只展示环保留 `refs=1`，不声称检测。

## 7. 已知边界

- `ct build` **跨单元** `box<T>` 不支持：实例/助手写在命名它的单元里，导出签名只有前向声明。
  单文件 compile 与单单元 build 可用。文档三处明示；不阻塞 E81。
- box 不进入 C ABI 导出面；C 侧只用 `T *` / 普通 struct / `void *`。
- `box<T>` 的 16 字节 / 8 字节是 CT 内部布局 golden，不是跨编译器 ABI 承诺。

## 8. 后果

- E81-1…6 的探针与 P-7.5 证据按本裁定实现；P-7.5 的限制 §6 写进证据。
