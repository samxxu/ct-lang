# D-004 — PH-41 原子命名与 C 标准边界（B′）

## 争点

Phase 41 草案把 `atomic` 变成关键字，并把 `atomic_load` / `atomic_store` / `atomic_cas` 设为保留名，生成 `_Atomic(T)`。独立评审发现：

- 破坏 `<stdatomic.h>` 正例（`atomic_int` + `atomic_load`）与同名用户函数；
- `_Atomic` 在严格 C99 下是 C11 扩展；
- `atomic_load(p)` 的指针形态与 L41-7 左值限制冲突；
- 通用 check-ast / test/run 没有 `-pthread`，p41 runtime 夹具会漏；
- 编辑器语法/check-grammar 未覆盖。

## 判决

A（现草案，保留名/关键字）**rejected**；C（按类型 fallback 保留标准名）**rejected**；D（plain T + `__atomic`，C99）**rejected**；**B′ accepted**。

B′ 口径：

1. `atomic` 是**上下文类型修饰**：只在后跟 `int` / `long` / `void *` / `bool` 时生效；`int atomic = 1;`、`atomic;` 保持普通标识符。
2. 内建操作命名为 `ct_atomic_load` / `ct_atomic_store` / `ct_atomic_cas`；`atomic_load` / `atomic_store` 保持普通调用，`<stdatomic.h>` 与用户同名函数不受影响。
3. 生成物 `_Atomic(T)`；PH-41 明确要求 **C11**：`ct compile` 文档要求 `-std=c11`，`ct build` 在存在原子单元时使用 C11（或新增 `--std=c11`），原子夹具以 C11 编译。
4. `ct_atomic_*` 第一实参按静态类型接受 `_Atomic(T) *`，包括 `&x` 和指针变量 `p`；不再要求语法左值。
5. `ct_atomic_cas` 只收地址形态 `ct_atomic_cas(&x, &expected, desired)`；by-value 报 L41-5。
6. 删除 L41-4（保留名）与 L41-9（`atomic` 非类型位置硬错）；`atomic_load` 不再保留。
7. 补 `-pthread` 到通用 check-ast / test/run；TSan nightly 覆盖 Linux；tmLanguage/check-grammar 增加 p41；补 store/cas 的 expected/desired 类型诊断。

## 证据

见 [`battle/p41-1/verdict.md`](../../battle/p41-1/verdict.md)、[`verify.json`](../../battle/p41-1/verify.json)：

- V1：`cc -std=c99 -pedantic-errors` 对 `_Atomic` 报 C11 extension；
- V2：bindings §7 正例使用 `atomic_int` + `atomic_load/store`；
- V3：通用 check-ast/test/run 无 `-pthread`；
- V4：本庭之前无 p41 battle/ADR；
- V5：编辑器无 atomic 语法/测试。
