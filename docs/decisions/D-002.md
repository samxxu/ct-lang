## 争点

`lib<base>.a` 里非导出的全局符号（trait vtable、内建 `Str_*` 等）怎么处理：

- **A**（ARCH）：接受它们留在 `nm -g`，用 `expected.nm` 快照锁定，文档注明「非 ABI」；
- **B**（REQ 证伪的方向）：链接期本地化（Mach-O `ld -r -exported_symbols_list` / ELF `objcopy --localize-hidden`），使 `nm -g` 只剩导出面。

触发：B-5 用户显式指令「不能确定的部分就 battle」；PH-39 D39-5 选 A 但未过庭（`question.md:7`）。

## 判决

**§7.9：`verdict: rejected`（对主张 A）。**

- A 的 J-1 不成立（V1/V3/V4/V5），反证清单 F-1/F-5 被证实、F-3 的符号面一半被证实 → 按 §7.9「判据未被满足，或反证至少一条失效条件被证实」判 `rejected`。
- A 被否不等于 B 成立（§7.9 末条）。B 在 J-1/J-3/J-5 成立，但在 J-2（严格「同一套命令」）与 J-4（成本/与 O1 冲突）不成立，故本 ADR **不判 B 成立**。
- 按 §7.10 **出口 1**：产出 `battle/p39-2/C-proposal.md`，再走一次单方案评审（主张=ARCH、反对=REVIEW、证据=VERIFY）。
- C 未过审前不得按 B 或 C 实施；C 的 Linux 分支必须实测。

## 理由（逐条对应判据）

- **J-1**：`nm -g` 的 12 个 defined global（V1）与消费者可 extern 内部 vtable/`str_len`（V3/V4）证明 A 的符号面 ⊋ `.abi.h`；V5 证明 `expected.nm` 对同名抢占恒绿，锁的是仓库回归，不是消费者契约（`counter.md:110`、`counter-r2.md:243`）。B 的合并 + 本地化实测使 `nm -g` 恰为导出（V6/V7/V8），但有 V9 的 `C` 边界，须 D39-8 与集合断言兜底。
- **J-2**：A 只用 `cc`/`ar`/`nm`（V11；macOS 实测，Linux 未测）；B 在 macOS 用 `ld -r`/`nmedit`、Linux 用 `objcopy`，是两套工具/两套语义（`counter-r2.md:99`、`claim-r2.md:48-49`）。J-2 原文是「同一套命令」，严格读 B 不过。
- **J-3**：V10 证明逐单元本地化断链，B 只能整档合并（V6/V7/V8）；constructor 未被丢弃（V8/V14）。J-3 对 B 成立但以合并为代价，这正是 J-4 冲突的来源。
- **J-4**：V12 证明 HEAD 无 `--lib`，双方行数都只是估算；B 的唯一实测形态使 `ar t` 1 成员，改冻结的 O1/§3.2，且夹具重写与 `nmedit` 每成员清单未计入其 35–45 行估算（`counter-r2.md:122,229`、`counter.md:194`），故 B 的 J-4 不成立。A 的 J-4 无法判定，不当作 A 的胜证。
- **J-5**：V1/V2/V3/V4 与 V6/V7/V8/V11/V14 均可重跑；B 的 Linux 分支已写 `skip`，未默绿。A 的 `expected.nm`/`ABI_VERSION` 门禁在 HEAD 不存在（V12），属未实现，不当作 A 的 J-1 胜证，也不据此加重 A 的 J-5 失败。

## 失效条件

出现以下任一，本 ADR 须重开：

1. `--lib` 落地后，实测证据推翻 V1/V3/V4/V5 或 V6/V7/V8 的任一条。
2. Linux 上 `--lib` 的密封分支被实测（成功或失败）；成功则 C 的 J-2/J-5 需重评，失败则 C 的出口回到 §7.10 出口 2。
3. C 的单方案评审未通过，或用户不接受「归档 1 成员」的 O1 新读法。
4. 用户决定改变导出集合（B39-1/D39-2）或 `--lib` 命名/确定性（D39-3/D39-4）——本 ADR 不覆盖。
5. 出现新证据证明 A 的 `<base>.nm` + `ABI_VERSION` 绑定能满足 J-1 字面（目前没有；且字面 J-1 要求 `nm` 干净，A 的机制不改变 `nm`）。
6. V9 的 `C` 符号在 D39-8 之外仍有其他残留路径；C 或 B 必须补门禁。
