# D-026 · v1.2 Typed/Lowered IR：设计裁定与实施时点

- 日期：2026-11-23
- 状态：**accepted（设计）；实施 deferred（未开工）**
- 目标：v1.2（`v1-PH-2`）；不进入 v1.0/v1.1 发布门禁
- 签收：REQ 2026-11-23（设计阶段验收；实施前由 REVIEW 复核）
- 批准：ARCH 2026-11-23（架构方向）
- 依据：[提案](../proposals/typed-lowered-ir.md)、[SH-112](../../issues/selfhost/sh112-typed-ir-architecture.md)、
  [SH-111](../../issues/selfhost/sh111-lowering-invariants.md)、[SH-113](../../issues/selfhost/sh113-builtin-live-boundary.md)、
  [v1 路线 §2.1](../planning/v1-release-plan.md)
- 决策范围：IR 形态、分层、emitter 契约、验证器、迁移/回滚原则与实施时点；
  **不含**优化器、C ABI、用户语法、跨项目排期

## 1 决策

1. **采纳两层 IR**：`TIR`（typed，语义已确定）+ `LIR`（lowered，C 形状已确定）；
   emitter 只消费 `LModule`，不再持有 `Symbols` / `TypeCheck` / `Module` 做语义判定。
2. **采纳统一清理 CFG**：scope 树 + 清理条目栈 + 每条出口的显式清理集；`return` /
   `break` / `continue` / 合法 `goto` / `?` 失败都生成清晰清理边；deferred body 整体 LIFO，
   随后 drop/release 整体 LIFO；errdefer 只走错误边。
3. **采纳发射前不变量验证器**：TIR 与 LIR 各一个检查点；失败给 `file:line:col`、不产出 C；
   诊断命名空间 `E-IR-1xx` 在实施时按 LANG-25 登记。
4. **采纳语义依赖图**：替换内建单元“源码文本判活”的近似；范围只限内建层与泛型实例，
   不做用户单元死代码删除；raw C 用声明依赖 + 保守兜底，不写 C 解析器。
5. **采纳渐进迁移**：S1 typed shadow → S2 LIR 子集 → S3 全量 LIR + 图 → S4 切换/重基线；
   每阶段可独立回滚，不搞一次性替换。
6. **本次只完成设计阶段验收**：不写代码、不改 `backend/`、不改版本号、不 bump MINOR、
   不开施工卡；SH-112 的 `status` 保持 `deferred`，由集成后的 REV 复核。

## 2 设计选择与取舍

| 选择 | 被否方案 | 理由 |
| --- | --- | --- |
| TIR + LIR 两层 | 单层 IR | 类型/实例化与 CFG/清理同时重写，无法分批验收；验证器也难分语义错与形状错 |
| 非 SSA，显式临时 | SSA + phi | 没有优化器；phi 只增加 lowering 与调试成本，C 后端不需要 |
| C 形状表达式树 + 明确顺序 | 全 3-address | 保持生成 C 可读、diff 小；只对有序性可观察的子表达式物化 |
| 统一清理集，lowerer 生成 | parser 继续物化到 `b` 槽 | 跨块/嵌套/errdefer 才能机械验证；parser 只保留语法职责 |
| 验证器在发射前 | emitter 内部断言 | 语义错误与打印错误分离；失败不产出半成品 C |
| 语义图只管内建层/实例 | 全模块死代码删除 | 后者会改变用户可见构建集合，是另一个产品决策 |
| 渐进切换 + 旧路径 oracle | 一次性替换 | 自举链与 golden 可回滚；差异可分批审 |
| 差异清单后重基线 | 直接改 golden | 防止“绿了但行为变了”被掩盖 |

## 3 为什么现在只做设计

- v1.0/v1.1 处于冻结/收口窗口，IR 是重写级工程，不能占发布门禁；
- SH-111 的轻量不变量刚落地，剩余项（I5 值类别、跨块顺序、`?` 旁表、`goto`）正好是 IR 的
  输入，但尚未稳定到可以据以冻结 LIR 契约；
- v1.0 的 seed 与静态 golden 尚未就绪；没有 seed 切换方案，IR 实施会断自举链；
- 设计本身需要先固定“哪些语义归 TIR、哪些形状归 LIR、emitter 边界在哪”，否则实施会边写边改。

| # | 前置 | 判据 |

| P1 | v1.1 稳定 | `v1-PH-1` 收口，SH-111 的 I1–I4 已绿；I5/R1/R2/R4/R5 有明确归属（可带入 v1.2，但需在 S1 前冻结规则） |
| P2 | SH-111 剩余项处置 | 每项写明“进 IR 哪个不变量/哪个阶段”或“仍留 v1.3+”，不得悬空 |
| P3 | 容量复算 | SH-109 函数表动态增长已落地；`MAX_TYPES` / `MAX_GENERIC_INSTS` / `MAX_STRUCT_INSTS` / `MAX_VARS` / `MAX_UNITS` 有预算或增长方案；不新增固定上限代替设计 |
| P4 | v1.0 seed 就绪 | `bootstrap/ct-ast/` 与 gate 13 可用；v1.2 源码能被 v1.0/v1.1 seed 编译；旧 seed 可保留 |
| P5 | golden 基线就绪 | SH-105 静态 golden 与 gate 12 可独立跑；差异清单模板与批准人已定 |

**容量说明**：SH-109 已把整程序函数表从固定 512 改为按需增长（初始 512、安全阀 65536），
因此 IR 新增 `em_*`/lowerer 函数不再受 501/512 预算约束；但类型表、实例表、变量表仍是固定
容量，必须在 S1 前复算，不能靠“先写再撞顶”。

## 5 实施门禁与回滚

| 阶段 | 必须通过 | 失败处置 |
| --- | --- | --- |
| S1 shadow | TIR 覆盖 100% 语料；V1–V4 绿；AST→C 逐字节不变；编译耗时 ≤ +10%（硬上限 +25%） | 停在 shadow，不进 S2 |
| S2 LIR 子集 | 子集语料逐字节；V5–V8 负例红；旧路径仍默认 | 切回 `--ir=off`，删子集 |
| S3 全量 | 全语料 IR→C；V1–V10 绿；p113 组全过；零文本判活 | 回 S2 或旧路径 |
| S4 切换 | 3 轮自举不动点；gate 12/13；差异清单批准；回滚演练绿 | 恢复旧默认与旧 seed |

- 每阶段一个可 revert 提交；S1/S2 不改默认路径。
- 差异清单只允许列明类别（临时编号、声明顺序、空行等），逐文件给批准人；不得用“等价”口头
  带过。
- S4 重基线提交与 IR 实现提交分开；旧 AST→C 路径在 v1.2 收口后再保留一个 release。

## 6 不实施的时点与后果

- **不实施时点**：本 ADR 生效到 `v1-PH-2` 开工前。此期间仓库没有 TIR/LIR/verifier/图；
  `backend/` 仍只有 `emit` 与 `mem`；SH-111 的 `invariant_check` 是 AST 级检查，不是 IR verifier。
- **触发**：v1.2 窗口开启 + §4 六项前置全过 + `v1-PH-2` 卡获批。缺一即继续 deferred，
  不改回 `open`，不提前写代码。
- **若 v1.1 延期或前置不满足**：v1.2 顺延，不设日历承诺；SH-112 继续 `deferred`，
  本文与提案不失效，但不得被引用为“已排期/已开工”。
- **设计验收的边界**：本 ADR 只证明设计可验收，不证明实现可行；实现可行性由 S1 spike 判定。
