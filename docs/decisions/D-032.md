# D-032 · 内部层 C 边界豁免：包根 manifest 覆盖子树，消费者侧不放开

- 日期：2026-11-28
- 状态：**proposed（REQ 起草；所有者 2026-11-28 批准方向；待 REVIEW 签收）**
- 目标：`v1-PH-2` 收口后窗口（1.2.0 已提交、未打 tag）；不改版本号、不打 tag
- 签收：REVIEW（**待签**，T-8 非作者席位；本 ADR 由 REQ 起草，不自签）
- 依据：所有者 2026-11-28 裁定（"strict 是防消费者直接调 C 库，不是防 selfhost / lib/core"；
  "子目录不该再要一份自己的 `ct.pkg`"）、[language-spec §4.66/§4.67](../language-spec.md)、
  [c-shim-contract N-8](../c-shim-contract.md)、[v1-PH-2 卡 E-V3-10](../phases/v1-PH-2/card.md)（判据由 CR-V3-1 改写）、
  [D-030](D-030.md)（`Str.print` 的 shim 声明先例）、
  [requirements-pool REQ-STD-COVER-1](../planning/requirements-pool.md)
- 决策范围：**内部层（`selfhost/ct-ast` 与 `lib/core`）的 `c-boundary` 取值方式**、
  `c_boundary_for` / `leaks_for` 的 manifest 解析语义、include-only shim 的退场、
  消费者默认值是否变化。**不含**：扩展 §4.67 补头集合、包侧 std 具体 API。

## 1 背景

v1.2 S9 把 C 边界默认翻成 strict（spec §4.66）：`.ct` / `.h.ct` 不允许 `#include`，
只允许 `#include "<本单元>.shim.h"`。为了自举与内置层，源码里给每个用到 libc 的单元
都新增了一个 shim。实测（2026-11-28）：

| 位置 | 数量 | 形态 |
| --- | --- | --- |
| `selfhost/ct-ast/**/*.shim.h` | 66 | **63 个只有 `#include`**，3 个还有 C 原型声明 |
| `lib/core/*.shim.h` | 6 | **全部只有 `#include`**（`Box` / `Option` / `Result` / `Str` / `String` / `Vec`） |
| `lib/core/utf16/*.shim.h` | 2 | **全部只有 `#include`**（`U16Str` / `U16String`） |
| `bootstrap/ct-ast/*.shim.h` | 68 | seed 里多 `Vec` / `Result`（内置层单元），无 utf16 |

现状是**用 74 个文件换一条判据**（E-V3-10 原文要求内部层零 allow）。

更深的问题是解析语义：`c_boundary_for` 只查 `-I` 根的 manifest（前缀匹配），
`leaks_for` 只查"单元自身目录"。**两者都没有"包清单覆盖子树"的概念**，
于是 `lib/core/ct.pkg` 管不到 `lib/core/utf16/`，子目录只能再放一份 manifest——
这正是"`ct.pkg` 满天飞"的根因，不是目录设计的问题。

## 2 决策

1. **内部层用两处 manifest 声明豁免**：`selfhost/ct-ast/ct.pkg` 与 `lib/core/ct.pkg`，
   各写 `c-boundary = allow`。不新增"路径前缀自动 allow"的特判。
2. **解析语义改为"包根 manifest 覆盖子树"**：从单元所在目录**向上**找最近的 `ct.pkg`，
   一旦找到即为该单元的包根，其键作用于整棵子树；**向上查找止于单元的所属根**
   （`-I` 根或内置层根），不越过、不走到文件系统根。
3. **`leaks_for` 同批对齐同一解析**：同一份 `ct.pkg` 的 `c-boundary` 与 `leaks`
   必须按同一个包根解析，不允许两个键各自一套作用域。
4. **找不到 manifest → strict**（`c-boundary`）与 `warn`（`leaks`，沿用现状默认）；
   找不到键 → `c-boundary` 为 strict、`leaks` 为 warn（沿用现状）。
5. **消费者默认不变**：strict 仍是默认；不为任何消费者放开 `.ct` / `.h.ct` 里的
   `#include`。消费者若真要直接调 C，仍须 `.m.ct`、shim 或显式 allow——这正是留痕。
6. **include-only shim 退场**：`selfhost/ct-ast` 66 → 3（保留有原型的
   `Module` / `ModuleBoundary` / `Pkg`）、`lib/core` 8 → 0、`bootstrap/ct-ast` 68 → 3；
   系统头移回各 `.h.ct` 顶部。
7. **消费者的"无需空 shim"走包侧（D 方案）。** 由 `ct-pkg/std` 补齐常用能力
   （[REQ-STD-COVER-1](../planning/requirements-pool.md)），让常见任务不产生 C 调用；
   这是产品路径，不是放宽 strict。
8. **判据同步。** E-V3-10 由 [CR-V3-1](../phases/v1-PH-2/card.md) 改写为
   「`selfhost/ct-ast` 与 `lib/core` 各用一处 manifest 显式 allow；仓库其它目录零 allow」；
   v1.2.0 的旧证据保留为历史。

## 3 备选与不采纳

| 方案 | 做法 | 结论 | 理由 |
| --- | --- | --- | --- |
| A 路径硬编码 allow | 编译器识别 `selfhost/**` 自动 allow | 不采纳 | 无开关、不可审计；判据无法机器验证 |
| **B 包根覆盖子树（采纳）** | 每层包一份 `ct.pkg`，作用于整棵子树；向上止于所属根 | **采纳** | 与 ct-pkg 的"包 = 目录树"一致；两处 manifest 覆盖 74 个 shim；有界、可负例验证 |
| B2 子目录再放一份 manifest | `lib/core/utf16/ct.pkg` | 不采纳 | 正是"`ct.pkg` 满天飞"；为 2 个文件复制包声明，属于规则缺失的补丁而非修复 |
| B3 无界祖先查找 | 一路向上找 `ct.pkg`，直到 `/` | 不采纳 | 会被 `$HOME` 或仓库外的遗留 manifest 意外命中，allow 的作用域不可预测 |
| C 放宽 `#include` | 允许 `.h.ct` 直接 include 标准头 | 不采纳（另立才做） | 等于允许直接调 libc，抹掉 strict 的目的；S9 明确不扩 §4.67 |
| D std 覆盖 | 包侧补齐常用能力 | **并行采纳** | 消费者真正不需要 C 调用；与编译器规则正交 |

## 4 契约与影响

| 项 | 约定 |
| --- | --- |
| 键名 / 取值 | `c-boundary = allow|strict`、`leaks = warn|error`（既有键，不新增语法） |
| 解析顺序 | CLI / `CT_C_BOUNDARY` → 从单元目录向上的**最近** `ct.pkg`（止于所属根）→ 默认（`strict` / `warn`） |
| 内置层 | 内置层根（`CT_CORE_DIR` / `./lib/core` 等解析结果）即其包根，`lib/core/ct.pkg` 覆盖含 `utf16/` 的整棵子树 |
| 嵌套包 | 子目录自带 `ct.pkg` 时，它就是那棵子树的包根，**以最近的为准**；父包的键不外溢到子包 |
| 生成物 | `#include` 回到各 `.c` / `.h` 顶部；shim 只在有 C 原型时存在；用户语料生成 C 逐字节不变 |
| seed | 片末 `gen-seed.sh` 重生成，`check-seed` 两轮逐字节；seed shim 68 → 3 |
| 回滚 | 删两处 `ct.pkg` 并恢复 shim 与 include 位置；解析回退本身可单独 revert |
| 施工前提（DEV 先验证） | 新解析不得改变"无 manifest → strict/warn"的现有行为；不得越过所属根；`leaks` 的作用域变化必须由负例覆盖 |
| 文档同步（REQ，验收前） | spec §4.66 现写"包括 Ct 仓自己的 `selfhost/**`、`lib/core/**`…"，实施后需补内部层 manifest 例外与"包根覆盖子树"的解析口径；[c-shim-contract](../c-shim-contract.md) N-8 补同一句。文档改动与实现同批，不提前改 |

## 5 风险

| # | 风险 | 处置 |
| --- | --- | --- |
| 1 | 包根判定错误，allow 越出包边界 | 向上查找止于所属根；负例：包外目录、仓库根、`$HOME` 的 `ct.pkg` 都不得生效 |
| 2 | 嵌套子包被父包 allow 罩住 | "最近 manifest 为准"；负例：子包写 `c-boundary = strict` 时其单元必须 strict |
| 3 | `leaks` 作用域变化影响既有包 | 同批对齐 + 负例；默认仍是 warn，只有显式 `error` 才升级 |
| 4 | `ct.pkg` 被 `ct build` 当作完整包清单，要求 name/version | DEV 先验证；若触发包模式，回来报证据，不改 ADR 私自换方案 |
| 5 | 消费者误以为默认已放宽 | CR-V3-1 第 3 条：普通无 manifest 的 `.ct` / `.h.ct` 仍 strict、生成物逐字节不变 |

## 6 验收（DEV 实施、REVIEW 签收）

1. `selfhost/ct-ast/ct.pkg` 与 `lib/core/ct.pkg` 各只含 `c-boundary = allow`（外加注释）；
2. shim：`selfhost/ct-ast` 66 → 3、`lib/core` 8 → 0、`bootstrap/ct-ast` 68 → 3；
3. `ct --show-c-boundary` 四个正例：`selfhost/ct-ast/<单元>`、`lib/core/<单元>`、
   `lib/core/utf16/<单元>` 均 `allow`；普通无 manifest 目录的 `.ct` 为 `strict`；
4. 三个负例：① 删掉 `lib/core/ct.pkg` → 其单元与 utf16 都回到 `strict`；
   ② 在 `lib/core/utf16/` 放一份 `c-boundary = strict` 的 `ct.pkg` → 该子树 strict（最近者为准）；
   ③ 在包外目录放 `c-boundary = allow` 的 `ct.pkg` → 包内单元不受影响；
5. `leaks` 对齐：同一个 `ct.pkg` 写 `leaks = error` 时，其子树单元按 `error` 处理，
   父目录的键不外溢；负例覆盖；
6. `bash selfhost/gen-seed.sh`；`check-seed` 两轮逐字节；
   `CT_C_BOUNDARY=allow bash selfhost/check-goldens-ast.sh <ct>` 25/25；
   `bash selfhost/check-all.sh` 8 门；`check-warnings` 0；`python3 test/docs/check-docs.py` OK；
7. 普通无 include 的 `.ct` 生成物逐字节不变（CR-V3-1 第 3 条）。
