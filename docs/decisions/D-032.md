# D-032 · 内部层 C 边界豁免：显式 manifest allow，消费者侧不放开

- 日期：2026-11-28
- 状态：**proposed（REQ 起草；所有者 2026-11-28 批准方向；待 REVIEW 签收）**
- 目标：`v1-PH-2` 收口后窗口（1.2.0 已提交、未打 tag）；不改版本号、不打 tag
- 签收：REVIEW（**待签**，T-8 非作者席位；本 ADR 由 REQ 起草，不自签）
- 依据：所有者 2026-11-28 裁定（"strict 是防消费者直接调 C 库，不是防 selfhost"）、
  [language-spec §4.66/§4.67](../language-spec.md)、[c-shim-contract N-8](../c-shim-contract.md)、
  [v1-PH-2 卡 E-V3-10](../phases/v1-PH-2/card.md)（判据由 CR-V3-1 改写）、
  [D-030](D-030.md)（`Str.print` 的 shim 声明先例）、
  [requirements-pool REQ-STD-COVER-1](../planning/requirements-pool.md)
- 决策范围：**内部层（`selfhost/ct-ast`）的 `c-boundary` 取值方式**、include-only shim 的退场、
  消费者默认值是否变化。**不含**：扩展 §4.67 补头集合、`lib/core` 的取值、包侧 std 具体 API。

## 1 背景

v1.2 S9 把 C 边界默认翻成 strict（spec §4.66）：`.ct` / `.h.ct` 不允许 `#include`，
只允许 `#include "<本单元>.shim.h"`。为了自举，编译器源码每个用到 libc 的单元都新增了
一个 shim。实测（2026-11-28）：

| 位置 | 数量 | 形态 |
| --- | --- | --- |
| `selfhost/ct-ast/**/*.shim.h` | 66 | **63 个只有 `#include`**，3 个还有 C 原型声明 |
| `bootstrap/ct-ast/*.shim.h` | 68 | seed 里多 `Vec` / `Result`（内置层单元） |

这些 include-only shim 没有任何声明价值：它们是"该单元的系统头清单"，
在 selfhost 里形成 60+ 个噪声文件。同时 E-V3-10 原文要求
「`selfhost/` 与 `lib/core/` 零 allow」，所以现状是**用 66 个文件换一条判据**。

## 2 决策

1. **内部层豁免用显式声明，不用路径白名单。** 在 `selfhost/ct-ast/ct.pkg` 写
   `c-boundary = allow`；`gen-seed.sh` 已有 `ct build --emit-c -I selfhost/ct-ast`，
   `c_boundary_for` 会读该 `-I` 根下的 manifest，因此覆盖其下全部单元。
   **不新增**"路径以 `selfhost/` 开头就自动 allow"的代码分支。
2. **范围只到 `selfhost/ct-ast`。** `lib/core` 不豁免：它是被消费的内置层，
   且 `Str.shim.h` / `String.shim.h` 等确有 C 原型（D-030 先例），维持零 allow。
3. **消费者默认不变。** strict 仍是默认；不为任何消费者放开 `.ct` / `.h.ct` 里的
   `#include`。消费者若真要直接调 C，仍须 `.m.ct`、shim 或显式 allow——这正是留痕。
4. **include-only shim 退场。** 把系统头移回各 `.h.ct` 顶部；保留 3 个仍有 C 原型的 shim。
   预期 `selfhost/ct-ast` 的 shim：66 → 3。
5. **消费者的"无需空 shim"走包侧（D 方案）。** 由 `ct-pkg/std` 补齐常用能力
   （[REQ-STD-COVER-1](../planning/requirements-pool.md)），让常见任务不产生 C 调用；
   这是产品路径，不是放宽 strict。
6. **判据同步。** E-V3-10 由 [CR-V3-1](../phases/v1-PH-2/card.md) 改写为
   「selfhost 一处 manifest 显式 allow；lib/core 零 allow」；v1.2.0 的旧证据保留为历史。

## 3 备选与不采纳

| 方案 | 做法 | 结论 | 理由 |
| --- | --- | --- | --- |
| A 路径硬编码 allow | 编译器识别 `selfhost/**` 自动 allow | 不采纳 | 无开关、不可审计；"自举也遵守 strict"的证据消失；判据无法机器验证 |
| B 显式 manifest allow（采纳） | `selfhost/ct-ast/ct.pkg` 写 `c-boundary = allow` | **采纳** | 一处声明、可 `--show-c-boundary` 验证、可用删文件做负例 |
| C 放宽 `#include` | 允许 `.h.ct` 直接 include 标准头 | 不采纳（另立才做） | 等于允许直接调 libc（`printf`/`open`/`ioctl`），抹掉 strict 的目的；且 S9 明确不扩 §4.67 |
| D std 覆盖 | 包侧补齐常用能力 | **并行采纳** | 消费者真正不需要 C 调用；与编译器规则正交 |

## 4 契约与影响

| 项 | 约定 |
| --- | --- |
| 键名 / 取值 | `c-boundary = allow`（既有键，stable-subset 冻结中；本 ADR 不新增语法） |
| 读取位置 | `ct build` 的 `-I` 根下的 `ct.pkg`；`selfhost/ct-ast` 已是既有 `-I` 根 |
| 生成物 | `#include` 回到各 `.c` / `.h` 顶部；shim 只在有 C 原型时存在；用户语料生成 C 逐字节不变 |
| seed | 片末 `gen-seed.sh` 重生成，`check-seed` 两轮逐字节 |
| 回滚 | 删 `selfhost/ct-ast/ct.pkg` 并恢复 shim 与 `.h.ct` 的 include 位置（单提交 revert） |
| 施工前提（DEV 先验证） | 存在该 manifest 时，`ct build` / `ct check` 除 `c-boundary` 外不改变包语义与产物形状。若触发其它包行为，**回来报证据**，不得私自换成路径豁免 |

## 5 风险

| # | 风险 | 处置 |
| --- | --- | --- |
| 1 | `ct.pkg` 被 `ct build` 当作完整包清单，要求 name/version 等字段 | DEV 先验证；必要时只用 `--c-boundary=allow` 构建参数，并由本 ADR 的修订记录替换方案（不静默换） |
| 2 | 新增 selfhost 子目录不在 `-I` 根前缀内，不受豁免 | 记录在案；后续新目录并入 `selfhost/ct-ast` 前缀或显式加 `-I` |
| 3 | 消费者仍写空 shim，误以为本 ADR 已解决 | 本 ADR 只解决内部层；消费者路径是 REQ-STD-COVER-1，验收时分开报告 |
| 4 | 有人把"selfhost allow"当成放宽全局默认 | 负例判据：普通 `.ct` 仍 strict（CR-V3-1 第 3 条） |

## 6 验收（DEV 实施、REVIEW 签收）

1. `selfhost/ct-ast/ct.pkg` 只含 `c-boundary = allow`（外加注释）；`lib/core` 无 allow；
2. shim 66 → 3（保留有原型的三个）；`bootstrap/ct-ast/*.shim.h` 同步减少；
3. `ct --show-c-boundary selfhost/ct-ast/<任一单元>` 报 `allow`；删掉 `ct.pkg` 后报 `strict` 且门禁红（负例）；
4. `bash selfhost/gen-seed.sh`；`check-seed` 两轮逐字节；`CT_C_BOUNDARY=allow bash selfhost/check-goldens-ast.sh <ct>` 25/25；
   `bash selfhost/check-all.sh` 8 门；`check-warnings` 0；`python3 test/docs/check-docs.py` OK；
5. 普通无 include 的 `.ct` 生成物逐字节不变（CR-V3-1 第 3 条）。
