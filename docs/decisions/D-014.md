## 背景

外部《CT 语言组 —— 包管理契约与原生实现》（2026-11-20 收）提出：把发布、校验、索引生成
全部收进 CT，index 仓只保留纯数据，并发布契约 v1、conformance 与 CI 二进制。该提案与
D-010 §6（`ct pkg` 保持 B′）和 `battle index-pkg-1` 的判决直接冲突，也与 `ct pkg check`
只承诺 PK-1/2/5/8 的既有口径冲突。

需求方于 2026-11-20 逐项过完七个异议并作出裁定；本文记录裁定结果，作为契约 v1 的决策依据。

## 裁定

| # | 议题 | 裁定 |
| --- | --- | --- |
| 1 | 发布/索引生成是否收进 `ct` | **维持 B′**：`ct` 只新增只读 `ct index verify`；发布、tag、索引生成留在 `ct-pkg/index` 的 CI，凭据不进通用二进制 |
| 2 | `ct pkg check` 判据范围 | **先做 PK/R/S 归属矩阵**：逐条分给 CT（离线可判定）/ 包仓 / index CI；本仓只并入离线可判定项 |
| 3 | 契约 v1 落点 | **扩展现有** [ct-pkg-get-contract](../planning/ct-pkg-get-contract.md)，不新建平行 `contract-v1.md`；PK/R/S 只引用、不重定义 |
| 4 | 多 registry / 多索引 | **单索引**：`--index` > `CT_INDEX` > `$CT_HOME/index/index`；不承诺多索引并存，多源由调用方合并索引文件 |
| 5 | 五字段旧索引行 | **按行立即硬错**：命中五字段行即失败，其余六字段行照常可用；推翻契约 I12 的“只读兼容” |
| 6 | CI 分发 | **最小可用产物**：每个 MINOR 发布 `linux-x64` tar.gz + `.sha256`，GitHub Release 稳定 URL；节奏随 tag |
| 7 | 排期与归属 | 契约/向量/矩阵立即做（REQ，非 phase）；`ct index verify` 与产物开 **v0-PH-83（v0.83.0）**，排在 v0-PH-82 后、v1.0 前；index 仓脚本废弃由其自行确认 |

## 后果

- 契约 v1 需要新增：摘要伪代码与测试向量、spec 语法、单索引优先级、MVS、判据归属矩阵、
  五字段按行硬错条款；
- `ct get` 的旧行行为由“可读不可装”改为“命中即硬错”；**发布前置条件**：index 仓先把
  五字段行清零，再发带硬错的版本，否则 `ct/hal` 等存量包会立刻不可安装；
- 新增 `v0-PH-83`，不改 v0-PH-80→81→82→v1.0 的顺序；
- 不新增 `ct pkg release` / `ct index build|refresh`；`ct index` 只做只读校验；
- conformance 数据与 runner 作为契约 v1 的配套交付，先数据后 runner。

## 失效条件

- 若需求方重新裁定把发布/索引生成收进 `ct`，需显式覆盖本文件第 1 条与 D-010 §6；
- 若引入多索引并存或 `publisher→索引` 映射，需覆盖第 4 条；
- 若 index 仓未能在硬错版本发布前清零五字段行，第 5 条的发布时间表必须推迟或改为默认关闭。
