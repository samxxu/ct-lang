# D-022 · v1.0 bootstrap seed：冻结 ct-ast 自身生成的 C

- 日期：2026-11-23
- 状态：**accepted（seed 策略）**；实现归 [`v1-PH-0`](../phases/v1-PH-0/card.md)
- 目标：v1.0（`v1-PH-0`）；决定“只保留哪条自举起点”，不决定其余 cutover 细节
- 签收：USER 2026-11-23（授权 REQ 裁定）；复核待 REVIEW
- 依据：[v1 路线 §1.2](../planning/v1-release-plan.md)（原列 A/B/C 三案）；2026-11-23 实测（§2）
- 决策范围：只裁 seed 来源与退役边界；不改语言语义、发射格式、门禁编号以外的流程

> **2026-11-23 修订（所有者）**：v1.0 **先不清理 L0–L2**。它们保留为独立回归 oracle，
> 只把 ct-ast 的构建/安装路径换成 seed。删除 L1/L2 另立卡，不进 v1.0。§1.3、§1.4、§4
> 已按此改；其余结论不变。

## 1. 决策

1. **seed = 冻结 ct-ast 自身生成的 C 集**：`bootstrap/ct-ast/`（27 个 `.c` + 26 个头，
   约 50,945 行、2.3 MB），由收口版本的 ct-ast 生成，随每个 release tag 重新生成一次。
2. **`install.sh` 走 `cc bootstrap/ct-ast/*.c -o ct`**，不再 L0→L1→L2→ct-ast；`ctc` 兼容别名保留。
3. **L1（`selfhost/l1`）与 L2（`selfhost/l2`）在 v1.0 保留**，作为独立的回归 oracle
   （gate 2/3/4/5 照旧自建自测）；但**不再参与 ct-ast 的构建与安装**——`install.sh` 与
   `check-ast` 的 ct-ast 段改由 seed 构建。删除 L1/L2 另立卡（不属 v1.0）。
   原因：v1-PH-0 要把 `match` 写进 ct-ast 源码，而 L2 不认识 ADT/`match`（§2.2），
   L2 一旦继续充当 ct-ast 的编译器就会断链；把 L1/L2 降为 oracle 两者可共存。
4. **L0（`selfhost/l0/ctc.c`）保留**，继续支撑 gate 2/3/4/5 的旧链；它同时是与 seed
   不同源的独立实现，留作单文件夹具的对照。
5. **新增 gate 13 `check-seed.sh`**：以 `bootstrap/` 构建 → 重建 → 逐字节比较，两轮一致；
   `bootstrap/` 为只读生成物，手改即红（与 §2.3 的可复现实测对齐）。
6. **不退役 gate 2/3/4/5**；只改 `check-ast` 与 `ct-tour` 里“L2 构建 ct-ast”那一步，
   改由 seed 构建（§4）。

## 2. 证据（2026-11-23 实测，仓 `1c249313` + 工作树）

### 2.1 A 案（只留 L0）不成立

```console
$ cc -std=c99 selfhost/l0/ctc.c -o /tmp/v1probe/ctc
$ /tmp/v1probe/ctc selfhost/ct-ast/main.ct -o /tmp/x.c
selfhost/ct-ast/main.ct:17:1: error: 'import' is not supported by this compiler
```

L0 无 `import`，无法直接编译 ct-ast；A 案必须靠 L2 才能成立，与“去 L1/L2”冲突。

### 2.2 B′（冻结 L2 的 C 作 seed）不可行

**先澄清适用范围：L2 是今天的 ct-ast 引导编译器，这一点没有疑问。** 现行链
L0→L1→L2→ct-ast 中，ct-ast 源码用到的语法（`import`、多单元、泛型、trait、`Drop` 等）
正是 L2 提供的；L1 编不了 ct-ast，L0 连 `import` 都没有。本节否决 B′ 的理由**只针对
ADT / `match` 这一项**，不是“L2 没有语法能力”。

L2 缺的恰好是 ADT / `match`：它对这类源码**静默透传**，产物不是合法 C。

```console
$ /tmp/v1probe/l2 build /tmp/v1probe/a3.ct -o /tmp/v1probe/a3l2   # rc=0
$ wc -l /tmp/v1probe/a3l2/a3.c
13                       # 输出即源码：enum/match 原样抄进去
$ cc -std=c99 -c /tmp/v1probe/a3l2/a3.c
a3.ct:1:20: error: expected '= constant-expression' or end of enumerator definition
```

这不是新发现：[battle/p88-emit-match](../../battle/p88-emit-match/verdict.md) 的 J1 已用同一
现象判过“L2 前置不成立”（`L2` 发射 `enum NodeKind { AdtCtor(int n), … }` → `cc rc=1`；
同源码 ct-ast `rc=0`），并把它写成 `v1-PH-0` 的承接口：

> `v1-PH-0` 的 seed cutover 完成后，第一代 ct-ast 由新 seed 构建，**且该构建器能编
> ADT/`match`（v0-PH-84）源码**。

另有两处旁证：`selfhost/l2/core.ct` 中 `ADT` 命中 0（`match` 的 35 处全是注释与函数名，
不是 `match` 语句）；`selfhost/ct-ast` 今天没有 ADT 声明、也没有 `match` 语句，所以 L2
现在能编 ct-ast，与“L2 不支持 ADT/match”并不矛盾。

因此 B′ 的代价不是“L2 弱”，而是：**要么放弃 v1-PH-0 的 `match` 承接（需按 battle
承接口第 4 条显式覆盖判决），要么 seed 编不了第一代带 `match` 的 ct-ast。** 本 ADR 选前者
不覆盖、后者不受限的方案，即 B 严格档。

### 2.3 B 案可复现、确定性已验

```console
$ ct-ast build -I selfhost/ct-ast selfhost/ct-ast/main.ct -o /tmp/v1probe/bin1   # 生成 27 个 .c
$ ct-ast build -I selfhost/ct-ast selfhost/ct-ast/main.ct -o /tmp/v1probe/bin2
$ diff -r /tmp/v1probe/gen1 /tmp/v1probe/gen2
（无输出：逐字节一致）
$ cc -std=c99 -O1 /tmp/v1probe/gen1/*.c -o /tmp/v1probe/ctseed && /tmp/v1probe/ctseed -v
ct-ast v0.88.3
```

规模对照：ct-ast 自生成 50,945 行 / 2.3 MB；L2 生成 7,675 行 / 312 KB。

## 3. 被否方案

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| A 只留 L0 | 否决 | §2.1：L0 无 `import`，编译不了 ct-ast |
| B′ 冻 L2 的 C | 否决 | §2.2：L2 对 ADT/`match` 透传；seed 会冻结语言上限 |
| C 只发二进制 | 否决 | 破坏可复现与开源构建（原 §1.2 已定） |

| 8 `check-ast.sh` | 改 ct-ast 构建段 | 由 `L2 build ct-ast` 改为 seed 构建；L0→L1→L2 段仍跑但只服务 gate 2/3/4/5 的 oracle |

## 5. 风险与回滚

| # | 风险 | 处置 |
| --- | --- | --- |
| R22-1 | 2.3 MB 生成物进仓，评审噪声 | `bootstrap/` 只读、只在 release 提交里更新；PR 改动即由 gate 13 红 |
| R22-2 | seed 与源码同源，漂移不可见 | gate 13 两轮重建逐字节；每 tag 用当时 ct-ast 重新生成 |
| R22-3 | 新语法落地时旧 seed 解析不了 | seed 由**上一版 ct-ast**生成，保持一步自举；若某次语法增量连上一版都不认，按两阶段 bootstrap 处理并单独记录 |

回滚：`bootstrap/` 与 `install.sh` 同一提交回滚，旧链完整保留在 tag `v0.88.3`。
