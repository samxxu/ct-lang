# D-030 · `Str` / `String` 的 stdout 出口：方法而非内建函数

- 日期：2026-11-27
- 状态：**proposed（DEV 起草；待 REVIEW 签收）**
- 目标：`v1-PH-2` S8c（`LANG-30` / `REQ-PRINT-1`）；不改版本号、不打 tag
- 签收：REVIEW（**待签**，T-8 非作者席位；本 ADR 由 DEV 起草，不自签）
- 依据：[str-print-api](../proposals/str-print-api.md)（方案 A，所有者 2026-11-27 批准）、
  [LANG-30](../../issues/lang/lang-30-str-print-api.md)、
  [pointer-free-exemptions](../planning/pointer-free-exemptions.md) §2（E3 26 个样例）、
  [D-013](D-013.md)（`String` / `Str` 的复制与引用计数契约）、
  [language-spec §4.70](../language-spec.md)（`String` / `Str`）、
  §4.66–§4.67（C 边界与 libc 补头集合）
- 决策范围：**入口形态**（对象方法 vs 内建自由函数）、输出目标、字节语义、零分配判据、
  `fwrite` / `fputc` 的声明路径、与 `cstr()` / `printf` 的关系。
  **不含**：格式化、stderr、宽字符、`io::Writer` 抽象、`std::io` 改造。

## 1 决策

1. **入口是对象方法，不是内建函数。** `Str.print()` / `Str.println()`，`String` 同名转发到
   `as_str()`；不新增 `ct_print` / `ct_println` 一类全局名，也不扩 `ct_*` 内建族。
   理由：调用点 `name.print()` 与 `Vec` / `Map` / `Str` 的既有方法面一致；不进入用户
   命名空间；不需要新的解析/检查分支——它就是一次普通的 `impl Str` 方法调用。
2. **只做 stdout，返回 `void`。** 写失败不报错，与 `printf` 一致；错误出口另立 REQ。
   不提供 stderr 变体（`print_err` / `eprintln` 均不在本 ADR）。
3. **按字节写 `ptr[0..len)`。** `Str.len` 是字节长度；UTF-8 原样透传，不做编码转换。
   不看 `\0`：`a\0b` 写三个字节，这是与 `printf("%s")` 的关键差别，夹具必须钉住。
4. **`println` = `print` + 一个 `'\n'`。** 空视图的 `print` 写 0 字节；空视图的 `println`
   只写 `'\n'`。
5. **零分配。** 生成的 C 是 `fwrite(self->ptr, 1, (size_t)self->len, stdout)`；`println` 再
   `fputc('\n', stdout)`。不调用 `cstr()`，不 `malloc`，不复制缓冲区；`String` 的两个方法
   只把 `as_str()` 的视图交给同一段 `Str` 代码。
6. **`fwrite` / `fputc` / `stdout` 的声明走 `lib/core/Str.shim.h`（S9 方向）。**
   shim 里 `#include <stdio.h>`；**不把 `fwrite` 加进 §4.67 的自动补头集合**，也不要求
   调用方写 `#include` 或 `--c-boundary=allow`。
7. **不动既有语义。** `cstr()` 保留原语义（分配 + 调用方 `free`，C 互操作出口）；
   §4.67 的补头集合逐字节不变；`printf("%s")` 行为不变；不删任何 API。

## 2 备选与不采纳的理由

| 方案 | 形态 | 结论 | 理由 |
| --- | --- | --- | --- |
| **A（采纳）** | `Str.print()` / `Str.println()`，`String` 转发 | **采纳** | 零分配、零格式串、与方法面一致；调用点只多一个 `.print()` |
| B | 内建自由函数 `ct_print(Str)` / `ct_println(Str)` | 不采纳 | 与 `Vec` / `Map` 的方法面不一致；`ct_*` 名进入用户可见命名空间，冲突面更大；同样需要一条 C 边界声明，收益不抵风格分裂 |
| C | 扩 `printf` 格式串（`%v`） | 不采纳 | 改 C 语义、影响所有格式串，和「不重写 C 字面量」的既有约束冲突；不是本 REQ 的范围 |

方案 B 作为「方法不可行」的退路记录在提案里；实现证明方法可行（普通 `impl Str` 方法 +
shim 声明），因此不再启动 B。

## 3 契约

| 项 | 约定 |
| --- | --- |
| 签名 | `pub void Str.print()` / `pub void Str.println()`；`String` 同名两方法 |
| 输出目标 | 只 stdout；`fwrite` / `fputc` 到 `stdout` |
| 字节语义 | 写 `len` 个字节，UTF-8 原样；`len` 是字节数，不是码点数 |
| `\0` | 数据字节，不是终止符；按 `len` 全量写出 |
| 空视图 | `len <= 0`（或 `ptr == 0`）写 0 字节；不越界 |
| 返回 | `void`；忽略写入结果，不设 errno 契约 |
| 分配 | **零分配**；无 `cstr()` / `malloc` / `free` / 临时缓冲 |
| `String` | `self->as_str()` 后走同一段 `Str` 代码 |
| `cstr()` | 保留；仍会分配，文档标注「C 互操作、调用方 free」 |
| 与 `printf` | 不替代；两者都走 stdio 缓冲，同一流上的顺序一致（夹具混用一次钉住） |
| 平台 | Windows 文本模式可能把 `\n` 写成 `\r\n`；这是已知平台限制，不加平台分支，不在字节契约内 |
| freestanding | 无 stdout 概念，本 API 不适用；`--freestanding` 下不承诺可用 |

## 4 C 边界与零分配判据

- `Str.shim.h` 增加 `#include <stdio.h>`；`Str.h.ct` 只 include 自己的 shim（§4.66）。
- §4.67 的自动补头集合**不变**：`fwrite` 不在表里，本 ADR 不申请加入；`printf` 一族照旧。
- 机械判据（`test/ast/lang30_print.sh`）：
  1. 生成 C 的 `Str_print` 体出现 `fwrite`、`Str_println` 体出现 `fputc`；
  2. 两个体都不出现 `malloc` / `free` / `cstr`；
  3. `String_print` / `String_println` 体出现 `String_as_str` 且无分配；
  4. `ct compile` 与 `ct build` 的输出与 `prog.expected.out` 逐字节一致；
  5. ASAN 无报告（LSan 不可用的平台用退出码 `ct_str_live_count()` 兜底，见夹具）。

## 5 后果

- E3 的 26 个 examples 可以去掉 `char *` + `printf("%s")` 的打印阻碍
  （[pointer-free-exemptions](../planning/pointer-free-exemptions.md) §2）；真正的 C 互操作
  （`va_list` / `strcmp` / C 结构体字段）仍按 E1 保留并逐条登记理由。
- spec 新增 §4.78，§4.70 的方法表补两个名字；glossary / tutorial 同步。
- 不改版本号、不改诊断码、不动 `std::io`；回滚只需 revert 一个提交。

## 6 回滚

- 改动落在 `lib/core/Str.h.ct`、`lib/core/Str.shim.h`、`lib/core/String.h.ct` 与夹具/文档；
  单提交可 revert，revert 后 `check-goldens-ast` / `check-seed` 不受影响（`lib/core` 不进
  seed 的编译器闭包）。
- 本 ADR 不新增诊断码，不进入 `docs/diagnostics/codes.md`。

## 7 未决 / 边界

- stderr、格式化、宽字符、`io::Writer`：不在本 ADR，留给后续 REQ。
- 写入失败的可见性（`ferror` / 返回值 / 诊断）：本 ADR 明确不做，与 `printf` 一致。
- REVIEW 签收后把状态改为 `accepted`；签收前本 ADR 只作为实现依据，不声称已定稿。
