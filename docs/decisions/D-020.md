# D-020 · 绑定点转换协议（LANG-26 ADR）

- 日期：2026-11-22
- 状态：**accepted（设计）**；实现延后到 v1.1
- 目标：`v1-PH-1` 起（v1.1）
- 签收：REVIEW 2026-11-22（T-8 非作者席位）
- 批准：EDITOR 2026-11-22
- 依据：[LANG-26](../../issues/lang/lang-26-binding-site-conversion.md)、
  [评估](../reviews/2026-11-22-req-node-conversion-protocol-eval.md)、
  [LANG-25](../../issues/lang/lang-25-diagnostic-code-registry.md) 诊断码边界、`stable-subset` 三档

## 1. 决策

采用**仅绑定点、两档协议**：

| 项 | 规则 |
| --- | --- |
| 转换位置 | 只允许四类绑定点：声明初始化、赋值、`out` 实参、`return`；表达式内（算术、普通实参、条件、下标）**不转换** |
| 宽松档 | `as<T>`：源类型固有方法或已 import 的映射 trait；缺失字段/类型不匹配给 `T` 的零值/缺省值 |
| 严格档 | `.to<T>() -> Option<T>`：失败返回 `None`，不静默兜底 |
| 绑定点默认 | 裸写（无 `as`/`to`）在四类绑定点走**宽松档**；需要失败可见时显式 `.to<T>()` |
| 查找顺序 | ① 源类型固有方法 `as<T>`/`to<T>`；② 已 `import` 的映射 trait；③ 都不命中 → 专门诊断（不是“未声明标识符”） |
| 歧义 | 多个 trait 候选且无更具体者 → error，列出候选与 import 指引；不得按声明顺序静默取第一个 |
| `--types` | 转换结果类型显式写入类型流；全语料 FP=0 是门禁；新增语料进 J-6 |
| 生成 C | 等价于显式 `as<T>()` / `.to<T>()` 调用；对照组逐字节一致（除调用点位置信息） |

## 2. 表达式禁区（负例）

```ct
Vec<int> v = node;          // OK：声明初始化
v = node;                   // OK：赋值
f(out v);                   // OK：out 实参
return node;                // OK：return（返回类型可转换）
int x = node + 1;           // error：表达式内不转换
g(node);                    // error：普通实参不是绑定点
```

## 3. 诊断与 --types

- 未 import 映射 trait：`no conversion from 'Node' to 'Vec<int>'; import std::json::NodeMap or call .to<Vec<int>>()`；
- 歧义：`ambiguous conversion ...; candidates: A, B; disambiguate with .as<T>() / .to<T>()`；
- 表达式内：`conversion is only allowed at a binding site (declaration/assignment/out/return)`；
- 稳定诊断码归 LANG-25（v1.2）；v1.1 先给稳定文案，不承诺 code。

## 4. 回滚

- 特性开关：编译期 `CT_BINDING_CONVERSION=0` 关闭（默认开仅在 v1.1 批准后）；
- 关闭后行为回到 v1.0：绑定点也不转换，旧代码不受影响；
- 回滚不改语法、不改已生成 C；测试夹具保留并标 skip 原因。

## 5. 实施边界

- v1.0 不实现；ADR 通过不等于特性已交付。
- v1.1 实现前先做容量复算；SH-109 已在当前 pre 窗口改为动态增长（初始 512、65536 安全阀），
  不再受固定 `MAX_FUNCS 512` 或 ≤11 约束。
- 连带义务（J-6 行、`stable-subset` 三档、`capabilities.tsv`、idioms §11）在实现落地后登记，不在本 ADR 冒充已交付。

## 6. P-3 缺口复核（2026-11-24，DOC-99 P-3）

对照 v1.1 已落切片（声明 / 赋值 / `return` 三类绑定点 + `as<T>` / `.to<T>()` + 映射 trait）
与 D-020 §1–§5，剩余三项结论如下。

| 剩余项 | D-020 状态 | 结论 |
| --- | --- | --- |
| `out` 实参写回转换 | **未覆盖** | D-020 §1 把 `out` 列为绑定点，但没有定义“临时量 + 调用后回写”的语义。增量见 §6.1 |
| `decode<T>` 边界 | **部分覆盖** | D-020 只把 `.to<T>() -> Option<T>` 定为严格档；`decode<T>` 的解析/校验分工未定。增量见 §6.2 |
| `CT_BINDING_CONVERSION=0` 开关 | **部分覆盖** | D-020 §4 只写“编译期开关、默认开仅在 v1.1 批准后”，未定开关形态与关闭后的诊断。增量见 §6.3 |

### 6.1 `out` 写回

1. 调用点只对**形式参数类型与实参类型可双向转换**的 `out` 生成临时量：先按宽松档把实参当前值
   转成形式类型，传 `&temp`；调用返回后，只有 callee 明确写过 `temp` 才把 `temp` 转回实参类型
   并写入实参。callee 未写时保持实参原值。
2. 失败路径（返回 `false` / `err:` / 提前 `return`）**不撤销** callee 已写入的 `temp`；写回仍按
   第 1 条的“已写”判据执行。定值分析把该 `out` 实参视为“调用后可能已写”，与无转换的 `out` 一致。
3. 任一侧转换缺失或歧义 → 编译期硬错，文案复用 D-020 §3 的“no conversion / ambiguous”；
   不生成部分写回。
4. 实现必须保证临时量生命周期覆盖调用；错误路径的清理与 `defer` 不因临时量改变顺序。

### 6.2 `decode<T>` 边界

1. `.to<T>()` 是**值到值的严格转换**：失败返回 `None`，不解析文本、不构造动态值；
2. `decode<T>` 是**动态值/文本到 T 的解析入口**，归 v1.1 的映射层（`map binding` 注册表），
   不改变 D-020 的四类绑定点；解析失败返回映射层定义的错误（v1.1 定为 `Result<T, DecodeError>`），
   不静默零值；
3. 用户可提供 `map binding` 实现 `decode`，但只能通过显式 `import` 生效；未 import 仍按
   “no conversion” 诊断，不自动派生；
4. `decode<T>` 不进入 D-020 的“宽松默认”档：绑定点裸写只走 `as<T>` / `.to<T>()`。

### 6.3 开关

1. 形态：编译期环境变量 `CT_BINDING_CONVERSION=0`（实现落地时由 `ct`/`ct-ast` 读取）；默认开；
2. 关闭后：四类绑定点都**不转换**，回到 v1.0 行为；已显式写 `.as<T>()` / `.to<T>()` 的调用不受影响；
3. 关闭后的诊断：绑定点类型不匹配恢复 v1.0 的 `expected/got` 文案，不出现“conversion disabled”
   一类新提示（避免测试快照分叉）；需要提示时只在 `--debug` 输出；
4. 回滚只需一次提交：删除开关读取、恢复默认路径；测试夹具保留并标 `skip: CT_BINDING_CONVERSION=0`
   原因，不删除。
