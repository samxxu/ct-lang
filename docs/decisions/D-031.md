## 1 决策

1. **语法入口不变，只认读形态。** 触发形态仍是既有的 `recv[key]`。折叠的额外条件是：
   - `recv` 的静态类型是**非指针的用户 struct 值**（`struct X` 或 `X`，`X` 不是内建容器 /
     句柄 / ADT / 接口值）；
   - `recv` 可回溯到变量或字段链（`N_VAR`、`N_MEMBER`、`N_ARROW`、`N_INDEX`、
     `N_SLICE_INDEX`、`N_DEREF` 为根）；调用结果等临时量不折叠；
   - `key` 是**单个、无转义、无拼接**的字符串字面量，其内容与 `X` 的某个字段名逐字相等。
   命中即 `p["x"]` 在解析期改写为 `p.x`（`N_MEMBER`），不经过 `get`。
2. **字段优先，未命中再走既有 `get(char *)`；两者都命中即歧义硬错。**
   - 字段命中、且不存在**匹配且可见**的实例 `get`：折叠。
   - 字段命中、且存在匹配的实例 `get`：报歧义（`D031-1`），不静默选择。
   - 字段未命中、存在任何 `get` 声明：**完全交回既有下标协议**（含 D-028 的
     no-match / 歧义 / 参数类型文案），本 ADR 不改写这些诊断。
   - 字段未命中、且类型没有任何 `get`：报未知字段（`D031-2`），候选只列**字段名**。
   “匹配”沿用 D-028：方法名 + 参数个数 1 + 非 `static` + 字面量键的静态类型
   （`char *`）与形参 `type_key` 逐字相等；`get` 在定义单元私有 / `static` /
   参数类型不同都不算“匹配”。
3. **折叠落点在解析期一处完成，TIR/LIR 继承既有字段路径。**
   解析器在识别期解析到字段 id（`StructDef::struct_field_at` 的行号），用它判定命中/未命中、
   生成候选表；命中后把下标糖改写成与手写 `p.x` **同形**的 `N_MEMBER` 节点
   （接收者 + 字段名），**不在节点上保存字段 id**——节点字段槽是通用遍历的子树槽，
   保存 id 会被 hoist / invariant 扫描当成子节点。TIR 的 `TK_FIELD`、LIR 的
   `LE_FIELD` 与 AST 发射器都不新增第二套折叠：它们已经按字段访问打印。因此
   `--ir=off`（AST 发射器）与默认 LIR 路径产出同一 `recv.field`，C 中**无 `get` 调用、
   无 `__ct_*` 临时**。
4. **只读。** 折叠只在读位置发生。`p["x"] = v`、`p["x"] += v`、`p["x"]++` / `--`
   一律**不折叠**，仍走 D-028 的写形态与 L52-6 拒绝文案；`&p["x"]` 是读位置，可折叠为
   `&p.x`（字段地址，无临时）。这样“零开销下标”的收益只落在读，写语义不扩大。
5. **接收者不取址，但必须是 place。** 读形态的折叠不取接收者地址，也不物化临时；
   字段访问对值、字段链与数组元素都成立。接收者仍需可回溯到 place（决策 1 排除调用
   结果等临时量），但 D52-4 的“写形态接收者必须是左值”不被放宽也不被引用。
6. **不引入映射表。** 折叠只查符号表里既有的 `StructDef` 字段行（`struct_field_at`）；
   不建字符串到字段的全局表，不改 `type_key`，不改既有 `get` 的 C 符号。
7. **一层键。** 只折叠单个字面量；`p["a"]["b"]` 的第二层仍按既有规则处理（对普通 struct
   值仍是 C 下标 / 既有错误），本 ADR 不承诺多级折叠。

## 2 诊断（冻结）

新增两条，位置一律指向 `[`，一次只报一条：

```text
type 'P' has an ambiguous constant-key subscript: both field 'x' and 'get(char *)' match; write the field access or 'get("x")'
type 'P' has no field 'nope': candidates are 'x', 'y'
```

- `D031-1`（并存歧义）只在“字段命中 + 匹配的实例 `get` 存在”时出现；`get` 的名字与
  参数类型按解析结果写进文案，不列全部重载。
- `D031-2`（未知字段）只在“字面量键未命中字段 + 类型没有任何 `get` 声明”时出现；
  候选按声明顺序列出**全部字段名**，每个用单引号，逗号加空格分隔；字段为空时省略
  `: candidates are …`，只留 `type 'P' has no field 'nope'`。
- 前向声明（`defined == 0`）的字段表未知：不折叠、也不报未知字段，交回既有 L52-1。
- 非字面量键（变量、数组元素、表达式）完全不进本 ADR：`x[k]` 的既有诊断逐字不变。
- 既有的 L52-1…L52-10、D028-1…D028-3 全部保留；本 ADR 只新增上述两条。唯一的行为变化是
  “字面量键 + 无 `get` 的普通 struct”从 L52-1 改为 `D031-2`（例如 `p52_no_get` 夹具）：
  这是把“没有下标协议”细化为“没有这个字段”，属于本能力的定义面，REVIEW 签收时确认。

## 3 兼容与零回归边界

| 面 | 保证 |
| --- | --- |
| 既有 `get` 类型（无同名字段） | 字段未命中 → 原 `get` 路径；生成的 C、诊断、求值次数逐字节不变 |
| `get` 与字段并存 | 新增歧义硬错，不再静默走 `get` |
| `Vec` / `Map` / 切片 / C 数组 / 指针 | 分支未改；`v[0]` / `m["k"]` / `arr[1]` / `p[2]` 不变 |
| `String` / `Str` / `Box` / ADT / 接口值 | 明确**不折叠**，继续走各自既有规则（实现句柄字段不得被常量键绕过） |
| 写形态 | `=` / 复合赋值 / `++` / `--` 不折叠，L52-2、L52-6 文案不变 |
| 非字面量键 | 既有解析与诊断完全不变 |
| 生成 C | 折叠点只产生 `recv.field`；无 `get`、无 `__ct_*` 临时、无新分配 |
| 自举 / seed | 改 `selfhost/**` 后 seed 两轮逐字节；旧语料生成 C 逐字节不变 |
| 版本 / tag | 不改 `CTC_VERSION`、不动 tag、不改 issue 状态 |

## 4 备选与不采纳

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 只在发射器把 `get("x")` 打印成 `p.x` | 不采纳 | 类型检查与 TIR/LIR 仍认为这是方法调用；`--ir=off` 与 LIR 会分叉，且拿不到字段 id |
| 建“字段名 → 下标”的映射表 | 不采纳 | 与符号表重复；字段增删要同步两张表，正是本卡禁止的映射表 |
| 字段优先但并存时静默选字段 | 不采纳 | 改变既有 `get` 类型的行为且无法从源码判断意图；与 D-028“不静默选择”冲突 |
| 字段优先但并存时静默选 `get` | 不采纳 | 新能力在并存类型上永远不生效，零开销下标失效 |
| 支持写形态 `p["x"] = v` | 不采纳 | 写语义要处理 `set`、借用写、`own` 右值与单次求值；本卡边界明确排除 |
| 键可以是运行期字符串 | 不采纳 | 那就是 `get`，不是编译期折叠；需要运行期映射 |
| 同时覆盖接口值下标 | 不采纳 | 接口值下标是 I2 / Q-8（`D-034`）的独立卡，混入会让本卡的判据不可单独回滚 |
| 在 LIR 再写一遍折叠 | 不采纳 | 解析期已是唯一真相；TIR/LIR 的字段路径自动继承，第二套实现只会增加分叉面 |

## 5 回滚

- 实现分两个相邻提交，均只改 `frontend/parse/`：
  - **T1**（`ExprCore.h.ct` 的 trait 声明 + `ExprSubscript.h.ct` 的识别/排除/接收者判定 +
    `Expr.h.ct` 的下标分支）：只折叠“类型没有任何 `get`”的形态；
  - **T2**（`ExprSubscript.h.ct`）：字段优先、`get` 回退、并存歧义与未知字段诊断。
  夹具、spec/glossary/example、语料 pin、seed 与发射 C pin 各自独立提交。
- 回滚顺序：先 revert T2 → 只剩 T1 的基础折叠（无 `get` 类型），`get` 类型行为回到旧路径；
  再 revert T1 → `p["x"]` 完全回到 L52-1 / `get`。夹具与文档可一并回滚或保留（保留时它们
  表达的期望会变红，按测试资产处理）。
- 行为细化带来的两处 pin 必须与实现同批：`p52_no_get` 的诊断字节（p86 E86-4 的 343 条
  清单重钉一行）、`p85_corpus_sha.tsv`（新增一条样例）、`p88_metrics` 的 `emitted_after`。
- 回滚后 `check-goldens-ast`、`check-seed` 必须仍绿；seed 用回滚后的编译器重生成。
- 不改协议版本、不删任何既有 API、不新增诊断码 registry 条目（`D031-*` 是 ADR 内编号，
  不是 `docs/diagnostics/codes.md` 的机器码）。

## 6 不做（边界）

- 写形态与复合赋值、`++` / `--`；
- 嵌套常量键（`p["a"]["b"]`）、数组 / 切片 / 容器下标折叠；
- 接口值（trait 对象）上的下标派发（I2 / Q-8，另卡 `D-034`）；
- 变量键、运行期键、字符串到字段的查表；
- 非字面量键的 `get` 解析规则（D-028 原样）；
- 跨单元字段可见性的新规则：折叠与手写 `p.x` 同判据，不新增私有字段诊断；
- 其它运算符重载、`$[k]`（`into` 块内）、多级连写；
- 解析点之后的声明可见性：折叠与既有下标协议一样读取**解析这一刻**的符号表，
  调用点之后才声明的 `impl` / 结构体定义在该点不可见（既有行为）；本 ADR 不
  引入预扫描，也不改变这条顺序语义。

## 8 技术审定结论（ARCH，2026-11-28）

> 范围：只审定 §1 的 Q1–Q4 与 §3 的 R2；不改实现、spec、测试与 seed。
> 结论：**接受，附条件**。实现先于 ADR 签收落地（§4）不改变本审定的独立性；条件未补齐时
> 以本节为准补测/补文档，不以“已实现”默认成立。

### 8.1 Q1 触发面：接受（附条件）

- **判定依据成立。** 折叠需要“键在编译期已知、字段在编译期可解析、接收者是无需求值改写的
  place”。字面量 + 非指针 struct 值 + 可回溯接收者恰好是同时满足三者的最大集合：变量键/拼接/
  转义只能落到运行期 `get`，临时量接收者要么物化临时（与“零开销”卖点相反），要么改变求值
  次数，都应排除。§1.1 的条件与 D-028 的 `type_key` 判据同源，不引入新的类型规则。
- **实现路径可辩护。** 只读既有 `StructDef` 字段行（§1.6），不建字符串到字段的映射表；这与
  §4 否决的“建表”方案互斥，保证了字段增删不必同步第二张表。
- 附条件 **C1**：非 place 接收者（`f()["x"]`）保持**不折叠**，诊断保持既有 L52-1，不得落到
  D031-2；现探针只覆盖变量/字段链/数组/泛型实例四类正例，需补一条临时量负例。
- 附条件 **C2**：`&p["x"]`（读位置）折叠为 `&p.x` 是**新增可编译形态**，需一条正例探针；并在
  spec §4.79 写清“折叠判定先于 L52-7 的取址拒绝”，否则同一表达式会出现两套解释。
- 附条件 **C3**：前向声明（`defined == 0`）字段表未知时不折叠也不报未知字段（§2 已写），需
  一条探针覆盖，防止解析顺序调整后把“未知”误报成 D031-2。

### 8.2 Q2 字段优先 + 并存歧义硬错：接受

- **字段优先是唯一不产生语义漂移的顺序。** 静默选 `get` 会让新能力在并存类型上永远不可达；
  静默选字段会把既有程序从 `get` 悄悄改成字段读取，且无法从源码判断作者意图。硬错与 D-028
  §1.6 / D028-2 的“不静默选择”一致，文案同时给出两条显式替代写法，迁移成本可度量。
- 附条件 **C4**：歧义只在 `get` **匹配且可见**时触发（名字 + 1 参 + 非 `static` + `char *`
  形参逐字相等 + 非单元私有）。私有 / `static` / arity 不符 / 参数类型不同都不构成 D031-1，
  否则会把本来合法的旧程序误伤成“歧义”；需至少补 private 与“参数类型不同”两条负例。

### 8.3 Q3 诊断语义变更：接受（附条件）

- 把 L52-1（没有下标协议）在“字面量键 + 无 `get` 的普通 struct”上细化为 D031-2（没有这个
  字段）是本能力的定义面：字面量键的语义就是字段名，拼错必须定位到字段并列出候选；沿用旧
  文案会让 `p["nope"]` 与 `p["x"]` 落进同一条“无协议”，静态价值减半。
- 附条件 **C5**：D031-2 候选按**声明顺序**列全部字段、单引号、逗号加空格；类型无字段时省略
  `: candidates are …`；类型有任何 `get` 时一律交回 D-028，D031-2 与 D028-1 不得同时出现
  （位置一律指向 `[`，一次一条）。
- 附条件 **C6**：该细化必须在 spec §4.64 的 L52-1 条与 §4.79 同时可见（spec 现已如此），并在
  release note / 迁移说明里列为唯一的行为细化项。

### 8.4 Q4 边界：接受

- 写形态、嵌套常量键、容器/数组/接口值常量键全部不做，是正确的 1.2 最小面：写形态要引入
  `set` / 借用写 / 单次求值；嵌套会与 D-028 的多级链、I2 抢解析表；接口值下标已有独立卡
  （`D-034`）。§3 的零回归表与这些边界一致。
- 附条件 **C7**：嵌套 `p["a"]["b"]` 目前只是“不承诺”，需一条探针钉住**实际行为**（折叠两层
  或落回既有规则都可接受，但契约必须与实测一致），避免 spec 的“不做”与实现递归折叠矛盾。
- 附条件 **C8**：接口值（trait 对象）上的字面量键明确不进 I1，由 `D-034` §3 写死；两卡共用
  D-028 解析表但互不改写，回滚互不牵连。

### 8.5 R2（并存歧义由可编译变硬错）：可接受，属有意的 breaking

- **触发面极窄。** 只有“类型同时有字段 `f` 与匹配的实例 `get(char *)`，且源码写 `p["f"]`”
  才从可编译变硬错。仓库内 25 条用户语料与 83 条 IR 语料**零命中**：折叠开启后
  `check-goldens-ast` 25/25、`test/ir` 83 语料逐字节仍全绿（命中即硬错，不可能通过）；
  逐个核对现有 `get(char *)` 夹具，字段名与所用字面量键也均不相等（`p52_read` 字段
  `n`/`seen` vs 键 `a`/`z`；`p52_str_only` 字段 `found` vs 键 `name`；`index_overload_both`
  字段 `n`/`tag` vs 键 `new`/`x`；`p52_generic` 字段 `value` vs 键 `k`）。该形态只出现在新增的
  `lang31_ambiguous` 负例里。
- **替代方案更差。** 静默字段优先是语义漂移，静默 `get` 优先让新能力失效，二者都违背 D-028
  的“不静默选择”；“加警告”不可行——Ct 当前没有可依赖的警告通道，且警告不阻止语义变化。
  故硬错是唯一可辩护的处置。
- 附条件 **C9**：spec §4.79、release note 与 LANG-31 必须把该 breaking 写成**显式迁移项**，
