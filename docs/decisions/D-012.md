## 背景

《泄漏防护三板斧》提出「直接环检测 / strict 升 error / debug 环扫描」。复核后确认：
可确定的编译期部分进 PH-82；无法可靠实现的运行期环扫描不进卡。battle 对四项口径逐条裁定。

## 1 裁定

| 项 | 结论 | 说明 |
| --- | --- | --- |
| 配置键 | **`leaks`（`warn` / `error`）** | 缺省 `warn`；`error` 同时升级现有 `potential leak` 诊断与直接环告警；与 `c-boundary = strict` 互不影响 |
| 直接环范围 | **仅 `box<X>` 字段，限深 3 条边** | 自环、A→B→A、A→B→C→A 命中；同一环只报一次；容器/泛型/接口/typedef/间接环不计 |
| 默认级别 | **warning**；`leaks = error` 时 error | 文案写「可能泄漏，除非手工破环」，不写「会泄漏」 |
| 豁免 | **`/* ct: allow-cycle */` 注释** | 必须与 `struct` 声明同一行；`ct check` 报告被抑制点；不引入属性语法 |
| L3 | **从 PH-82 descope** | `--debug-leaks` 维持 D-011 J-4c：只报未配对 alloc/release 计数，不叫环检测；运行期「未释放句柄清单」另立提案，先解决根注册 |
| 排期 | **PH-82 在 PH-81 之后；v1.0 顺延到 PH-82 之后** | 单卡 `v0.82.0`；L1 + L2 + L4 同卡，L3 不进 |

## 2 理由

- `box<T>` 是 PH-81 的产物，PH-82 的环检测以它为前提；
- 句柄按值复制，栈/寄存器副本没有统一根注册点；「从根集标记可达」不可可靠实现；
- 现有 `potential leak` 只覆盖 `own`/裸指针，`leaks = error` 不能宣称覆盖句柄运行期泄漏；
- 注释 pragma 在现有词法内可实现；属性语法不存在，单为豁免开语法不划算。

## 3 后果

- 新增 [phase82](../design/phase82.md)，状态「规划中（未开卡；PH-81 收口 + 本 ADR）」；
- roadmap 增加 Phase 82 行；`v1-PH-0` 的顺延锚点改为 PH-82；
- 不修订 D-011 J-4c，不改变 `--debug-leaks` 的现有语义；
- 不改 `ct.pkg` 的 `c-boundary`；不改源码、不 bump。

## 4 不采纳

- 宽键 `strict = on`（与 `c-boundary = strict` 撞车）；
- `--debug-leaks` 现稿「从根集标记可达 + 环判定」（根集不可枚举）；
- 属性式豁免（无属性语法）；
- 直接环默认 error（对手工破环写法一刀切）。
