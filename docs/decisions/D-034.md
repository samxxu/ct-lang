- 决策范围：接口值 `o[k]` / `o[k] = v` 的**解析口径**、`index` 标记的语法位与词法、阶段一/阶段二

## 1 决策

1. **D-028 边界保持分裂（选 (i)）。** 具体类型（非接口值）的 `[]` 只认固有 `impl` 的 `get` /
   `set`；trait 里标 `index` 的 `get` / `set` **只服务接口值**的 `[]`。
   - **派发模型不同的语法不应共用一套解析。** 具体类型今天是静态直调 `<T>_get`（零 vtable、
     零间接），接口值是 vtable 槽调用。统一会在同一语法上并存两套派发、两套求值/所有权路径，
     使 D-028 §4“唯一名 `get` / `set` 的生成 C 逐字节不变”无法保持。
   - **已发布语义不在一张新卡里改。** D-028 已 accepted，spec §4.64 明文“trait 提供的 `get`
     不算（只认固有 `impl`）”。选 (ii) 等于在同一张卡里重写已发布规则，I2 的回滚不再独立：
     revert I2 会把具体类型语义一起带回去。
   - **会与 I1 的优先级表冲突。** 具体 struct 有字段 `x`、trait 又标了 `index get(char *)` 时，
     `p["x"]` 是折叠、歧义还是走 vtable？D-031 §1.2 的“字段 + `get` = 歧义”只针对**固有**
     `get`；把 trait `get` 纳入就必须重开 D-031 的优先级与负例。
   - **成本收益不对称。** (ii) 还要为多 trait / 多实现、泛型实例、私有方法、借写
     `*get(k) = v` 重新定序并补负例，而 I2 的目标只是“接口值 opt-in”。
   - **代价（可接受）**：具体类型要用 `[]` 仍需固有 `impl`，同一逻辑可能要在 trait impl 与固有
     impl 各写一份。推荐写法是固有 `get` 转调共享自由函数，或在该位置使用接口值（`Store s`）。
   - 若未来要改 (ii)，必须单独立 ADR 扩 D-028，并至少补：固有 `get` 与 trait `index get` 同键
     （固有优先）、两个 trait 各带同键 `index get`（歧义）、字段 + trait `index get`（对齐
     D031-1）、私有 / `static` trait 方法、泛型实例替换、`*o[k] = v` 借写、跨单元头。
   - **分裂口径的可观察结果**：具体类型 `JsonStore` 即使实现了带 `index` 的 `Store`，`j["x"]`
     仍按 D-028 报“没有固有下标”（无固有 `get` 时是 L52-1），**不得**提示 trait 的 `index get`；
     要用接口值下标，写 `Store s = j; s["x"]`。I2-C1 §10.1 A9 钉住这条。

2. **`index` 只允许出现在 trait 方法签名的 `)` 之后、`;` 之前，一次一个。**
   - 语法位与既有 `mut` 后置修饰词同型（spec §4.10：`int f() mut;` 合法，前缀 `mut int f();`
     拒绝并提示后置写法）：本卡规定 `Ret name(params) index;`，前缀 `index Ret name(...)`、
     写在 `;` 之后或重复写 `index index` 一律硬错（D034-7）。
   - `index` **不是保留字**：`int index`、`c.index`、字段 `index`、方法名 `index`
     （`int index(Str k);`）全部保持普通标识符；识别只发生在“trait 方法声明尾部、紧邻 `;` 的
     那一个标识符”。
   - `impl` 侧（含 `.h.ct` 的 impl）重复写标记是硬错（D034-3），不做“两处取并集”或“以 impl
     为准”。标记属于 trait 声明这一处。
   - 作用域：只对产生 vtable 的动态 `trait` / `pub trait` 生效。`.m.ct` 的静态 `map trait`
     不产生接口值，不识别本标记，也不承诺专门文案；不得把标记语义扩到静态映射层。
   - 同一 trait 内方法声明顺序仍是 vtable 槽顺序（既有行为）；标记不改变顺序、不新增槽。

3. **接口值 `o[k]` 只在 trait 的 `index` 方法里按实参静态类型匹配。**
   - 接收者静态类型必须是接口值（trait 对象）；解析读**trait 声明**（`impl` 不参与决议）。
   - 匹配沿用 D-028 §1.1：名字 `get` + 参数个数 1 + 非 `static` + 实参静态类型与形参
     `type_key` 逐字相等；不做隐式转换、不做数值提升。
   - **键类型与字面量**：字符串字面量的静态类型是 `char *`（spec §4.64 / §4.70），因此
     `o["name"]` 只命中 `get(char *k) index`。`Str get(Str k) index` 对 `o["name"]` **不命中**，
     按 D034-2 报键类型不匹配。RFC 评估 §3.1.1 样例里的 `Str get(Str k) index` + `s["name"]`
     据此更正为 `Str get(char *k) index`（或先把键绑定为 `Str` 变量）；这不是新增语义，而是
     D-028 既有类型规则的直接结果，**不允许**为字面量加 `char * → Str` 的隐式匹配。
   - 多个 `index get` 按实参键类型分派（`get(char *)` / `get(int)` 并存合法）；同一键类型重复
     是 D8 的硬错。
   - 未标 `index` 的 `get` 不参与 `[]`，仍是普通方法（`o.get(k)` 可调用）。
   - 接口值上的字面量键**不做 I1 折叠**：I1 只作用于非指针用户 struct 值（D-031 §6），两卡
     共用 D-028 解析表但互不改写。
   - 落点：解析期把 `o[k]` 改写成与显式 `o.get(k)` **同形**的既有方法调用节点（`N_MCALL` /
     **`aux = 3`**，接口值 vtable 调用；D-028 固有下标仍是 `aux = 9`），TIR / LIR / 发射器零
     新增分支；生成 C 与显式调用逐字节一致**限唯一名（单键）trait**（多键见 §8 E2）。

4. **阶段一 `o[k] = v` 一律拒（`E-V3-9e`）。** 写族（`=`、`+=`、`++` / `--`）在阶段一的检查点
   直接报 D034-4，不先解析 `get`、不写产物；`&o[k]` 沿用 L52-7 的取址拒绝文案。理由：阶段一
   没有 `index set` 槽语义，任何“先读后写 / 借写”的模拟都会引入临时量与求值次数变化；无条件
   拒绝让阶段一判据与阶段二解耦，回滚只需删这一段检查。D034-4 在 I2-4 后已由 D034-8 接班
   （§8 E4）；本项作为**阶段一历史判据**保留，HEAD 不再产生。

5. **阶段二写入只走 trait 声明的 `index set`；“只读实现被写入”在类型层不可能存在。**
   即三选一中的**“不允许该标注组合”**。
   - `o[k] = v` 合法，当且仅当接收者的静态 trait 声明了与键匹配的 `void set(K, V) index`。
     trait 没声明 → 编译期硬错 D034-8，不落运行期检查。分派只按键类型（`set` 首参）选版，
     值类型按既有实参兼容性检查，**不是**选版维度（与 D-028 §1.2 一致）。
   - Ct 的 trait 完整性规则（spec §6.1 约束表：`trait method 'm' is not implemented for
     struct 'S'`）要求 impl 实现每个抽象方法，因此“trait 有 `set index` 但某个 impl 没有”本身
     是既有硬错，不存在运行期缺实现的分支。默认体（spec §4.39）是**用户写的**方法体，编译器
     不合成空实现。
   - 否决“空实现”：静默丢弃写入直接违反最小惊讶原则，且逐字节 / ASAN 都抓不到语义丢失。
   - 否决“运行期报错”：Ct 无异常；在每个 `o[k] = v` 上分叉会破坏“与 `o.set(k, v)` 逐字节
     一致”的判据，并给只读实现新增失败通道。
   - 因此 `E-V3-9f` 的 B2 负例期望是**编译期硬错**（trait 未声明 `index set`），不是运行期诊断。
     `get` 返回 `V *` 时的 `*o[k] = v` 是普通解引用写，不属于本项，边界见 §8 E3。

6. **写入值所有权按签名决定，不另立模型（D-013）。** `V` 值形参 = 按值传入：标量即复制；
   `String` / 按值 struct 按 D-013 §3 的按值传参 retain（引用计数 +1），**不是深拷贝**。
   `V *` 形参 = 视图：不 retain、不复制，调用方保留所有权，视图生命周期不得越过对象。
   生成 C 必须与显式 `o.set(k, v)` 逐字节一致，因此不额外插入 retain / release、不物化临时。
   `own` / `borrow` 右值沿用 D-028 的 L52-9 拒绝口径（阶段二同样硬错），避免借写生命周期歧义。

7. **阶段二只允许 `void set(K, V) index;`。** 非 `void` 返回 → 硬错 D034-6；参数个数不是 2 →
   既有 L52-4 口径；`static` → 既有 L52-5 口径。失败语义（`Result` / `bool` / 缺省返回值）
   不在本次 ADR：`o[k] = v` 仍是语句，没有结果值，避免把“写入失败”塞进表达式类型。

8. **同一 trait 内同键类型的 `index get` / `index set` 各至多一条。** 重复 → 硬错 D034-5；
   判定只看键的 `type_key`，与返回类型无关（`V` 与 `V *` 同键也算重复）。**同名 + 同 `type_key`
   的声明无论是否标 `index` 一律硬错**（§8 E1）：两条都标 `index` 仍由 D034-5 报；其余组合报
   声明期重复方法。未标 `index` 的 `get` 不参与 `[]`；它“不构成歧义”只适用于**不同签名**
   （参数个数或任一参数 `type_key` 不同）；命名调用 `.get(k)` 的重载决议仍按既有规则（取第一个
   同名方法），本 ADR 不改。

9. **标记是 trait 公开声明的一部分，随 `.h.ct` 的 `pub trait` 进公开头。** trait 在 A 单元声明、
   impl 在 B、调用在 C：C 必须能从 A 的公开头看到 `index`，否则按 D034-1 拒绝；`ct build`
   全量重编保证三者一致。只保证**同一次构建内**一致；不承诺预编译接口库，也不承诺跨版本
   vtable 稳定。

10. **不新增 vtable 槽，不承诺槽位 ABI。** `index` 只是给已有 `get` / `set` 槽加“可作为 `[]`”
    的属性：槽数、槽序、槽偏移与不加标记时完全相同；`o[k]` 与 `o.get(k)` 的生成 C 逐字节
    一致**限唯一名（单键）trait**；多键见 §8 E2。槽位号 / 布局 / 跨版本兼容留待语言面稳定
    后的独立 ABI ADR；接口库仍以源码分发。

## 2 诊断文案（冻结）

新增诊断，位置规则：下标形态一律指向 `[`；标记形态指向 `index` 记号；`D034-5` 指向第二个
标记；`D034-6` 指向 `set`。一次只报一条。

**诊断码口径（2026-11-28 定）**：`D034-1…8` 是**本 ADR 的本地标签**，不是
`docs/diagnostics/codes.md` 的 registry 码。实现沿用 I1 先例，直接使用下列文案、**不新增
`E-` 码**——registry 要求源码字面量与表行集合完全相等，跨席位分开提交会让 `check-docs` 必红。
唯一例外：若 DEV 判断必须编码，**同一提交内**同时补 `codes.md` 对应行（level / meaning /
version / sample / test），并在提交信息注明“LANG-25 例外”。

```text
D034-1  trait 'T' declares no indexed get; 'o[k]' is not available
D034-2  trait 'T' has no indexed 'get' matching key type 'int': candidates are 'char *'
D034-3  the 'index' marker belongs to the trait declaration, not the impl
D034-4  interface subscript is read-only in this phase; declare 'void set(K, V) index' (stage 2)
D034-5  trait 'T' marks more than one indexed 'get' for key type 'char *'
D034-6  an indexed 'set' must return void: 'int set(char *, int)'
D034-7  the 'index' marker goes after the parameter list and before ';'
D034-8  trait 'T' declares no indexed set; 'o[k] = v' is not available
```

- `D034-2` 的候选只列该 trait 中**标了 `index`** 的 `get` 的键类型（按声明顺序、单引号、逗号
  加空格）；trait 没有任何 `index get` 时先命中 `D034-1`，不再列空候选。写入形态把文案里的
  `'get'` 换成 `'set'`（`trait 'T' has no indexed 'set' matching key type 'int': candidates
  are 'char *'`），与 D-028 读写分开报告的口径一致。
- `D034-5` 把 `'get'` 换成 `'set'` 即写入侧同一文案；键类型按 `type_key` 展示。
- `D034-3` / `D034-7` 共用“标记位置”语义：impl 重复写、前缀写、重复两次、写在 `;` 之后都归
  这一类；不产生多条诊断。
- 既有 L52-4 / L52-5 / L52-7 / L52-9 文案逐字保留，只是把作用对象从“固有下标”扩到接口值
  的同名检查点；不新增“接口值专用”的重复文案。

## 3 与 D-028 / I1 的边界（不改什么）

- **不改 D-028 已发布行为**（D1=(i)）：具体类型的固有 `get` / `set` 解析、借写 `*get(k) = v`、
  C 符号去歧义、诊断与生成 C 逐字节不变。`o[k]` 的接口值路径只读 trait 声明，不回看固有
  `impl`，也不把 trait `get` 借给具体类型。
- **不做运行期映射**：接口值下标在解析期静态落到既有 vtable 槽，不建“字符串键 → 方法”的
  运行期表、不做反射、不改变 `o.get(k)` 的调用形态。
- **不动 I1 的 struct 路径**：`D-031` 的触发条件、字段优先、D031-1 / D031-2 与折叠结果不变；
  接口值上的字面量键明确不折叠，两卡共表但互不改写。

## 5 备选与不采纳

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 具体类型统一到 trait `index get`（D1=(ii)） | 不采纳（留待独立 ADR） | 两套派发并存、重开 D-028 优先级与 I1 冲突面；回滚不独立 |
| 新增 `Indexable` / `IndexableMut` trait | 不采纳 | 所有者已裁；且会给每个 `get` 意外加语法 |
| 为接口值新增 vtable 槽或槽位号 | 不采纳 | 所有者已裁；`get` / `set` 本就是 trait 方法 |
| 只读实现写入 = 空实现 | 不采纳 | 静默丢写入，测试与 ASAN 都抓不到 |
| 只读实现写入 = 运行期报错 | 不采纳 | 无异常机制；破坏逐字节一致并新增失败通道 |
| 字面量键隐式匹配 `Str` 形参 | 不采纳 | 违背 D-028“逐字相等、不做隐式转换”；并会让 `char *` / `Str` 两个键类型产生歧义 |
| 接口值字面量键走 I1 折叠 | 不采纳 | 接口值没有静态字段表；I1 只对 struct 值 |
| `set` 返回 `Result` / `bool` | 不采纳（本次） | 会把失败语义塞进 `=` 表达式；留待后续 ADR |
| 运行期键 → 方法的映射表 | 不采纳 | 那就是反射；与静态解析的既有协议冲突 |

## 6 验收挂点（`E-V3-9e` / `E-V3-9f`）

不重复列命令与夹具细节；用例清单与执行命令以
[I2-C1 §10](../design/i2-interface-subscript-construction.md#10-验收清单e-v3-9e--e-v3-9f) 为准。

| 阶段 | 判据 | 映射 |
| --- | --- | --- |
| 阶段一（`E-V3-9e`） | trait 标 `index` 后 `o[k]` 经 vtable 槽解析，生成 C 与 `o.get(k)` 逐字节一致（**唯一名 trait**；多键不承诺同槽，见 §8 E2）；未标 / 键不匹配 / impl 重复标记 / 同名同键重复 / 阶段一写形态 / 非接口值误用各有硬错；固有 impl 路径零回归 | I2-C1 §10.1 A1–A9 |
| 阶段二（`E-V3-9f`） | `void set(K,V) index` 后 `o[k] = v` 与 `o.set(k, v)` 逐字节一致（**唯一名 `set`**）；无 `index set` 的 trait 写入是**编译期**硬错（D5）；键不匹配 / 所有权越界分别硬错 / 借用拒绝；阶段一生成 C 不变 | I2-C1 §10.2 B1–B5，且需 §10.1 全绿 |

## 7 回滚与不做

**回滚**：I2-1…I2-3 单独 revert 后接口值下标消失、具体类型路径不变；I2-4 单独 revert 后写形态

## 8 Errata（2026-11-28，REV F1–F6）

> 依据：REV 报告 `docs/reviews/2026-11-28-i2-rev.md`（`issue/revi2`，2026-11-28）。本节只收紧 /
> 澄清已经实现或已被实现、文档采纳的口径，不改 D1–D10 的决策方向，不改 A1–A9 / B1–B5 的验收
> 判据；D-034 仍为 **accepted**。

### E1（F1）同名 + 同 `type_key` 一律硬错

- **规则**：同一动态 trait 内，两条方法声明若同名、参数个数相同、且每个参数的 `type_key` 逐字
  相等，即同一 vtable 签名，**一律硬错**，与是否标 `index` 无关。
  - 两条都标 `index`：仍由 **D034-5** 报，判定与文案不变。
  - indexed + unindexed、unindexed + unindexed：声明期硬错，文案
    `trait 'T' declares duplicate method 'm' with the same parameter types`（`a93e6701`；
    夹具 `test/ast/errors/i2_dup_method.ct`，探针 `I2-1_dupmix`）。该检查是声明期通用文案，
    **不占** D034-1…8 编号。
- **D8 限定**：未标 `index` 的 `get` 不参与 `[]`；它“不构成歧义”只适用于**不同签名**
  （参数个数或任一参数 `type_key` 不同）。同名且同键的未标 `get` 按上条硬错，不再“不构成
  歧义”；不同键类型（`get(char *)` / `get(int)`）仍可并存，未标的那条只是不参与 `[]`。
- **理由**：I2-3 的槽名 `$<enc(type_key)>` 只按参数类型键生成，同键同名必然同时发射两个 C
  成员 / 函数，`cc` 报 duplicate member；D8 原句把该组合写成“不构成歧义”，与 I2-3 冲突。
- **边界**：只作用于动态 trait / `pub trait`；`.m.ct` 静态 `map trait` 不产生 vtable，维持
  D2 的“不识别”。不改变命名调用取第一个同名方法的规则。

### E2（F2）“与显式 `o.get(k)` 逐字节一致”限唯一名 trait

- D3 末句与 D10 的“生成 C 与显式调用逐字节一致”**限唯一名（单键）trait**：trait 内只有一个
  同名 `get` / `set` 时成立（A1 / B1）。
- 多键 trait（同名 `get` 按不同键类型并存）下：`o[k]` 按键 `type_key` 选中对应 `$<enc>` 槽；
  显式 `o.get(k)` 仍按既有命名调用规则取**第一个**同名方法（D8），不看键类型；二者不承诺
  同槽、也不承诺逐字节一致。例：`get(char *) index` + `get(int) index` 时 `t[5]` → `get$int`，
  `t.get(5)` → `get$char_2a`（并给既有 type-mismatch 警告）。
- D3 的 `aux = 9` 更正为 **`aux = 3`**（接口值 vtable 调用）；`aux = 9` 是 D-028 固有下标，
  以[实施契约 §2](../design/i2-implementation-notes.md) 为准。
- **判据不变**：A2 只要求 `s["k"]` / `s[7]` 分别命中正确槽、符号不同；A1 / B1 的 `diff` 为空
  仍只在唯一名夹具。

### E3（F5）`*o[k] = v` 不属于 `o[k] = v` 的 set 协议

- D5 的“只读实现被写入在类型层不可能存在”只覆盖 set 协议 `o[k] = v`。若 `get` 返回 `V *`，
  `*o[k] = v` 是普通指针解引用写：沿用 D-028 中 `*get(k) = v` 的既有指针 / 借用语义，**不需要**
  trait 声明 `index set`，也不受 D034-8 约束；只读性由 `get` 的返回类型决定。
- 因此阶段一 / 阶段二的“只读”不是“只读 trait 的任何可达内存都不可写”；要禁止 `*o[k] = v`
  须另立规则（不在 I2 范围）。
- 不改 D5 的 set 派发、所有权与“无运行期缺实现”判据。
