## 1. 裁定

E85-2 按**降级口径**成立：验收 = spike **已执行** + 度量（前后行数、编译耗时）+ 测试语料
逐字节一致的原始输出 + sharp edge 清单 + **明确的门结论**（“整子系统新语法等价重写”
门**不通过**）。不再要求 E85-2 的字面“门通过”。

这是**判据改写**，不是把“不通过”记成“通过”：卡 §7.3 写“有条件通过（D-018）”，
并同时保留门结论“不通过”。

## 2. 依据

1. 卡 §1.3 的“完整等价重写（选一个子系统）”在词法器上实质等于 PH-86 的工作量：
   [spike 的 sharp edge](../design/p85_spike.md) 第 3/4/5 条表明 `Str` token 视图会波及
   Parser/Expr/Stmt，且词法器没有错误通道、`?` 无处可挂。
2. R85-1 是**风险处置**：允许“退化为按 inventory 逐项替换”，但不把门记成通过——
   所以需要一条 decision 把 E85-2 的验收改成“证据齐 + 明确结论”。
3. D-017 A1 两级制：spike 的第 1 层证据（66 个语料文件逐字节）已由 REV 独立复现
   （归档重建 + patch 应用 + `corpus-manifest` diff 空）。

## 3. 后果

1. **PH-86 按 per-function 拆**：`punct`（141 行）→ `number`（83 行）→
   `quoted`/`pp_line` → `Str` token 视图；每段独立红/绿与验收，**不承诺**一次整体重写。
2. E85-2 在卡 §7.3、`AGENTS.md`、`docs/history/phase-log.md`、`docs/roadmap.md`、
   `docs/session-map.md` 统一记“**有条件通过（D-018）**”，不得再写“E85-1…8 全部无条件通过”。
3. spike 的度量、逐字节证据与 sharp edge 仍是 PH-86 的输入；若 per-function 切片证明
   整体重写可行，另立 decision 恢复“整体门”，不回填 PH-85。

## 4. 失效条件

- 若 REV/EDITOR 要求字面门：必须补一次真正的完整新语法等价重写（至少一个完整子系统，
  含 `Str` 视图 / `?` / `defer` / `match` 中适用部分），以 66 语料逐字节、自举不动点、ASan
  为证；这会消耗 PH-86 的预算，故不在 PH-85 回填。
- 若 D-017 A1 改为单级制（取消“编译器自身发射允许差异”），本口径需重估。
