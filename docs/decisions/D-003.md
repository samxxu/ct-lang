# D-003：`--runtime-checks` 拒绝不稳定接收者；switch 内 defer 全面禁止

## 争点

`--runtime-checks` 下 `arr[pick()].area()` 可能段错误且无 runtime 消息；`switch` 内 defer 当前连 case 内嵌套块也禁止。

## 判决

- **A（接受边界 + 文档）`rejected`**：J-1 要求任何被接受的派发遇空 vtable abort；A 仍接受并 rc=139，文档不能改变接受集。
- **B（sound guard）`accepted`，按 B′ 收紧**：
  - 接收者沿 `MEMBER`/`ARROW` 取根；未物化 `N_CALL` 根拒绝；已物化（`text3`）放行。
  - `N_INDEX` 根只在索引/基址子树含 `N_CALL`/`N_POST`/`N_PRE`/`N_ASSIGN` 时拒绝；`arr[0]`/`arr[i]` 放行。
  - 文案 `runtime checks need a stable receiver; bind it to a local first`；位置用既有 `fail_from`（列 1 限制记录在规范）。
  - `switch` 内 defer 全面禁止（含 case 嵌套块/循环体），补负例。
- **C（全量 hoist + 放宽 switch）`rejected`**：成本/风险超出 v1。

## 证据

`battle/p38-1/verify.json` V1–V4；claim/counter 的 E1 原始输出。A 的 rc=139、B 原型的 rc=1 带位置、`arr[0]` rc=7、off guard=0/on=2。

## 后果

- 实现后 `p37_rt_probe` 必须覆盖拒绝/放行两类；`p38` 补 switch 嵌套负例。
- 全量 `check-all` 绿后才谈 v0.38.0；`v0.37.0` tag 仍含旧缺陷，不移动。
