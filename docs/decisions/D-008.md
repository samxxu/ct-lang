# D-008 · libc I/O 作为内置例外，按调用补头

- 日期：2026-11-17
- 状态：**accepted**
- 范围：v0-PH-65 的 strict C 边界；不改变 v0-PH-65 已冻结的 R1–R7 卡面，实施另开 [SH-89](../../issues/selfhost/sh89-libc-io-auto-include.md)
- 关联：[battle cinclude-1](../../battle/cinclude-1/verdict.md)、[battle cinclude-2](../../battle/cinclude-2/verdict.md)

## 背景

CT 不识别 `printf`；它按未知 C 函数发射，生成物能编译是因为内置层头文件的
`#include` 被带进 `.c`。实测空程序也带 `<stdio.h>`/`<stdlib.h>`/`<string.h>`，
既不是“调用才补”，也不符合 strict 的 `.ct` 禁直接 include。

用户裁定：`printf` 这类高频可变参数 I/O **作为内置函数**，不用 `#include`、不用
`import`；出现调用时由编译器补正确的头，没有调用不补。

## 裁定

### 1. 自动补 `<stdio.h>` 的闭集

| 类别 | 函数 |
| --- | --- |
| 格式化输出 | `printf`、`fprintf`、`sprintf`、`snprintf` |
| 格式化输入 | `scanf`、`fscanf`、`sscanf` |
| 非可变参数但同属 stdio I/O | `puts`、`putchar`、`fputs`、`fputc`、`fflush`、`perror` |

`dprintf`、`asprintf` 属 POSIX/GNU，列入**后续可选项**，本决定不要求首批实现。
`putf` 不是 ISO C 函数；若为自定义函数，按普通函数处理，不自动补 stdio。

### 2. 宽字符

`wprintf`、`fwprintf`、`swprintf`、`wscanf`、`fwscanf`、`swscanf` 自动补
`<wchar.h>`，作为独立组；宽字符未启用时不得静默按窄字符处理。

### 3. 不自动补头的可变参数函数

`syslog`、`err`、`errx`、`warn`、`warnx`、`execl`、`execlp`、`execle`、
`fcntl`、`ioctl`、`open`、`openat`、`semctl`、`syscall`、`strfmon` 等
**不进入自动 include 集**：它们的头不同、频率低，走 `.m.ct`/`.shim.h` 或显式声明。

`vprintf`、`vfprintf`、`vsnprintf`、`vscanf` 等接收 `va_list`，**不是可变参数函数**；
不因名字前缀自动补头。

### 4. 触发与边界

- 只对**直接调用**触发；仅取地址/函数指针不触发。
- 用户已定义同名函数/宏时，不抢；按用户声明处理，或报签名冲突。
- 每个头只补一次；位置在 banner 后、内置层 prologue 前。
- `--freestanding` 下不自动补头；`printf` 等未由 shim 提供时硬错。
- strict 下这是**显式 libc 内置例外**，不是“C 库已被封装”；文档必须写清。
- 不做 `printf` 格式串与实参类型检查；与 C 一致，由用户负责。

## 当前实现与目标的差距

当前生成物对空程序也带 stdio/stdlib/string，来源是内置层头文件/发射器 prologue，
不是调用检测。实施 SH-89 时必须先让“未调用不带 stdio”成立，再做闭集补头；
否则只是把无条件 include 换个理由。

## 实施顺序

1. 建立函数名 → 头的闭集表（先 stdio，宽字符单独）；
2. 在调用点/发射前检测直接调用，去重后补头；
3. 收掉内置层无条件 include（不破坏 CT 核心/既有代码）；
4. 加负例：空程序无 stdio、`printf` 有 stdio、`syslog` 不补 stdio、用户同名不抢、
   `--freestanding` 硬错；
5. 更新 golden 与文档。

## 非目标

- 不把 `syslog/err/fcntl/ioctl/open` 纳入自动补头；
- 不做完整 libc 封装或格式串检查；
- 不改 `--freestanding` 的“无 libc”承诺；
- 不把本决定塞进 v0-PH-65 的冻结任务卡。

## 代价与风险

- 需要 AST/调用点扫描与头映射，可能影响编译时间；
- 内置层自身也调用 `printf`，收掉无条件 include 后要保证它自己可编译；
- 用户同名函数、宏、函数指针的边界要逐条测试；
- 宽字符/`dprintf` 的平台差异要显式列范围。

## 失效条件

- 若 CT 后续提供完整的 I/O 包装/`std::io` 且决定禁止直接 `printf`，本决定重开；
- 若 `--freestanding` 改为允许 libc shim 自动注入，本决定的边界需重写。
