# D-010 · 官方包身份 `ct/std`、内置 pin 表与发布/消费边界

- 日期：2026-11-19
- 状态：**accepted**（需求方定稿）
- 范围：PH-77；跨仓项（`ct-pkg/std`、`ct-pkg/index`）只列要求，不在本仓实现
- 关联：[PH-77](../design/phase77.md)、[ct-pkg-get-contract](../planning/ct-pkg-get-contract.md)、[PKG 索引审计](../reviews/2026-11-17-pkg-index-audit.md)、[battle index-pkg-1](../../battle/index-pkg-1/verdict.md)、[battle index-install-1](../../battle/index-install-1/verdict.md)

## 背景

`install.sh` 安装后推荐 `ct get ct/std`，但无索引时限定名硬错；裸名 `std` 回落 registry 并取最高 tag；
`ct-pkg/std` 清单写 `publisher = std`，与 AGENTS 包表假定的 `$CT_HOME/pkg/ct/std/<version>/` 不一致。
发布端（`ct-pkg/index/tools/package.sh`）与消费端（`ct get`）各自演进，缺少成文边界。

## 裁定

1. **官方身份**：`publisher = ct`，规范名 `ct/std`；`std/std` 是错误身份，只作为迁移来源识别。
2. **裸名省略**：仅官方可用，`std` ≡ `ct/std`；第三方必须写 `publisher/name`，同名也不例外；
   裸名命中多个 publisher 时硬错。
3. **版本展示**：`ct get` 展示规范 `url@<包版本>`，tag 单列；文本 / `--quiet` / `--json` 一致。
4. **内置 pin 表**：官方包的版本来源是编译期内置表（url + tag + sha256），随 `ct` 版本更新；
   不联网、不读可变索引。显式 `--index` / `CT_INDEX` 命中 `publisher = ct` 行时以索引为准。
   发布清单必须包含更新 pin 表，并有与官方索引行的一致性探针。
5. **旧锁迁移**：`ct update` 遇到 `std/std` 自动迁移为 `ct/std` 并打印前后；旧 store 只读保留；
   `ct verify` 对旧身份告警不误红；`ct build` / `ct install` 不重写 lock；禁止静默双写。
6. **`ct pkg` 边界**：保持 [battle index-pkg-1](../../battle/index-pkg-1/verdict.md) 的 B′——`ct pkg` 是
   `ct install` 别名 + 原生 `check`，不执行、不透传 `package.sh`；发布留在 index 仓或 CI。
7. **发布/消费契约**：[ct-pkg-get-contract](../planning/ct-pkg-get-contract.md) 为两端规范文本；
   发布端必须用隔离 `HOME`/`CT_HOME` 的 `ct get --index` 回放新索引行，比对摘要后才能推送；
   找不到 `ct` 时不得以告警跳过（Q2 待外部仓修复）。

## 后果

- `ct-pkg/std` 需改 `publisher = ct` 并发新 tag（不可原地改旧 tag）；索引行六字段同步；
- 既有 `std/std` 锁经 `ct update` 迁移；旧 store 保留，回退可用；
- 内置 pin 表成为新的信任根；过期风险由发布清单与一致性门禁覆盖；
- 不新增安装期 git/index 依赖，不改变 B′ 的离线边界。

## 失效条件

- 若未来官方包改为“跟随索引最新”且接受非可复现安装，第 4 条需重写；
- 若 `ct pkg` 复开透传，需新裁决显式覆盖第 6 条与 `index-pkg-1`；
- 若索引引入签名/pin 并成为默认信任根，第 4 条的内置表可降级为兜底。
