## 1 四类分流

| 分类 | 判定条件 | 落点 | 版本动作 |
| --- | --- | --- | --- |
| **A bug** | ① 规范 / 设计 / 已冻结 phase 卡里有一条**对用户可见的承诺**，实现没兑现；或 ② 编译通过但**静默给错结果** / 静默发射坏 C | **PATCH** | `0.53.x` 连续递增；一次 fix 一个 PATCH |
| **B 新特性** | 以前从未支持的**新语法 / 新协议 / 新工具能力**；或只存在于 `REQ-*` 需求池、尚未写入冻结契约的条目 | **新 phase** | `PH-54` 起顺延；一个 phase 一个 MINOR |
| **C 设计拒绝** | 规范 / 设计文档里**明文写「不做」**，且不是「暂未实现」 | **不排期** | 只补文档说明，避免反复当缺陷提 |
| **D 缺证据** | 已有实现或 commit 声称已修，但**没有夹具 / 没有复跑记录** | 补夹具或补文档 | 不单独发版；并入相邻 patch 的回归或 phase 收口证据 |

## 2 边界条款（避免反复争论）

1. **「issue 里写过」不等于「承诺过」。** `REQ-*` 需求池、`open` issue、提案里的候选，都是待排期需求；
   只有规范正文、已冻结 phase 卡、已发布契约才构成 bug 判据。
2. **「已知洞」不等于「不是 bug」。** 规约写了「已知洞 / 静默空值」但用户可见结果是错值，仍判 A；
   典型：`v[0]` 在只有 `get(char *)` 时静默返回缺键（LANG-4）。
3. **「要动符号表 / 代码生成 / ABI」的语言能力，即使 issue 早已存在，也判 B 走 phase。**
   典型：REQ-JSACCESS-1 的重载 / 按键类型分派；新增 C 符号名与派发规则属于语言语义变更，不是 patch 能装下的。
4. **bug 的修复若依赖尚未存在的模型字段，允许随 phase 的首个切片修，不单独发 patch。**
   典型：PKG-5 缓存键裸名依赖 `publisher` 身份，只能随 PH-54 S1 修；但必须在切片卡里列为第一任务。
5. **文档缺陷不占 PATCH。** 纯文案 / 判据设计缺口按 V-4「纯文档不 bump」处理，随相邻版本或 phase 收口提交。
6. **没有夹具的「已修」只能记 D，不能记绿。** 提交正文必须带红证；只有实现没有夹具，按未修处理。

## 3 版本与顺序

### 3.1 版本语义（与 AGENTS 对齐）

- **PATCH**：一次 fix 一处缺陷、只 `+1` 一次；不同 issue 不得合并进同一个 PATCH（V-3）。
- **MINOR**：一个 phase 一个 MINOR，MINOR 必须等于 phase 号（V-1）；phase 内不得跨多个 MINOR。
- **收口**：每个 PATCH / phase 收口必须在同一次动作里完成版本号、README、受影响 golden（V-5）。

### 3.2 固定顺序

1. **patch 级 bug 优先清**：`0.53.2` 起连续发，不攒批；先止血静默错值 / 静默坏 C。
2. **PH-53 可选链不插队**：patch 队列清完后才进 PH-53 的 S0（卡面若已收口，则只保留槽位；
   若主控要求重开，从 S0 重新走）。
3. **包机制改造不插队**：按 PH-54 排队，位置在 PH-53 之后。
4. **其它新特性 phase**：PH-55 起，排在包机制之后。

### 3.3 并行边界

- 同一文件族（`TypeCheck` / `Expr` / `Emitter` / golden）的 patch **必须串行**。
- 不同文件族（lexer、l0/l1 容量、pkg 工具）可以并行开发，但**发版必须串行**，每个 PATCH 只带一个 issue。
- ABI / 生成头变更（如 LANG-9）必须单独发，且期间不合并其它 Emitter / header 改动。

## 4 示例判定

| 条目 | 分类 | 理由 |
| --- | --- | --- |
| LANG-4 `v[0]` 静默空值 | A | 静默错值；REQ-JSACCESS-1 已有硬错承诺 |
| LANG-5 结果作接收者（字段形态） | A | 静默发射坏 C；规约 §4.64 承诺成员跳转编译期报错 |
| `Map` plain `m["a"].x` / `m["a"]["b"]` | A | `[]` 结果是 `V *`，未解引用即落坏 C；属容器基本可用性 |
| REQ-JSACCESS-1 重载 / 类型分派 | B | **自定义包装类型**的新协议，不是 `Vec`/`Map` 的需要（两类容器各自只有一个 `get`）；新语义 + 符号表 / ABI 变更 |
| LANG-12 属性访问（静态 struct） | C | 无规范承诺；字段访问沿用 C 语义，字段不存在即编译错误 |
| LANG-12′ `Map` 点访问（仅容器糖） | B 条件 | `m.server?.host` 等价 `m["server"]?.host`（PH-53 已覆盖），属冗余语法糖；仅在主控明确要求时开 PH-56，且不与静态 struct 共用协议 |
| SH-73 trait 临时接收者 | C | 明文「有意的实现边界」，只补文档 |
| LANG-13 三级链 | A + D | 静默拒绝是 bug；已修但夹具缺失，先补证据再记绿 |
| SH-76 内置层找不到 | A | 随附标准库探测缺安装相对候选，找不到时静默继续解析 → 有效代码被误诊、裸泛型落坏 C |
| PKG-5 缓存键裸名 | A→phase | 定性是 bug，但依赖 `publisher`，随 PH-54 S1 首任务修 |
| DOC-69 / DOC-71 | D | 纯文档，不 bump |
