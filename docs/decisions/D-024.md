# D-024 · 映射声明点的 C 类型证据（SH-60 / D-60-2）

- 日期：2026-11-23
- 状态：**accepted（校验口径）**；实现随 SH-60 同批，不 bump 版本（本轮任务口径）
- 目标：v1.0 之前的 ct-ast 小修，不新增 phase
- 签收：REQ 2026-11-23（owner 交底授权 REQ 裁定，见 SH-60 任务交底）
- 依据：[SH-60](../../issues/selfhost/sh60-mct-signature-types-decorative.md) 2026-11-09 裁决；
  语言表面 §4.10（静态映射）与 §4.42（`type` 别名）；[D-023](D-023.md)
- 决策范围：只定 `.m.ct` **trait 方法签名**（返回类型与参数类型）里裸类型名的准入证据；
  不动 `map … for type <ctype>` 的宿主拼写、recipe 参数、普通 `.ct` / `.h.ct` 的类型读取

## 1. 决策

`.m.ct` 的 `pub trait` 方法签名里，每个类型名必须满足下列之一，否则在**声明点**报
`error: unknown type '<X>' in a .m.ct trait signature; declare 'pub type <X> = <C spelling>;'
in this unit or include the header that typedefs it`：

| # | 证据 | 例子 |
| --- | --- | --- |
| E1 | C 内建类型词，或类型读取器本来就认识的 C typedef | `int`、`char *`、`unsigned long`、`size_t`、`ssize_t`、`ptrdiff_t`、`wchar_t`、`va_list`、`int8_t`…`uint64_t`、`FILE`、`DIR` |
| E2 | 本单元或已 import 单元声明的类型 / trait / 类型别名 | `struct Builder`、`CRequest`（`pub type`） |
| E3 | 由本单元 `#include` 的标准头提供的 typedef（编译器内建表） | `#include <time.h>` + `time_t`、`clock_t`；`#include <sys/types.h>` + `off_t` / `pid_t`；`#include <stdint.h>` + `intptr_t`；`#include <stdbool.h>` + `bool` |
| E4 | 同单元 `pub type X = <C spelling>;` 别名；右侧允许不透明 C 拼写 | `pub type Stmt = sqlite3_stmt;` 后用 `Stmt *` |
| E5 | 显式 `struct` / `union` / `enum` + tag 拼写 | `struct SqliteStmt *`（C 前向声明合法，视为自证） |

两个要点：

1. **`#include` 本身不是证据。** 编译器不解析 C 头，`#include <string.h>` 不能给
   `TotallyBogus *` 背书——这正是 SH-60 的 2b 例句，必须继续报错。
2. **项目/第三方 C 头里的 typedef 走 E4。** 头文件仍要 include（生成的 C 需要它），但
   签名里用别名，别名就是 CT 源码里可审的声明点；不在签名里直接写裸 typedef 名。

## 2. 为什么不用「有 `#include` 就全局豁免」

| 方案 | 判定 | 理由 |
| --- | --- | --- |
| 单元有任意 `#include` → 未知名字全放行 | 否 | 2b 例句恰好有 `#include <string.h>` + `TotallyBogus *`，缺陷原样保留；等于把校验关掉 |
| 扫描 `#include` 指向的头文件找 `typedef` | 否 | 要复刻 C 预处理（条件编译、宏、include 搜索路径）、跨平台路径不可靠，远超「小修」；解析失败还会反向误报 |
| 维护「标准头 → 标准 typedef」表（本决策 E3） | **采纳** | 有限、可枚举、可测；覆盖 `time_t` / `off_t` / `pthread_t` 等真实用法 |
| 项目类型只认 `pub type` 别名（本决策 E4） | **采纳** | 显式、可 diff、可审；右侧不透明拼写本来就被 §4.42 允许 |

## 3. 误报防线（必测）

- `size_t` / `FILE` / `intN_t` / `va_list` 已在类型读取器的内建词表里，**任何位置**都接受
  （E1），不需要 `#include`；新规则不会把它们变成错误。
- `time_t` / `clock_t` / `off_t` / `pid_t` / `pthread_t` / `socklen_t` / `bool` / `wchar_t`
  等按 E3 只在包含对应标准头时接受；`time_t` + `#include <time.h>` 安静，缺头才报错。
- `pub type` 右侧不检查（§4.42 明确允许不透明 C 拼写），所以 `pub type Stmt = sqlite3_stmt;`
  不会连锁报错。
- 显式 tag 拼写（E5）放行：`struct Foo *` 是 C 的前向声明，不会被误判成裸未知 typedef。
- 只查 `.m.ct` 的 trait 方法签名：普通 `.ct` / `.h.ct` 的未知类型仍由 `cc` 兜底
  （test/ast/50_header_type、51_cast_header_type 的放行是有意为之），不在本决策范围。

## 4. 实现落点

- `frontend/parse/ParseSupport.h.ct`：单元级 `#include` 记录 + 标准 typedef / 头文件表；
  `map_sig` 标志只在该单元 trait 方法签名被读取时打开。
- `frontend/parse/Parser.h.ct`：`parse_program` 记录 `.m.ct` 的 `#include`；
  `parse_trait` 在返回类型与参数类型读取前后开/关 `map_sig`。
- `frontend/parse/Expr.h.ct`：`parse_type` 的「未知名字保留为不透明拼写」分支，在
  `map_sig` 打开时改为证据校验；只限定符前缀（`const TotallyBogus *`）同样检查，
  `int Foo` / `struct S Foo` 里的 `Foo` 仍是声明名，不误判。
- 严重级：`ct_sem_error`，build 与 check 都退出 1，产品一个字节都不写。

## 5. 证据与边界

- 正例：`ok_builtin.m.ct`（`size_t` / `FILE`）、`ok_time.m.ct`（`time.h` + `time_t`）、
  `ok_alias.m.ct`（`pub type Stmt = proj_stmt;`）均 `ct check` 退出 0。
- 负例：`bad.m.ct`（`string.h` + `TotallyBogus *`）、`bad_const.m.ct`、`bad_return.m.ct`、
  `bad_time.m.ct`（缺 `time.h`）均退出 1，错误文本见 §1；`build_bad.ct` 走 import 的 build
  路径同样在声明点失败。
- 生成 C 不变：本决策只加声明期诊断，不碰发射器。

**未覆盖**：不校验 `pub type` 右侧的拼写（有意）；不覆盖 `.h.ct` 声明点（由 `cc` 兜底）；
第三方头 typedef 若不想写别名仍会被拒，这是本决策选定的代价。
