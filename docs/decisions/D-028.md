# D-028 · 用户类型下标协议：名 + 参数类型、读写/借写与二值化

- 日期：2026-11-27
- 状态：**accepted（设计）；实施 `v1-PH-2` S2**
- 目标：`v1-PH-2` S2（`REQ-JSACCESS-1` → `REQ-INDEX-1`）；不改版本号、不打 tag
- 签收：REQ 2026-11-27（设计阶段验收）
- 批准：ARCH 2026-11-27（协议方向）
- 依据：[REQ-JSACCESS-1 / REQ-INDEX-1](../planning/requirements-pool.md#L71-L142)、
  [user-index-operator](../proposals/user-index-operator.md)、
  [custom-index-protocol](../proposals/custom-index-protocol.md)、
  [v1-PH-2 卡](../phases/v1-PH-2/card.md)、D52-2/D52-5/D52-6/D52-8
- 决策范围：用户类型 `[]` 的匹配维度、读写/借写三形态、C 符号去歧义、拒绝清单与诊断文案；
  **不含**接口值下标、`x[k].field`、多级连写、其它运算符重载、缺失/越界语义

## 1 决策

1. **匹配维度 = 方法名 + 参数个数 + 非 `static` + 实参静态类型。**
   实参类型与形参声明类型都归一到 `type_key`（去空白、去 `const` / `volatile`、折叠整数别名）
   后**逐字相等**才命中；不做隐式转换、不做数值提升、不做 typedef 别名展开。
   字面量的类型按既有静态类型规则：`"k"` 是 `char *`，`0` 是 `int`（D32-5：后缀不改变字面量类型）。
   实参静态类型推不出来时硬错，不回退 C 下标（维持 D52-5）。
2. **同类型并存不同参数类型的 `get` / `set` 是合法的**，在同一个固有 `impl` 块里按声明顺序排列。
   `x[k]` 读按实参类型选 `get`；`x[k] = v` 写按实参类型选 `set` 的首参。
3. **C 符号去歧义：第一个同名方法保持 `<Type>_<name>` 不变**，第 2 个起追加后缀
   `$<enc(k0)>[$<enc(k1)>…]`，`enc` 是 `type_key` 的单射转义（`[A-Za-z0-9]` 原样，
   其余字节写成 `_hh` 两位小写十六进制；编码超过 120 字节时退化为 `h` + FNV-1a 32 位十六进制）。
   `$` 不是 Ct 标识符字符，因此不会与用户方法名相撞；唯一名方法**零变化**（旧语料逐字节）。
4. **读写/借写三形态**（返回值形态由签名决定，D-IX-2）：
   - 读 `x[k]` → 匹配的 `get(k)`；`V *get` 时读到的是指针。
   - 写 `x[k] = v` → 优先匹配的 `set(k, v)`；没有匹配的 `set` 但匹配的 `get` 返回 `V *` 时，
     展开为 `*get(k) = v`（借写形态，接收者与下标各求值一次）。两者都没有 → 硬错。
   - 借写 `*x[k] = v` → 走通用解引用赋值（读形态已经给出指针），保持既有形状。
5. **`+=` / `++` / `&x[k]` 二值化取“全硬错”**（D-IX-7）：值形态与借用形态的文案一致，
   分别沿用 L52-6 / L52-7 的逐字文案，不新增“只求值一次”的临时节点。
   理由：支持它们要在下标糖上引入物化临时与再调用，属于新的求值语义，不在本 ADR 范围；
   包层写法是读回再 `set`。
6. **无匹配 / 歧义 / 推不出类型都是编译期硬错**，并且候选清单列出**签名**（返回类型 + 名字 +
   参数类型），不是只列名字。命中 0 条与命中 ≥2 条的文案分开，便于断言。
7. **AST 与 LIR 走同一套名字**：解析器把后缀记在糖节点的一个空闲文本槽，
   AST 发射器拼 `<Type>_<method><suffix>`，TIR 的 `cname` / 调用目标键带同一后缀，
   LIR 打印因此与 AST 逐字节一致。TIR/LIR 不新增类型判定，只搬运解析器已经算好的名字。

## 2 诊断文案（冻结）

```text
type 'X' has no subscript matching 'get(int)': candidates are 'char *get(char *)'
type 'X' has no subscript: cannot infer the subscript type; bind it to a local first
type 'X' has an ambiguous subscript: candidates are 'int get(int)', 'int get(int)'
type 'X' has no writable subscript matching 'set(int, V)': candidates are 'void set(char *, int)'
type 'X' has no subscript: declare 'V get(K)' in impl X
type 'X' has no writable subscript: declare 'void set(K, V)' in impl X
type 'X' has no subscript: 'get' must take 1 parameter
type 'X' has no writable subscript: 'set' must take 2 parameters
type 'X' has no subscript: 'get' must be an instance method
type 'X' has no subscript: 'get' is private to its unit
a custom subscript supports only '='; use set(k, v)
cannot take the address of a custom subscript; bind it to a local first
```

前四行是新增；其余是 v0-PH-52（L52-*）的逐字文案，位置与文本都不回归。
只读写（无 `set` 且无指针 `get`）仍报 L52-2 原文；“有 `set` 但键类型不匹配”报新增的
writable no-match 行。

## 3 被否方案

| 方案 | 否因 |
| --- | --- |
| `get` / `get_ref` 分名 | 名字集匹配会让规则面翻倍；`V` 与 `V *` 已是语言里的借用/拷贝区分（D-IX-2 议题 B） |
| 引入 `Index` / `IndexMut` trait | `[]` 是静态糖，trait 是 vtable 派发；接口值无法保证每个实现都有 `get`（D-IX-4） |
| 所有重载方法统一改名（包括第一个） | 旧语料与已发布符号全变，零回归承诺作废 |
| 用 `_` 代替 `$` 做后缀分隔 | Ct 标识符允许 `_`，用户可写出同名方法构造碰撞 |
| 用隐式转换/数值提升来匹配（`int` 实参也命中 `long`） | 选择变模糊、多候选；与 D52-6 的“静默错值”同类问题 |
| 支持 `+=` / `++` / `&x[k]` | 需要在下标糖上新增单次求值临时，属于新语义；D-IX-7 判为统一硬错 |

## 4 零回归边界

| 面 | 保证 |
| --- | --- |
| 唯一名 `get` / `set` | C 符号、`[]` 展开、诊断文本与 v0-PH-52 逐字节一致 |
| `Vec` / `Map` 内建下标 | 分支未改；`v[0]` / `m["k"]`、写保护文案不变 |
| C 数组 / 指针 / 结构体指针 | 仍走 C 下标；`p52_c_passthrough` 的 `arr[1]` / `p[2]` / `px[0].n` 不变 |
| 泛型实例 | 形态参数按实例实参替换后比较；`Box<int>` 仍发射 `Box_int_get` |
| 未重载类型的命名调用 | `.get(k)` / `.set(k, v)` 的解析路径未改 |

## 5 范围外（本 ADR 不承诺）

- 命名调用 `.get(x)` 的重载决议：重载类型上它仍解析到**第一个**同名方法；
  D-028 只保证 `[]` 的按键分派。要按类型调用请用 `[]`，或等后续 ADR。
- 接口值（trait 对象）上的下标派发；`x[k].field` / `x[k].m()`；多级连写；
  `$[k]`（`into` 块内）；其它运算符重载。
- 缺失/越界语义：语言不规定；借用形态用 `NULL`，值形态用 `Option` / 包自己的哨兵（D-IX-3）。
- typedef 别名作为键类型：不展开，用户写别名时按别名逐字比较。
