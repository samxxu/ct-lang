# D-029 · 函子签名糖 `(A,B) => R`：与函数指针同型的书写糖

- 目标：`v1-PH-2` S3（`REQ-FUNCTOR-1`）；不改版本号、不打 tag

- 依据：[REQ-FUNCTOR-1](../planning/requirements-pool.md#L311-L323)、

- 决策范围：`(A,B) => R` 的类型语法、参数名、展开拼写、与函数指针/闭包/trait 的关系、
  ABI、IDE 展开、诊断文案与零运行期成本判据；
  **不含**调用语义、闭包捕获规则、trait 派发、函数指针的既有能力边界

## 1 决策

1. **`(A,B) => R` 不是新类型，只是现有函数指针类型 `R (*)(A,B)` 的另一种书写。**
   解析器在类型位置把它展开成同一个抽象声明符拼写；此后 AST、TIR、LIR、发射器、
   符号表与 ABI 看到的字节完全等同于手写 `R (*)(A,B)`。不存在「函子类型」这一
   独立种类，也没有新的类型检查节点或运行期表示。
2. **参数名可选，且只服务可读性。** `(int a, char *s) => int` 与
   `(int, char *) => int` 展开为同一类型。名字不进入类型拼写、符号键、诊断或生成 C。
3. **出现位置 = 现有函数指针类型能出现的全部位置**：局部/全局声明、形参、struct 字段、
   union 字段、`typedef` 目标、函数指针数组，以及 `.h.ct` 的 `pub` 声明。
   它不是表达式，也不是调用语法；`f(1)` 仍是普通调用，`(int)=>int` 后仍要写声明名
   （`(int) => int f;`），与 `int (*f)(int);` 的写法顺序一致。
4. **语义、闭包与 trait 关系全部沿用现状**（§5）：函子类型走静态直调；不产生
   vtable、不装箱、不分配。非捕获闭包仍按闭包绑定规则落到该类型上；捕获闭包仍只是
   绑定、不能被当作可存储的值（与今天的函数指针一致）。
5. **C 发射与手写函数指针逐字节相同。** 同一份语法骨架只把类型拼写从
   `R (*)(A,B)` 换成 `(A,B) => R` 时，生成的 `.c` 必须逐字节相等；这是「零运行期
   成本」的唯一机械判据（§4）。
6. **诊断使用规范拼写 `R (*)(A,B)`**，不把糖的原文回显成另一种类型；这样错误信息与
   C 编译器、`.abi.h`、`--emit-map` 使用同一套拼写。缺括号、元数不符、返回类型不符
   都有稳定、可断言的位置化文案（§7）。

## 2 语法

```text
functor-type  := "(" [ functor-param { "," functor-param } [ "," "..." ] ] ")" "=>" type
functor-param := type [ IDENT ]
```

- 参数类型用既有的类型文法；参数名可有可无，解析时丢弃。
- 零参数写 `()`，也接受 C 的 `(void)`；两者都展开为 `R (*)(void)`。
- 末位 `...` 表示变参尾部，规则与现有函数指针相同：前面必须至少有一个参数类型，
  且 `(void, ...)` 非法。
- 返回类型 `R` 取既有类型文法；`R` 可以是 `void`，但不能是函数指针或另一个函子
  （沿用「不返回函数指针」，嵌套报 `nested function pointers are not supported`）。
- 逗号、`=>` 与参数表内的空白不影响展开；`=>` 是既有词法器已经认识的独立记号
  （闭包字面量也用它），不新增关键字，不改变 `>=` / `==` / `->`。
- 右箭头之后必须能读出一个类型；缺少 `(`, `)`, `=>` 或 `R` 都是定位到源位置的
  语法错误，不静默回退成 C 标识符。

正例（同一类型）：

```c
(int, int) => int add;              /* int (*add)(int, int); */
(int x, int y) => int add;          /* 同一类型，x/y 丢弃 */
(void) => int tick;                 /* int (*tick)(void); */
(char *s) => void sink;             /* void (*sink)(char *); */
(const char *fmt, ...) => int logf; /* int (*logf)(const char *, ...); */
```

声明名、数组维度与初始化器都在类型之后，与 C 声明顺序一致：

```c
(int, int) => int op = add;         /* 声明 + 初始化 */
(int, int) => int tbl[2] = { add, sub };  /* 函数指针数组 */
struct Ops { (int, int) => int bin; };     /* 字段 */
int apply((int, int) => int f, int a, int b); /* 形参 */
typedef (int, int) => int BinOp2;   /* typedef 目标 */
```

## 3 类型与展开

| 糖 | 展开（规范拼写） | 说明 |
| --- | --- | --- |
| `(A,B) => R` | `R (*)(A, B)` | 抽象声明符；声明名在发射时插进 `(*)` |
| `() => R` / `(void) => R` | `R (*)(void)` | 零参数 |
| `(A, ...) => R` | `R (*)(A, ...)` | 变参尾部 |
| `(A x, B y) => R` | `R (*)(A, B)` | 参数名丢弃 |

- 展开发生在 `parse_type` 内一次完成；`fnptr_state` 不置位，因此调用方按普通类型
  继续读声明名、数组维度与初始化器。
- `type_key` 与 `chk_assignable` 看到的是展开后的拼写，所以糖与手写函数指针在
  重载、赋值、比较、ABI 哈希中天然同一。不新增「函子」类型键。
- `typedef` 的种类判定沿用 `strstr(type, "(*")`：糖展开后同样命中函数指针别名，
  别名可继续作局部、参数与字段，行为与手写别名一致。

## 4 ABI 与零运行期成本

- **ABI**：函数指针按 C 的普通函数指针传递，参数与返回类型就是 `A…` / `R` 的 C 类型；
  没有隐藏 `self` / `env` 参数，没有包装结构，没有间接层。跨单元 `.h`/`.h.ct` 的
  `pub` 声明发射同一个 `R (*name)(A, B)`，所以 ABI 与手写函数指针逐字节一致。
- **生成 C**：只在声明处插入声明名，调用处仍是 `(*f)(args)` / `f(args)`（按既有规则）；
  不新增 `static` 符号、typedef、wrapper、vtable 或分配。
- **机械证据（S3 验收）**：两个只有类型拼写不同的源文件（同一目录、同一相对路径、
  同一行号布局），分别生成 `.c` 后用 `cmp` 比较，必须逐字节相等；再各编译成可执行
  文件比较符号表与运行输出。判据命令写在 §11。
- **不引入的新成本**：不因糖改变闭包捕获；捕获闭包仍按绑定处理，不生成「函子对象」；
  不使用糖的单元逐字节不变。

## 5 与 trait / 闭包 / 函数指针的关系

| 机制 | 关系 | 判据 |
| --- | --- | --- |
| 函数指针 | **同一类型**。可互相赋值、比较、作字段/数组元素，签名一致时无转换 | 正例 F1/F4；生成 C 相同 |
| 闭包字面量 | 糖不改变闭包规则：非捕获闭包仍可绑定到该类型并调用；捕获闭包仍是绑定、不能存储/返回/拷贝 | 正例「闭包赋值」；诊断与手写函数指针一致 |
| `(fn, env)` 回调对 | 糖只写单个函数指针类型，不自动等于 `(fn, env)`；闭包作实参仍要求宿主声明相邻的 `ret (*fn)(void *env, …)` + `void *env` 对 | 既有 L25-1…L25-4 不动 |
| trait / vtable | 不参与。函子类型不做动态派发；trait 接口值仍是 `struct X_iface`，两者不能隐式互转 | 正例 F3：调用点是直调 |
| `map` / 静态映射 | 无交互；映射方法可带函子类型形参，按普通类型发射 | 既有映射规则不变 |

## 6 IDE 语法高亮与展开

编辑器插件（`ct-vscode`）不在本仓；本仓给出它必须消费的**语法契约**，并保证编译器
展开与文档一致（[editors/README.md](../../editors/README.md)）。

- **高亮范围**：`(` … `)`（函子参数表）与 `=>`（箭头）作为一个类型片段高亮；
  箭头后直到声明名之前的类型词沿用普通类型高亮。`=>` 只在类型位置表示函子；
  表达式位置的 `(params) => body` 仍是闭包，两者由上下文区分，词法器不做区分。
- **展开/悬浮**：`(A,B) => R` 的规范类型是 `R (*)(A, B)`；hover、签名帮助与
  `--emit-map`/`.abi.h` 使用规范拼写。参数名不进入展开。
- **错误定位**：缺 `)`/`=>`/`R`、嵌套函数指针、元数与返回类型不符都由编译器给出
  源位置；编辑器只做透传，不自行改写类型。
- **测试边界**：插件侧 `npm test` 在高亮断言里增加 `=>` 与参数表两个 scope；
  本仓的 gate 6 已随插件迁出退役，不在本仓复制插件测试。

## 7 诊断（冻结文案）

```text
a functor type needs a '(A, B) => R' shape
a 'void' functor parameter must be the only parameter
nested function pointers are not supported
a function cannot return a function pointer; use a struct field or an 'out' parameter
function pointer arity mismatch: expected 'int (*)(int, int)', got 'int (*)(int)'
function pointer type mismatch: expected 'char * (*)(int, int)', got 'int (*)(int, int)': return type differs
```

- 前三行是新增或沿用；`nested function pointers…` 沿用既有文案。
- 后两行只在**两侧签名都可判定**时触发：声明类型是函数指针（糖或手写），初始化器
  或赋值右侧是函数名、`&函数名`、或函数指针变量。闭包字面量、C 库函数、typedef
  别名、`(void *)`、`ref`/`out` 或变参函数不触发，避免把「不可判定」误报成错误
  （D32-4 的口径）。**参数拼写不在这里判定**：typedef 别名不由解析器展开，逐字比较
  会产生假阳性，留给 C 编译器；本阶段只判元数与返回类型。
- 元数据：`arity mismatch` / `type mismatch` 子串沿用既有诊断码映射
  （`W-TYPE-001` / `W-TYPE-002`），不新增码；语法错误走 `E-PARSE-999` 兜底。
- 位置：语法错误指向糖的 `(`；签名不符指向初始化器/赋值右侧的起点。

## 8 被否方案

| 方案 | 否因 |
| --- | --- |
| 引入独立的 `Func<A,B,R>` 类型或 trait | 会产生第二个类型系统与派发路径；违背「只做签名书写、不新增运行期机制」 |
| 用 `typedef` 预声明一组固定元数的别名 | 元数无法覆盖；用户仍要记别名名；ABI 多一个名词 |
| 让糖成为闭包专用签名（自动带 `env`） | 会把「回调签名」和「闭包传输形态」混为一谈；C 函数指针与 `(fn, env)` 对是两种 ABI |
| 参数名参与类型/命名 | 名字是文档，不是类型；参与后同一签名的两种写法不再同一，破坏零成本判据 |
| 缺括号时回退成 C 标识符或隐式补全 | 静默错误；用户看不到自己写错，且生成 C 可能非法 |
| 为糖生成 wrapper 以支持捕获闭包 | 捕获闭包需要 env 生命周期，属新运行期机制；保持「绑定」即可 |

## 9 零回归边界

| 面 | 保证 |
| --- | --- |
| 既有函数指针写法 `R (*name)(A,B)` | 解析、发射、诊断逐字节不变 |
| 闭包 | 捕获规则、`(fn, env)` 检查、trampoline 命名与输出不变 |
| trait / 接口值 / 泛型实例 | 分支未改；糖展开后只是普通类型拼写 |
| 旧语料 | 未使用糖的 `.ct` 生成 C 逐字节不变（S3 证据：基线对照） |
| 诊断 | 既有文案与位置不回归；新签名检查只在可判定时触发 |

## 10 范围外（本 ADR 不承诺）

- 函数指针的已有边界：不返回函数指针、不支持嵌套声明符、函数指针数组不能作形参
  （糖不放宽这些；它们仍是硬错）。
- `ref` / `out` 形参与函数指针的组合（既有硬错）。
- 捕获非空闭包转成可存储的函子值（需要显式装箱/结构体 + trait，不在本糖范围）。
- 语法高亮插件本身的实现与测试（在 `ct-vscode` 仓，按该仓 `npm test`）。
- 把 `(A,B) => R` 用作函数返回类型：这是「不返回函数指针」的同一条边界，糖不放宽；
  写成返回类型会得到上面的定位错误，而不是非法 C。
