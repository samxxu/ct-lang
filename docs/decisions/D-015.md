## 1 裁定：硬错路线（C-1(b)）

采用**硬错路线**，不做结构体局部隐式零初始化：

1. **`release` 只作用于已定义存储**：字段的旧值只有在“确定已定义”时才自动 `release`；编译器
   无法证明已定义的形状**硬错**，不生成对未初始化存储的读，也不静默跳过。
2. **确定已定义的来源**：
   - struct 局部以聚合初始化器声明（`{ … }`，含 `{ 0 }`）：按 C 的零填充语义，其全部 owning
     字段视为已定义；
   - 同一函数内、外层直线执行的字段赋值（含循环之前），并且没有被分支 / 循环体 / `switch`
     条件化；
   - 全局 struct 的字段（静态存储零初始化）。
3. **分支合并（第四轮 R7 修正）**：`if` 之后字段是否已定义按
   `defined_after = defined_before || (then_defined && else_defined)` 计算；无 `else` 时
   `else_defined = defined_before`。因此：
   - 分支前已定义（聚合 `{ … }` / 直线赋值）→ 分支内的赋值是重赋（release 旧值），分支后
     仍已定义，后续重赋合法；
   - 只有 `then` 定义、无 `else` → 分支后仍未定义，后续重赋按 §1.4 硬错；
   - `then` 与 `else` 都定义 → 分支后已定义（两个 arm 各自 release 旧值 / 首次定义）。
   递归 `if` 用同一公式；arm 块用绝对深度标记，嵌套 `if` 不会吞掉外层 arm 的状态。
4. **未确定初始化的字段重赋 → 硬错**：例如
   ```ct
   Holder h;
   if (cond) { h.tag = a; }
   h.tag = b;                      /* error: field 'h.tag' may be undefined ... */
   ```
   诊断形如 `field 'h.tag' may be undefined before this assignment; the compiler cannot release
   the old owning value safely (initialise the struct with '{ 0 }', or release it explicitly)`。
   `switch` 的 `case`、循环体里对循环外 struct 的首赋同理。
5. **循环内重赋**：字段在循环**之前**已确定定义（聚合初始化或直线赋值）→ 每次迭代
   `retain` 新值并 `release` 旧值（`field_loop0` / `field_loop_pre` / `field_loop_long` 均
   `final live=0`）；循环体里首次出现的赋值若属于循环外声明的 struct → 硬错
   （`field_loop_bare`）。循环体内新声明的 struct 每轮新建，不视为重赋。
6. **整结构体赋值**：`h = other` 的源是 place 且目标类型含 owning 字段 → 硬错
   `whole-struct assignment would shallow-copy its owning String field`；函数调用结果 / 视图
   （如 `Map.entry` 的借用副本）不拦，保持既有借用语义。
7. **`goto`**：函数内有 `goto` 且存在带 owning String 字段的 struct 局部（或裸 owning 句柄）
   → 硬错 `a goto cannot cross an owning String scope`；不做跨作用域精确分析。
8. **不可精确的形状登记为泄漏**：`p->tag`、`(&h).tag`、索引目标（容器 glue 自己的协议）、
   跨函数写、并发写不做自动 `release`；旧值泄漏可接受，触发条件与去向写进卡 §7.9.7。
9. **沿用既有边界的形状**：`foreach` 的 `item`、`for` 初始化器里的句柄、嵌套结构体字面量
   （字段本身是含 `String` 的结构体）、泛型实例里 `T` 位置的局部；去向见卡 §7.9.7。

## 2 不选零初始化路线（C-1(a)）的理由

- 零初始化是语言语义变化（未初始化字段从“未定义值”变成零句柄），需要 USER 对语义本身的
  签收；硬错路线不改变任何合法程序的行为，只拒绝当前会读未定义存储的形状。
- 硬错可机械验证：被拒绝的形状有稳定诊断与负例（`p80_retain` 的 6 个负例），合法程序
  的诊断与生成 C 不变。
- 需要安全重赋的写法有明确出口：`Holder h = { 0 };`（显式零初始化器）或显式
  `release()`；两者都在诊断里点名。

## 3 与 D-013 的关系

D-013 §3 的“字段赋值 retain；重新赋值先 retain 右值、再 release 旧值”保持不变。本 decision
只规定**无法证明旧值已定义**时以硬错实现该承诺，而不是以“保守 release”或“已登记泄漏”改写它；
D-013 原文不改，合同解释以本记录为执行口径。
