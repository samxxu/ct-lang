## 7 非阻断更正项（不改变结论）

1. 卡 §7 写 `check-ast 1494 passed`；本机在 `2afca600` 实跑为 `1495 passed, 0 failed,
   4 skipped`，与收口提交正文的 1495 一致。§7 的 1494 应改为 1495。
2. 卡 §7 写「golden 无变化」；字面上 51 个 golden/ABI 文件的 banner 从 `0.68.0` 变为
   `0.69.0`。语义上确实零变化（非 banner 行 0），建议改写成「golden 仅 banner 更新，无
   非 banner 变化」，与 §3 的实测口径一致。
3. R1 / R3-unreach 的红证 baseline 写的是更早的文档提交（`fd216b80` / `d275ec25`），不是
   test 提交的直接父（`f3cf3762` / `395f4865`）。红证仍可复现，但按 6.6 T-7 应直接写父提交，
   或在红证里注明「中间仅文档提交」。
4. 卡 §0 范围写「CFG/基本块；definite assignment」，§7 承认 R1 未物化基本块图、R2 只做
   「无任何 return 且无循环」与「函数内从未赋值」的可判定子集。披露是诚实的，但 §0/§1 的
   措辞仍高于实现；建议把 §0 的范围改成「结构化终止判定 + 保守定值子集」，或补一条
   scope note，避免后续按「已有 CFG」引用。
5. 新增的 `ct check --semantics` 只出现在 phase 卡片、phase-log 与方案里，README 的 CLI
   表（`README.md:448`）与 `docs/language-spec.md` §4.53 未提。新用户可见开关应补进 CLI
   文档。
6. 卡 §3 的 R3 deliverable 含 `goto 越界`，但 v0-PH-70 没有新增 goto 探针/实现；goto 的
   `test/ast/32_goto` 与 defer/own 跨作用域检查是既有能力。建议在 §7 注明「goto 沿用既有
   检查」，而不是让读者以为本轮覆盖了它。
7. `p70_flow.sh` / `p70_cfg.sh` 头注释标 `v0-PH-70-R1`，卡 §3 把 flow 归 R3，提交 `b3e01c79`
   也标 R1；属标签漂移。`read of uninitialized variable` 诊断没带变量名、行列是 `1:0`，
   与 `phase70-r2-plan.md` 的 `use of uninitialized variable 'x'` 不一致，属诊断质量。
8. `ct compile --semantics` 被静默接受（rc=0，不生效），`ct build --semantics` 报
   unknown option；与 `--types` 只在 `ct check` 合法的口径不一致，建议下一轮统一。
