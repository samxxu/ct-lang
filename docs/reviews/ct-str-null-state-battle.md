# `Str` 空状态提案：主张席 / 反证席 / 裁判席

| 项 | 值 |
| --- | --- |
| 对象 | [ct-str-builtin-type-proposal.md](../proposals/ct-str-builtin-type-proposal.md) 的 §3.6、P3、P6、P7、P8 与 §2.4 方法层 |
| 性质 | 设计评审（一轮对抗，仅文档）；不改实现、不排期 |
| 基线 | v0.61.1；`Str` 现状见 [Str.h.ct](../../lib/core/Str.h.ct) |
| 评审方式 | 三条路线各自立论并给可验证判据；反证席逐点攻击；裁判席逐项给结论 |
| 证据边界 | 本轮为**设计评审**，未执行实现探针；事实只引本仓规范与代码 |

> 本轮只回答一个问题：`Str` 是否允许表示「没有值」。P1–P8 中已由负责人拍板的部分不重开，
> 但在 R5–R7 里逐条检验它们与空状态的相互作用。

---

## 0 三条待评路线

| 路线 | 类型层面 | 空串 | 方法成本 | 构造点如何处理 `char *p = NULL;` |
| --- | --- | --- | --- | --- |
| **A 不表示空状态** | 不变量：存活且构造成功的 `Str` 满足 `data != NULL`、`len >= 0`，缓冲区至少 `len + 1` 字节且末尾为 `\0` | `len == 0` 的合法值，与其它长度没有特殊分支 | 方法**不判空**：`length()` 读字段，其余走 §2.4 的长度版 | 待定：拒绝、当空串，还是可失败构造（终止已被 §3.7 的失败政策排除） |
| **B 表示空状态** | `data == NULL && len == 0` 表示无值，与 C 的 `NULL` 对齐 | 只能靠 `data != NULL && len == 0` 表达；`is_empty()` / `length()` 两个结果相同 | 方法**先判空**，再走底层调用 | 直接落到无值状态，不额外分支 |
| **C 结构同 A，允许构造失败** | 与 A 相同，不加状态字段 | 与 A 相同 | 与 A 相同，不判空 | `NULL` 视为一次**显式构造决定**：可失败构造（`bool` + out 或可选值），失败时不产出 `Str` |

三路线的分歧不在布局（都不新增字段），而在**「无值」这件事放在哪里**：
A 放在类型之外、由调用方在进入 `Str` 之前处理；B 放进值本身；C 放在构造函数的返回通道上。

## 1 主张席

### 1.1 逐路线立论与可验证判据

| # | 路线 | 主张 | 可验证判据（实现后） |
| --- | --- | --- | --- |
| C1 | A | 构造成功的 `Str` 永远可安全交给 C 函数 | 对任意 `Str s`（含空串）调用 `to_c_str()` / 长度版 C 函数，ASAN 无 NULL 解引用；`s.data` 永不为 NULL |
| C2 | A | 方法层没有前置守卫 | `length()` 展开为单条字段读；`equals` / `compare` / `find` 展开后与 `char *` 侧同形，映射表内无 `if (data == 0)` |
| C3 | A | 空串是普通值 | `Str s = "";` 与 `Str t = "abc".slice(0, 0);` 的 `length()` 均为 0，两者 `equals` 为真，无需特殊分支 |
| C4 | B | 与 C 的 `NULL` 语义直接对齐 | `Str s = p;`（`p == NULL`）后 `s.data == NULL`，可原样传回期望 `NULL` 的 C 接口，无需判空 |
| C5 | B | 空状态在类型内可检测 | `s.data == NULL` 是唯一判据；`is_empty()` 与「无值」返回同一结果 |
| C6 | C | 失败不进入类型，调用点必须处理 | 可失败构造的返回值必须被使用；忽略返回值给固定诊断；成功后不变量与 A 相同 |
| C7 | C | 构造点之外零成本 | 除构造点外的方法与 A 完全同形；映射表不出现判空分支 |
| C8 | B | 无值可与空串并存 | `{NULL, 0}` 与 `{非空指针, 0}` 是两个可区分的状态；`length()` 都为 0 但 `data` 不同 |

### 1.2 主张席结论

三路线都能自洽。差异是**成本落在哪一层**：B 把成本摊到每个方法（判空）和每个读者（先看 `data`）；
A 把成本摊到构造点（调用方必须先处理 `NULL`）；C 把成本集中在构造函数的返回通道。
从 P4「方法层是映射」和 P3「布局是承诺」看，A / C 不引入方法层分支，B 必然引入。

## 2 反证席

### 2.1 逐点攻击

| # | 针对 | 反例 / 边界 | 代价与判定 |
| --- | --- | --- | --- |
| R1 | B：零成本映射 | B 要求每个方法先判空。`length()` 还能读字段，但 `equals` / `compare` / `find` / `slice` / `concat` / `split` 都要在展开处插 `if (data == 0)`；`split` 还要定义「无值切分」返回空容器还是空段。这与 P4「展开后与直接调用 C 函数等价」直接冲突：`Str` 宿主的映射与 `char *` 宿主不再同形 | **零成本映射被破坏**。判 B 不成立，除非 P4 降级为「有空状态时不保证零成本」 |
| R2 | A / C：静默转空串 | `Str s = strstr(hay, needle);` 未找到时返回 `NULL`。若构造点把它当空串，`s.length() == 0` 与「找到了空串」不可区分，错误沿返回值、字段、容器一路传到输出层；A 的方法不判空，因此**没有任何可观测点**能发现它 | **静默错误传播**。判 A 必须同时禁止静默转空串，否则 A 比 B 更危险 |
| R3 | B：可观察性（返回值） | `Str f()` 返回 `{NULL, 0}` 时，调用方写成 `if (r.length() == 0)` 会把「失败」当「空串」；若写成 `if (!r.data)`，就把 P7 定义的只读字段当成状态位使用 | 类型内多了一个语义位，但没有任何方法能查询它；**状态只能靠字段值观察**，与 P3「布局承诺」里「调试器所见与文档一致」冲突：调试器看到 `{0, 0}`，却要靠约定才知道这是无值 |
| R4 | B：可观察性（实参 / 结构体字段） | `void g(Str s)` 无法区分调用方传的是空串还是无值；`struct Rec { Str name; }` 落盘或跨 FFI 时，`{NULL,0}` 在 C 侧是合法写法，语言侧却把它当特殊状态。字段初值若允许 `Str name;`（未初始化），在 A 下是无效值，在 B 下会被误读成「无值」 | **字段位置的区分不可靠**：未初始化与无值撞车，FFI 与落盘各有一套解释。判 B 不成立 |
| R5 | 已定 P6：借用可存变量 | A / C 下 `const char *q = s.data;` 保证非 NULL，`if (!q)` 只可能来自 `find` 未找到，含义唯一。B 下 `q` 可能为 NULL，`find` 未找到也返回 NULL，**两种 NULL 无法区分**：调用方无法判断「这个 `Str` 没有值」还是「查找失败」 | **与 P6 的可组合性冲突**。判 B 不成立；A 让借用指针的 NULL 只保留一个含义 |
| R6 | 已定 P7：`data` 只读 | B 把「有没有值」编码在 `data` 是否为 NULL 上，而 `data` 是只读字段。这意味着一个**只读字段同时承担「内容地址」与「状态位」两个职责**；P7 的职责划分（只读定形内容归 `Str`，修改走可变缓冲区）无法覆盖状态位：缓冲区侧没有对应的「无值」，`Buf` → `Str` 转换后状态会丢 | **状态在类型间不一致**。判 B 不成立，除非给缓冲区也加空状态，那会扩散到 P7 的范围之外 |
| R7 | 已定 P8：逐宿主独立映射 | 同名同义要求 `p.is_empty()` 与 `s.is_empty()` 语义一致。B 下 `Str` 侧的 `is_empty()` 要么把无值算作空（与空串撞车），要么不算（那么无值是「非空」），两种都与 `char *` 侧不一致；两种映射不再同义 | **破坏 P8 的命名约定**。判 B 不成立 |
| R8 | A / C：C 互操作摩擦 | 大量 C 函数用 NULL 表示失败或缺失：`strchr` / `strstr` / `getenv` / `realpath` / `fgets` 失败。A 下不能直接 `Str s = f(...)`，必须先在 `char *` 侧判空再构造；C 函数把 NULL 当「可选参数」（如某些日志、句柄接口）时，`Str` 无法表达，只能在边界退回裸指针 | **真实摩擦，但不构成否决**：摩擦集中在边界，且是可枚举的；判受理为已知成本，要求写进文档，不得宣称 `Str` 完全替代 `char *` |
| R9 | B：宣称「与 C 对齐」 | C 的 `""` 与 `NULL` 本就不同；B 要真正对齐，就必须保证空串的 `data` 非 NULL。要么每次空串分配 1 字节（`Str s = "";` 一次 `malloc`），要么共享一个静态空串——后者与 `Drop` 的 `free` 冲突（释放静态区是未定义），要规避就得加「不释放」标志，即第三个字段 | **要么每次空串分配，要么加字段**。判 B 的「对齐」收益不成立 |
| R10 | A：释放态与不变量 | 现行 `Drop` 把 `data = 0; len = -1`（[Str.h.ct:23-29](../../lib/core/Str.h.ct#L23-L29)），`str_from_len` 分配失败也返回 `len = -1`（[Str.h.ct:39-43](../../lib/core/Str.h.ct#L39-L43)）。A 的不变量在释放后与构造失败时不成立；若 A 成立，「存活值」与「已释放值」的边界必须由 §3.7 的失败政策先钉死 | **A 必须以 §3.7 的失败政策为前提**。判 A 受理为不变量，但不能声称「任何 `Str` 变量都满足」 |
| R11 | A：构造点运行期不可判 | `char *p = getenv("X"); Str s = p;` 编译期无法证明非 NULL。若规范写「终止」，与 §3.7 已裁定的「不终止」冲突；若写「未定义」，把高频错误变成 UB；若写「空串」，即 R2 的静默传播 | **A 的构造点必须有一条固定规则**，不能留空。判 C 是可落地的第三条路 |
| R12 | C：可失败构造的调用点 | 可失败构造返回 `bool` + out 时，调用方可以忽略返回值；返回可选值时，语言侧是否有可选类型？没有就得造一个，成本外溢到其它类型 | **C 需要一条「忽略返回值即诊断」的规则**，否则与静默转空串等价。判 C 受理，附该条件 |
| R13 | A / C：`find` 与空状态歧义 | 若采纳 B，§2.4.5 的「未找到返回 `NULL`」与「无值 `Str` 借出的指针」都是 NULL；裁判已在 R5 判定冲突。A 下 `find` 的 NULL 唯一含义是未找到，规则更简单 | **A 降低 §2.4.5 的歧义**。判 A 受理 |
| R14 | A / B：`Map` 键与比较 | `Map` 的 `Str` 键按 `len` 比较（[language-spec.md:2419](../language-spec.md#451-泛型-struct固有方法与内置容器phase-29)）。B 下无值键与空串键 `len` 都是 0，落进同一个桶；若把「无值」当独立键，就得给比较加特例，与 §3.5 的字节比较规则冲突 | **B 会让键空间塌缩**。判 B 不成立 |
| R15 | A：与 FFI 同形 struct 对传 | P3 承诺同形 C struct 可直接对传；C 侧可以构造 `{NULL, 0}` 传进来，直接击穿 A 的不变量。若对传前不做校验，A 的不变量只覆盖「语言侧构造的值」，文档必须写明 | **A 的适用范围要限定**；判 A 受理，但 FFI 规则未定前不得宣称跨边界后仍成立 |
| R16 | B：`split` / `slice` 的返回值 | 无值 `Str` 上调 `slice` / `split` 应返回什么？返回 `{NULL,0}` 会继续传播无值；返回空串会把无值悄悄降级为合法值；两种都不符合「B 让无值可传播」的初衷 | **B 的语义无法在方法层闭合**。判 B 不成立 |

### 2.2 反证席结论

- B 在**方法层、借用层、映射层、键比较层**四处都要特例，且没有一处能给出与 `char *` 宿主同义的规则；
  它换来的只有「与 C 的 NULL 字面对齐」，而 R9 表明这种对齐本身也不彻底。
- A 的类型不变量成立，但**单独使用**会把 `NULL` 变成静默空串（R2）或 UB（R11），必须有构造点规则。
- C 是 A 的构造点补丁：把「来源是 NULL」变成一次显式决定，失败不产出 `Str`，因此不破坏 A 的不变量。

---

## 3 对冲

两席在事实层面无分歧：三路线都不改布局，都能实现。分歧在**「无值」由谁负责**。
主张席认为三路线自洽；反证席认为 B 的自洽只在类型定义里，一进入方法、借用、映射、键比较就不自洽。
可收敛的形态是「A 的不变量 + C 的构造点」，而不是「B 的状态位」。

---

## 4 裁判席

### 4.1 结论：**部分受理**

- **受理 A 的类型不变量**：`Str` 不表示「没有值」。
- **受理 C 的构造点规则**：类型不加状态，「来源是 NULL」只在构造点显式决定。
- **不受理 B**：把无值编码进 `{NULL, 0}`。
- **不受理静默转空串**：无论 A 还是 C，构造点都不得把 `NULL` 静默降级为空串。

### 4.2 逐项结论

| 项 | 结论 | 依据 |
| --- | --- | --- |
| 类型层面是否表示空状态 | **不受理（B）** | R3 / R4：状态只能靠只读字段观察，实参与字段位置不可靠；R7：破坏 P8 同名同义；R14：`Map` 键塌缩；R16：方法层无法闭合 |
| 存活 `Str` 的不变量 | **受理（A）** | 构造成功即 `data != NULL`、`len >= 0`、缓冲区 `len + 1` 字节且末尾 `\0`；空串是 `len == 0` 的普通值；R1、R13 表明这是保住 P4 零成本映射与 §2.4.5 单一 NULL 含义的唯一形态 |
| 方法层是否判空 | **不受理判空** | R1：判空守卫会让 `Str` 映射与 `char *` 映射不同形，直接违背 P4 与 P8 |
| `char *p = NULL; Str s = p;` | **受理 C**：在构造点处理，且必须显式 | R2 / R11 / R12：三条路里只有 C 既不给类型加状态，也不把错误静默降级 |
| 编译期可判定的 `NULL` / `0` 字面量 | **受理为诊断**：`Str s = NULL;` / `Str s = 0;` 直接拒绝 | 与 §3.6 既有的「不受理隐式 `NULL` → `Str`」一致；字面量是唯一能在编译期拦下的情形 |
| 运行期才知为 `NULL` 的实参 | **受理为固定行为**：必须走可失败构造或显式判空后再构造；隐式转换不接受 | R2 的静默传播不可接受；R11 的 UB 不可接受；终止已由 §3.7 的失败政策排除，具体形态（可失败构造 / 固定诊断）由项目组定 |
| 需要表达「可能没有值」 | **受理**：显式可失败构造（`bool` + out 或可选值），失败时不产出 `Str` | R12；这是 C 的落点，且不污染类型布局 |
| 可失败构造的返回值被忽略 | **受理为诊断**：忽略即报错 | 否则与静默转空串等价（R12） |
| `str_from(NULL)` 的既有行为 | **受理为「显式调用的既定语义」**：仍返回空串 | 事实基线 [Str.h.ct:51-60](../../lib/core/Str.h.ct#L51-L60)；调用方写明的决定，与隐式转换不是同一条路径 |
| 空串是否特殊分配共享缓冲 | **不受理共享静态空串** | R9：与 `Drop` 的 `free` 冲突，规避需第三个字段，违背 P3 |
| C 侧 NULL 结果的承载 | **受理为边界义务**：先在 `char *` 侧判空，再构造 `Str` | R8；文档必须写清，不得宣称 `Str` 完全替代 `char *` |
| C 侧把 NULL 当可选参数 | **受理为边界例外**：该类调用点退回 `const char *` 或显式 `NULL` | R8；`Str` 无法表达可选；属 §2.5 同类的显式边界 |
| FFI 同形 struct 传入 `{NULL, 0}` | **受理为不变量缺口**：跨边界前必须校验或明确不保证 | R15；在 §3.4 的 FFI 规则定稿前，A 的不变量只覆盖语言侧构造的值 |
| 释放态 `len = -1` | **前置依赖已关闭**：负责人 2026-11-16 裁定分配失败取显式失败返回（`bool` + 出参 + 错误码），构造失败不产出 `Str` | R10；该裁定同时废除了「构造失败返回 `len = -1` 释放态」，A 的不变量由此成立 |

### 4.3 已定裁定与本次结论的分界

**已定（负责人，不重开）**

- P1 字面量仍是 `char *`，目标类型为 `Str` 时转换；
- P2 值语义取拷贝；
- P3 两字段布局是语言承诺（`data` + `len`，`data` 为 `const char *`）；
- P4 方法层是映射，不是第二套实现；
- P5 `Str` 归语言侧，std 完全移除；
- P6 借用指针可存变量，随 `Str` 失效，无借用检查器；
- P7 `data` 只读，构造与修改走可变缓冲区；
- P8 静态映射按宿主各自定义，不共用表。

**本次结论（评审席给出，仍属提案、待项目组评估）**

- `Str` 不表示「没有值」，空串是 `len == 0` 的合法值；
- 方法层不判空，不因空状态加任何前置守卫；
- `NULL` 来源只在构造点处理，必须显式；隐式转换不接受 `NULL`；
- 不采纳 `{NULL, 0}` 作为无值状态；
- 不采纳「静默转空串」；
- 可失败构造是表达「可能没有值」的唯一形态。

**仍待项目组决定（本轮不越权）**

- 运行期 `NULL` 的固定行为（可失败构造 / 固定诊断；终止已被 §3.7 排除）；
- 可失败构造的具体形态（`bool` + out，还是引入可选类型）；
- FFI 同形 struct 对传是否校验不变量（与 §3.4 同批）；
- 空串是否允许共享静态缓冲（本轮判不受理，若要重开需同时解决 `Drop` 与 P3）。

### 4.4 裁判附注

- 本轮不给排期、不分配 phase；是否落成施工卡由项目组决定。
- A 与 C 是**组合**结论，不是二选一：A 定类型不变量，C 定构造点；单取 A 会退化为静默空串（R2）或 UB（R11）。
- 反证席的 R1、R7、R9、R14 是否决 B 的四条硬依据，不再以「与 C 的 NULL 对齐」为由重开。
- 与 §3.6 既有的「`NULL` 语义待定」相比，本轮把「类型是否表示无值」和「构造点如何处理 `NULL`」拆成了两个问题：
  前者已判（不表示），后者仍需政策（终止 / 诊断 / 可失败构造的具体形态）。
- 本轮列为成立前提的「构造失败不得产出 `Str`」已由负责人 2026-11-16 的失败政策裁定关闭：
  分配失败取显式失败返回，不终止、不返回半成品、不返回空值。空状态的不变量因此不再依赖未定政策。
