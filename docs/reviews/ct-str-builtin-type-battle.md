## 1 主张席

### 1.1 主张与可验证判据

| # | 主张 | 可验证判据（实现后） | 依据 |
| --- | --- | --- | --- |
| C1 | 字面量仍是 `char *`；只有目标类型是 `Str` 时转换 | `Str s = "x";` 构造 `Str`；`char *p = "x";` 仍是 `char *`；不存在「无目标类型时字面量变 `Str`」的路径 | [language-spec.md:47](../language-spec.md#L47)、[:2559](../language-spec.md#L2559) |
| C2 | `Str a = b;` 是深拷贝 | 改 `b` 内容不影响 `a`；`a` 与 `b` 的 `data` 不同；ASAN 无 double-free | 现行浅拷贝：[language-spec.md:2560](../language-spec.md#L2560) |
| C3 | 右值为临时值时直接转移，不额外拷贝 | `Str a = f();` 的分配计数比「先构造再拷贝」少一次；无泄漏 | 需新的转移规则；现行规范无 |
| C4 | 布局是语言承诺 | C 侧 `offsetof(data)==0`、`offsetof(len)==sizeof(char *)`；`sizeof` 与语言侧一致 | [Str.h.ct:18-21](../../lib/std/Str.h.ct#L18-L21) |
| C5 | 同形 C struct 可直接对传 | 以同布局 C struct 按值传入/传出，字段值与语言侧一致 | 现行按值 struct 规则：[language-spec.md:2003](../language-spec.md#L2003-L2005) |
| C6 | 方法层不搬进编译器 | `impl Str` 与自由函数位置不变；编译器只做身份识别与代码生成 | [Str.h.ct:132-139](../../lib/std/Str.h.ct#L132-L139) |
| C7 | 转换边界可枚举且不扩散 | 声明、赋值、传参三处生成转换；返回、字段初值、容器字面量、三目按最终裁定的边界处理 | P1；此前转换评审的收窄口径 |
| C8 | 内嵌 `\0` 由 `len` 保证 | `Str` 与 `Str`、`Str` 与 `char *` 的比较按 `len` + `memcmp`，`a[0]` 后的 `\0` 不截断 | [language-spec.md:2559](../language-spec.md#L2559)、[:2419](../language-spec.md#L2419) |

### 1.2 主张席结论

三条前提可以落成语言契约：`Str` 的布局已经具备，`Drop` 与自由函数已存在，缺的是「内置身份 +
拷贝语义 + 边界」的明文规定。C1–C8 足以构成验收面。

## 2 反证席

### 2.1 逐条反证

| # | 针对 | 反例 / 边界 | 代价与判定 |
| --- | --- | --- | --- |
| R1 | P2 与现行语义 | 现行 §4.56 明写「按值传递浅拷贝指针，不自动深拷贝，需显式 `retain()`」；P2 把同一句 `Str a = b;` 从 O(1) 浅拷贝改为 O(n) 深拷贝 | 这是**已发布语义的破坏性变更**，不是补文档；依赖共享 buffer 的调用点会变，`retain()` 会变成重复拷贝。判 **受理前提，但必须配迁移与兼容说明** |
| R2 | C3 的「临时值直接转移」 | 现行没有 `Str` 的移动构造/转移规则，只有 `own` 与 AutoDrop 的语句级记账；`Str a = f();`、`Str a = b;`、`Str a = b.retain();` 三种右值的判定不同；临时值若被多处使用，转移会提前失效 | 需要定义「临时值」的语法/类型判据与转移点；否则 double-free 或悬空。判 **规则未定，不能按一句话实现** |
| R3 | P2 的开销可见性 | `loop 1000000 { Str s = p; }` 每次分配+拷贝；调用点没有标记；`retain()` 显式时读者知道有拷贝，隐式后不知道 | 文档写清是必要条件，但不是充分条件；热点路径需要可观测手段（计数/诊断）或明确的 `char *` 视图写法。判 **受理，但代价可见性不足** |
| R4 | C4 / 「内置」身份 | `Str` 仍是 `lib/std` 的 `pub struct`；若用户可重定义同名类型或改字段，布局承诺不成立 | 编译器必须拒绝重定义/改布局，或在门禁里断言；否则「语言承诺」只是文档。判 **需加防重定义规则** |
| R5 | C5 同形 C struct 对传 | 现行类型规则把不同具名 struct 的按值互传判为硬错（v0.53.2 例外），同形 C struct 是不同具名类型；直接对传会绕过 `Drop` 的所有权记账 | 需要新增 FFI 结构兼容规则（按布局还是按声明），并定义对传后的释放责任。判 **承诺可受理，当前实现不支持，不能宣称已可用** |
| R6 | C6 方法层 | P2 生效后 `retain()` 在「自动深拷贝已覆盖」的场景是冗余；但 `retain()` 仍是公开 API，语义是「显式深拷贝」；若方法搬进编译器，`Drop` / `release` 的实现位置与自举链都要动 | 保留方法层成本最低；搬进编译器收益不明确。判 **不受理搬进编译器** |
| R7 | C7 转换边界 | 目标类型可以出现在返回、字段初值、容器字面量、三目；若不封闭，隐式分配会扩散到任意表达式；`char *` → `Str` 形参当前是硬错，撤销后既有错误用例会变绿 | 需要固定「只允许声明/赋值/传参」，其余保持显式；`Str` → `char *` 的隐式借用涉及生命周期，另案。判 **边界必须封闭** |
| R8 | C8 内嵌 `\0` 与 C 对传 | `Str` 可含 `\0`；同形 C struct 按值对传后，C 侧按 NUL 处理会在第一个 `\0` 截断；调试器看到 `len` 与 C 字符串视图可能不一致 | 布局承诺不能改变 C 的字符串语义；必须在文档与诊断里写明截断边界。判 **表示受理，C 侧截断需明示** |
| R9 | §3.6 `NULL` | `str_from(0)` 返回 `len=0` 的空串（拥有型），不是 `{0,-1}`；若隐式转换接受 `NULL`，会把「缺失/错误」压成空串；若不接受，需要在每次转换做运行时判空 | 两种选择都有成本；静默接受最危险。判 **不受理隐式 `NULL`**，要求显式 `str_from` |
| R10 | §3.7 OOM | 赋值/传参没有返回值通道；现行 `str_from_len` 失败返回 `len=-1`；若隐式路径终止，库代码会杀进程；若返回释放态，调用方又难以逐处判空 | 两种语义并存会分裂；测试也难以稳定注入。判 **不受理「默认终止」**，先定 OOM 政策再实现隐式拷贝 |
| R11 | P1 的空字面量 | `Str s = "";` 会分配一个空串；若高频构造空串，开销可见；是否允许静态空串共享需另定 | 不影响 P1 成立，但要在文档里写清空串也分配。判 **需在开销文档中列明** |

### 2.2 反证席结论

三条前提的**方向**可以成立，但实现层有四个硬约束：

1. P2 是破坏性语义变更，必须配迁移，不是改一行代码；
2. 临时值转移没有现成规则，必须先定义判据；
3. 同形 C struct 对传当前不成立，不能把「承诺」写成「已可用」；
4. `NULL` 与 OOM 是隐式转换的两个失败口，必须先定政策。

## 3 裁判席：逐项结论

| 项 | 结论 | 理由与依据 |
| --- | --- | --- |
| P1 字面量属性 | **受理（已定）** | 负责人拍板；实现上要撤销 `char *` → `Str` 形参的硬错（[language-spec.md:2000-2005](../language-spec.md#L2000-L2005)），改为目标类型触发；不引入「字面量随上下文变类型」 |
| P2 值语义取拷贝 | **受理（已定），附迁移条件** | 与现行 §4.56 浅拷贝冲突（[language-spec.md:2560](../language-spec.md#L2560)）；必须改写规范、给兼容窗口；`retain()` 保留，但文档要说明自动深拷贝已覆盖的场景 |
| P3 两字段布局 | **受理（已定）** | 源码布局已一致（[Str.h.ct:18-21](../../lib/std/Str.h.ct#L18-L21)）；需要加 `offsetof`/`sizeof` 门禁与「禁止重定义」规则 |
| P3 同形 C struct 对传 | **受理为承诺目标，当前不宣称可用** | 现行不同具名 struct 按值互传为硬错（[language-spec.md:2003](../language-spec.md#L2003-L2005)）；须新增 FFI 兼容规则并定义释放责任 |
| 内置定义落在哪一层 | **已被负责人 2026-11-16 裁定覆盖：走 B（语言层）**；原 A 建议作废，迁移条件保留（见 §6） | 负责人要求 `Str` 从 std 完全移除、迁到语言侧；自举与旧产物问题在 B 路线内解决 |
| 与现有声明的关系 / 迁移 | **受理分阶段；不受理一次性切换** | 旧代码依赖浅拷贝，直接切换会静默改变行为；先诊断/警告，再切语义，最后移除旧路径 |
| 方法层归属 | **已被负责人裁定覆盖：方法层随 `Str` 迁到语言侧，且为映射而非独立实现**（见 §6） | `Str` 方法不另写实现，编译期展开为与 `char *` 方法同一套 C 函数的直调；std 不再保留定义 |
| 与 `char *` 的隐式转换边界 | **受理「声明/赋值/传参」三处；不受理返回、字段初值、容器字面量、三目；不受理 `Str` → `char *` 隐式借用** | 隐式分配必须可枚举；借用涉及生命周期，另案处理（显式视图函数） |
| 内嵌 `\0` 的表示与比较 | **受理 `len` + `memcmp`；不受理 NUL 结尾视图** | 现行 `Map` 的 `Str` 键已按 `len` + `memcmp`（[language-spec.md:2419](../language-spec.md#L2419)）；C 侧截断需明示 |
| `NULL` 语义 | **不受理隐式 `NULL` → `Str`** | `str_from(0)` 返回空串而非缺失态（[Str.h.ct:51-60](../../lib/std/Str.h.ct#L51-L60)）；隐式接受会把错误压成空串；要求显式 `str_from` |
| OOM 政策 | **不受理「默认终止」；隐式拷贝在政策确定前不实现** | 现行 `str_from_len` 返回 `len=-1`（[Str.h.ct:40-43](../../lib/std/Str.h.ct#L40-L43)）；终止会杀宿主进程，释放态又迫使逐处判空；需项目级政策 |
| `retain()` | **受理保留** | 显式深拷贝仍有场景；P2 后自动拷贝覆盖的场景不必再手写，但函数不删 |

## 4 裁判结论：**部分受理**

**受理**

1. `Str` 的内置身份：语言规范承认类型名、两字段布局、`Drop`、P1/P2/P3 三条前提；
2. 布局承诺与门禁：`data` / `len` 顺序与名字固定，新增字段按破坏性变更处理；
3. 方法签名归语言侧，实现为与 `char *` 同一套 C 函数的映射（§6 覆盖原「留在 `lib/std`」的建议）；
4. 转换边界收窄为声明、赋值、传参三处；其余位置保持显式；
5. 内嵌 `\0` 按 `len` + `memcmp` 比较；
6. `retain()` / `release()` 保留，不因自动深拷贝删除。

**不受理**

1. ~~立即把 `Str` 定义搬进编译器 prelude（B 路线）~~——**已被负责人 2026-11-16 裁定覆盖，见 §6**；
   保留为历史理由：自举与迁移成本仍需在 B 路线内解决；
2. 一次性切换 P2，不做迁移——会静默改变已发布语义；
3. 把方法体写成编译器内置算法（而不是 C 函数映射）——与 §6 的映射模型冲突；
4. 返回、字段初值、容器字面量、三目的隐式转换——分配点不可枚举；
5. `Str` → `char *` 的隐式借用——生命周期规则未定；
6. 隐式 `NULL` → `Str`——会把缺失/错误压成空串；
7. 隐式拷贝默认终止——与现行释放态冲突，且无项目级 OOM 政策；
8. 只用 NUL 结尾视图比较 `Str`——违反 `len` 契约。

**仍需项目组决定**

1. P2 的迁移窗口与兼容诊断形式（警告多久、何时切语义）；
2. 「同形 C struct 直接对传」的 FFI 兼容规则（按布局还是按显式声明）与释放责任；
3. B 路线的迁移细节（自举、旧产物、shim 期限）；
4. `NULL` 的显式路径是否保留 `str_from(0)` 的空串语义；
5. OOM 政策（终止 / 释放态 / 仅显式路径可失败）；
6. 空字面量的分配与文档口径；
7. 规范 §4.56 的改写范围与版本位。

## 6 负责人后续裁定（2026-11-16）

本节记录评审后负责人给出的裁定，覆盖 §3 中「内置定义层」与「方法层归属」两条建议；
§4 的「部分受理」结论保留，执行路径以本节为准。

### 6.1 归属

- `Str` 的签名与语义全部归语言侧；使用方不再定义、不再重复提供，只消费。
- `Str` 从 std 侧完全移除、迁到语言侧。
- 落点：语言层 prelude / 编译器内置声明；v0.62.0 起可用，std 侧仅保留不含定义的兼容 shim；
  v0.63.0 删除 shim，std 侧完全移除。
- 原 §3 的 A 建议与「不受理立即走 B」不再作为执行口径，保留为历史评审意见；迁移、自举与
  旧产物问题仍需在 B 路线内解决。

### 6.2 方法层：映射，不是第二套实现

- `Str` 方法不另写实现；编译期展开为与 `char *` 方法**同一套底层 C 函数**的直调，实参取 `data`，
  需要长度的位置再传 `len`；无间接调用、无动态派发；展开后与直接调用该 C 函数等价。
- 同名同义：`char *` 侧已有的方法名与语义，`Str` 侧逐一对应，不得两套名字。
- 变体选择：同一能力同时有带长度版本与 NUL 版本时，取带长度版本；`Str` 允许内嵌 `\0`，
  不走 `str*` 系列；`len` 直接读字段，O(1)。
- 唯一显式例外：C 函数强制要求 NUL 结尾（解析类、路径类、系统调用参数类），必须显式
  `to_c_str()` / `copy_to()`，不能隐式完成。

### 6.3 反证与裁判补充

| # | 反证 | 裁判 |
| --- | --- | --- |
| R12 | 「无代价」若被读成「无分配」不成立：切片、拼接、切分的底层 C 调用仍分配/拷贝；映射只消除派发层 | 受理映射模型；文案改为「无派发开销，底层调用成本仍在」，不得写成零成本 |
| R13 | 带长度查找（`memmem`）并非所有 C 库都有；没有时需同语义回退，不能宣称同一函数 | 受理变体规则；要求给出可移植回退，仍不新增 `Str` 专用算法实现 |
| R14 | 同名同义但复杂度不同：`len` 在 `Str` 为 O(1)、`char *` 为 O(n)；替换调用点可能改变性能 | 受理；文档必须标复杂度，不能只写同名 |
| R15 | 显式 NUL 例外需要清单；只写「解析/路径/系统调用」仍可能遗漏 | 受理；要求按 C 函数族列清单，未列入的默认走长度版 |
| R16 | std 完全移除与迁移窗口冲突：v0.62.0 的 shim 仍是 std 文件 | 受理；shim 不含定义，v0.63.0 删除；「完全移除」指最终态 |

**裁判补充**：方法映射受理；「零成本」限定为无派发开销；B 路线受理；std 移除分两版完成。
§4 的部分受理结论不变；R1、R5、R9、R10 仍是实施前必须闭环的四项。
