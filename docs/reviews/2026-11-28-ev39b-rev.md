## 3. 可读性抽查（2–3 条正面证据 + 残余）

### 正面证据 1：`Symbols.c` 的容量 guard 函数

`frontend_sym_Symbols_frontend_sym_SymbolOps_ensure_fn_capacity`（`bootstrap/ct-ast/Symbols.c:1454` 起）：

- 函数名带 `frontend_sym_Symbols_...` 命名空间，接收者显式 `_self`；
- guard 顺序清楚：`need <= 0`、`need > CAP_LIMIT`、空表 `calloc`、`while` 增长；
- `Vec_frontend__sym__Fn_push` 的调用点只做一件事，失败返回 `-1`；
- 4 空格缩进、花括号换行，未出现 minify/多语句同行。

### 正面证据 2：`EmitExpr.c` 的早期失败与局部命名

`backend_emit_Emitter_backend_emit_EmitExpr_emit_ref_arg`（`bootstrap/ct-ast/EmitExpr.c:456` 起）：

- `n < 0` 先报 `a ref/out argument is missing`，随后才读 `nodes[n]`；
- 局部 `k` 明确缓存 `nodes[n].kind`，后续分支使用 `k`；
- 失败路径统一走 `vptr->fail` / 返回 `-1`，没有隐式 fallthrough。

### 正面证据 3：`EmitExpr.c` 的穷尽分派

`backend_emit_Emitter_backend_emit_EmitExpr_emit_field`（`bootstrap/ct-ast/EmitExpr.c:1098` 起）：

- `match` 展开为显式的 `if (tag == 0) ... else if ...`，每个变体一个臂，无 fallthrough；
- 临时 `__ct_match18` 只读一次 `nk`，命名可追踪；
- 控制流虽然长，但结构是扁平的，读者能逐臂对照源码 `NodeKind`。

### 残余

1. **长条件行**：`emit_ref_arg` 中 400+ 字符的复合 `if`（Vec `get`/`at` 识别）是典型残余；`Symbols.c` 的 `if`/`else if` 链也有同类长条件。
2. **match 展开冗长**：`emit_field` 的 19 个 `else if` 臂、`emit_cond` 的嵌套 `if/else` 运算符选择，语义可读但控制流结构重复/嵌套；属于 SH-123 的 P2，不在本轮清零。
3. **D2/D3 残留**：`Pkg` 43、`Symbols` 24 处 `snprintf`，全仓 `realloc` 87；这些是已登记“不改/后续”项，不是本轮 clean。

**未发现** minify 式单行压缩或无名临时量；命名与缩进符合生成 C 的可读性要求。
