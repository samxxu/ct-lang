## 3 E80-1…8 逐条

### E80-1 布局与 `_Static_assert`：✅ 通过

- `String` / `Str` 均 16 B，`ct_str_hdr` 8 B，`_Static_assert` 随 `.ct` 源进入生成的 C 并由 `cc` 编译；不是只写在文档里。
- `refs = -1` 的 literal / empty 在 `release()` 后仍为 `-1`，`ct_str_live_count()` 不增；`abi` / `trace` 两条夹具均绿。
- 头文件注释与生成结构一致：`struct String { char *ptr; int len; }`、`struct ct_str_hdr { int refs; int aux; }`（[`lib/std/Str.h.ct`](../../lib/std/Str.h.ct) 顶部；生成 C 第 25–36 行）。

### E80-2 L1 immortal / 借用 / U16 仅工厂：✅ 通过

- `String s = "x"` / `String g = "..."` 绑定 `ct_str_lit_*` 静态块，`refs=-1`；`Str v = "x"` 是借用视图。
- `U16String` / `U16Str` 无隐式字面量：`neg_utf16_literal`、`neg_u16str_literal` 均硬错，实际 `U16String` 只从 `from_utf8` / `from_utf16` 工厂进入。
- 卡 §7.9.2 的“字面量实参只覆盖自由函数、`U16String.from_utf8("abc")` 需先绑定 `Str`”是已登记边界；E80-2 没有要求静态工厂实参隐式绑定，因此不构成 E80-2 失败。

### E80-3 不可变 / 只读下标：✅ 通过

- `p80_methods` 的 `neg_write_index`（`s[i] = ...`）与 `neg_u16_write`（`u[i] = ...`）均报 `read-only subscript`；`p80_cstr` 的 `neg_data_write` 报 `immutable`。
- `String` 没有 `set` 方法；`s[i]` 返回单码点 `Str`，`U16String[i]` 返回单 code unit `U16Str`，均为只读视图。

### E80-4 码点 / 字节 / slice：✅ 通过

### E80-5 `.data` / `cstr()` / printf 负例：✅ 通过（E80-5 断言）；D-013 §2 字面类型见 O1

- `.data` 只读、不保证 NUL；`cstr()` 复制并补 NUL；子视图 `.data` 没有插入 NUL：`subview=98,99,100`（`bc` 后紧跟父串的 `d`）。

### 4.3 §3 自动 retain：❌ 未实现（阻断）

#### 证据 A：夹具自己把缺口钉成回归

```console

$ sed -n '1,12p' test/ast/p80_layout/trace.ct
/* PH-80 S5a-1 / D-013 §3: the refcount trace at every position the retain
 * contract names - literal (immortal), explicit copy/retain/release, a
 * by-value parameter, a return, a struct field, a `Vec` element and
 * `own`/`delete`.

 * The protocol this phase ships is explicit: `copy()` / `retain()` share the
 * buffer and bump `refs`, `release()` drops one reference. A `Vec` insertion
```

## 8 诚实性：是否“未覆盖写成通过”

## 9 不阻断观察

- **O1 `.data` 静态类型措辞。** D-013 §2 与 spec §4.70 写“静态类型 `const char *` / `const uint16_t *`”，但实现把 `.data` 降为 `s.ptr`（`char *`），且 `const char *p = s.data;` 也硬错；实际是“只能下标的只读视图”，比 decision 更严。建议二选一：把 decision/spec 改成“index-only view，不作为值传出”，或实现真正可赋值的 `const char *` 视图。E80-5 的三类负例已成立，故本轮不据此单独打回，但它确实是 D-013 §2 的字面偏差。

### 11.3 B1（阻断）嵌套 `break` / `continue` 仍漏 release

`continue` / `break` 直接写在循环体顶层时正常；但写在嵌套 `if` 里时，`sb_jump_release()` 只释放**最内层** block（[`Emitter.h.ct:717-723`](../../selfhost/ct-ast/backend/emit/Emitter.h.ct#L717-L723)），外层循环体里的 owning 句柄没有被释放。最小反例：

```ct
#include <stdio.h>
int main(void)
{
    Str lit = "abc";
    int i;
    for (i = 0; i < 2; i++) {
        String s = lit.to_string();
        printf("iter %d refs=%d live=%d\n", i, s.refs(), ct_str_live_count());
        if (i == 0) {
            continue;
        }
        if (i == 1) {
            break;
        }
    }
    printf("after loop live=%d\n", ct_str_live_count());
    return 0;
}
```

```console
$ ./jump2; echo exit=$?
iter 0 refs=1 live=1
iter 1 refs=1 live=2
after loop live=2
exit=0
```

生成的 C 直接把 `continue;` / `break;` 写在 `String_release(&s)` 之前，且两个分支都没有释放：

```c
for (i = 0; i < 2; i++) {
    struct String s = Str_to_string(&lit);
    printf("iter %d refs=%d live=%d\n", i, String_refs(&s), ct_str_live_count());
    if (i == 0) {
        continue;
    }
    if (i == 1) {
        break;
    }
    String_release(&s);
}
```

对照：直接写在循环体顶层的 `continue` 会生成 `String_release(&s); continue;`（`after loop live=0`），所以问题定位在“跳转只释放最内层 block”，不是 `continue` 完全不支持。该结果直接反驳 SH-102 处置段与卡 §7.9.1 的“所有出口（return / break / continue / 末尾 `}`）release”声明；属于用户要求的“漏 release”，阻断。

### 11.4 B2 字段重赋旧值不 release（D-013 §3 “重新赋值”的泄漏）

`sb_assign` 只对局部绑定计算 `release_old`（[`Emitter.h.ct:805`](../../selfhost/ct-ast/backend/emit/Emitter.h.ct#L805)：`release_old = (idx >= 0 && g_sb.own[idx] && !borrowed)`）；字段 / 全局 / 解引用的 `idx < 0`，因此旧值永不 release。最小反例：

```ct
struct Holder { String tag; }
int main(void)
{
    Str a = "aaa";
    Str b = "bbb";
    String x;
    Holder h;
    x = a.to_string();
    h.tag = x;                       /* retain x */
    printf("after1 tag=%d x=%d live=%d\n", h.tag.refs(), x.refs(), ct_str_live_count());
    h.tag = b.to_string();           /* reassign an already-initialized field */
    printf("after2 tag=%d x=%d live=%d\n", h.tag.refs(), x.refs(), ct_str_live_count());
    x.release();
    printf("after_x_release tag=%d live=%d\n", h.tag.refs(), ct_str_live_count());
    h.tag.release();
    printf("final live=%d\n", ct_str_live_count());
    return 0;
}
```

```console
$ ./field_reassign; echo exit=$?
after1 tag=2 x=2 live=1
after2 tag=1 x=2 live=2
after_x_release tag=1 live=2
final live=1
exit=0
```

`final live=1` 说明第一次 `h.tag` 持有的 buffer 在字段重赋时泄漏。D-013 §3 写的是“**重新赋值**：先 retain 右值，再 release 旧值”，没有限定“仅局部变量”。若按 DEV 的窄解释（字段只在赋值时 retain、旧值由作者负责，见 §7.9.4/§7.9.7），应在 D-013 或卡上补明该限定；否则这是字面意义上的 D-013 §3 未满足。该条与 B1 独立，至少是 P1 级泄漏。

### 11.5 B3 已登记边界中仍有 UAF / 双重释放

### 11.6 未发现过度 retain；`refs=-1` 跳过成立

在覆盖到的命名位置上没有发现双 retain：

- `p80_retain` 的 `copy refs=2 keep=2` → `after copy release keep=1`；`field refs=2 keep=2` → `field after keep release refs=1`；`stolen refs=3 field=3` → `h.tag.release()` 后 `stolen refs=2`；`pass refs=2 keep=2` → `keep.release()` 后 `stolen refs=1`；`after reassign keep=2 other=2 live=1`；`final live=0`。
- 额外正例：全局 / 解引用非局部返回各 retain 一次（`g=2 x=2` → `y=3 g=3` → `y.release()` 后 `g=2`）；自赋值 `w = w` 不改变 refs；重赋 literal 释放旧值（`x=1 live=1`）；提前 return 走 move（`early z=2 x=2`）；U16 参数 / 字段 / pass-through 的 refs 分别为 `2→1`、`2→1`、`2→1`；`U16String.split` 的 `live 5→2→0`；`Vec<String>` 的 `vec push keep=2` / `vec_release keep=1` 与首轮一致。
- `refs=-1` 的 literal / empty / local copy 在 `p80_retain` 中为 `-1`，retain / release 均跳过。

即：B1/B2 是“漏 release”，不是“双 retain”；覆盖到的位置没有过度 retain。

### 12.3 R6（阻断）字段赋值 / 重赋在条件分支与循环中仍错

#### R6a 条件分支未执行 → release 未初始化字段（ASan SEGV）

```ct

int main(int argc, char **argv)
{
    Str lit = "abc";
    Holder h;
    int cond = (argc > 100);       /* runtime false */
    if (cond) {
        h.tag = lit.to_string();   /* not executed */
    }
    h.tag = lit.to_string();       /* source-safe: writes before any read */
    printf("after branch refs=%d live=%d\n", h.tag.refs(), ct_str_live_count());
    h.tag.release();
    return 0;
}
```

```console
$ ./field_branch_rt; echo exit=$?
```

生成的 C 把未执行的 `if` 分支当成“字段已赋值”，在后面的赋值里无条件 release 旧值：


根因是字段记账是**词法/静态**的：`sb_field_mark()` 在 `if` 体内赋值后就把 `h.tag` 标成 known
（[`Emitter.h.ct:962-975`](../../selfhost/ct-ast/backend/emit/Emitter.h.ct#L962-L975)），后续
`release_old` 由 `sb_field_known()` 决定（[`Emitter.h.ct:1104-1137`](../../selfhost/ct-ast/backend/emit/Emitter.h.ct#L1104-L1137)），
不区分该分支是否执行。这正是 SH-102 “未赋过值的字段不 release”声明的反例；也违反 D-013 §3
“字段赋值 / 重新赋值”的安全性。`cond` 用编译期常量 `0` 同样复现（`field_branch` 为 ASan BUS）。
