## 3 E80-1…8 逐条

### E80-1 布局与 `_Static_assert`：✅ 通过

- `String` / `Str` 均 16 B，`ct_str_hdr` 8 B，`_Static_assert` 随 `.ct` 源进入生成的 C 并由 `cc` 编译；不是只写在文档里。
- `refs = -1` 的 literal / empty 在 `release()` 后仍为 `-1`，`ct_str_live_count()` 不增；`abi` / `trace` 两条夹具均绿。
- 头文件注释与生成结构一致：`struct String { char *ptr; int len; }`、`struct ct_str_hdr { int refs; int aux; }`（[`lib/std/Str.h.ct`](../../lib/std/Str.h.ct) 顶部；生成 C 第 25–36 行）。

### E80-2 L1 immortal / 借用 / U16 仅工厂：✅ 通过

- `String s = "x"` / `String g = "..."` 绑定 `ct_str_lit_*` 静态块，`refs=-1`；`Str v = "x"` 是借用视图。
- `U16String` / `U16Str` 无隐式字面量：`neg_utf16_literal`、`neg_u16str_literal` 均硬错，实际 `U16String` 只从 `from_utf8` / `from_utf16` 工厂进入。
- 卡 §7.9.2 的“字面量实参只覆盖自由函数、`U16String.from_utf8("abc")` 需先绑定 `Str`”是已登记边界；E80-2 没有要求静态工厂实参隐式绑定，因此不构成 E80-2 失败。

### E80-3 不可变 / 只读下标：✅ 通过

- `p80_methods` 的 `neg_write_index`（`s[i] = ...`）与 `neg_u16_write`（`u[i] = ...`）均报 `read-only subscript`；`p80_cstr` 的 `neg_data_write` 报 `immutable`。
- `String` 没有 `set` 方法；`s[i]` 返回单码点 `Str`，`U16String[i]` 返回单 code unit `U16Str`，均为只读视图。

### E80-4 码点 / 字节 / slice：✅ 通过

- `p80_methods` 的 `u8` 行覆盖 `len`（字节）/`char_len`（码点）/`byte_at`/`codepoint_at`/`get`/`s[i]`/`char_at`/`byte_slice`/`byte_index_of(_from)`；`p80_methods/prog.expected.out` 的 `u8 bytes=104,195,169,108,108,111`、`u8 cps=104,233,108,108,111` 与 UTF-8 预期一致。
- `String.slice` 返回新 owning：`u8 slice len=2 refs=1 live=2`（`test/ast/p80_methods/prog.ct:47-48`）；`Str.slice` 在 [`lib/std/Str.h.ct:349`](../../lib/std/Str.h.ct#L349) 返回 `Str`，`str_slice` 仍是借用（`Str.h.ct:362`）。

### E80-5 `.data` / `cstr()` / printf 负例：✅ 通过（E80-5 断言）；D-013 §2 字面类型见 O1

- `.data` 只读、不保证 NUL；`cstr()` 复制并补 NUL；子视图 `.data` 没有插入 NUL：`subview=98,99,100`（`bc` 后紧跟父串的 `d`）。
- `printf("%s", s.data)` 硬错：`read-only raw view without a NUL guarantee`；`s.data[0] = 'x'` 硬错：`immutable`。
- 但 D-013 §2 写的“静态类型为 `const char *` / `const u16 *`”在实现中没有以该类型暴露：生成的 C 直接把 `.data` 降为 `s.ptr[0]`（`char *`），且 `const char *p = s.data;` 也被同一条“不能作为值传出”的硬错拒绝。即实现比 D-013 更严（index-only），不是字面意义上的 `const char *` 值。该差异不构成 E80-5 的失败，因为它要求的三类负例全部成立；见 O1。

### 4.3 §3 自动 retain：❌ 未实现（阻断）

#### 证据 A：夹具自己把缺口钉成回归

```console
$ grep -n 'gap' test/ast/p80_layout/expected.trace.out
3:gap param_refs=1 (no automatic retain on a by-value parameter)
$ sed -n '1,12p' test/ast/p80_layout/trace.ct
/* PH-80 S5a-1 / D-013 §3: the refcount trace at every position the retain
 * contract names - literal (immortal), explicit copy/retain/release, a
 * by-value parameter, a return, a struct field, a `Vec` element and
 * `own`/`delete`.
 *
 * The protocol this phase ships is explicit: `copy()` / `retain()` share the
 * buffer and bump `refs`, `release()` drops one reference. A `Vec` insertion
 * is the one automatic position (the container element glue calls `retain`);
 * a plain by-value parameter, return or field assignment is a shallow struct
 * copy and is NOT auto-retained yet - the `gap` lines below pin that fact
 * until D-013 §3's automatic half lands. */
```

卡 §7.9.1 与 spec §4.70、`lib/std/README.md`、`lib/std/Str.h.ct:23-28` 都同文自认“按值传参 / 返回 / 字段赋值未自动 retain”。这不是隐藏缺陷，但确实是 D-013 §3 的未实现。

#### 证据 B：按值传参 → ASan UAF（最小复现）

```ct

    String s = lit.to_string();
```

## 8 诚实性：是否“未覆盖写成通过”

1. **D-013 §3 的缺口不是隐瞒，但被“全通过”话术盖过。** 卡 §7.9.1、spec §4.70、`lib/std/README.md`、`Str.h.ct:23-28` 都明写“按值传参 / 返回 / 字段自动 retain 本轮未实现”；`trace.ct` 甚至用 `gap param_refs=1` 把它钉成回归。但卡头“E80-1…8 全通过”、§7.4 E80-8 的“✅ 通过”、以及 `AGENTS.md` 第 590 行的“E80-1…8 全通过”没有同时写 D-013 §3 未满足。E80-1…8 本身不含自动 retain 判据，所以“E80 全绿”为真并不能推出“D-013 满足”；把两者并列成“PH-80 收口完成”就是未覆盖写成通过。
2. **E80-8 的“spec 三处同步”被高估。** 新增 §4.70 存在且 `p80_docs` 绿，但 §4.56、glossary、tutorial §10.13 仍以现在时描述已删除的旧 owning `Str`（`str_from` / `str_c_str` / 深拷贝 `retain` / `impl Drop for Str`）；这些 API 在 `v0.80.0` 已不存在。`p80_docs.sh` 只 grep §4.70 关键词，未扫描旧节。此为本轮第二处覆盖缺口（O2），不改变 D-013 §3 的阻断结论，但 E80-8 不应写成“全绿”。
3. **删旧本身是真实的。** `StrLegacy.h.ct` 已删、`namespace std::str` 已无、`std::str::Str` 仅负例；12 个消费者已迁移；外部 dry-run 在仓外可重跑。这一点没有“假删旧”。
4. **C-7 证据与命令输出一致。** 在演练时点 `85a69bd0` 复现的 revert 状态与 23 条 FAIL 均与卡一致；卡也声明了只回滚实现提交的粒度限制。未发现伪造。

## 9 不阻断观察

- **O1 `.data` 静态类型措辞。** D-013 §2 与 spec §4.70 写“静态类型 `const char *` / `const uint16_t *`”，但实现把 `.data` 降为 `s.ptr`（`char *`），且 `const char *p = s.data;` 也硬错；实际是“只能下标的只读视图”，比 decision 更严。建议二选一：把 decision/spec 改成“index-only view，不作为值传出”，或实现真正可赋值的 `const char *` 视图。E80-5 的三类负例已成立，故本轮不据此单独打回，但它确实是 D-013 §2 的字面偏差。
- **O2 旧 `Str` 文档残留。** [`docs/language-spec.md:2594`](../language-spec.md#L2594)（§4.56）、[`docs/glossary.md:89`](../glossary.md#L89)、[`docs/tutorial.md:1584`](../tutorial.md#L1584) 仍写 `str_from` / `str_len` / `str_slice` 旧语义与深拷贝 `retain`，与 §4.70 的“旧类型已删除”矛盾。建议另立 `DOC-*` 或随 SH-102 修复一并清理；`p80_docs.sh` 应加旧节负例。
- **O3 `std::str` 外部命名空间。** [`examples/wave1-demo/src/main.ct:7`](../../examples/wave1-demo/src/main.ct#L7) 的 `import std::str::String` 是 ct-pkg `std` 的 `char *` 映射层，[`lib/std/README.md`](../../lib/std/README.md) 明确 `str` / `io` / `math` 仍由该包提供；[`test/modules/p29_builtin_std/needs_std.ct:3`](../../test/modules/p29_builtin_std/needs_std.ct#L3) 的 `import std::str;` 是内建层不含该命名空间的门禁负例。二者不是 old owning `Str` 的残留，但仓内仍能 grep 到 `std::str`，建议在删旧说明里点名这两处，避免下一轮误判。
