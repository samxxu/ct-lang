## 1 需要 ARCH 判的四件事

| # | 问题 | 现行建议 | 若要否决，代价 |
| --- | --- | --- | --- |
| Q1 | **触发面**：只认「字符串字面量键 + 非指针用户 struct 值 + 可回溯到变量/字段链的接收者」 | 保持最窄面：字面量、无转义/拼接、非临时量 | 收窄即失去本次能力；放宽（变量键/临时量）会把运行期语义拉进编译期 |
| Q2 | **优先级**：字面量键先查字段；字段与实例 `get(char *)` 并存时报**歧义硬错**，不静默选择 | 保留硬错 | 改为“字段优先、静默忽略 get”会掩盖一类真实歧义；改为“get 优先”则与 RFC 卖点相反 |
| Q3 | **诊断语义变更**：字段未命中且类型无 `get` 时，由 L52-1「没有下标协议」改为 D031-2「没有这个字段」并列出候选字段 | 接受该细化 | 保留旧文案则 `p["nope"]` 无法区分“无协议”与“拼错字段”，能力价值减半 |
| Q4 | **边界**：写形态、嵌套常量键、容器/数组/接口值常量键全部不做 | 保持 1.2 最小面 | 放宽任一项都会与 D-028 / I2（`D-034`）抢解析表 |

## 3 请重点看的边界与风险

**边界**

- 接收者必须可回溯（变量、字段/箭头链、数组/切片元素、解引用）；调用结果等临时量不折叠；
- 前向声明的字段表未知时，**不折叠也不报未知字段**（保守）；
- 转义、拼接、变量键一律不进本节，交回 §4.64 的 `get`；
- `&p["x"]` 属读位置，可折叠为 `&p.x`；
- `Box<T>` 内部字段不可达（`Box` 不折叠，报既有 D-028 诊断）；
- 与 D-028 的分工：I1 只改 **struct + 字面量**；接口值下标归 I2（`D-034`），两者共用解析表但互不改写。

**风险**

| # | 风险 | 现状处置 |
| --- | --- | --- |
| R1 | 字段名进入字符串后，重命名不再有编译期保护 | 字面量键在编译期解析到真实字段 id；未知键硬错并列候选字段；跨仓拼写漂移仍无保护 |
| R2 | **并存歧义由“可编译”变“硬错”**（原本走 `get` 的代码） | 属有意的 breaking；`D-031` 与 spec §4.79 已写明；1.2 窗口内是否接受需 ARCH 确认 |
| R3 | place 判定与 D52-4 同源，后续若放宽临时量可能回归 | 探针锁定链式/数组/泛型实例三类接收者；临时量保持不折叠 |

## 5 ARCH 结论（已填，2026-11-28）

| 项 | 结论 |
| --- | --- |
| 技术方案总体 | **接受但附条件**：方案本身（字面量键 + 非指针 struct 值 + place 接收者、字段优先、解析期唯一落点、只读）技术成立；条件为 C1–C10，均为测试/文档补齐项，不改协议与生成 C。详见 `D-031` §8。 |
| Q1 触发面 | **接受**。字面量 + 非指针 struct 值 + 可回溯接收者是编译期可判定的最大集合；变量键/拼接/转义只能走运行期 `get`，临时量会引入临时或改变求值次数。附条件：C1 临时量负例保持 L52-1、C2 `&p["x"]` 正例并写清先于 L52-7、C3 前向声明探针。 |
| Q2 字段优先与歧义硬错 | **接受**。静默选字段是语义漂移，静默选 `get` 让新能力失效；硬错与 D-028“不静默选择”一致，并给出两条显式替代写法。附条件 C4：只有匹配且可见的 `get` 才触发 D031-1，私有/`static`/arity/参数类型不同均不触发。 |
| Q3 诊断语义变更 | **接受**。把“无下标协议”（L52-1）细化为“无此字段”（D031-2）是本能力的定义面，否则拼错字段无法定位。附条件 C5：候选按声明顺序、一次一条、有 `get` 时完全交回 D-028；C6：spec §4.64 与 §4.79 同步可见。 |
| Q4 边界 | **接受**。写形态、嵌套键、容器/数组/接口值常量键不做，是 1.2 的正确最小面，避免与 D-028 多级链和 I2 抢解析表。附条件 C7：嵌套键用探针钉住实际行为；C8：接口值字面量键不进 I1。 |
| 风险 R2（breaking）是否可接受 | **可接受（有意 breaking）**。触发面仅“字段 + 匹配 `get(char *)` 且源码用同名字面量键”；仓库 25 条用户语料 + 83 条 IR 语料零命中；静默两选一与“加警告”均更差。附条件 C9：spec/release note/LANG-31 写成显式迁移项；C10：EDITOR 签收前不建 tag。 |
| 附条件 / 后续项 | C1–C10 见 `D-031` §8.1–§8.6（补测 4 条、spec 状态行同步、release note 迁移说明、EDITOR 签收后才可 tag）；均不要求改 D-028、生成 C 或 seed。 |
| 日期与签署 | ARCH 2026-11-28 |
