# 评估：v1-pre 源码单元切分提案（v3 裁定）

| 项 | 值 |
| --- | --- |
| 评估对象 | 外部《v1-pre 重写期的源码组织——单元细切分》（v2，2026-11-21 收；仓外文件） |
| 评估方 | REQ |
| 结论 | 方向受理；按 A/B/C/D 四组逐条裁定，升 v3；落点 [D-017](../decisions/D-017.md) |
| 关联 | [v1 路线](../planning/v1-release-plan.md)、[D1–D9](2026-11-21-v1-campaign-eval.md)、[PH-84](../design/phase84.md) |

## 1. 事实核对

| 项 | 现状 |
| --- | --- |
| 规模 | ct-ast 42,773 行；`Emitter` 8,811、`Expr` 8,806、`Stmt` 4,863、`Parser` 4,493 |
| 产物命名 | 发射文件名 = `units[u].base + ".c"`；拆分/改名会改变输出集合 |
| 定义顺序 | 函数/全局可先用后定义；类型/trait 必须先声明 |
| golden 现状 | `check-goldens.sh` 是 L1 定向；ct-ast 无“编译单元集合”oracle |
| 文件级状态 | `Emitter` 有 `g_sb`、`g_slice_used`、`g_emit` 等 |

## 2. A 组：判据（全部改写）

| # | 争议 | v3 裁定 |
| --- | --- | --- |
| A1 | R 切片“golden 零 diff”不可行 | **两级制**：测试语料发射产物逐字节不变；编译器自身实现的发射 C 允许差异，靠自举不动点 + ASan + 行为测试 |
| A2 | “集合一致、增删即红”与拆分矛盾 | 改为**期望集合基线 + 旧→新映射**；允许有意变更，同一 commit 更新基线 |
| A3 | `git diff -M` 判不了纯移动 | J1 = **函数体哈希集合不变 + 机械行白名单**（import/include/声明重排） |
| A4 | “import 图无环”未证明 | J4 = **M 不新增环**；先交现状环清单；破环单独成案 |
| A5 | 4K 阈值与文件尺寸不匹配 | 先按函数分布校准；校准前用“单元数不设上限、阈值仅告警” |

## 3. B 组：可行性（全部接受补盘点）

| # | 争议 | v3 裁定 |
| --- | --- | --- |
| B1 | 文件级状态无法“零逻辑变更”搬移 | 行为不变、**接口可变**（static→pub、状态暴露）；交付状态清单 + 归属规则 |
| B2 | 小写泛名与现有命名/产物冲突 | 命名 = `<Subsystem><Role>.h.ct`（PascalCase、全局唯一）；产物影响进 M0 卡 |
| B3 | “定义先于使用”事实错误 | 修正：函数/全局可先用后定义；类型/trait 必须先声明 |
| B4 | `Str` token 生命周期/NUL | 源缓冲生命周期覆盖解析阶段；NUL API 迁移带长比较与 `cstr()`；归词法器 R 卡 |
