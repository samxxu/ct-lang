## 1. 提案摘要

- §3 自举去级：J-6 后拆 L1/L2、先做 goldens 静态化、保留 L0 种子；
- §4 把 ct-ast 用新语法重写，并提前到 v1.0 之前；
- §2 发布前清单 G1–G10；
- §5 顺序：golden 静态化 → 去级 → ADT（可选）→ 四切片重写 → 三轮自举 → v1.0。

## 3. 已定项（已落计划）

见 [v1-release-plan §1.5](../planning/v1-release-plan.md#L57-L71)：

## 4. 重写部分（v1-pre，D1/D3 已定）

见 [v1-release-plan §2.3/§2.6](../planning/v1-release-plan.md)：

- PH-84 先做最小 ADT/match，为重写提供穷尽判别；
- PH-85 inventory 先行 + 单切片 spike，量出行数/编译耗时/golden 逐字节/Sharp edge；
- spike 通过才排后续切片（PH-86–88）；
- 自举复用现有 fixpoint；
- 不依赖未落地特性（含 S4 函子）。

## 6. 风险提示

| 风险 | 说明 |
| --- | --- |
| 重写提前 | 把 MAJOR 收口从“删旧管线”扩大为“42.8k 行重写”，失败隔离与版本纪律变差 |
| 零拷贝词法器 | `Str` 非 NUL 结尾，现有 `strcmp`/`%s` 用法需系统性改造，不是纯语法替换 |
| 函子依赖 | S4 未落地；在重写中引入会同时改变两件事的失败归因 |
| 并发开发 | 多会话并行提交；“不冻结 + rebase”会放大冲突成本 |
| deadline | 与“不承诺时间”口径冲突，且 J-6 证据量未知 |
