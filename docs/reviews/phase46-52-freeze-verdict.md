## 0 裁决席实测（四个对撞点）

### 0.1 `v[0]` 在方案 A 下的真实行为

```sh
CT_STD_DIR=/tmp/ct-head/lib/std /tmp/ct-head/ct-ast p52_map0.ct -o p52_map0.c   # rc=0
cc -Wall -Wextra -std=c99 p52_map0.c -o p52_map0                                  # rc=0
./p52_map0                                                                         # zero=0x0 hit=7, rc=0
```

- 生成代码里 `get` 有 `if ((_self->h == 0) || (k == 0)) return 0;`（`Vec.h.ct:260-269` 的同一分支）。
- `0` 是 C 的空指针常量，`cc -Wall -Wextra` **零告警**。
- **裁定事实**：方案 A 下 `v[0]` 会展开成 `get(0)`，**不硬错、不崩溃、静默返回 0**。主张席与反证席
  在这一点的结论一致；分歧只在「是否可接受」。→ v0-PH-52 的 RL1-E12 必须收缩，`v[0]` 不主张。

### 0.2 v0-PH-50 的出参形态

```sh
# take(Vec<Str> *v, Str *out) { *out = v->get(0); }  +  s.release(); v.release();
cc -std=c99 -fsanitize=address p50_outparam.c -o p50_asan && ./p50_asan             # rc=134
```

```text
AddressSanitizer: attempting double-free ... in Str_release
  #2 Vec_Str__elem_release  #3 Vec_Str_release  #4 main
freed by ... Str_release  #2 main
```

- **裁定事实**：`try_get(..., V *out)` 对带所有权的元素（`Str` / `use Drop`）**必然双释放**；
  `get` 返回的是容器持有的借用副本，出参再释放一次。→ **换设计，不修形态**。

### 0.3 v0-PH-51 泛型实例的零告警

```sh
CT_STD_DIR=... ct-ast p51_generic.ct -o p51_generic.c   # rc=0
cc -Wall -Wextra -std=c99 p51_generic.c -o p51_generic  # rc=0，零告警
./p51_generic                                           # rc=139
grep: Vec_int_push(&p, 7)   # 形参是 void *self
```

- **裁定事实**：泛型实例的方法形参是 `void *`，`S_f(&p)` 不触发 `incompatible-pointer-types`，
  `cc` 完全看不见；非泛型实例才有 `S *` 形参并出 warning。→ v0-PH-51 的判据不能只靠 `cc` 告警，
  必须断言**生成 C 的实参形态**（`p` 而非 `&p`），并把泛型实例列为主用例。

### 0.4 v0-PH-48 的两个独立决策所依据的代码

| 事实 | 位置 |
| --- | --- |
| 胶水只为「本单元符号表里的非模板 struct」发射；`has_drop_impl` 为真就 `continue`（不发射） | `Emitter.h.ct:3101-3115` |
| 本单元对每个 `uses_drop` struct 都发 `static … _Drop_drop(void *self);` 前置原型 | `Emitter.h.ct:2615-2619` |
| 消费单元看不到 impl 时 `has=0` → 发函数体；无 Drop 字段时体为 `(void)_self`（空桩） | `Emitter.h.ct:3114-3139` |
| 第二个发射点 `try_release_payload` 对指针字段**早退**，与胶水不同判据 | `Emitter.h.ct:5764-5770`、`:5800-5801` |

- **裁定**：这是两个决策，分别裁（见 §1 R48-1 / R48-2），不合并。

### 4.1 签字后的取舍记录

两条建议值之间存在张力的地方，按「不破坏 JS 风格访问目标 + 最小改动」取：

| 张力 | 取舍 | 理由 |
| --- | --- | --- |
| U-2 A（Drop 符号默认可见）vs v0-PH-46 的实例归属 | 取 **U-2 A**，v0-PH-46 的 D46-2 不动 | 46 裁的是 **C 结构体定义**归属，48 裁的是 **函数符号**可见性；两者不在同一命名空间。若为 48 走 B（要求 `pub`），会迫使所有 Drop 加 `pub`，改动面远大于收益 |
| U-1 A（保留 `[]`、只主张字符串键）vs 数字下标静默空 | 取 **U-1 A**，但把「参数类型匹配（`v[0]`）」登记为长期需求 REQ-JSACCESS-1，不占相号 | 撤回 `[]` 会丢掉 JS 风格访问的语法入口；扩到方案 B 会拖住 52。保留语法 + 登记后续，既不砍目标也不扩本期 |
| U-3 A（深拷贝、删 `put_owned`）vs 键所有权完整性 | 取 **U-3 A** | 加所有权位会改 `MapEntry` 布局与全部 `Map` golden，违反「最小改动」；深拷贝已消除借用失效与 `\0` 碰撞 |
