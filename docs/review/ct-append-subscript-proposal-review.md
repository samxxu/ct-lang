# 研判记录 · 追加下标语法提案（`v[] = x`）

- 日期：2026-11-15
- 对象：[ct-append-subscript-proposal](../proposals/ct-append-subscript-proposal.md)
- 证据基线：HEAD `v0.53.1` 重建 `ct-ast`（`/tmp/cthead`）
- 形式：逐条反证（主张 → 反证 → 裁定）
- 结论：**通过方向**，但只在「语句级语法糖、仅 `Vec`、失败即 abort、不放开 `v[i] = x`」
  四条同时成立时通过；本轮不排 phase 卡、不改 `selfhost/**`

## 1 主张席

- `Vec::push(x)` 已存在，缺的只是与读下标对称的写法；
- `v[] = x` 最短、语义直观，且今天本来就是解析错误，不存在兼容负担；
- 降级到既有 `push`，零 ABI。

## 2 反证席

| # | 反证 | 裁定 |
| --- | --- | --- |
| C1 | 只是语法糖，不值得扩语法 | 部分成立。若目标是可读性，语法糖就是收益；但必须限制为语句级、无返回值，且不引发「下标可写」的连锁期待。 |
| C2 | 用户会以为 `v[i] = x` 也能写 | 成立。`v[i] = x` 保持现状（`read-only; use set(i, v)`），并在文档/诊断里明确「空下标是追加，不是写任意下标」。 |
| C3 | `push` 失败返回 0，赋值语句丢返回值 | 成立，**必须定**：推荐失败即 abort，与 `Vec::from` 分配失败 abort 一致；静默忽略不通过。 |
| C4 | `v[]` 与 `v[i]` 解析会冲突 | 不成立。`[` 后紧跟 `]` 再紧跟 `=` 才进入追加形态；`[expr]` 路径不变。读位置的 `v[]` 继续硬错，可改更明确文案。 |
| C5 | 对 `Map` 也应适用 | 不成立。`m[] = v` 没有键，语义不成立；硬错并提示 `put(k, v)`。 |
| C6 | C 数组也应该能 `a[] = x` | 不成立。C 数组不可增长；给专门诊断，不静默套用 `Vec` 语义。 |
| C7 | `v[] = v[0]` 的求值顺序不明 | 成立。规定先算 RHS 再 `push`；`at()` 的借用指针在追加后失效，文档写明。 |
| C8 | 容量增长/越界语义要重新定义 | 不成立。完全复用 `push`：翻倍、失败返回 0（本语法再 abort）、无越界概念；`has`/`at` 不变。 |
| C9 | 会动 ABI | 不成立。降级为 `Vec_<enc>_push` 调用，不新增符号；`.abi.h` 逐字节不变。 |
| C10 | 应顺手放开 `v[i] = x` 保持一致 | 否决。`set` 越界是 no-op，放开赋值会引入静默不写；另案处理，不夹带。 |

## 3 裁定

- **定性**：语法糖（B 类），不是 bug、不是新容器语义；
- **通过条件**：
  1. 只允许语句位置 `v[] = x;`，无返回值；
  2. 只对 `Vec<T>`，`Map` / C 数组 / `Str` 硬错；
  3. `push` 失败即 abort，不静默；
  4. `v[i] = x` 保持拒绝，非目标写死；
- **落点**：拟占 **PH-61**（在 PH-59 / PH-60 之后）；若 PH-56 容器语法批次复活，作为其切片；
- **不排 phase 卡**：待需求定稿、roadmap 登记后再开。

## 4 未决问题（进需求定稿前回答）

1. abort 的错误文案与退出码（建议 `Vec: append failed`，与 `Vec::from` 一致）；
2. 读位置 `v[]` 的新文案是否统一为 `empty subscript is only allowed on the left of '='`；
3. 是否同时提供 `append` 方法别名（本提案不要求）；
4. 未来是否单独立项「`v[i] = x` 的越界语义」，与本提案解耦。

- 在需求定稿前，本语法不进入 patch 队列。
