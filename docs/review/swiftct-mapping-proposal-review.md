# 研判记录 · SwiftCT 静态映射两项提案（模型导出 / 视图注记）

- 日期：2026-11-15
- 对象：[ct-model-export-proposal](../proposals/ct-model-export-proposal.md)、
  [ct-view-annotation-proposal](../proposals/ct-view-annotation-proposal.md)
- 证据基线：HEAD `v0.53.1`（`a8f9a113`），`ct-ast` 由 L0→L1→L2→ct-ast 链在 `/tmp/cthead` 重建
- 形式：逐条反证（主张 → 反证 → 裁定），两席均以可复现证据为准
- 结论：**两项均进入需求定稿阶段**；模型导出先定稿，注记等模型 schema 冻结后定稿；
  本轮不排 phase 卡、不改 `selfhost/**`

## 1 模型导出提案

### 1.1 主张席

- `--emit-map` 已被证伪为生成器输入：`file` 指向 `lib/std/Vec.h.ct`，输入单元缺失（SH-79），
  且没有字段表/可见性/kind/形参类型；
- 外部解析 `.h.ct` 等于复刻前端；
- 因此需要一个稳定、版本化的 `--emit-model`。

### 1.2 反证席

| # | 反证 | 裁定 |
| --- | --- | --- |
| C1 | 先扩 `--emit-map` 更省事 | 否。调试映射的 `calls`/`maps` 形状会被冻结成契约，后续改调试字段就破生成器；且 `--emit-map` 的 `file` 语义（单 prog）与多单元模型冲突。维持「新入口」 |
| C2 | 两套序列化会漂移 | 成立，列为**实施前置**：`--emit-map` 与 `--emit-model` 共用一个内部模型结构，只换序列化；否则提案不通过 |
| C3 | `visibility` 现在不可信（LANG-9 未落地） | 成立。**2026-11-15 已定**：schema 第一版允许 `visibility: "unknown"`，不得猜、不得据此过滤字段；LANG-9 落地后填真值 |
| C4 | 绝对路径可接受 | 否。生成器需要可复现输入；强制相对路径，验收断言不含 `/tmp/` |
| C5 | 与 LANG-10 / PH-58 合并成一条总需求 | 否。诊断码与模型契约的变更节奏不同；只共享信封/版本/路径/确定性四条口径（提案 §5） |
| C6 | schema 版本号多余 | 否。外部消费者必须能判断兼容性；固定 `schema_version: 1`，只增不改，破坏性变更 +1 |

### 1.3 裁定

- **通过方向**：新增 `--emit-model`，不扩 `--emit-map` 的契约面；
- **通过条件**：共用一个内部模型（C2）、`visibility` 允许 `unknown`（C3）、相对路径（C4）、
  schema 版本（C6）；
- **下一步**：写 `REQ-MODEL-*` 需求定稿（字段集、CLI、schema v1、验收 M1–M8），进 roadmap 后
  才开 phase 卡；拟占 **PH-59**，排在 PH-58 之后。

## 2 视图注记提案

### 2.1 主张席

- 外部清单会漂移，注释无法校验；
- `pub const` 能表达值，但会产生导出符号，且没有字段校验；
- `view` 子句能同时做到编译期校验、零 ABI、模型可导出。

### 2.2 反证席

| # | 反证 | 裁定 |
| --- | --- | --- |
| C7 | 用 `pub const` 就够了，何必加语法 | 否。实测 `pub const struct Node ROOT` 生成 `extern const struct lib_Node lib_ROOT;`，会进 ABI；且字段名是字符串，重命名不报错（提案 §5 对比表） |
| C8 | 注释 pragma 更轻 | 否。编译器不读就无法校验；模型导出要再写注释解析器，工具链分裂 |
| C9 | `view` 关键字会撞名 | 部分成立。限定为「struct 体 `}` 之后」的上下文关键字，字段/变量名 `view` 加回归；不新增全局保留字 |
| C10 | 私有字段被注记引用会泄露 | 成立，列为**需求定稿开放项**：允许但标 `visibility`，或只允许 `pub`；二者择一写进 REQ。**2026-11-15 负责人已定：模型导出全量字段（含非 `pub`），`visibility` 在 LANG-9 前标 `unknown`；注记能否引用私有字段仍按此口径执行** |
| C11 | 注记会滑向运行时框架 | 风险成立。非目标写死（无 JSX/无绑定执行/无属性协议），评审守住 |
| C12 | 注记应先于模型导出（先有声明再谈导出） | 否。注记没有统一下游就是「写了没人读」；模型 schema 先行，注记才有出口。顺序反了 |

### 2.3 裁定

- **通过方向**：`view` 子句（方案 A），不做 `pub const` 描述符、不做注释 pragma；
- **通过条件**：上下文关键字（C9）、私有字段策略定稿（C10）、非目标冻结（C11）；
- **前置依赖**：PH-59 的模型 schema 冻结后再写 `REQ-VIEW-*`；拟占 **PH-60**；
- 本轮**不**开 phase 卡、不改前端。

## 3 两项之间的关系

- 模型导出（PH-59）**先于**注记（PH-60）：注记的产物必须落进已冻结的模型 schema；
- 二者与 PH-58 的关系：PH-58 是诊断/位置；模型导出只把位置当可选字段，不阻塞；
- 与 PH-53 / PH-54 / PH-57：无依赖，不改动其判据。

## 4 未决问题（进需求定稿前必须回答）

1. `--emit-model` 的输出目标是文件还是 stdout？`-` 是否表示 stdout？
2. 多根单元时是「一个合并模型」还是「每根一个文件」？（提案倾向合并，按 `units` 区分）
3. `visibility` 在 LANG-9 落地前是否允许 `unknown`，还是干脆不输出该键？
4. `view` 的 `state` 是否必须恰好一个？是否允许 `state` 指向非字段的表达式（第一版禁止）？
5. 私有字段能否被 `child` / `state` 引用？**模型导出侧已定**：全量字段都导出、`visibility` 标
   `unknown`/真值；注记侧按同一口径（允许引用，标可见性），不再作为阻塞项。
6. 嵌套视图的环如何处理（允许/报错）？
7. 模型里是否导出 enum 成员（第一版列为非目标，需确认 SwiftCT 是否必需）。
